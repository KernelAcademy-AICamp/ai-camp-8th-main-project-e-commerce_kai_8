# 플로팅 검색 — 설계안

> 상태: Codex 리뷰(2026-08-16) 반영 완료. 사용자 최종 승인 대기.

## 배경·요구사항 (사용자 결정 사항)

- **대상**: aTee 첫 페이지(`/`)에만 플로팅 검색창을 추가한다.
- **동작**: 스크롤을 내리면 검색창이 원형 버튼으로 축소되는 애니메이션. 축소 상태에서 클릭하면 다시 검색창으로 확장.
- **범위**: UI만이 아니라 **실제 검색까지** 구현 (백엔드 검색 RPC 포함).
- **결과 표시**: 별도 페이지가 아니라 **같은 페이지의 모자이크 피드가 검색 결과 모드로 교체**된다. 검색어를 지우면 원래 피드 복귀.
- **실행 시점**: 엔터/검색 버튼 **제출 시에만** 검색 (실시간 디바운스 아님).
- **위치**: 하단 중앙 플로팅 (엄지 도달 영역).
- **구조**: `features/feed/search/` — feed의 하위 기능 (기존 `detail/`, `wishlist/`와 같은 패턴).

## 현재 코드 컨텍스트

- Next.js App Router + TS + Tailwind PWA. clean architecture + MVVM (`frontend/AGENTS.md`).
- 첫 페이지: `frontend/app/page.tsx` → `MosaicFeed` (2열 masonry, window 스크롤 기반 무한 스크롤).
- 데이터: Supabase RPC (`rpcPost`) — `c_feed_page`(무작위, keyset 커서), `c_mix_page`(개인화), `c_similar_page`(임베딩 유사).
- 뷰모델: `use-feed-view-model.ts` — 개인화/무작위/유사 폴백 로직 보유. `paused` 옵션으로 로드·계측 중지 지원.
- 테마: 다크 (#0a0a0a 배경, Cosmos형 피드 — 결정 기록 O-22).
- 백엔드: `backend/supabase/migrations/*.sql`로 RPC 관리. anon 쿼리는 statement_timeout 8초.

## 1. 백엔드 — 검색 RPC

새 마이그레이션으로 `c_search_page(p_query text, p_after bigint, p_size int)` RPC 추가.

### 검색 대상·노출 자격 (리뷰 #1)

- 실제 뷰 이름은 **`c_feed_products`** (마이그레이션 `20260814100000_c_feed_view.sql`).
- 검색 후보는 뷰 조회만으로 부족하다 — 현재 `c_feed_page`가 적용하는 **`c_thumb_dims.card_ok` 자격을 동일하게 적용**해서, 기본 피드에서 제외된 상품(표·라벨·디테일 이미지 썸네일)이 검색으로 재노출되지 않게 한다 (`20260816180000_mix_weight_and_card_filter.sql` 참고).
- 매칭: 제목(title)·브랜드명(brand_name) 대소문자 무시 부분 일치. 검색어를 공백으로 나눠 **모든 단어가 제목 또는 브랜드에 포함**되면 매칭.

### 인덱스·성능 (리뷰 #1, #5)

- `c_feed_products`는 일반 뷰라 인덱스를 만들 수 없다 → **기반 테이블 `c_goods`의 title·brand_name**(또는 결합 표현식)에 pg_trgm GIN 인덱스를 만든다.
- **pg_trgm 확장 활성화**(`create extension if not exists pg_trgm`)를 같은 마이그레이션에 포함한다 (현재 마이그레이션엔 없음). 확장 설치 스키마와 operator class 지정도 명시한다.
- pg_trgm 한계를 인지하고 시작한다: 3글자 이상("나이키", "티셔츠")은 인덱스 유효, **2음절 단독 검색어("반팔", "블랙")는 인덱스 이점이 거의 없어 스캔으로 퇴화**할 수 있다. 띄어쓰기 변형·오타·한영 별칭·의미 검색은 미지원 — MVP 한계로 문서화.
- **구현 단계에 EXPLAIN (ANALYZE, BUFFERS) 검증을 포함**한다: 단독 2음절·3음절·영문 브랜드·복합 검색어를 각각 측정하고, anon 8초 timeout 안에서 안전한지 확인한다. 2음절 성능이 수용 불가면 대응(예: 결과 수 제한, 최소 길이 정책)을 그때 결정한다.

### 입력 방어·권한 (리뷰 #6)

anon이 직접 호출 가능한 RPC이므로 서버에서 방어한다 (`20260816230000_mix_input_guard.sql` 선례):

- 검색어 길이 상한·단어 수 상한, NULL·공백류(탭·개행) 정규화.
- `p_size` 범위 제한.
- 사용자 입력의 `%`, `_`, `\`는 **리터럴로 escape** — `%` 제출로 전체 카탈로그 스캔을 만들 수 없게 한다.
- `security definer` 사용 시 `search_path` 고정.
- `revoke all from public` 후 `anon`·`authenticated`에만 grant (`c_feed_page` 패턴).

### 정렬·페이징 (리뷰 #7)

- **MVP 정렬은 `goods_no` 오름차순으로 확정** — 관련도 정렬이 아니라 단순·안정 keyset을 의도적으로 선택한다(페이지 간 중복·누락 없음). 관련도 정렬이 필요해지면 (점수, goods_no) 복합 커서로 확장한다.
- `p_after`는 마지막 `goods_no` 커서.
- 응답 행 구조는 `c_feed_page`와 동일 → 프론트에서 기존 `mapFeedDto` 재사용.

### 모드 전환·상태 소유 (리뷰 #8, #9)

- `MosaicFeed`가 검색 모드의 소유자다. 검색 상태 훅(`use-search-state`)은 **상세 스택과 같은 층위(MosaicFeed)에서 항상 유지** — 상세가 열려도 언마운트하지 않아 입력값·축소 상태가 보존된다. 상세가 열린 동안 검색 UI는 렌더는 유지한 채 비표시·비포커스로만 만든다.
- **기본 피드의 DOM은 검색 모드에서 유지하지 않는다** (전체 카드 DOM + 옵저버를 계속 살려두는 비용 회피 — 상세 레이어조차 3층 제한하는 코드베이스 방침과 일치). 보존하는 것은:
  - `use-feed-view-model` 훅 상태(상품 목록·커서) — 훅은 MosaicFeed에 있으므로 그리드만 조건부 렌더하면 자연히 유지된다.
  - `window.scrollY` — 아래 스크롤 전이 참고.
- 검색 모드에서는 기본 피드 그리드를 렌더하지 않고 검색 그리드를 렌더한다. 카드 dimensions(width/height)가 데이터에 있어 masonry 높이가 결정적이므로, 복귀 시 이미지 로드 전에도 레이아웃 높이가 재현된다.
- `use-feed-view-model`은 "절대 불변"이 아니라 **최소 변경 허용**: 기존 `paused` 옵션에 검색 모드를 OR 조건으로 넘기는 수준(호출부 변경)이면 훅 내부 수정 없이 가능할 것으로 보이나, 센티널 재연결 등 작은 수정이 필요하면 허용한다.
- `FeedGrid`의 카드 타입(`FeedCardViewData`)이 현재 `use-feed-view-model.ts`에 정의되어 있어 검색 훅이 기존 뷰모델 파일에 의존하게 된다 → **표시용 타입을 재사용 가능한 위치로 이동**(예: presentation 공용 타입 파일)해 검색·피드 훅이 같은 표시 계약을 공유한다.

### paused 계약 (리뷰 #3)

명시적 활성 조건을 정의한다:

- **기본 피드 훅**: 상세가 열렸거나 **검색 모드이면** paused.
- **검색 피드 훅**: 상세가 열렸거나 **검색 모드가 아니면** paused (검색 그리드는 상세 아래에서 DOM상 보이므로 hidden 우연에 의존하지 않고 명시적으로 막는다).
- 모드 전환 직전에 날아간 로드 응답은 **버린다** (아래 요청 경합 규칙과 동일 세대 검사).
- 검색 결과에서 상세 스택이 열린 동안 검색 센티널의 추가 로드도 중지.

### 검색어 상태·요청 경합 (리뷰 #4)

- 상태를 둘로 분리한다: **입력 중 검색어**(input 값)와 **제출된 검색어**(현재 결과를 소유). 결과 라벨·페이징은 제출된 검색어만 참조한다. 결과를 본 뒤 입력을 수정해도 결과는 그대로다.
- **요청 세대(generation) 번호**로 경합을 방어한다 — 응답 도착 시 세대가 다르면 폐기:
  - A 제출 중 B 제출 → 늦게 온 A 응답 폐기.
  - 요청 중 검색 해제 → 응답 폐기.
  - 이전 검색의 재시도 타이머가 새 검색에 개입하지 않음 (재시도도 세대 검사).
  - 새 검색 제출 시 커서(`p_after`)·목록 초기화 후 시작.

### 상세·계측 연동

- 검색 그리드도 같은 `FeedGrid`·`FeedSkeleton`·`ProductCard` 재사용. 카드 탭 시 **기존 `useDetailState` 스택을 기본 피드와 공유**해 상세가 그대로 열린다.
- 검색 노출은 개인화 노출 계측(`onImpress`)에 **기록하지 않는다** (검색 노출은 취향 신호와 성격이 다름). 상세 열기·찜 행동은 기존 중앙 경로로 그대로 기록된다.

### 스크롤 전이 (리뷰 #2)

피드는 window 스크롤을 쓰므로 hidden/언마운트 시 문서 높이가 줄어 `scrollY`가 강제로 당겨진다. 상태 전이를 명시한다:

1. 검색 제출(모드 진입) 직전: 현재 `window.scrollY` 저장.
2. 검색 결과 표시·새 검색 제출 시: 문서 최상단으로 이동.
3. 검색 해제(모드 이탈): 기본 피드 그리드를 먼저 레이아웃에 복귀시킨 뒤 저장한 위치로 복원.
4. 복원·이동 과정의 **프로그램적 스크롤은 검색창 축소/확장 판정에서 제외**한다.

(상세 스택의 `savedScrollTop`은 상세 내부 컨테이너 전용이라 재사용하지 않는다.)

## 3. 검색창 UI·애니메이션

- **확장 상태**: 하단 중앙 플로팅 알약형 — 반투명 다크(`bg-neutral-900/90` + backdrop-blur), 얇은 보더, 🔍 아이콘 + 입력창 + (입력 있을 때) X 버튼.
- **축소 상태**: 지름 ~48px 원형 버튼(🔍만). 스크롤 **아래로** 일정량 넘게 내리면 축소. **위로** 스크롤하거나 축소 버튼을 탭하면 재확장 (탭 시 입력 포커스까지).
- **전환**: CSS transition(너비·둥글기·내용 opacity, ~250ms). 라이브러리 추가 없음. 축소돼도 입력값 유지.
- **표시 범위**: 첫 페이지에만. 상세 레이어가 열려 있는 동안은 비표시(언마운트 아님 — 상태 보존, 리뷰 #9).
- **동의 배너와의 겹침** (리뷰 #10): 최초 방문 시 `ConsentNotice`가 하단 고정(z-40)으로 같은 영역을 차지한다 → 배너가 보이는 동안 검색창을 배너 위로 밀어 올린다(검색은 항상 접근 가능해야 하므로). 안전 영역(safe-area-inset-bottom)과 피드 하단 패딩도 검색창 높이만큼 확보한다.
- 제출하면 키보드가 닫히고 피드가 검색 결과로 교체, 결과 상단에 "'검색어' 결과" 최소 표시.

## 4. 엣지 케이스·실패 처리 (리뷰 #10)

- 결과 0건: "결과 없음" 안내 + 검색어 지우기 버튼.
- **RPC 실패: 자동 무한 재시도 대신 오류 표시 + 수동 재시도 버튼** (검색은 명시적 사용자 행동이고 폴백 피드가 없으므로, 빈 스켈레톤을 계속 보여주며 서버를 두드리지 않는다).
- 빈 검색어·공백만 제출: 무시 (검색 모드 진입 안 함).
- `%`·`_` 등 특수문자 제출: 서버에서 리터럴 escape (리뷰 #6).

## 5. 테스트 (리뷰 #10)

- 검색 API 매핑 테스트 (`search-api.test.ts`) — 기존 `feed-api.test.ts` 패턴.
- 검색 상태 훅: 제출/지우기/축소·확장 전이, 입력값 vs 제출 검색어 분리.
- 요청 경합: A 제출 후 B 제출, A가 늦게 응답 → A 폐기. 요청·재시도 중 검색 해제 → 폐기.
- 모드 전환: 깊은 피드 → 0건 검색 → 해제 후 스크롤 복원. 상세가 열린 동안 검색 추가 로드 중지.
- 백엔드: `card_ok=false` 상품 검색 제외, `%`·`_`·다중 공백·2음절 한국어·복합 검색어, 페이지 경계 중복·누락 (pytest).
- 완료 확인: `npm run check` **+ `npm run test`** (check에는 test가 포함되지 않음) + Orca 브라우저 실기기 흐름 확인 — 검색 결과에서 상세 → 유사 상세 체인 → 뒤로가기, 동의 배너와 검색창 겹침.

# 설정 화면 버전 표기 — 설계

- 작성: 2026-08-20
- 상태: 합의됨 / 구현 전
- 관련: [마이페이지 분리 설계](2026-08-19-my-page-design.md) §1 (설정 화면 구성)

## 배경

설정 화면(`/settings`)에 이 앱이 어떤 버전인지 알려주는 표기가 없다. 제품으로서 갖춰야 할 기본 정보이고, 문제를 이야기할 때 "어느 버전에서 봤는지"를 가리킬 근거가 된다.

릴리즈 워크플로가 이미 `frontend/package.json`의 version과 git 태그를 올리고 있으므로, 표기할 값 자체는 존재한다. 화면으로 꺼내오기만 하면 된다.

## 범위

**이번 조각** — 설정 화면 맨 아래 한 줄 표기. 버전 + (프로덕션이 아닐 때만) 환경.

**이번 조각이 아닌 것**

- **"앱 정보" 섹션 신설** — 지금 넣을 항목이 버전 하나뿐이다. 이용약관·만든 사람 같은 항목이 생기면 그때 묶는다.
- **커밋 식별자 표기** — 프리뷰 배포끼리 구분하려면 필요하지만, 이번 목적은 "제품 기본 정보"이지 "어느 빌드인지 판별"이 아니다.
- **업데이트 알림·새로고침 유도** — 버전을 *보여주는* 것과 최신 여부를 *판정해 행동을 유도하는* 것은 다른 기능이다.

## 1. 보이는 것

설정 화면 맨 아래, 계정 삭제 섹션 다음. 가운데 정렬된 작은 회색 한 줄. 링크·버튼이 아닌 순수 표시.

```
┌──────────────────────────────┐
│  ←                           │
│                              │
│  개인화 안내              ⌄  │
│  [개인화 데이터 모두 지우기]   │
│                              │
│  계정 삭제                    │
│  [탈퇴하기]                   │
│                              │
│        aTee v0.1.12          │  ← 작은 회색
└──────────────────────────────┘
```

환경별 표기:

| 환경 | 표기 |
| --- | --- |
| 프로덕션 | `aTee v0.1.12` |
| 프리뷰 | `aTee v0.1.12 · preview` |
| 로컬 개발 | `aTee v0.1.12 · local` |

**프로덕션에만 꼬리표를 떼는 이유.** 실사용자가 보는 화면에 내부 용어를 노출하지 않기 위해서다. 꼬리표가 없다는 것이 곧 프로덕션이라는 신호가 된다.

## 2. 값의 출처

두 값을 **빌드 시점에 번들로 주입**한다.

- **버전** — `frontend/package.json`의 `version`. 릴리즈 워크플로가 올리는 바로 그 값이라 사람이 따로 맞출 필요가 없다.
- **환경** — Vercel이 빌드에 넣어주는 `VERCEL_ENV` (`production` / `preview`). 로컬에서는 이 값이 없다.

**Vercel이 자동 노출하는 `NEXT_PUBLIC_*` 계열 변수에 기대지 않는다.** 그 자동 노출은 프로젝트 설정에 달려 있어 조용히 꺼질 수 있다. 빌드 설정에서 명시적으로 넘기면 설정과 무관하게 동작한다.

### 대안과 기각 사유

| 방법 | 기각 사유 |
| --- | --- |
| 버전 문자열을 상수 파일에 직접 적기 | 릴리즈마다 사람이 맞춰야 한다. 어긋나면 화면이 **틀린 정보를 보여준다** — 표시 전용 정보가 조용히 거짓이 되는 유일한 안이다. |
| 커밋 SHA를 버전 대신 사용 | `a3f9c1e`는 사용자에게 의미가 없다. 목적과 맞지 않는다. |
| 런타임에 서버가 버전을 응답 | 정적 정보 하나 때문에 왕복을 만든다. 빌드 시 고정으로 충분하다. |

## 3. 구조

`frontend/AGENTS.md`의 레이어 규칙을 따른다.

- **domain** — 주입된 버전·환경 문자열을 받아 **화면에 그릴 한 줄을 만드는 순수 함수**. 프로덕션이면 꼬리표를 떼고, 값이 비었을 때 안전한 결과를 낸다. React·브라우저 API를 쓰지 않는다.
  - 환경 판정은 **`production`만 특별 취급하고 나머지는 받은 문자열을 그대로 꼬리표로 쓴다.** 환경값이 아예 없으면 `local`로 본다. Vercel이 앞으로 새 환경 이름을 늘려도 표기가 깨지지 않는다.
- **presentation/components** — 그 문자열을 렌더하는 표시 전용 컴포넌트. 상태·이벤트 없음이라 view-model 훅을 두지 않는다(레이어가 필요 없으면 만들지 않는다는 규칙).
- **app/settings/page.tsx** — 계정 삭제 섹션 뒤에 조립만 한다.
- **빌드 설정** — 두 환경변수를 번들에 주입.

값이 비어 있을 때의 동작은 domain이 정한다. 표기할 버전이 없으면 **그 줄 전체를 그리지 않는다** — `aTee v` 같은 깨진 문자열을 내보내는 것보다 낫다.

## 4. 알고 남겨두는 한계

1. **프리뷰는 항상 "마지막으로 릴리즈된 버전"을 보여준다.** 릴리즈 워크플로는 `develop` → `main` 승격 때 version을 올리므로, 아직 릴리즈되지 않은 커밋이 프리뷰에 있어도 버전 숫자는 그대로다. `· preview` 꼬리표가 이를 "릴리즈 0.1.12 이후의 프리뷰"로 읽히게 해준다.
2. **프리뷰끼리는 구분되지 않는다.** 서로 다른 PR의 프리뷰가 같은 문자열을 보여준다. 커밋 식별자를 넣지 않기로 한 결과다.
3. **Vercel 대시보드에서 프리뷰 배포를 프로덕션으로 승격하면 그 화면은 계속 `preview`로 보인다.** 값이 빌드 시점에 고정되기 때문이다. 지금 릴리즈 흐름은 `main` push → 새 빌드라 해당되지 않지만, 승격 기능을 쓰기 시작하면 표기가 거짓이 된다.

## 5. 완료 기준 (관찰 가능한 것)

- 로컬 개발 서버에서 `/settings`를 열면 맨 아래에 `aTee v0.1.12 · local`이 보인다.
- `frontend/package.json`의 `version`을 다른 값으로 바꿔 다시 띄우면 화면의 숫자가 그 값으로 바뀐다.
- PR 프리뷰 URL의 `/settings`에서 `aTee v0.1.12 · preview`가 보인다.
- domain 함수 테스트(vitest)가 통과한다 — 프로덕션이면 꼬리표 없음 / 프리뷰·로컬이면 꼬리표 붙음 / 버전이 비었으면 줄을 그리지 않음.
- `npm run check`가 통과한다.

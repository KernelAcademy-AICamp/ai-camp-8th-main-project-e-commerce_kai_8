# 설정 성별 토글 — 설계 (2026-08-21)

> 상태: 사람 승인 완료. Codex 교차 리뷰 6회를 거쳐 차단급(①) 0건.
> 앞선 결정: [큐레이션 성별 필터](../../plans/2026-08-21-curation-gender-filter.md) ·
> [행동 기반 성별 피드 하드 필터](2026-08-20-gender-feed-personalization-design.md)

## 목적

사용자가 **설정에서 남/여를 직접 고르고**, 그 선택 하나로 피드·검색·상세 하단 탐색·큐레이션이
**그 성별 상품만**(공용도 제외) 보여주게 한다.

## 왜 지금 이 모양인가 — 앞선 두 결정과의 관계

1. **#63 행동 기반 성별 피드 하드 필터**(2026-08-20)는 사용자에게 묻지 않고 행동으로 성별을
   판정해 피드를 "해당 성별 + 공용"으로 걸렀다. 수동 설정 UI는 그때 "범위 밖(후속 후보)"였다.
2. **큐레이션 성별 필터**(#75·#76, 2026-08-21)는 큐레이션을 **공용까지 뺀** exact 필터로 바꿨다.
   제품 책임자 결정의 근거는 실측이었다 — 공용은 어깨 중앙 52cm로 남성과 같고 92%가 46cm 이상이라
   **실측상 남성복**이며, 사용자 인터뷰에서도 공용 썸네일의 여성 모델에 거부감이 컸다. 그 계획은
   **"BROWSE는 이번에 건드리지 않는다 — 큐레이션 결과를 눈으로 본 뒤 따로 정한다"** 로 끝난다.

이 설계는 그 후속이다. **판정을 행동에서 사람의 선택으로 바꾸고, 공용 제외를 앱 전체로 넓힌다.**

## 결정 사항

| 갈림길 | 결정 |
|---|---|
| 공용(카탈로그의 약 18~19%) | **완전 제외** — 선택한 성별과 등식으로 일치하는 것만 |
| 판정 방식 | **첫 진입 강제 선택**(건너뛰기 없음), 이후 설정 화면에서 변경 |
| 저장 | 기기 + 계정. **계정은 취향과 별도 테이블·전용 RPC로 분리** |
| 검색 충돌 | **설정이 항상 이긴다** — 질의의 성별어보다 우선(성별과 '전용' 여부 둘 다 덮는다) |
| 검색 경로 | **v1·v2 둘 다** 성별을 받는다 (v2 활성화 여부는 이 작업 밖) |
| 행동 판정(#63) | 요청에 싣는 값을 **설정으로 교체**한다. 죽은 코드 삭제는 다음 조각 |
| 이번 조각 범위 | 설정·게이트 · 피드 · 검색 · 상세 하단 유사 · **큐레이션의 성별 출처** · 백엔드 평가 호출자 |
| 다음 조각 | 보관함(원본/화면용 분리) · #63 죽은 코드·데이터 정리 |

### 큐레이션이 범위에 들어온 이유

초안에서는 "큐레이션은 정적 JSON에 성별이 없다"며 범위 밖으로 뒀는데, #75·#76이 그 전제를 깼다.
지금 큐레이션은 **`ProfileSummary.gender`(행동 판정)** 를 읽는다. 판정을 설정으로 바꾸면서
큐레이션만 놔두면 **한 앱 안에서 성별의 진실이 둘**이 된다. 성별 **출처만** 바꾸는 작은 변경이므로
이번 조각에 포함한다. 큐레이션의 나머지 규칙(상품 단위 필터, 최소 슬라이드 수)은 건드리지 않는다.

부수로 고쳐야 할 것이 하나 있다: 지금 FOR YOU는 **앵커가 없으면 조기 반환**해서 성별 필터도 함께
건너뛴다. 강제 선택 뒤에는 앵커가 없어도 성별은 늘 정해져 있으므로, **취향 정렬은 앵커가 있을
때만, 성별 필터는 항상** 걸리게 분리한다.

# 이번 조각

검증 가설: **사람이 고른 성별 하나가, 첫 화면부터, 피드·검색·유사·큐레이션에서 공용까지 뺀 채
일관되게 유지된다.**

## 0단계 — 실측 게이트 (코드 없이 진행/중단 판정만)

공용을 빼면 피드 후보풀이 약 41%로 줄어든다(#63의 "성별+공용" 약 59%에서). 재는 것은 **판단에
필요한 만큼**으로 한정하되, 다음 세 축은 빠뜨리지 않는다.

- **후보 배수** — #63이 쓰는 벡터 버킷 후보 배수는 통과율 59% 기준(약 17배)이다. 41%에서는 산술로
  24~25배가 나온다. 이 값을 시작점으로 두고 **ANN 후보가 목표 수에 못 미치는 빈도**를 관찰해
  확정한다. 이미지 벡터 행의 성별 분포가 카탈로그 분포와 같다는 근거는 **없다** — 실측으로 본다.
- **연속 페이지 고갈 — 실제 클라이언트 재생.** 같은 인자로 반복 호출하면 안 된다. 클라이언트처럼
  **이전 응답 상품을 제외 목록에 누적**하며 부른다. 제외 상한이 600이고 한 페이지가 30장이라
  **20페이지가 정확히 상한에 닿는 지점**이므로, 상한을 넘긴 뒤 반복·짧은 페이지가 생기는지 보려면
  **21페이지째까지** 본다. 앵커는 대표값 둘(0개, 최대 사용량)만.
- **버킷별로 기록.** 전체 30장이 채워져도 특정 버킷(세션·장기·부분·반대·다양성)이 먼저 고갈될 수
  있다. 페이지마다 전체 수와 **버킷별 채움 수**를 남기고, 중복은 **페이지 내부 중복**과
  **누적 고유 비율**을 분모와 함께 나눠 적는다.
- **응답 시간** — 웜 평균만으로는 tail이 숨는다. cold 1회 + warm 반복에 더해 **warm p95**와
  **서버 statement timeout(8초) 내 성공률**을 남기고 **동시 호출을 최소 1회** 해 본다.
  피드·믹스·유사·검색 v1·검색 v2를 각각 잰다.
- **중단 기준** — 30장 미달 반복 · 특정 버킷 고갈 · 제외 상한 이후 반복 · timeout 실패 중 하나라도
  나오면 **중단하고 수치와 함께 보고**한다.
- 완료 기준: 위 수치와 "진행 가능/중단" 판정, **후보 배수 최종치**가 기록돼 있다.

## 1단계 — 설정 상태: 저장·동기화

- **기기**: 취향 프로필과 별개 키. 값은 남성/여성/없음(미선택).
- **계정**: 취향 행에 얹지 않고 **별도 테이블 + 전용 RPC**로 분리한다. 개인화 초기화가 취향 행을
  통째로 지우기 때문에, 같은 행에 두면 "초기화해도 성별은 남는다"를 지킬 수 없다. 기존 취향 RPC
  시그니처를 건드리지 않아 오버로드 사고도 피한다.

  **수명주기·권한** (기존 계정 데이터와 같은 규칙):
  - 사용자 참조는 **삭제 연쇄**로 건다 — 계정 삭제가 성별 행도 함께 지운다. 이것을 관찰한다.
  - 테이블에 **RLS**를 켜고 직접 접근 권한은 회수한다. 접근은 RPC로만.
  - RPC는 **대상을 인자로 받지 않고 호출자 인증 주체만 본다**(남의 설정을 건드릴 손잡이를 만들지
    않는다). 고정 검색 경로, 로그인 사용자에게만 실행 권한.
  - **잘못된 값은 오류로 거부**한다. 조용히 정화하지 않는다.

- **신원 전환**: 이 저장소는 "지울 것이 아니라 **남길 것을 열거**"하는 방식이라, 새 키는 로그아웃·
  탈퇴 시 자동으로 지워진다. 이것을 의도된 동작으로 확정한다(앞 사용자의 성별이 다음 사용자에게
  새지 않는다).

  **비회원 → 로그인 승계**는 찜과 같은 순서를 탄다(빼두기 → 정리 → 다시 불러오기). 따라서:
  - 정리 **직전에** 성별을 승계 전용 키로 빼두고, **그 키를 "남길 것" 목록에 등록**한다.
    등록하지 않으면 승계값이 정리에서 사라진다.
  - 다시 불러온 뒤 **"계정에 값이 없을 때만 저장"을 서버에서 원자적으로** 수행한다. 읽고 나서
    쓰면 두 호출 사이에 다른 기기가 값을 써서 계정 우선 규칙이 깨진다.
  - 실패하면 승계 키를 남기고 재시도한다. **다만 재시도 실패가 게이트를 영원히 막지 않는다** —
    기기 값으로 확정하고 동기화만 재시도하며, 설정 화면에 동기화 실패를 표시한다.

- **읽기 우선순위**: 계정 값 > 기기 값. **"계정에 값 없음"과 "계정 읽기 실패"를 구분**해, 실패를
  값 없음으로 오인해 다시 묻지 않는다.

- **다기기 경합**: 성별 저장은 취향 동기화(주기적 업로드)에 얹지 않는다. **오래된 쓰기 방지는
  서버에서** 한다 — 갱신 시각은 서버 시각으로 찍고, 쓰기 RPC는 **클라이언트가 읽었던 갱신 시각을
  받아 그 시각의 행일 때만** 덮는다.

  **행 모델**: "계정에 값 없음"은 **행이 없음**이고 성별 열은 비어 있을 수 없다. 행은 있는데 값이
  비는 상태를 허용하면 "값이 있음"과 "행만 있음"을 구분할 수 없다.

  **반환 계약** — 응답이 **도착한 경우** `적용됨 여부`·`최종 성별`·`최종 갱신 시각`을 돌려준다.
  클라이언트 상태는 셋이다.
  - **적용됨** — 그대로 진행.
  - **충돌**(다른 기기가 더 최신) — 이전 로컬 값으로 되돌리는 게 **아니라** 반환된 **서버 값을
    설치하고** 그 값으로 피드·검색을 다시 시작한다.
  - **미확인**(응답 자체가 없음) — 서버 최종값을 알 수 없다. 로컬 값을 유지한 채 재시도 큐에 넣는다.
    "항상 최종값을 돌려준다"는 응답이 도착한 경우에만 성립한다.

- 완료 기준: 다른 기기에서 로그인해도 같은 값 · 개인화 초기화 후에도 성별은 남음 · 로그아웃하면
  다시 물음 · 계정 삭제 시 성별 행도 사라짐(직접 조회로 확인) · 비회원 선택은 계정에 값이 없을
  때만 승계되고 있으면 계정 값이 이김.

## 2단계 — 온보딩 게이트 (요청을 실제로 막는 구조)

- **덮어 씌우는 방식이 아니다.** 성별 상태를 공유 저장소로 두고 `미확정 → 확정`을 표현하며,
  **초기값은 동기적으로 "미확정"**이어야 한다. 기본을 확정으로 두거나 기기 저장소 읽기를 effect
  뒤로 미루면 마운트 즉시 도는 첫 로드가 그대로 나간다.
- **세 훅 인스턴스 모두에 결합한다.** 지금 일시정지 조건은 자리마다 다르므로(메인/대체 피드,
  검색 결과, 상세 하단 유사) 각자의 조건 **앞에** "미확정"을 더한다. effect 실행 순서에 기대지 않는다.
- 확정은 기기 값 읽기 + (로그인 시) 계정 조회 + 승계 처리가 **모두 끝난 뒤 한 번** 일어난다.
- **예외 경로**: 설정·처리방침·로그인·인증 콜백 화면은 막지 않는다(비회원도 접근 가능해야 하고
  삭제·처리방침 링크를 막으면 안 된다 — 로그인 화면 설계 2026-08-19).
- **선택 전에는 홈을 렌더하지 않는다.** 가리기만 하면 부족하다 — 홈은 BROWSE·FOR YOU 두 칸을 항상
  렌더하고, 큐레이션 칸은 마운트되는 순간 앵커 제목 조회까지 한다. 확정 전에는 **홈 자체를
  마운트하지 않고** 선택 화면만 그린다.
- **선택 화면은 별도 경로가 아니라 홈 안의 상태**로 둔다. 히스토리 항목을 새로 쌓지 않으므로
  뒤로가기 스택 설계 문제가 아예 생기지 않는다.
- **"선택 후 뒤로가기가 앱 밖으로 나가지 않는다"는 기준은 폐기한다.** 앱 루트에서 뒤로 가면 앱을
  나가는 것이 정상이다. 대신 **선택 화면으로 되돌아가지 않는 것**을 기준으로 삼는다.
- 완료 기준: 새 브라우저·설치형 PWA 콜드스타트·새로고침·백그라운드 복귀 네 경우 모두, 선택 전
  네트워크에 피드·검색·유사·앵커 제목 조회가 **0건**. 이미 선택한 상태에서는 선택 화면이 다시 뜨지
  않는다.

## 3단계 — 서버: 다섯 함수의 성별 계약

모두 **등식**이며 공용과 미상은 빠진다.

- 피드(무작위)·믹스(개인화): 기존 "성별 또는 공용"을 등식으로 바꾸고, 벡터 버킷 후보 배수를
  0단계 결과로 조정한다.
- 검색 v1·v2: 성별을 받는다. v2는 파서가 성별과 '전용' 여부를 따로 내므로 **둘 다 설정 값으로
  덮는다** — 성별만 덮고 '전용' 여부를 질의 값으로 두면 공용이 다시 새어 정책이 깨진다. 서버 내부의
  모든 분기(폴백 갈래, 자판 복원·오타 교정 후보)에 같은 값을 쓴다.
- 유사: 성별을 받는다(지금은 인자가 없다).

**입력 계약 — 성별 인자는 필수이고, 잘못된 값은 거부한다.**
지금 피드 함수는 허용 밖 값을 **비움으로 정화**해 필터를 끈다. 공용까지 빼는 새 정책에서 그 동작은
**필터가 조용히 꺼져 반대 성별과 공용이 다시 노출되는** 실패다. 더 나쁜 것은, 새 인자에 **기본값을
주면 시그니처를 지워도 옛 요청이 막히지 않는다는 점**이다 — 성별을 안 싣는 옛 번들의 요청이 새
함수에 그대로 매칭돼 기본값으로 채워지고, 정화 로직을 만나 **정상 응답으로 필터 없는 결과**를
받는다. 따라서:
1. 다섯 함수의 성별 인자는 **기본값 없이 필수**로 만든다.
2. **누락·비어 있음·허용 밖 문자열은 모두 오류로 거부**하고, 본문에 정화 경로를 남기지 않는다.
3. 완료 기준에 **옛 요청 형태를 실제로 보내 거부되는 것**과 허용값만 통과하는 것을 확인하는 항목을
   넣는다.

**기존 정의 교체 시 반드시 함께 할 것**
- 다섯 기존 시그니처를 같은 마이그레이션에서 **지우고 최신 본문으로 다시 만든다.** 덮어쓰기만 하면
  옛 함수가 남아 호출이 모호해지거나 조용히 옛 정의가 선택된다.
- **의존 객체를 먼저 조사한다** — 저장소 검색에 안 잡히는 뷰·함수가 실제 DB에 있으면 마이그레이션이
  중간에 실패한다. 하나라도 나오면 같은 마이그레이션에 재생성을 포함하거나 **중단하고 보고**한다.
  조회 결과는 빈 결과여도 기록에 남긴다.
- **함수 수준 설정을 다시 부여한다.** 믹스와 유사에는 정렬용 메모리 설정이 별도로 걸려 있다
  (벡터 질의 성능 개선, 2026-08-16). 다시 붙이지 않으면 **아무 오류 없이 응답 시간과 timeout
  성공률이 회귀한다.** 기존 함수들의 설정을 먼저 조사해 전부 재적용하고 목록을 남긴다.
- **인자 배치**: 기본값 인자 뒤에 필수 인자를 둘 수 없다. 필수인 성별을 첫 기본값 인자보다 앞에
  놓거나 다른 배치를 택하고, 호출부의 이름 지정 인자도 함께 확인한다.
- 검색 v2 정의 파일의 "이 파일이 정본" 경고와 "시그니처는 바뀌지 않는다"는 전제를 함께 갱신한다.

**배포 중간 상태** — 시그니처를 지우므로 배포 순간 **열려 있던 탭**의 옛 번들은 오류를 받는다.
이 앱에는 **서비스 워커가 없다**(관련 파일·의존성·등록 코드 모두 없음). 따라서 워커 캐시가 옛 번들을
계속 제공하지 않고, 사용자가 전체 새로고침을 하면 현재 배포의 화면과 번들로 복구된다. (홈 경로에
명시적 무캐시 헤더는 없으므로 "중간 캐시가 절대 옛 화면을 주지 않는다"까지는 저장소 설정만으로
보장되지 않는다 — 실제 캐시 헤더 관찰은 구현 완료 기준으로 둔다.) **옛 시그니처를 호환용으로 남기지
않는다** — 성별 없는 호출이 필터를 우회한다.

**되돌리기** — 성별 인자의 의미가 바뀌므로 비움 롤백은 "필터 없음"만 복구하고 #63 동작을 되살리지
않는다. **이전 정의를 복구하는 롤백을 같이 만들고 실제로 한 번 돌려 본다.** 안 돌려봤으면 "되돌릴 수
있다"고 적지 않는다.

완료 기준: 직접 호출로 — 다섯 함수 각각 한쪽 성별을 넣으면 반대 성별·공용·미상이 0건, 반대쪽도
대칭, 잘못된 값과 옛 요청 형태는 거부, 커서를 이어도 유지. 옛 시그니처가 남지 않았음을 확인.

## 4단계 — 클라이언트: 설정값을 네 경로에 싣기 + 세대 폐기

- 피드(개인화·무작위·폴백)·유사·검색 요청이 **설정값**을 싣는다. **#63의 우세 성별 판정은 더 이상
  호출하지 않는다** — 진실을 둘로 두지 않는다. 죽은 코드 삭제는 다음 조각.
- **큐레이션의 성별 출처도 설정으로 바꾼다.** 그리고 **취향 정렬은 앵커가 있을 때만, 성별 필터는
  항상** 걸리도록 분리한다(지금은 앵커가 없으면 성별 필터까지 건너뛴다).
- 검색은 첫 페이지뿐 아니라 **모든 페이지에 같은 성별**을 보낸다(성별은 질의문에 실리는 자연어가
  아니라 별도 인자다).
- **설정이 바뀌면 세대를 폐기한다.** 검색 훅에는 이미 제출 단위 세대와 늦은 응답 폐기 가드가 있으니
  **성별을 세대 키에 더한다.** 반면 **기본 피드·상세 유사 훅에는 세대가 없어** 응답이 검증 없이
  붙는다 — 세대를 새로 만들어 이전 세대의 늦은 응답을 버린다. 폐기 대상은 결과·커서·사용된 질의·
  제외 목록·진행 중 요청 전부다.
- **이미 열린 상세는 닫지 않는다(수용한 제한).** 상세의 진실은 히스토리 항목의 표식이고 닫는 수단은
  뒤로가기 한 번뿐이라, 다층 상세를 한 번에 비우려면 별도 계약을 새로 만들어야 한다. 이 기능에 비해
  크고 되돌리기 어려우므로, **열려 있거나 뒤로가기로 되살아난 상세는 그대로 두고 하단 유사만** 새
  성별로 받는다. 하드 필터의 목적은 탐색·검색에서 반대 성별이 떠오르지 않게 하는 것이지 이미 본
  상품을 소급해 지우는 것이 아니다.
- 다중 탭: 다른 탭의 변경을 저장소 이벤트로 받아 같은 폐기를 수행한다. 값의 출처는 계정 우선 규칙을
  따른다.
- 완료 기준: 설정을 바꾸면 화면이 즉시 새 성별로 갈아엎히고, 검색 2페이지에도 성별이 실리며, 반대
  성별로 검색해도 결과가 새지 않는다. 다른 탭에서 바꾸면 상세는 남고 하단 유사와 피드가 새 성별로
  다시 시작한다. 느린 네트워크에서 이전 성별 응답이 뒤늦게 와도 섞이지 않는다. 피드·유사·검색·
  큐레이션이 행동 판정 성별을 더 이상 읽지 않는다.

## 5단계 — 오류 분류 (거부 계약과 함께 가야 한다)

지금 피드 훅은 실패를 2초 뒤 **무조건·무제한 재시도**하고, **개인화 실패를 오류 종류와 무관하게
무작위 폴백으로 넘긴다.** 잘못된 인자로 개인화가 거부되면 무작위도 같은 인자로 거부되고, 그 실패가
다시 무한 재시도로 들어간다. 기존 결함이지만 거부 계약이 이것을 실제로 드러내므로 함께 고친다.

- 설정 저장소가 허용값만 내보내 잘못된 값이 나갈 경로 자체를 없앤다(1차 방어).
- RPC 오류가 **응답 상태를 담은 구조화된 오류**를 던지게 한다. 지금은 문자열에 섞여 있어 판정할 수
  없다.
- **오류 종류별 경계**:

  | 오류 | 개인화 | 상세 유사 | 검색 | 자동 재시도 |
  |---|---|---|---|---|
  | 계약 오류(인자·시그니처) | 폴백 금지, 오류 노출 | 폴백 금지, 오류 노출 | 오류 노출, 대체 피드 금지 | **금지** |
  | 일시 제한(요청 과다 등) | 무작위 폴백 | 무작위 폴백 | 재시도 안내 | 간격을 늘려 상한 내 허용 |
  | 인증·권한 | 폴백 금지, 오류 노출 | 폴백 금지, 오류 노출 | 오류 노출 | 금지 |
  | 서버 오류·네트워크·시간 초과 | 무작위 폴백 | 무작위 폴백 | 재시도 안내 | 상한 내 허용 |
  | 정상 0건 | 오류 아님 | 기존 계약 유지 | 대체 피드 표시 | 재시도 아님 |

  표에 없는 나머지 클라이언트 오류는 **계약 오류로 간주해 폴백·재시도하지 않는다**(분류기가 놓쳐
  구현마다 동작이 갈리지 않게 하는 기본값).
  **정상적인 후보 부족은 오류가 아니다** — 앵커가 없으면 개인화를 부르지 않고 무작위로 가고, 버킷을
  못 채우면 짧은 페이지가 정상 응답으로 온다. 그 계약은 그대로 둔다.
- **재시도 상한의 단위**: 훅 인스턴스별로 센다. 한 번이라도 성공하면 0으로. **세대가 바뀌면(성별
  변경 포함) 0으로 되돌려 즉시 다시 시도**한다. 메인 피드와 상세 유사는 따로 센다.
- **상한 도달 시**: 스켈레톤을 계속 보여주는 대신 **오류 상태를 반환**하고 그 자리에 오류와
  새로고침 안내를 그린다(지금 훅은 스켈레톤 여부만 반환하므로 반환값과 렌더 계약을 함께 넓힌다).
- **시간 초과 판정 근거**: 지금 클라이언트 마감시한은 개인화(5초)·검색(10초)에만 있고 무작위 피드와
  유사에는 없다. 두 호출에도 마감시한을 둘지 서버 제한에만 의존할지 구현 계획에서 정한다 —
  정하지 않으면 "시간 초과면 폴백"을 관찰할 수 없다.

## 6단계 — 백엔드 평가·테스트 호출자 갱신

성별을 필수로 만들면 **프론트 말고도 이 함수들을 직접 부르는 곳이 깨진다.** 빠뜨리면 회귀 검증
수단 자체를 잃으므로 이번 조각에 포함한다.

- **유사 품질 게이트**(`backend/embed/gate_recall.py`) — 인자만 붙이면 **서빙만 성별로 걸리고 정답
  질의는 전체 성별이라 재현율이 인위적으로 떨어진다.** 정답과 서빙을 같은 성별로 맞추거나 게이트를
  성별별로 두 번 돌리는 것 중 하나를 고른다.
- **검색 평가 풀**(`backend/eval/build_pool.py`) — 지금 한 풀을 전체 성별로 만든다. 성별별 풀을
  따로 만들지 평가 범위를 명시적으로 바꿀지 정하고, **산출물에 어떤 성별 기준인지 적고 기존 기준선
  비교 방식도 갱신**한다. 한 성별을 임의로 하드코딩하면 기존 지표와 비교할 수 없다.
- **검색 폴백 테스트**(`backend/tests/test_search_fallback.py`) — 인자 하나 붙이는 것으로 끝나지
  않는다. **질의의 성별어를 기대하던 테스트를 "설정이 이긴다"는 새 계약에 맞춰 다시 쓴다.**

## 7단계 — 설정 화면과 고지

- **컨트롤은 남성/여성 두 선택지**로 둔다(켜고 끄는 스위치가 아니다 — 두 값은 대등하고 "꺼짐"에
  해당하는 상태가 없다). 온보딩을 지난 뒤 미선택 상태는 존재하지 않는다.
- 현재 값을 표시하고 **저장 중 / 저장 실패 / 충돌 / 동기화 실패**를 화면에 드러낸다. 특히
  **충돌은 실패가 아니다** — 값이 바뀌어 보이는 이유를 알려야 한다. 저장 실패면 화면과 로컬 값을
  이전 값으로 되돌린다(화면만 바뀌고 서버가 모르는 상태를 만들지 않는다). 접근성 이름과 키보드 조작.
- 값을 바꾸면 피드가 처음부터 다시 시작한다는 것을 한 줄로 알린다(별도 확인 대화상자는 두지 않는다).
- **고지를 사실과 맞춘다.** 설정 화면의 개인화 안내와 **공개 처리방침** 두 곳 모두 "성별 같은 추가
  정보는 요청하지 않는다"고 적혀 있다. 사람이 고른 성별을 계정에 저장하게 되므로 어긋난다. 보관
  기간·삭제 범위·로그아웃 시 수명도 함께 적는다. PRD의 관련 항목도 갱신 대상.

## 8단계 — 검증 기록

관찰 가능한 완료 기준의 결과를 기록하고, 안 돌려본 것은 **"미검증"**으로 남긴다.
남길 지표: 0건율 · 30장 미달률 · 페이지 내부 중복과 누적 고유 비율 · 버킷별 채움 수 · 성별별
페이지당 후보 수 · 설정 변경 후 첫 유효 요청까지의 시간 · warm p95와 시간 초과 성공률 · 질의
성별어와 설정이 충돌할 때의 결과 수와 대체 피드 전환 비율 · 늦은 응답 폐기 건수.

## 부록 — 교차 리뷰에서 잡힌 것 (Codex 6라운드)

설계가 실제 코드와 어긋났던 지점들이다. 같은 실수를 반복하지 않기 위해 남긴다.

1. **검색 기본 경로는 v1이다.** v2는 빌드 시 고정되는 플래그로 꺼져 있어, v2만 고치면 실제 배포
   검색은 성별을 무시한다.
2. **개인화 초기화가 취향 행을 통째로 지운다.** 같은 행에 성별을 얹으면 "초기화해도 남는다"가 불가능.
3. **최상위 가드들은 화면을 막지 않는다.** 덮어 씌우는 것만으로는 첫 요청을 못 막는다.
4. **후보 배수는 통과율에서 나온 수다.** 공용을 빼면 통과율이 바뀌므로 기존 값의 근거가 사라진다.
5. **새 인자에 기본값을 주면 옛 요청이 그대로 통과한다.** 시그니처를 지워도 막히지 않고, 정화
   로직을 만나 필터 없는 정상 응답이 된다 — 배포 중 하드 필터 우회.
6. **함수를 다시 만들면 함수 수준 설정이 사라진다.** 오류 없이 성능만 회귀한다.
7. **오류를 한 덩어리로 묶으면 일시 제한이 영구 오류가 된다.** 서버가 회복해도 못 돌아온다.

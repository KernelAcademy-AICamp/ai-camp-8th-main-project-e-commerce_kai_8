# 상세페이지 → 하단 탐색 이어가기 디자인

- 날짜: 2026-08-14
- 상태: 승인됨 (사용자 확인)
- 참고: Cosmos 앱 인터랙션 영상(상세→하단 스크롤→탐색 그리드 전환)

## 배경

aTee 상세페이지는 현재 이미지 슬라이더 + 상품 정보에서 끝난다. 개인화 알고리즘 도입 전에,
상세에서 아래로 스크롤하면 다시 탐색(모자이크 그리드)으로 이어지는 인터랙션을 먼저 만든다.
탐색이 끊기지 않는 이 구조는 이후 개인화 추천이 들어갈 자리(상세 하단 그리드)를 미리 확보한다.

## 사용자 경험

1. 상세페이지에서 상품 정보 아래로 계속 스크롤하면 새 탐색 그리드(2열 모자이크)가
   구분 라벨 없이 자연스럽게 이어진다.
2. 원본 상품(히어로)이 화면에서 사라지면:
   - 상단 중앙에 원본 상품 썸네일 칩이 나타난다 — 탭하면 상세 맨 위로 스크롤 복귀.
   - 하단 중앙에 '맨위로(↑)' 원형 버튼이 나타난다 — 탭하면 동일하게 맨 위로 복귀.
3. 그리드의 상품을 탭하면 새 상세가 스택 위로 열린다(기존 카드→상세 확대 애니메이션 유지).
   상세→탐색→상세→탐색… 무한 체인이 가능하다.
4. 뒤로가기(버튼·브라우저 뒤로가기·스와이프)는 스택을 한 단계씩 되짚는다.
   직전 상세로 돌아가면 보던 스크롤 위치가 복원된다. 스택이 비면 메인 피드로 돌아간다.

## 그리드 데이터

- 기존 `c_feed_page` RPC를 재사용한다.
- 시드는 (세션 시드 + 해당 상품 goodsNo)에서 **결정적으로 파생**한다.
  - 같은 상세로 돌아오면 같은 그리드가 재현된다(스크롤 복원과 일관).
  - 상품마다 다른 피드가 나온다.
  - 개인화 알고리즘 도입 시 이 파생 시드 피드를 "유사 상품 추천"으로 교체하면 된다.
- 응답에서 현재 보고 있는 상품은 제외한다.
- 무한 스크롤(센티널)은 메인 피드와 동일하게 동작한다.

## 아키텍처

기존 오버레이 구조를 유지하고 최소로 확장한다 (라우트 전환·URL 동기화는 이번 범위 밖).

- `useDetailState`: 단일 상태 → 스택(배열).
  - `open` = push + `history.pushState` (레벨마다 히스토리 1칸).
  - popstate = 최상단 닫힘 애니메이션 후 pop.
  - 화면에는 스택 최상단만 렌더한다. 새 레벨로 들어갈 때 현재 스크롤 오프셋을 스택에
    저장하고, 복귀 시 복원한다.
- `use-feed-view-model`을 시드·제외 상품 파라미터를 받도록 일반화한다.
- `MosaicFeed`의 2열 그리드 마크업을 공용 그리드 컴포넌트로 추출해 메인 피드와
  상세 하단 그리드가 같은 코드를 쓴다.
- 시드 파생 함수는 `domain/`에 순수 함수로 둔다.
- 레이어 규칙(presentation → domain ← data) 준수.

## 엣지 케이스

- 상세 안 그리드의 무한 로드: IntersectionObserver 기본(viewport) 루트로 중첩 스크롤
  컨테이너에서도 동작 — 구현 중 확인한다.
- 깊은 체인: 최상단 한 장만 렌더하므로 DOM 부담 없음. 스택은 메모리에만 존재 —
  새로고침 시 메인 피드로 (현행과 동일한 한계).
- 닫힘 애니메이션: 스택 pop에서도 기존 축소 복귀를 사용. 원점 카드가 화면 밖이면
  기존 fallback(페이드)으로 처리.

## 테스트

- domain: 시드 파생 함수, 스택 전이(open/pop/스크롤 저장) 로직 단위 테스트.
- view-model: 제외 상품 필터·시드 주입 동작 테스트.
- 완료 전 `npm run check`(lint + typecheck + format) 통과.

## 범위 밖 (이번에 하지 않음)

- 개인화/유사도 기반 추천 (다음 단계에서 이 그리드를 교체)
- 상세 URL 공유(라우트/쿼리 동기화)
- 그리드 진입 시 별도 섹션 라벨·저장 버튼 등 부가 UI

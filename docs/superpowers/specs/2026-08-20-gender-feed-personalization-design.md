# 행동 기반 성별 피드 구분 — 설계 (2026-08-20)

## 목적

남성 상품을 자주 보는 사용자에게는 남성 전용+공용만, 여성 상품을 자주 보는 사용자에게는 여성 전용+공용만 피드에 나오게 한다. 남성 쇼핑몰/여성 쇼핑몰이 나뉘어 있는 것이 일반적일 만큼 확실한 구분이 목표이며, 사용자에게 아무것도 묻지 않고 행동만으로 민감하게 판정한다.

## 결정 사항 (사용자 합의, 2026-08-20)

| 갈림길 | 결정 |
|---|---|
| 판정 방식 | **행동 추론만** — 별도 UI·가입 질문 없음 (PRD O-13 "가입 시 수집"은 이 기능과 무관하게 미구현 유지) |
| 구분 강도 | **전체 하드 필터** — 판정이 서면 개인화·반대취향·다양성 등 모든 버킷과 무작위·폴백 경로까지 해당 성별+공용만 |
| 민감도 | **매우 민감** — 성별 있는 앵커 몇 개만 쌓여도 잠금, 반대 신호 몇 번이면 풀림(대칭) |
| 판정 위치 | **기기(클라이언트)** — "취향 계산은 기기, 서버는 보관만" 계약(PR #44) 유지 |

## 배경 — 2026-08-18 성별 토글 기각과의 관계

당시 기각 사유는 성능이었다: `c_goods`(310MB, 속성 인덱스 없음)를 매 요청 거르는 방식은 개수를 세는 것만으로 statement timeout이 났다. 이번 설계는 다른 경로다 — 피드 후보는 좁은 물질화 테이블 `c_thumb_dims`(약 22.6만 행)에서 나오고, 여기엔 `gender` 열이 이미 실려 있다(`20260816220000_freshness_bonus.sql`). `c_feed_view` 주석에도 "회원 성별 필터는 후속 작업 — gender를 미리 노출해 둔다"고 예고돼 있다. 단, 그때의 교훈대로 **기획보다 실측이 먼저**이며, 성능 게이트를 첫 단계로 둔다.

데이터 전제: `gender` 커버리지 99.2%, 값은 남성(약 9.3만)/여성(약 9.0만)/공용(약 4.1만) 3종. 값 없는 1,911건은 null이 아닌 빈 문자열.

## ① 기기 판정 로직

- 기기 프로필의 앵커(탭·찜 등 행동한 상품)에 **상품 성별을 함께 기록**한다. 행동 시점에 클라이언트가 상품 객체(성별 포함)를 이미 들고 있으므로 추가 조회가 없다.
- 이미 저장된 기존 앵커에는 성별이 없으므로, **최초 1회 상품 번호로 성별을 채워 넣는다**(PK 목록 조회라 저렴).
- **판정**: 성별이 남성/여성인 앵커만 모수로, 가중치 합 기준 우세 성별 비율이 문턱 이상이고 그런 앵커가 최소 개수 이상이면 그 성별로 잠금. 공용·성별 미상 앵커는 모수에서 제외한다.
  - 시작값(튜닝 대상, 실측으로 조정): 비율 60%, 최소 앵커 3개.
- **풀림은 대칭**: 비율이 문턱 아래로 내려가면 즉시 전체(null)로 복귀.
- 하드 필터 중 피드에는 반대 성별이 안 나오지만, **검색 경로**로 반대 성별 상품을 행동하면 신호가 쌓여 풀린다.
  - 미확인: 검색 결과 응답에 상품 성별이 실리는지 — 구현 때 확인하고, 없으면 그 행동은 성별 모수에서 제외(성별 미상 취급)한다.

## ② 서버 변경

- `c_mix_page`·`c_feed_page`에 **`p_gender text default null`** 인자 추가.
  - null이면 완전히 기존 동작(하위 호환).
  - '남성'/'여성' 외 값은 서버가 null로 강제 — 기존 입력 방어 패턴(`20260816230000_mix_input_guard.sql`) 유지.
- 필터 위치는 **후보풀**: `c_thumb_dims` 기반 base_pool에 `gender in (p_gender, '공용')` 조건. 여기서 걸러야 partial/opposite/diversity 버킷이 한 번에 커버되고, "좁은 테이블 정렬 → 유계 지연 조인" 패턴이 유지된다. `in` 조건이라 빈 문자열 행도 자연히 배제된다.
- 벡터 검색(session/longterm) 버킷은 `c_thumb_dims` 존재 조건에 같은 필터를 붙이고, 필터율만큼 ANN 후보 배수를 조정한다.
- partial 버킷의 기존 "같은 성별" 조건은 그대로 둔다(하드 필터 하에서 자동 부합).
- **성능 게이트 (첫 단계)**: 함수를 바꾸기 전에 `c_thumb_dims`에 성별 조건을 얹은 실측(EXPLAIN ANALYZE·응답 시간)을 먼저 한다. 느리면 부분 인덱스(예: `gender` 대상, 피드 노출 조건부)를 만들어 재실측하고, 그래도 회귀가 남으면 중단하고 보고한다.

## ③ 적용 범위·롤백

- 개인화(`c_mix_page`)·무작위(`c_feed_page`)·폴백 **세 피드 경로 모두 같은 인자**로 필터되어 체감이 일관된다.
- 비회원은 O-37(비회원 신호 기록 꺼짐)에 따라 앵커가 없으므로 자동으로 미적용(항상 전체).
- 롤백: RPC 인자가 nullable 하위 호환이라 **클라이언트가 인자를 보내지 않으면 즉시 기존 동작**. 재빌드가 필요한 `NEXT_PUBLIC_*` 플래그에 의존하지 않는다.
- 범위 밖(후속 후보): 마이페이지 취향 카드에 성별 상태 표시, 수동 성별 설정 UI.

## ④ 검증 — 관찰 가능한 완료 기준

1. 남성 상품을 몇 번 탭하면 → 다음 피드 페이지부터 여성 전용 상품이 0건으로 보인다. 여성 방향도 동일.
2. 반대 성별 상품을 몇 번 행동하면 → 잠금이 풀려 전체 성별이 다시 보인다.
3. 필터 적용 전후 피드 응답 시간 실측 비교에서 회귀가 없다.
4. 믹스 실패 폴백 경로에서도 필터가 적용된 결과가 보인다.

## 미확인·미정 목록

- 검색 결과 응답의 성별 포함 여부 (①에서 대응 방침 정의됨).
- 비율·최소 앵커 수 문턱값 — 시작값만 정했고 실측으로 조정.
- 부분 인덱스 필요 여부 — 성능 게이트 실측 결과에 따름.

## 1. 배경과 목표

aTee 피드는 현재 22.6만 실데이터를 세션 시드 무작위 순서로 보여준다(개인화 없음). 이 설계는 PRD §7의 개인화 원칙 — 추천 포트폴리오 5유형, 신호 강도 서열, 장기/세션 취향 분리 — 를 실제로 돌리는 전체 파이프라인을 정의한다.

**완료 기준(합의):** 사용자의 행동(탭·찜·`이 스타일로 계속 탐색`)에 따라 피드 구성이 눈에 보이게 변하고, 모든 노출·행동이 유형 태그와 함께 기록된다. Gate 1 실험군 배정은 이번 범위가 아니며, 계측에 정책·버전 필드를 남겨 나중에 스위치를 얹는다.

### 이 작업의 위치 (PRD와의 관계 — 명시)

이 작업은 **익명 개인화 프로토타입**이다. PRD가 정의한 Gate 1(회원 D7 재방문 대조 실험)의 실험 단위는 "가입 온보딩을 완료한 회원"이며, 익명 기기 ID로 잰 재방문은 그 실험이 아니다(저장소 삭제·기기 변경 시 신규처럼 보임). Gate 1을 실행하려면 계정·승계·고정 실험 배정이 추가로 필요하고, 그것은 이 설계의 후속이다. 이 프로토타입의 목적은 **개인화 파이프라인이 실제로 돌고 체감되는지**를 먼저 확인하는 것이다.

### 이 설계에서 확정된 제품 결정 — 결정 기록·PRD 갱신은 구현 0단계에서 즉시 수행

1. **장기 취향의 주체 = 익명 기기 ID** (localStorage UUID). PRD "회원만 장기 개인화"의 완화이며, 위 프로토타입 위치 설명이 전제다. 계정 도입 시 프로필을 승계한다.
2. **LLM 자연어 검색을 aTee에 보조 진입점으로 추가** (Non-goal 완화 — 주 경험은 여전히 무한 탐색 피드, 검색 결과도 피드 형태로 이어짐). 검색 자체는 별도 스펙으로 설계하고, 이 설계는 그 토대(임베딩·필터 컬럼)를 제공한다.
3. **임베딩 모델 = `google/siglip2-base-patch16-256`** — 실데이터 1,498장 3종 비교로 확정([비교 문서](../../atee/foundation/embedding-model-bakeoff.md)). 한국어 검색 질의를 임베딩 모델이 직접 처리한다.
4. **임베딩 대상 = 썸네일 + 갤러리 전체(약 93만 장)** — 갤러리 사진이 매칭되면 그 사진을 피드 카드로 노출하고, 상세를 열면 해당 슬라이드에서 시작한다(딥링크).
5. **Supabase Pro(유료, 월 $25·8GB) 전환** — 무료 500MB로는 93만 장 벡터(이진만으로도 실제 ~200MB급, 정밀 재정렬 벡터 포함 시 그 이상)가 물리적으로 불가능하다(리뷰 Blocker ①). 유료 전환으로 정밀 벡터의 서버 보관·재정렬(§3)이 가능해진다.

## 2. 전체 그림

```
[프론트 (기기)]                    [Supabase Pro]                  [로컬 배치 (Mac, 1회+α)]
익명 기기ID·세션ID                  c_events (신호 로그, RPC 경유)     썸네일+갤러리 93만 장
행동 신호 수집 ─────────────────▶   이미지 벡터 테이블                 다운로드+크기 측정
취향 프로필 (localStorage,            - halfvec 정밀(재정렬용)         → SigLIP2 임베딩+분류
  기기에서 계산·갱신)                  - 이진 표현식 인덱스(후보 생성)    → 품질 게이트 → 적재
     │                               - 유형·그래픽 라벨, 메타 축      (원본 float32는 로컬 보관)
     └─ 프로필 요약을 담아 호출 ──▶  추천 RPC ── 5유형 믹스 페이지 반환
                                    (폴백: 기존 c_feed_page 무작위)
```

핵심 선택 두 가지:

- **프로필은 기기(클라이언트)가 계산·보관한다.** 자기 이벤트로 장기·세션 취향을 갱신해 localStorage에 저장하고, 피드 요청 때 요약(앵커 목록 + 축 선호)만 서버에 보낸다. 서버에 사용자별 상태·배치 작업이 없어 단순하고, 계정 승계 시 프로필을 그대로 올리면 된다. 서버의 이벤트 로그는 평가·계측 전용으로 프로필 계산과 분리된다.
- **추천은 RPC 한 번으로 5유형이 섞인 한 페이지를 받는다.** 실패하면 기존 무작위 피드로 폴백하고 개인화인 척하지 않는다(PRD 원칙).

## 3. 임베딩 파이프라인 (약 93만 장)

- **대상:** 썸네일 226,313장 + 갤러리 약 70만 장(보유율 ~80%, 상품당 평균 3.9장 — 표본 실측). 벡터 키는 (상품번호, 슬롯) — 슬롯 0=썸네일, 1~n=갤러리 순번.
- **다운로드+측정 동시:** 갤러리 이미지를 받으면서 가로세로 픽셀도 기록한다(카드 영역 예약용 — `c_thumb_dims` 파이프라인 재사용). 안전선·재개 가능 구조는 기존 배치를 따르고, URL 노화 대비 실패 URL은 상품 API로 갱신을 시도한다. 배치 소요 추정(하룻밤)은 임베딩 기준이며 **다운로드·디코딩·재시도 시간은 별도**다 — 실행 계획에서 구간별로 추정한다.
- **이미지 유형 분류:** 임베딩과 같은 벡터로 zero-shot 분류 — `착용샷 / 단품컷 / 디테일·원단 / 사이즈표·라벨`. **카드 노출·유사 검색 대상은 착용샷·단품컷만.** 분류 신뢰도가 낮은 이미지는 `보류`로 두고 검색 대상에서 제외한다. 적재 전 표본 사람 판정으로 분류 정확도를 확인한다(기준: 표본 200장에서 카드 노출 부적합 이미지의 오통과율을 확인하고 임계값을 조정).
- **그래픽 성향 라벨:** `무지 / 그래픽 / 레터링`. 상호 배타적이지 않으므로(레터링도 그래픽의 일종) **다중 라벨 + 대표 라벨** 구조로 저장한다.
- **저장 전략 (Pro 전제):**
  - 서버: `halfvec(768)` 정밀 벡터(93만 장 ≈ 1.4GB) + **이진 양자화 표현식 인덱스**로 후보를 넓게 뽑고(oversampling) 같은 쿼리 안에서 정밀 재정렬 — pgvector 정석 패턴. 원본 float32는 로컬 보관(재계산·실험용).
  - **품질 게이트(적재 전 수치 고정):** 사람이 고른 대표 앵커 30개 + 텍스트 질의 10개의 정답셋 기준, 이진 후보→정밀 재정렬 결과가 전수 정밀 검색 대비 **Recall@30 ≥ 0.9**. 미달 시 oversampling 배수를 올리거나 인덱스 구조를 바꿔 재측정.
  - **PoC 선행:** 전체 적재 전에 5만 장 규모로 실제 테이블·인덱스 크기와 검색 p50/p95를 측정하고, 자격 필터(WHERE)를 붙인 ANN의 반환 부족 문제(iterative scan/oversampling 필요 여부)를 함께 확인한다.
- **중복 제거 원칙:** 피드에는 상품당 1장(가장 유사한 이미지)만, 같은 세션에서 같은 상품은 다시 노출하지 않는다. 컬러웨이·동일 이미지 재사용 상품 간 중복(상품번호가 달라 걸러지지 않음)은 알려진 한계로 두고, 반복 노출률 계측으로 심각도를 확인한 뒤 유사도 임계 기반 그룹핑을 후속 검토한다.
- **완료 기준:** 아무 상품이나 골라 "이 이미지와 닮은 상품"을 조회하면 결과가 나오고, 갤러리 사진이 매칭된 경우 그 사진이 카드로 보이며, 탭하면 상세가 해당 슬라이드에서 열린다.

## 4. 행동 신호 수집

- **이벤트 종류:** 노출(카드가 뷰포트에 실제로 보임) · 탭(상세 열기) · 찜/찜해제 · `이 스타일로 계속 탐색` · 판매처 이동 · **세션 시작/종료(또는 마지막 활동 시각 heartbeat)**. 체류시간 등 모호한 신호는 v1에서 수집하지 않는다(PRD: 약한 보조 신호). 세션 종료는 비활성 30분 기준(미정 플래그 — 실험 계획에서 확정)으로 클라이언트가 판정한다.
- **공통 필드:** 이벤트 ID(클라이언트 생성 UUID — 배치 재전송 중복 제거 키), 기기 ID, 세션 ID, 클라이언트 발생 시각, 서버 수신 시각, **모델 버전·프로필 버전·피드 정책**(개인화/무작위/폴백), 실험 배정 필드(현재는 고정값 — Gate 1 대비 예약).
- **노출 이벤트 추가 필드** (PRD §7 요구): 노출 ID, 포트폴리오 유형(source_bucket)·**신선도 플래그(별도 필드)**, 페이지 내 순위, 카드 크기(열·픽셀 높이), 화면 위치, 노출 이미지 슬롯, 시드.
- **행동-노출 연결:** 탭·찜·스타일탐색·판매처 이동 이벤트는 해당 상품의 노출 ID를 함께 기록해 어느 노출(유형·위치)에서 발생했는지 귀속한다.
- **저장·방어:** `c_events`는 anon 직접 insert가 아니라 **RPC 경유**로 기록한다 — 요청당 이벤트 수·크기 상한, 값 범위 검증, 이벤트 ID 중복 무시, 기기별 일일 상한. 남용으로 한도를 채우는 경로를 막는다. select는 계속 거부.
- **용량 산식:** 사용자 수 × 세션 수 × 평균 노출 수 × 행 크기로 추정하고 보존 기한·상한을 운영한다. 예: 30명 × 30세션 × 500노출 × ~150B ≈ 70MB — Pro 8GB에서 문제없으나 상한은 유지.
- **프라이버시:** 기기 ID는 **가명 행동 식별자**다(개인정보와 직접 연결되진 않지만 장기 행동을 잇는 영속 ID). 삭제 수단 = 설정의 로컬 초기화 + 기기 ID 기준 서버 이벤트 삭제 요청 경로(요청자의 기기 ID 보유 자체를 소유 증명으로 간주 — 미정 플래그: 정책 문서화 시 재검토). PRD P0의 고지·동의 문구도 이 작업에서 함께 노출한다.

## 5. 취향 표현 (축)

| 축 | 재료 | 커버리지 |
|---|---|---|
| 그래픽·무드 | SigLIP2 벡터 + 무지/그래픽/레터링 다중 라벨 | 전체(임베딩) |
| 색 | `color_codes` 54코드 → 색군 그룹 | 99.7% |
| 가격 | `price_final` 구간 | 100% |
| 브랜드 | `brand` | 100% |
| 핏 | `fit` (보조 — 보유 28%) | 28.1% |
| 신선도 | `season_year` (프록시 — 한계 명시 아래) | 97.5% |

- *유사* = 벡터 근접. *부분 일치* = 한 축만 일치(예: 색군 같고 그래픽 다름). *반대 제안* = 축 반전(무지↔그래픽, 무채↔원색).
- **신선도 한계:** `season_year`는 출시·입고 시각이 아니라 시즌 표기이고, 카탈로그는 1회 수집 스냅숏이라 "새로 입고"를 알 수 없다. v1의 신선도 가산점은 season_year 프록시로만 하고, 진짜 신상품 신호(증분 수집·최초 발견 시각)는 후속 작업으로 명시한다.

## 6. 취향 프로필 (장기/세션 분리)

- **형태:** 가중치 붙은 **앵커 이미지 목록** + 축 선호 요약(색군 분포·가격대·그래픽 성향). 평균 벡터 하나로 뭉개지 않아 취향이 여러 갈래여도 각각 유지된다. **bounded summary 원칙** — 원시 이벤트를 쌓지 않고 요약만 보관한다(localStorage ~5MB 한도).
- **규칙(초기값 — 구현 계획에서 조정 가능):**
  - 앵커 상한: 장기 50개·세션 20개. 초과 시 가중치 최저부터 가지치기.
  - 신호 가중 서열(PRD): 반복 탐색 < `이 스타일로 계속 탐색` < 찜 < 판매처 이동. 찜 해제는 해당 앵커 제거.
  - 시간 감쇠: 장기 앵커 가중치는 세션 단위로 서서히 감쇠. 한 세션의 행동이 장기에 들어가려면 세션 종료 시점에 반영(하루의 이례적 탐색이 즉시 덮지 않음).
  - 자기강화 방지: 노출 대비 행동으로 보정 — 많이 보여줘서 생긴 행동은 가중을 덜 받는다(클라이언트의 자기 노출 기록으로 계산).
  - 멀티탭: 세션 프로필은 탭(브라우저 탭) 단위, 장기 프로필 갱신은 저장 직전 재읽기 후 병합(마지막 쓰기 우선이 아닌 앵커 합집합+가중 최대). 
  - 버전: 프로필에 스키마 버전·모델 버전을 기록 — 모델 교체 시 앵커는 상품 ID라 유지되고 벡터는 서버에서 새 모델로 조회되므로 마이그레이션은 버전 필드 확인만으로 충분.
  - 손상 복구: 파싱 실패 시 백업 슬롯(직전 정상본 1개)에서 복원, 백업도 실패면 콜드스타트.
- **보관:** localStorage(익명 기기 ID와 함께). 서버 호출 시 요약만 전송.

## 7. 추천 포트폴리오 믹스

- **초기 비율** (페이지 30장, 계측 보고 조정): 장기 취향 40% · 현재 세션 관심 20% · 부분 일치 15% · 반대 제안 10% · 다양성·탐색 15%. 소수점 슬롯은 다양성으로 내림 배분. PRD의 5번째 유형 "시간적 새로움"은 슬롯이 아니라 각 슬롯 안의 가산점 + 노출 이벤트의 신선도 플래그로 구현한다(§4·§5).
- **RPC 계약:**
  - 여러 유형에 동시에 해당하는 상품의 귀속: 세션 > 장기 > 부분 일치 > 반대 > 다양성 순으로 먼저 잡은 유형에 귀속(중복 후보는 비율 계산 전에 제거).
  - 유형별 후보 부족 시 backfill: 부족분은 다양성 슬롯으로 채우고, 페이지 응답에 실제 채운 유형 구성을 담아 노출 이벤트에 그대로 기록.
  - 페이지 안정성: 각 페이지 요청은 요청 시점의 프로필 요약을 사용한다 — 페이지 간 프로필이 변해도 이미 받은 페이지는 불변, 커서는 페이지 단위로만 유효.
- **콜드스타트:** 신호가 없으면 100% 다양성 피드(= 기존 무작위 피드). 신호가 쌓일수록 개인화 슬롯이 차오른다.
- **`이 스타일로 계속 탐색` 직후:** 실제 노출 60장(약 2페이지) 동안 세션 슬롯을 일시적으로 크게 올렸다가 복귀 — 페이지 요청 수가 아니라 노출 수 기준(프리페치로 소진되는 것 방지).
- **중복 제거:** 같은 세션에서 이미 노출된 상품 제외 — 클라이언트가 최근 노출 목록(상한 600개)을 요청에 실어 보낸다. 상한을 넘는 긴 세션에서는 오래된 노출부터 재등장할 수 있음을 알려진 한계로 명시(반복 노출률 가드레일로 관찰).

## 8. 신규 UI

- 상세 화면에 **찜 토글(하트)** 과 **`이 스타일로 계속 탐색` 버튼** 추가 → 상세 3요소(찜·스타일탐색·판매처 이동) 완성.
- 찜 목록은 localStorage 보관 + 최소한의 보관함 화면(피드에서 진입하는 목록 뷰). 서버에는 찜 이벤트만 기록.
- 길게 누르기 단축 동작·최초 온보딩은 **이 작업의 범위 밖**이다. PRD P0 요구로는 유지되며 별도 작업에서 충족한다(P0에서 제거하는 것이 아님).

## 9. 실패 처리

- 추천 RPC 실패·타임아웃 → 기존 무작위 피드로 폴백, 개인화인 척 표시하지 않음. 폴백 발생도 계측.
- 이벤트 전송 실패 → 로컬 큐 재시도(이벤트 ID로 중복 방지), 최종 유실 허용.
- 프로필 손상 → 백업 슬롯 복원 → 실패 시 콜드스타트(§6).
- 품질 게이트 미달 → 적재 보류, oversampling·인덱스 조정 후 재측정(원본 벡터가 로컬에 있어 재계산 불필요).
- 이미지 무효(404 등) → 해당 이미지 슬롯 제외, 썸네일이면 기존 원칙대로 상품 제외.

## 10. 계측·평가

- 모든 노출에 유형(source_bucket)·신선도·순위·카드 크기·정책·모델 버전 기록 → 유형별 찜률·판매처 이동률, 반복 노출률, 다양성, 유효 탐색 시간(세션 시작/종료 기반)을 SQL로 산출 가능(PRD §7 평가 요구).
- Gate 1 실험 배정은 미구현 — 이벤트의 배정 필드는 예약해 두고 고정값 기록.
- 회귀 확인: 고정 앵커 상품들의 유사 검색 결과 스냅샷을 두고 모델·압축 변경 시 비교.

## 11. 검색과의 관계 (경계)

- 검색(LLM query-gen + 텍스트→이미지)은 **별도 스펙**으로 설계한다.
- 이 설계가 제공하는 토대: SigLIP2 벡터(한국어 질의 직접 처리 확인됨), 유형·그래픽 라벨, 메타데이터 필터 컬럼. 검색 SQL은 `WHERE 메타필터 + 이진 후보 → 정밀 재정렬` 한 쿼리로 결합 가능.
- 검색어 실시간 벡터 변환의 실행 위치(Supabase Edge Function vs Vercel 함수)는 검색 스펙에서 확정.

## 12. 용량 계획 (Supabase Pro 8GB 전제)

| 항목 | 크기 (추정 — PoC에서 실측 후 확정) |
|---|---|
| 기존 사용(c_goods 347MB 등) | ~429MB |
| halfvec(768) 93만 장 | ~1.4GB |
| 이진 표현식 인덱스 + PK | 수백 MB (PoC 실측) |
| 유형·그래픽 라벨, 이미지 크기 | 수십 MB |
| 이벤트 로그(상한 운영) | ~100MB |
| **합계** | **~2.5GB / 8GB — 여유 충분** |

- 무료 한도 전제의 `size_measures` 삭제(+105MB)는 **불필요해졌다**. (참고: 열 삭제는 공간을 즉시 반환하지 않고 테이블 재작성이 필요하며, 그 공간은 다른 테이블이 재사용할 수 없다 — 무료 유지 시나리오가 성립하지 않았던 이유.)
- 비용: 월 $25. 검증 종료 후 다운그레이드하려면 벡터 테이블을 지우고 무료로 복귀(원본 벡터는 로컬 보관이므로 재적재 가능).

## 13. 구현 순서 (각 단계 끝 = 관찰 가능한 결과)

0. **문서·플랜 정비** — 결정 기록에 §1의 결정 5개 추가, PRD 해당 절 갱신(비회원 장기 개인화 완화·보조 검색·프로토타입 위치), Supabase Pro 전환 실행 → *결정 기록·PRD에 반영 확인*
1. **PoC 적재** — 5만 장 규모 벡터 테이블·인덱스 실측(크기·p50/p95·필터 recall) → *수치 보고서*
2. **임베딩 파이프라인** — 93만 장 다운로드+크기 측정 → SigLIP2 임베딩+분류 → 품질 게이트(Recall@30 ≥ 0.9) → 전체 적재 → *"닮은 상품" 조회 동작*
3. **유사 탐색 UX** — 매칭 갤러리 사진 카드 노출 + 상세 슬라이드 딥링크 → *눈으로 확인*
4. **행동 신호 수집** — 이벤트 RPC·로깅 가동 → *DB에 노출·탭 이벤트 확인(중복 제거 포함)*
5. **찜·스타일 탐색 UI** — *버튼 동작 + 이벤트 기록 확인*
6. **취향 프로필 + 믹스 RPC** — *내 행동에 따라 피드 구성이 변하는 것 확인*

각 단계는 착수 시 이 설계를 근거로 별도 구현 계획(`docs/plans/`)으로 쪼갠다.

## 14. 이 설계에서 다루지 않는 것 (후속)

- Gate 1 실험군·대조군 배정 스위치와 회원 실험 단위(계정·승계·고정 배정)
- 가입·온보딩, 성별·사이즈 자격 필터(익명 단계 미적용 — 단, ANN 필터 대응은 PoC에서 선측정)
- 포트폴리오 비율 자동 조절(초기값은 고정 상수)
- 명시적 부정 신호(`관심 없음` 등 — PRD P2)
- 진짜 신상품 신호(카탈로그 증분 수집·입고 갱신)
- 컬러웨이·동일 이미지 상품 그룹핑(반복 노출률 보고 판단)
- LLM 검색 스펙(별도 문서) · 길게 누르기·온보딩(별도 작업, P0 유지) · 푸시(PRD P1)

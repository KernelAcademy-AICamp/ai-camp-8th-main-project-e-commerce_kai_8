# 설계 — 개인화 3차: 분류 교정 + 축 고도화 + 신선도 가산점

> 상태: **확정 (2026-08-16 제품 책임자 승인 — Codex 외부 리뷰 12건 반영한 v2)** · 작성: 2026-08-16
> 근거: [개인화 알고리즘 설계](2026-08-14-personalization-algorithm-design.md) §5·§7 · [2차 계획 실행 기록](../../plans/2026-08-16-personalization-signals-profile-mix.md)
> 선행 결정(2026-08-16 제품 책임자): 컴퓨트 업그레이드는 **보류**(이번 라운드는 소프트웨어만). 재분류 검증은 **AI 자체 검증만**(사람 판정 없음).
> 외부 리뷰: Codex(gpt-5.6-sol xhigh)가 지적 12건 제시, 전건 검증 후 반영. 핵심 발견 2건(가중치 역전·전 경로 필터 누락)은 기존 코드 버그로 이 설계의 선행 수정(§0)이 됐다.

## 배경 (이 repo를 모르는 사람을 위한 설명)

aTee는 티셔츠 22.6만 개(이미지 96.7만 장, SigLIP2 벡터)를 2열 무한 피드로 탐색하는 PWA다. 2차 작업까지로 행동 신호 수집·취향 프로필·5유형 포트폴리오 믹스(`c_mix_page` RPC)가 develop에 병합됐다. 이번 라운드는 2차에서 남긴 후속 3건(분류 교정·축 고도화·신선도 가산점)에, 외부 리뷰로 드러난 기존 버그 2건 수정을 더해 진행한다.

1. **표·라벨(3류) 오분류 교정** — 이미지 유형 zero-shot 분류에서 3류("size chart") 프롬프트가 실제로는 뒷모습·전신 착용샷 6.1만 장(6.3%)을 흡수했다(사람 판정 200장에서 3류 50/50 전부 오분류). 임시로 노출 필터를 `img_type <> 2`로 완화해 둔 상태라, 진짜 사이즈표가 피드에 노출될 수 있다(3류 썸네일 상품 약 1만 개).
2. **부분 일치·반대 축 고도화** — 믹스 RPC v1 축이 임시 구현이다: 부분 일치 = 같은 성별+가격 ±30%, 반대 = 그래픽 라벨 반전. 설계 원안은 색군 기반: "색군 같고 그래픽 다름"(부분 일치), "무채↔원색"(반대).
3. **신선도 가산점** — 현재 노출 이벤트에 `is_fresh` 플래그만 기록하고, 각 유형 슬롯 안에서 신상품을 우대하는 가산점은 미구현.

## §0 선행 수정 — 리뷰로 확인된 기존 버그 (새 범위)

- **앵커 가중치 역전**: 현행 세션·장기 재정렬 점수가 `(emb <#> anchor) / w`인데 `<#>`는 음수 내적이라, 가중치가 높은 앵커의 후보가 오히려 뒤로 밀린다(예: 유사도 0.8에서 w=1 → -0.8, w=2 → -0.4 — 오름차순 정렬에서 후자가 밀림). 가중치가 의도대로 유리하게 작용하는 식으로 교정한다(구체 식은 구현에서 결정, 교정 전후 앵커별 후보 구성 비교로 확인).
- **이미지 유형 필터의 전 경로 누락**: 유형 필터가 세션·장기(ANN) 후보에만 걸려 있고, 부분 일치·반대·다양성 슬롯과 기본·폴백 피드 뷰(`c_feed_products`)는 썸네일을 유형 검사 없이 반환한다. **현행 자격(`img_type <> 2`)을 우선 모든 노출 경로에 일관 적용**한다(뷰에 넣을지 각 슬롯 조건에 넣을지는 성능 실측으로 결정). A 단계 게이트를 통과하면 §2에 따라 이 자격이 표·라벨(3)까지 제외하도록 강화된다. 완료 기준: 부분·반대·다양성·폴백 각 경로의 응답 표본에서 제외 대상 유형이 0건.

## §1 전체 구조와 데이터 흐름

서버(Supabase) 내부 로직과 로컬 임베딩 파이프라인만 바뀐다. **믹스·유사 RPC의 시그니처(입출력)는 그대로**라 프론트엔드는 원칙적으로 무변경이고, 기존 폴백·계측 경로도 그대로 동작한다.

- **§0(선행 수정)**: `c_mix_page`(+필요시 피드 뷰) 마이그레이션.
- **A(재분류)**: 로컬 `backend/embed/data/embed_state.db`의 96.7만 벡터 → 새 프롬프트로 재스코어(이미지 재임베딩 없음) → 홀드아웃 평가 → Supabase `c_img_vecs` 버전 붙여 일괄 갱신 → 게이트 통과 시에만 필터 강화.
- **B(색군 축)**: 공식 색 코드 사전 기반 매핑 테이블 + `c_mix_page` 부분 일치·반대 로직 교체.
- **C(신선도)**: `c_mix_page`의 **재정렬 단계에만** 가산점 추가(ANN 후보 생성 불변).
- **계측 분리**: 노출 이벤트의 정책 필드에 알고리즘 버전 태그를 올려(예: 믹스 v2) 배포 전후 지표를 버전별로 분리 집계한다.

## §2 A — 표·라벨 프롬프트 개선·재분류

- **분류 버전 고정**: 모델 리비전(HuggingFace revision pin)·전처리·프롬프트 세트·라벨 병합 규칙(보조 클래스를 0~3 코드로 접는 규칙 포함)을 하나의 분류 버전으로 정의하고 기록한다. **신·구 `type_conf`는 비교 불가**(프롬프트 세트가 바뀌면 softmax 분모가 바뀜) — 기존 신뢰도·임계값을 재사용하지 않는다.
- **평가 체계(기존 200장의 한계 반영)**: 기존 판정 도구는 맞음/틀림만 기록하고 정답 클래스가 없어 자동 채점 기준으로 못 쓴다. 대신 ① **AI가 정답 라벨(0~3)을 부여한 층화 홀드아웃 표본**을 새로 만들고(프롬프트 선택용 표본과 분리 — 같은 표본으로 고르고 평가하는 과적합 방지), ② 진짜 표·라벨 **양성 표본**을 확보해(새 3류 고신뢰 후보에서 AI 확인) 정밀도·재현율을 수치로 산출한다. 표본 크기·합격선(예: 3류 정밀도 ≥90%, 뒷모습 오분류 잔존 ≤1%)은 구현에서 확정해 기록한다.
- **보수적 필터 전환**: 홀드아웃 게이트를 **통과한 경우에만** 유사·믹스·피드의 노출 자격을 표·라벨(3)·디테일(2) 제외로 강화한다. 통과하지 못하면 현행 `<> 2`를 유지하고 결과·원인을 기록해 후속(사람 판정 등)으로 넘긴다 — 어중간한 분류로 정상 상품 6만 장을 다시 잃는 회귀를 금지.
- **반영(버전·복구 가능)**: `c_img_vecs`에 분류 버전 열을 추가하고, `img_type`·`type_conf`·버전을 **함께** 갱신한다(라벨 동일 행도 신뢰도는 새 체계로). 배치 갱신은 재개 가능한 체크포인트, 갱신 후 행 수·클래스 분포를 로컬 DB와 대조, ANALYZE 수행. 구버전 분류는 로컬 DB에 보존해 복구 자료로 삼는다. Micro 인스턴스이므로 배치 크기를 제한해 WAL·캐시 축출 부담을 관리한다.

## §3 B — 색군 매핑 + 부분 일치·반대 축

- **정본은 공식 코드 사전**: `color_codes`는 무신사 공식 54코드다. 매핑은 무신사 필터 메타(코드→색 이름)를 정본으로 만들고, 상품명 키워드 분석은 **검수 보조**로만 쓴다(상품 12.1%가 다중 코드라 상품명 최빈값은 편향됨 — 리뷰 실측). 공식 사전을 얻지 못하면 그때 상품명+AI 검수 조합으로 대체하되 근거를 기록한다.
- **매핑 테이블**: `c_color_groups(code, group_name, is_achromatic, is_vivid)`. `group_name`은 색 계열(블랙계·화이트계·그레이계·블루계·레드계 등), `is_achromatic`/`is_vivid`는 계열과 **독립 속성**(예: 네이비는 블루계·무채 아님·원색 아님). 54코드 전부 매핑(누락 없음)을 테스트로 강제하고, 새 코드 유입 시 "기타" 처리 규칙을 둔다.
- **다중값·엣지 규칙(명시)**:
  - 앵커·후보 모두 색군 집합으로 다루고, **교집합이 있으면 색군 일치**로 본다.
  - 반대 제안의 색 축은 **무채↔원색만** 대상으로 한다. 앵커가 무채·원색 어느 쪽도 아니면(중간색) 색 축 반대는 건너뛰고 그래픽 반전만 쓴다. 무채와 원색 코드를 동시에 가진 앵커는 우세 코드(첫 코드) 기준.
  - 색 코드 없는 상품(0.3%)은 부분 일치·반대 후보에서 제외(다양성으로는 노출 가능).
  - 배열 전개 조인으로 상품이 중복 집계되지 않게 중복 제거를 명시한다.
- **부분 일치(15%)**: 최고 가중 앵커와 **색군은 일치하고 그래픽 성향은 다른** 상품. 현행 성별·가격 조건의 보조 유지 여부는 후보 수 실측으로 결정.
- **반대 제안(10%)**: 현행 그래픽 반전에 무채↔원색 반전 추가(결합/교대는 실측으로 결정).
- **그래픽 축 표본 검증**: 부분·반대가 의존하는 `graphic` 라벨(무지/그래픽/레터링, 3택 강제)의 정확도를 이번에 표본으로 확인하고 기록한다(부정확하면 축 사용 방식을 조정).

## §4 C — 신선도 가산점

- **적용 위치 고정**: ANN 후보 생성(IVFFlat `ORDER BY binary_quantize ... <~>`)은 **손대지 않는다** — 정렬식에 다른 항을 섞으면 인덱스가 무력화되어 96.7만 행 스캔이 된다(앵커당 반복이라 Micro에서 즉시 타임아웃급). 신선도는 이미 좁혀진 후보 집합의 **재정렬 단계에서만** 반영하고, EXPLAIN으로 이진 인덱스 사용을 확인한다.
- **무작위 계열(부분·반대·다양성)**: `is_fresh DESC` 같은 전면 우대는 금지(후보가 충분하면 전부 올해 상품으로 채워짐). 시드 결정적인 **소폭 가중**(예: 슬롯 일부만 신선 우선, 목표 노출 상승 폭 상한)으로 구현 — 방식·상수는 구현에서 정하되 상수로 분리.
- **페이지 불변성 유지**: 같은 시드 → 같은 페이지(가산점 포함 전 과정이 결정적).
- **한계 명시**: `season_year`는 시즌 표기 프록시다('0000' 7.2만·NULL 0.6만 — 이들은 신선 아님으로 처리). 효과는 알고리즘 버전 태그로 분리된 신선도 비율·유형별 행동 지표로 비교한다.

## §5 회귀 방지·에러 처리

- RPC 실패 시 무작위 폴백 경로, 스크롤 복원, 상세 하단 유사 탐색 등 기존 동작 회귀 금지.
- **서버 입력 방어**: 믹스 RPC는 anon이 직접 호출 가능하므로 서버 측에서 앵커 배열 길이·제외 목록 길이 상한, 비유한수(NaN·Infinity) 가중치 거부, NULL 제거를 명시적으로 수행한다(현재는 클라이언트 상한에만 의존).
- 재분류 update는 배치·멱등·버전 표시(§2). 필터 강화는 별도 마이그레이션으로 분리해 단독 롤백 가능하게 — 단, 이는 필터의 롤백이지 분류 데이터의 롤백이 아니므로 분류 복구 자료는 로컬 DB 보존으로 확보(§2).
- 컴퓨트는 Micro(RAM 1GB) 유지 전제 — 콜드 1~2.5초 특성은 이번 범위에서 바뀌지 않음(업그레이드는 보류 결정).

## §6 성능 게이트 (완료 기준을 수치로)

실사용급 프로필(세션 2·장기 3 앵커)+제외 600개+30장 요청 기준:

- 웜 p50이 현행(1.3~2.8초) 대비 악화 ≤20%, 웜 p95 ≤ 5초(클라이언트 타임아웃 내).
- 콜드 ≤ 8초(anon statement_timeout 내 — 폴백 미발생).
- 동시 2~4 요청에서 실패·타임아웃 없음(work_mem 64MB가 정렬 노드마다 잡히는 위험 확인 — 문제 시 완화).
- EXPLAIN으로 ANN 경로의 이진 인덱스 사용 확인, temp spill 없음.

## §7 테스트·검증

- backend pytest: 색군 매핑 무결성(54코드 전원 매핑·속성 조합 유효), 재분류 파이프라인 순수 로직(라벨 병합 규칙 등).
- 분류 검증: 홀드아웃 정밀도·재현율 수치, 클래스 전환 행렬(어느 유형에서 어느 유형으로 몇 건), 로컬↔원격 행 수·분포 일치.
- SQL 검증: 같은 입력·시드의 완전 동일 응답(결정성), 30장 충족·유형별 quota와 backfill, 제외 목록 재등장 0건, **부분·반대·다양성·폴백 경로 각각에서 제외 유형 0건**, 색군·그래픽 축 조건 만족 표본 확인, 엣지(색 없음·다중 색·중간색 앵커·존재하지 않는 앵커).
- Orca 브라우저: 특정 색 상품 찜 후 부분 일치·반대 카드가 색군 논리에 맞는지, 상세 하단 유사 탐색·피드에서 표·라벨 이미지가 사라졌는지 확인.
- `npm run check`·vitest·pytest 게이트 통과 후 develop 대상 PR.

## 진행 형태

계획 문서 1개(`docs/plans/`), 단계별 완료 기준, 브랜치 1개 → develop PR 1개. 순서: **§0 선행 수정 → A(재분류·게이트·필터) → B(축) → C(가산점) → 통합 검증**. §0은 독립 버그 수정이라 맨 앞에서 바로 체감 확인이 가능하고, A가 끝나야 B·C의 후보 풀이 올바른 분류 위에서 동작한다.

## 미정 (지어내지 않고 남겨둔 것)

- 가중치 교정의 구체 식, 전 경로 유형 필터의 구현 위치(뷰 vs 슬롯별) — 성능 실측으로 결정
- 홀드아웃 표본 크기·합격선 수치 — 구현 시 확정해 기록
- 공식 색 코드 사전 확보 방법(필터 메타 API 가능 여부) — 구현에서 확인, 실패 시 대체 경로 기록
- 부분 일치의 성별·가격 보조 조건 유지 여부, 반대 축 결합/교대 방식, 신선도 가중 방식·상수 — 실측으로 결정
- 알고리즘 버전 태그의 구체 값 체계(기존 policy 필드 활용 형태) — 구현에서 결정

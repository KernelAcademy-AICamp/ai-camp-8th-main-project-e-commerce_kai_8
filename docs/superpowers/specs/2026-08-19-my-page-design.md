# 마이페이지 분리 — 설계

- 작성: 2026-08-19
- 상태: 합의됨 / 구현 전
- 관련: [로그인 화면 설계](2026-08-19-login-screen-design.md) §10 · [계정 찜 설계](2026-08-18-account-wishlist-design.md)

## 배경

피드 상단의 `ⓘ`가 무엇인지 알기 어렵고, 계정 관련 항목(로그인·로그아웃·탈퇴)이 "개인화 안내" 안에 섞여 있다. 계정을 별도 화면으로 빼고 개인정보 쪽은 설정으로 남긴다.

## 범위

**이번 조각** — 화면 구조만. 마이페이지 신설, 설정을 톱니로 분리, 아이콘 회색 통일.

**이번 조각이 아닌 것** — "내 취향" 카드. 취향 앵커의 썸네일을 보여주려면 **상품 번호 목록으로 조회하는 서버 함수**가 필요한데(지금 없다), 구조 변경과 새 기능을 한 조각에 섞지 않는다. 구조가 먼저 돌아가야 카드를 어디에 넣을지도 정확해진다.

## 1. 화면 배치

```
피드 상단:   ♡ 찜        👤 마이페이지        ← 형제. 같은 높이에 나란히
                          │
                          ├─ 계정 (상태 / 로그인 / 로그아웃)
                          └─ ⚙ 설정
                               ├─ 개인화 안내
                               ├─ 개인화 데이터 지우기
                               ├─ 계정 삭제
                               └─ 개인정보 처리방침
```

**찜은 마이페이지 밖에 둔다.** 안으로 넣자는 안도 있었으나 택하지 않았다 — 찜은 이 앱의 핵심 상호작용이고 PRD가 **찜률을 지표로** 잡는다. 한 단계 깊어지면 지표가 떨어져도 **기능 탓인지 위치 탓인지 가릴 수 없다.** 개인화 검증 단계에서 그 혼선은 비싸다.

## 2. 마이페이지

```
┌──────────────────────────────────┐
│                            ⚙     │
│                                  │
│   ◯   로그인이 필요해요             │
│       로그인하면 찜을 저장해요        │
│                                  │
│   [       로그인하기       ]       │
│                                  │
└──────────────────────────────────┘
```

- **우상단 톱니** → 설정.
- **아바타**는 회색 원. 시안의 보라 그라데이션은 쓰지 않는다 — 이 앱은 무채색이고, 사진에 시선이 가야 한다.
- **로그인 전**: "로그인이 필요해요" + 무엇이 좋아지는지 한 줄 + 흰 pill 버튼 → 로그인 화면.
- **로그인 후**: 이메일 + 로그아웃.
- **카드는 두지 않는다.** 지금 마이페이지가 가진 것은 계정뿐이고, 없는 기능을 카드로 약속하지 않는다. "내 취향" 카드가 생기면 그때 채운다.

**비회원도 들어갈 수 있다.** 아래에 설정이 달려 있고 거기에 개인정보 삭제 수단이 있다. 막으면 방침이 약속한 "설정의 초기화 버튼 한 번으로 지워진다"가 깨지고 OAuth 심사에도 불리하다.

## 3. 설정

지금 설정 화면에서 **계정 영역을 뺀다.** 대신 **계정 삭제를 여기로 옮긴다** — 되돌릴 수 없는 동작 둘(개인화 데이터 지우기·계정 삭제)이 한곳에 모이고, 실수로 누를 일이 줄어든다. 계정 삭제는 로그인한 사람에게만 보인다.

들어오는 길은 마이페이지의 톱니뿐이다. 피드 상단에서 설정으로 바로 가는 길은 없앤다.

## 4. 아이콘

전부 회색 계열로 통일한다.

**⚠️ 이모지는 색을 못 바꾼다.** `👤`(U+1F464)는 이모지라 플랫폼 폰트가 색을 정하고 CSS로 회색을 입힐 수 없다. 사람·톱니는 **인라인 SVG**로 넣는다. 지금 쓰는 `♡`(U+2661)는 텍스트 기호라 색이 먹으므로 그대로 둔다.

## 5. 완료 기준 (돌려서 눈으로 확인)

1. 피드 상단에 `♡`과 사람 아이콘이 **나란히** 있고, 둘 다 같은 회색이다.
2. 사람 아이콘을 누르면 마이페이지가 열린다.
3. 로그인하지 않은 상태에서 **마이페이지에 들어갈 수 있고**, "로그인이 필요해요"와 로그인 버튼이 보인다. 그 버튼은 로그인 화면으로 간다.
4. 로그인한 상태에서는 이메일과 로그아웃이 보인다.
5. 우상단 톱니를 누르면 설정이 열린다.
6. 설정에 **개인화 안내·데이터 지우기·처리방침**이 있고, 로그인했으면 **계정 삭제**도 있다. 계정 영역(로그인 버튼·이메일)은 없다.
7. **로그인하지 않아도 설정에 들어가 데이터를 지울 수 있다.**
8. 아이콘이 이모지가 아니라 회색으로 칠해진다.

## 5-1. 검증 기록 (2026-08-19, Aside 브라우저 + 프로덕션 빌드)

| 확인한 것 | 결과 |
|---|---|
| 피드 상단 | `♡`과 사람 아이콘이 나란히, **색이 정확히 같다**(`lab(66.128 …)`). 사람 아이콘은 SVG |
| 사람 아이콘 | `/my`로 감 |
| 마이페이지 (로그인) | 이메일 + 로그아웃 + 우상단 설정 |
| 마이페이지 (비회원) | **들어가짐.** "로그인이 필요해요" + 로그인하기 버튼 |
| 설정 | 개인화 안내·처리방침·데이터 지우기. **계정 영역 없음** |
| 설정 (비회원) | **들어가지고** 데이터 지우기·처리방침 그대로. **계정 삭제는 안 보임** |
| 설정 (로그인) | 계정 삭제가 보임 |
| 캐시 헤더 | `/my`·`/settings`만 `private, no-store`. `/`·`/login`·`/wishlist`는 캐시 가능 |

**검증하다 고친 것**: 개인화 안내가 *"위 계정 영역의 계정 삭제를 쓰세요"*라고 없어진 자리를 가리키고 있었다. 계정 삭제는 비회원에게 아예 보이지 않으므로 위치 대신 조건으로 바꿨다 — *"로그인한 상태에서 계정 삭제를 쓰세요"*.

**함께 옮긴 것**: 로그인 콜백이 이제 `/my`로 돌아온다. 그대로 뒀으면 로그인한 사람이 **계정이 보이지 않는 설정 화면**에 떨어졌다. 세션 갱신 경로와 캐시 차단 경로에도 `/my`를 넣었다 — 넣지 않으면 만료된 토큰이 마이페이지에서 갱신되지 않는다.

## 6. 미정

- 마이페이지 주소. `/my`로 두되 다른 이름이 나으면 구현 중에 바꾼다.

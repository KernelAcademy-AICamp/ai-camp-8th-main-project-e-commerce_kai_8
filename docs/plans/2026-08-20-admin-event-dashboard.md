# admin 이벤트 대시보드 — 실행 계획

- 작성: 2026-08-20
- 설계: [admin 이벤트 대시보드 설계](../superpowers/specs/2026-08-20-admin-event-dashboard-design.md)
- 브랜치: `develop`에서 `feature/admin-event-dashboard`를 딴다

> 이 계획에는 코드가 없다. [AGENTS.md](../../AGENTS.md)의 계획 작성 규칙에 따라 **무엇을 / 어떤 순서로 / 무엇이 보이면 끝**만 적는다. 구현 방법은 열어둔다.

## 목표

`c_events`에 쌓인 행동 신호를 브라우저에서 표로 볼 수 있게 한다. 허락된 사람만 본다.

## 사람이 먼저 해줘야 하는 것

AI가 자격증명을 갖고 있지 않아 대신할 수 없는 작업이다. 각 단계 안에 표시해뒀다.

- Supabase 콘솔 접근 (계정 생성)
- Vercel 계정과 프로젝트 생성 권한
- 대시보드를 볼 사람들의 구글 계정 이메일 목록

## 단계 요약

| 단계 | 무엇 | 끝났다는 신호 |
| --- | --- | --- |
| 1 | admin 전용 읽기 계정 만들기 | 그 계정으로 `c_events` 건수가 나오고, 쓰기는 거부된다 |
| 2 | 카드 하나가 로컬 화면에 뜬다 | 브라우저에 표 하나. 숫자가 `psql` 결과와 같다 |
| 3 | 출입 통제 | 로그인 안 하면 못 본다. 허용 목록 밖 계정도 못 본다 |
| 4 | Vercel 배포 | 폰에서 주소를 열면 로그인 화면 → 로그인하면 표 |
| 5 | 기존 지표 5개 이식 | 카드 6개. 전부 `psql` 결과와 대조표로 일치 확인 |

**1단계가 먼저인 이유**: 여기서 막히면 나머지 설계가 통째로 바뀐다. 화면부터 만들었다가 데이터를 못 읽는 것을 나중에 발견하면 만든 것을 버려야 한다.

**2단계가 화면의 첫 조각인 이유**: 이 제품의 핵심은 "숫자가 보인다"이다. 로그인·배포·꾸미기는 그다음이다.

## 1단계 — admin 전용 읽기 계정

**하는 일**

1. **(사람)** Supabase 콘솔에서 admin 전용 데이터베이스 계정을 만든다. 읽기 권한만 준다. **비밀번호는 어디에도 커밋하지 않는다 — 이 repo는 public이라 커밋하는 순간 인터넷에 공개된다.**
2. `c_events`에 그 계정의 읽기를 허용하는 정책을 마이그레이션 파일로 추가한다. 기존 마이그레이션 파일들과 같은 위치·같은 이름 규칙을 따른다.
3. 계정 생성 절차를 문서로 남긴다. 다음에 사람이 바뀌어도 재현할 수 있어야 한다. 다음을 포함한다.
   - 어떤 권한을 주고 어떤 권한을 주지 않는가
   - 비밀번호를 어디에 두는가 (Vercel 환경변수)
   - **새 테이블을 대시보드에 넣을 때** 무엇을 추가해야 하는가
   - **순서**: 계정이 먼저, 마이그레이션이 나중 (정책이 없는 계정을 가리키면 실패한다)

**완료 기준**

- 그 계정으로 `c_events` 건수를 세면 **0이 아닌 숫자**가 나온다.
  - 0이 나오면 정책이 안 먹은 것이다. 실패로 기록하고 원인을 찾는다. **0을 "데이터가 없나 보다"로 넘기지 않는다.**
- 같은 계정으로 `c_events`에 쓰기가 **거부**된다.

**커밋**: 마이그레이션 파일. 비밀번호가 안 섞였는지 확인한다.

### ✅ 1단계 결과 (2026-08-20)

| 확인 | 결과 |
| --- | --- |
| 역할 생성 | `atee_admin_ro` — `canlogin=true`, `super=false`, `createrole=false` |
| 읽기 | `set role atee_admin_ro` 후 `count(*) = 10,656` |
| **전체를 읽는가** | `postgres`로 센 값도 **10,656** — 정책이 거르는 것 없음 |
| **쓰기 거부** | `has_table_privilege(...,'delete') = false`, `update` = `false` |
| 정책 | `admin_ro_select_c_events` / SELECT / `{atee_admin_ro}` |
| 비밀번호 | 설정됨 (Vercel 환경변수로 4단계에 투입) |

**부딪힌 것**: `set role`이 `42501 permission denied`로 거부됐다. PostgreSQL 16부터 멤버십이 `admin`/`set`/`inherit`으로 쪼개졌는데 역할 생성 시 `set`이 안 붙는다. `grant ... with set true` 한 줄로 닫고 마이그레이션에 넣었다. 상세는 [설계 §9](../superpowers/specs/2026-08-20-admin-event-dashboard-design.md#9-미검증열린-항목).

**아직 안 닫힌 것**: 위 확인은 콘솔 안에서 역할을 갈아탄 것이라 **비밀번호·트랜잭션 풀러 경로는 통과하지 않았다.** 2단계에서 앱이 실제로 붙을 때 닫힌다.

## 2단계 — 카드 하나가 로컬 화면에 뜬다

**하는 일**

1. `admin/`을 만든다. `frontend/`·`backend/`와 같은 레벨. Next.js 앱 뼈대와 품질 도구(lint·typecheck·format·test)를 `frontend/`와 같은 기준으로 갖춘다.
2. 지표 폴더를 만들고 **카드 하나**를 넣는다. 내용은 가장 단순한 것 — 전체 이벤트 수, 오늘 이벤트 수, 최근 7일 이벤트 수 정도.
3. 그 SQL을 실행해 결과를 표로 그리는 경로를 만든다. **컬럼 이름을 그대로 표 머리글로 쓴다** — 결과 모양을 미리 알지 못해도 표가 나와야 한다.
4. 데이터베이스 접속은 **트랜잭션 풀러 주소**로 한다. `backend/.env.example`의 `SUPABASE_DB_URL`(세션 풀러)과 **다른 주소**다. 환경변수 이름도 backend와 달리해 혼동을 막는다.
5. `admin/.env.example`을 만들어 필요한 환경변수를 적는다. 실제 값은 넣지 않는다.
6. **접속 자체가 실패하면 화면 전체에 크게 알린다.** 이게 없으면 다음 단계부터 "0인지 못 읽은 건지"를 계속 헷갈린다.
7. 지표 폴더를 읽어 카드 목록을 만드는 부분에 테스트를 쓴다. 파일이 없을 때·순서가 어긋날 때를 포함한다.
8. CI에 `admin` 검사를 추가한다. 지금 [ci.yml](../../.github/workflows/ci.yml)은 `frontend`와 `backend`만 검사하므로, 그대로 두면 **admin 코드는 한 줄도 검사되지 않는다.**

**완료 기준**

- 로컬에서 개발 서버를 띄우고 브라우저를 열면 **표 하나가 보인다.**
- 그 숫자가 `psql`로 같은 SQL을 돌린 결과와 **같다.** (양쪽 출력을 나란히 남긴다)
- 환경변수의 접속 주소를 일부러 틀리게 하면 **표 대신 경고**가 뜬다. 빈 표나 0이 아니다.
- `admin`에서 품질 검사 명령이 통과한다.
- PR을 열면 CI에 admin 검사가 **돌고 초록불**이다.

**아직 안 하는 것**: 로그인. 이 단계의 앱은 로컬에서만 돌리고 **배포하지 않는다.**

### ✅ 2단계 결과 (2026-08-20)

| 확인 | 결과 |
| --- | --- |
| 카드가 화면에 뜨는가 | 이벤트 유입 카드 1개 — 전체 / 최근 24시간 / 최근 7일 / 기기 수 / 마지막 기록(KST) |
| 숫자가 DB와 같은가 | 대시보드 `10,354` = SQL Editor `select count(*)` `10,354` |
| 접속 실패 표시 | **실물로 확인됨.** TLS 오류 때 표 대신 화면 전체 경고가 떴고 "0이 아니라 알 수 없음"이라고 표시했다 |
| 자동 검사 | lint · typecheck · format · 테스트 21개 · build 모두 통과 |
| 빌드 시 DB 접속 | 불필요 — `/`가 `ƒ Dynamic`으로 잡힘 |
| **비밀번호 + 풀러 경로** | **닫힘.** 앱이 `atee_admin_ro`로 트랜잭션 풀러를 통해 실제로 붙었다 (1단계에서 남겨둔 항목) |

**부딪힌 것 1 — dedicated pooler는 Vercel에서 못 쓴다.** 콘솔이 기본으로 보여주는 트랜잭션 풀러(`db.<ref>.supabase.co:6543`)는 Pro 플랜의 dedicated pooler이고 **IPv6 전용**인데 Vercel은 IPv6를 지원하지 않는다. `Use IPv4 connection` 토글로 shared pooler(`aws-1-ap-northeast-2.pooler.supabase.com:6543`)를 써야 한다. 상세는 [설계 §2-3](../superpowers/specs/2026-08-20-admin-event-dashboard-design.md).

**부딪힌 것 2 — `sslmode=require`의 뜻이 도구마다 다르다.** Supabase의 Postgres 포트는 자체 CA로 발급한 인증서를 쓴다. psql·psycopg(libpq)는 `require`에서 CA를 검증하지 않아 지금까지 문제가 없었지만, `pg`는 `require`를 가장 엄격한 모드로 해석해 거부한다(`self-signed certificate in certificate chain`). 기존 경로와 같은 동작인 `no-verify`를 쓴다.

**숫자가 줄어 보였던 건 오류가 아니었다.** 중간에 앱에서 "개인화 데이터 모두 지우기"를 눌러 그 기기의 이벤트가 실제로 삭제됐다(`c_forget_device`). 삭제 기능이 약속대로 동작한 것이다.

**계획에 없었지만 함께 막은 구멍**: [ci.yml](../../.github/workflows/ci.yml)에 `admin` job 추가, [.husky/pre-commit](../../.husky/pre-commit)이 `frontend`에서만 돌던 것을 `admin`에도 적용. 둘 다 그냥 뒀으면 admin 코드가 아무 검사도 받지 않았다.

## 3단계 — 출입 통제

> **2026-08-21 — 3-A(임시 비밀번호)로 먼저 닫았다.** 아래 구글 로그인은 3-B로 미뤘다.
> 배포를 먼저 하고 싶다는 요청에 따른 것이며, **아무 통제 없이 배포하는 것보다
> 낫다**는 판단이다. 4단계의 잠금은 3-A로 풀린다.

### 3-A. 임시 — 공용 비밀번호 하나 ✅ (2026-08-21)

HTTP Basic 인증을 `admin/proxy.ts`에 붙였다. 주소를 열면 브라우저가 비밀번호를 묻고
판정은 서버에서 한다. 판정 로직은 `features/access/domain/basic-auth.ts`에 순수 함수로
분리해 테스트했다.

| 확인 (실행함) | 결과 |
| --- | --- |
| 인증 없이 접근 | `401 Unauthorized` |
| 응답에 대시보드 내용이 실리는가 | 0건 — 화면에서 가린 것이 아니라 아예 안 나간다 |
| 브라우저 비밀번호 창 | `www-authenticate: Basic realm="aTee admin"` 확인 |
| 401 응답 캐시 | `cache-control: no-store` |
| 정적 자산 예외 | 401이 아님 (matcher 예외가 맞게 걸림) |
| **환경변수를 빠뜨렸을 때** | **잠긴다.** 열리는 쪽으로 실패하지 않는다(fail closed) |

**이 방식이 못 하는 것** — 누가 봤는지 알 수 없다. 유출되면 전원에게 새 비밀번호를
다시 알려야 한다. 비밀번호는 ASCII만 쓸 수 있다(Basic 인증의 제약).

**적용 범위는 "전부 막고 예외만 뺀다"로 잡았다.** 경로를 하나씩 나열하면 나중에 페이지를
추가할 때 빠뜨리기 쉽고, 빠뜨린 경로는 조용히 공개된다.

### 3-B. 나중 — 구글 로그인 + 이메일 허용 목록

설계 §3이 정한 본안. 갈아끼울 때 고칠 곳은 `proxy.ts` 하나다 — 화면 코드는 출입 통제
계층을 모른다.

**하는 일**

1. 로그인하지 않은 요청은 어떤 경로로 들어와도 로그인 화면으로 보낸다.
2. 구글 로그인을 붙인다. 기존 서비스의 것을 재사용한다.
3. 로그인한 이메일이 **허용 목록**(환경변수)에 있는지 **서버에서** 확인한다. 없으면 데이터를 한 건도 보내지 않는다.
4. `admin/.env.example`에 허용 목록 변수를 추가한다.
5. 순수 로직(허용 목록 판정)에 테스트를 쓴다.

**완료 기준 — 실제로 뚫어본다**

- 로그아웃 상태로 대시보드 주소를 치면 **로그인 화면**이 뜬다.
- **허용 목록에 없는** 구글 계정으로 로그인하면 거절 화면이 뜨고 **숫자가 하나도 안 보인다.**
- 그 상태에서 브라우저 개발자도구 네트워크 탭을 열어봐도 **응답에 숫자가 실려 있지 않다.** (화면에서만 가린 것이 아님을 확인)
- 허용 목록에 있는 계정으로 로그인하면 2단계의 표가 그대로 보인다.

## 4단계 — Vercel 배포

**전제 — 2026-08-20 확인 완료**

admin은 **`frontend`와 다른 Vercel 계정**(개인 Hobby)에 올린다. 기존 계정의 무료 한도가 찼기 때문이다.

Vercel Hobby는 **조직 소유의 _private_ repo를 붙일 수 없다.** 이 repo는 조직(`KernelAcademy-AICamp`) 소유지만 **public**이라 제약에 걸리지 않는다. 조직 repo를 붙이려면 Owner이거나 레포 접근 권한이 있는 Member여야 하는데(Outside Collaborator는 불가), 작업자 계정이 Member임을 확인했다.

> ⚠️ **repo가 나중에 private으로 바뀌면 이 배포가 막힌다.** 아카데미 채점이 끝난 뒤 비공개로 돌리는 경우가 흔하다. 그때는 Pro로 올리거나 GitHub Actions에서 Vercel CLI로 배포하는 방식으로 바꿔야 한다. 갑자기 배포가 안 될 때 여기를 먼저 본다.

**하는 일**

1. **(사람)** Vercel에 **별도 프로젝트**를 만든다. Root Directory = `admin`. 리전 = `icn1`(서울).
2. **(사람)** 환경변수를 넣는다 — 데이터베이스 접속 정보(트랜잭션 풀러), 허용 목록, Supabase 접속 값.
3. **(사람)** **변경이 없으면 빌드를 건너뛰도록 설정한다.** Vercel은 기본적으로 repo에 push가 있을 때마다 빌드하므로, 그대로 두면 `frontend`만 고쳐도 admin이 매번 빌드되어 **무료 한도를 그냥 갉아먹는다.** `admin/`이 바뀔 때만 빌드하게 건다.
4. **(사람)** Supabase 인증 설정의 리다이렉트 허용 목록에 admin 주소를 추가한다. **이걸 빼먹으면 로그인 후 엉뚱한 곳으로 튕긴다.**
5. `admin/README.md`에 배포·환경변수·주소를 적는다. 어느 Vercel 계정에 올라가 있는지도 적는다 — `frontend`와 다른 계정이라 모르면 찾지 못한다.

**완료 기준**

- **폰에서** 배포 주소를 열면 로그인 화면이 뜬다.
- 허용된 계정으로 로그인하면 표가 보인다.
- 허용되지 않은 계정으로는 거절된다.
- **`frontend`만 고친 커밋을 하나 올려보면 admin 빌드가 "건너뜀"으로 표시된다.** 빌드가 돌면 3번 설정이 안 걸린 것이다.
- 배포 후에도 서비스(`frontend`)가 정상이다 — 데이터베이스 접속이 소진되지 않았는지 확인한다.

## 5단계 — 기존 지표 5개 이식

**하는 일**

1. [personalization_metrics.sql](../../backend/db/personalization_metrics.sql)의 5개를 카드로 옮긴다 — 유형별 노출→행동 전환, 정책 분포, 반복 노출률, 신선도 노출 비율, 세션당 탐색.
2. **한국 시간 기준을 한 군데서 정하고 모든 카드가 그것을 쓰게 한다.** 카드마다 각자 처리하게 두면 반드시 빠뜨리는 카드가 생기고, 그 카드만 조용히 하루 밀린 숫자를 보여준다.
3. 시간 변환 로직에 테스트를 쓴다.
4. **카드 하나가 실패해도 그 카드만** 실패로 표시하고 나머지는 정상 표시한다.
5. 카드가 **정상적으로 0건**인 경우와 **실패한** 경우를 화면에서 다르게 보여준다.

**완료 기준**

- 대시보드에 카드 **6개**가 보인다.
- 각 카드의 숫자를 `psql`로 같은 쿼리를 돌린 결과와 **나란히 놓은 대조표**를 낸다. 판정만 적지 않고 양쪽 원본 출력을 함께 낸다.
- 일부러 깨뜨린 SQL 카드를 하나 넣으면 **그 카드만** 실패로 뜨고 나머지 5개는 정상이다.
- 한국 시간 기준이 맞는지: 한국 시간 새벽에 발생한 이벤트가 **그날**로 집계되는 것을 실제 데이터에서 확인한다. 확인할 데이터가 없으면 **미검증으로 남긴다.**

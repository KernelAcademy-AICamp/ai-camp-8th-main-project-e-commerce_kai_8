## 배경 (이 repo를 모르는 사람을 위한 설명)

aTee는 티셔츠 22.6만 개(이미지 96.7만 장, SigLIP2 벡터)를 2열 무한 피드로 탐색하는 PWA다. 2차까지로 행동 신호 수집·취향 프로필·5유형 포트폴리오 믹스 추천이 동작한다. 이번 3차는 2차가 남긴 후속 3건과, 외부 리뷰(Codex)로 확인된 기존 버그 2건을 처리한다:

- **버그 ①** 추천 재정렬에서 앵커 가중치가 의도와 반대로 작용(높은 가중 앵커의 후보가 뒤로 밀림).
- **버그 ②** 부적합 이미지(디테일·원단 등) 제외 조건이 세션·장기 슬롯에만 있고 부분 일치·반대·다양성 슬롯과 기본 피드에는 없음.
- **후속 A** 이미지 유형 분류에서 "표·라벨" 클래스가 전부 오분류(실제론 뒷모습 착용샷 6.1만 장) — 프롬프트를 고쳐 로컬 벡터로 재분류(재임베딩 불필요).
- **후속 B** 부분 일치·반대 제안 축이 임시 구현(성별+가격 / 그래픽 반전) — 설계 원안대로 색군 기반으로 고도화.
- **후속 C** 신선도가 계측 플래그만 있고 노출 우대(가산점)는 미구현.

## 제약 (설계에서 옮김)

- 추천·유사 RPC의 입출력 시그니처는 바꾸지 않는다(프론트엔드 원칙적 무변경, 폴백·계측 경로 유지).
- Supabase는 Micro(RAM 1GB) 유지 전제. 벡터 후보 생성(ANN)의 정렬식은 손대지 않는다(인덱스 무력화 금지).
- 재분류의 엄격 필터 전환은 평가 게이트를 통과한 경우에만. 실패 시 현행 유지(정상 상품을 다시 잃는 회귀 금지).
- 페이지 불변성(같은 시드 → 같은 페이지) 유지. 서버 갱신 작업은 배치·멱등·재개 가능.
- 품질 게이트: `frontend/`는 `npm run check`+vitest, `backend/`는 pytest. 커밋·PR은 제품 책임자 요청 시에만.

## 단계와 완료 기준

### 0. 선행 버그 수정 — 가중치 역전 + 전 경로 이미지 필터

추천 RPC의 세션·장기 재정렬에서 앵커 가중치가 유리하게 작용하도록 수식을 교정하고, 현행 이미지 제외 자격(디테일·원단 제외)을 부분 일치·반대·다양성 슬롯과 기본·폴백 피드에도 일관 적용한다(적용 위치는 성능 실측으로 결정). 성능이 기존 응답 시간에서 유의미하게 나빠지지 않는지 확인한다.

- **완료 기준:** 가중치가 다른 두 앵커로 추천을 요청하면 높은 가중 앵커 계열 상품이 결과 상위에 더 많이 보인다(교정 전후 비교 수치를 실행 기록에 남김). 부분 일치·반대·다양성·폴백 각 경로의 응답 표본에서 제외 대상 유형 이미지가 0건이다. 웜 응답 시간이 기존 범위(1.3~2.8초) 대비 악화 20% 이내다.

### 1. A — 표·라벨 프롬프트 실험·재분류 (로컬)

분류 버전(모델 리비전 고정·전처리·프롬프트 세트·라벨 병합 규칙)을 정의하고, 로컬 벡터로 프롬프트 후보들을 재스코어해 비교한다. 평가는 새로 만든다: AI가 정답 라벨을 부여한 층화 홀드아웃 표본(프롬프트 선택용 표본과 분리)과 진짜 표·라벨 양성 표본으로 정밀도·재현율을 산출하고, 합격선(표본 크기 포함)을 이 문서 실행 기록에 확정해 적는다. 기존 신뢰도·임계값은 재사용하지 않는다.

- **완료 기준:** 홀드아웃 평가표(클래스별 정밀도·재현율·전환 행렬)가 실행 기록에 적히고, 합격선 통과 여부가 명시된다. AI가 새 3류 고신뢰·경계 표본과 기존 오분류(뒷모습) 표본 이미지를 직접 확인한 결과가 기록된다.

### 2. A — 서버 반영 + 필터 강화 (게이트 통과 시)

서버 벡터 테이블에 분류 버전 열을 추가하고, 로컬 재분류 결과(라벨·신뢰도·버전)를 배치로 갱신한다(체크포인트 재개 가능, 갱신 후 행 수·클래스 분포를 로컬과 대조, 통계 갱신). 1단계 게이트를 통과했으면 노출 자격을 표·라벨 제외까지 강화하는 마이그레이션을 별도로 적용한다. 통과하지 못했으면 현행 자격을 유지하고 원인·후속을 기록한다.

- **완료 기준:** 서버에서 분류 버전별 행 수를 SQL로 조회하면 로컬 집계와 일치한다. (게이트 통과 시) 상세 하단 유사 탐색과 피드에서 진짜 표·라벨 이미지가 보이지 않고, 뒷모습 착용샷은 정상 노출된다. 배치를 중단 후 재실행해도 결과가 같다.

### 3. B — 색군 매핑 + 부분 일치·반대 축 교체

공식 색 코드 사전(무신사 필터 메타)을 정본으로 54코드→색군 매핑 테이블(색 계열 + 무채/원색 독립 속성)을 만들고(확보 실패 시 상품명+AI 검수 대체, 근거 기록), 설계의 다중값·엣지 규칙(교집합 일치, 중간색 처리, 색 없음 제외, 조인 중복 제거)대로 부분 일치·반대 축을 교체한다. 부분 일치의 성별·가격 보조 조건 유지 여부와 반대 축 결합/교대 방식은 후보 수·체감 실측으로 정해 기록한다. 그래픽 축(무지/그래픽/레터링)의 정확도도 표본으로 확인해 기록한다.

- **완료 기준:** 54코드 전원 매핑 테스트가 통과한다. 특정 색군 상품을 찜한 뒤 추천을 받으면 부분 일치 슬롯에 같은 색군·다른 그래픽 상품이, 반대 슬롯에 축 반전 상품이 보이고, 응답 표본 SQL 검사에서 각 슬롯이 축 조건을 만족한다. 유형 분포(5유형 비율)가 유지된다.

### 4. C — 신선도 가산점

이미 좁혀진 후보의 재정렬 단계에만 신선도 우대를 넣는다(ANN 정렬식 불변 — 실행 계획으로 이진 인덱스 사용 확인). 무작위 계열은 전면 우대 금지, 시드 결정적인 소폭 가중으로 구현하고 상수는 분리한다. 노출 이벤트의 정책 필드에 알고리즘 버전 태그를 올려 배포 전후 지표를 분리한다.

- **완료 기준:** 같은 시드로 두 번 요청하면 완전히 같은 페이지가 온다. 신선도 비율 계측 SQL에서 가산점 적용 후 신선 상품 노출 비율이 적용 전보다 오르되 전면 쏠림이 아니다(수치를 실행 기록에 남김). 실행 계획에서 벡터 인덱스 사용이 확인된다.

### 5. 서버 입력 방어 + 통합 검증 · 마무리

추천 RPC에 서버 측 입력 상한(앵커·제외 배열 길이, 비유한수 거부, NULL 제거)을 넣는다. 성능 게이트(실사용급 프로필 기준: 웜 p50 악화 ≤20%·p95 ≤5초, 콜드 ≤8초, 동시 2~4 요청 무실패, temp spill 없음)를 실측하고, Orca 브라우저로 전체 흐름(찜 → 축 반영 → 신선도 → 폴백)을 확인한다. `npm run check`·vitest·pytest 통과 후 실행 기록을 남기고 develop 대상 PR을 연다.

- **완료 기준:** 비정상 입력(거대 배열·NaN 가중치)을 보내면 오류 없이 거부·정화된다. 성능 게이트 수치가 실행 기록에 적히고 전부 통과다. 기존 동작(무한 피드·스크롤 복원·뒤로 가기·상세 하단 유사 탐색·폴백)이 그대로 동작한다. PR이 열린다.

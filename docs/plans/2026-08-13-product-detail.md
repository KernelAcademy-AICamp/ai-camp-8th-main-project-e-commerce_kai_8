# 계획 — 카드 확대 전환 상세 화면 (이미지 슬라이드 + 판매처 이동)

> 상태: 확정 (2026-08-13 제품 책임자 승인 — 썸네일 우선 표시 지적 반영) · 작성: 2026-08-13
> 근거 결정: [결정 기록 O-23](../aTee/living/decision-log.md) — 바텀 시트 대신 카드 확대 전환의 상세 화면
> 선행 작업: [피드 프로토타입](2026-08-13-cosmos-feed-prototype.md) (PR #3로 병합됨)

## 배경 (이 repo를 모르는 사람을 위한 설명)

aTee는 티셔츠 이미지를 무한히 훑는 탐색 웹앱이다. 2열 masonry 무한 스크롤 피드 프로토타입까지 완성됐고, 이번에는 피드 카드를 탭했을 때의 **상세 화면**을 만든다.

제품 책임자가 확정한 경험:

- 탭하면 **클릭한 카드가 커지면서** 상세 화면으로 전환된다 (바텀 시트 아님).
- 상세 첫 화면에는 **무조건 대표 썸네일(피드에서 본 그 이미지)이 먼저** 보인다. 피드에서 이미 로딩된 이미지라 지연 없이 뜨고, 확대 전환의 연속성도 유지된다.
- **좌우로 스와이프하면 갤러리 이미지**가 이어서 보인다. 슬라이드 순서는 항상 `[썸네일, 갤러리 1, 갤러리 2, …]`.
- 첫 버전 범위는 **상품 정보 표시 + 판매처 이동**. 찜과 `이 스타일로 계속 탐색`은 다음 단계.
- 뒤로 가면 카드가 다시 줄어들며 **피드의 원래 스크롤 위치로** 돌아온다 (PRD 요구).

데이터 사실 (확인 완료):

- `c_goods`의 `gallery[]`: 전체 22.6만 중 76.5%가 보유, 중앙값 4장, 최대 53장. 갤러리가 없는 상품은 대표 썸네일 1장만 보여준다.
- 갤러리 경로는 상대경로라 CDN 도메인(`image.msscdn.net`)을 붙여야 한다.
- 판매처 링크는 상품 번호로 `https://www.musinsa.com/products/<상품번호>` 형태로 만들 수 있다 (실제 200 응답 확인).

## 범위

### 포함

- 카드 탭 → 확대 전환 → 상세 화면 (미지원 브라우저는 애니메이션 없이 즉시 전환)
- 상세: 이미지 슬라이드(가로 스와이프 + 현재 위치 표시), 제목·브랜드·가격, `판매처로 이동` 버튼
- 뒤로가기(버튼·브라우저 뒤로가기 모두)로 피드 복귀 시 스크롤 위치 유지
- 판매처는 새 탭으로 열고, 돌아와도 상세·피드 상태 유지

### 제외

- 찜, `이 스타일로 계속 탐색`, 개인화 반영
- 사이즈·착용감 등 추가 상품 정보 (첫 버전은 식별·이동에 필요한 최소만)
- 가입·계측

## 단계와 완료 기준

### 1. 샘플 데이터에 갤러리 보강

기존 400개 샘플에 갤러리 이미지 URL 목록을 붙인다(상대경로 → 절대 URL 변환 포함).

- **완료 기준:** 샘플에서 갤러리 있는 상품의 URL 몇 개를 브라우저에 넣으면 실제 착용컷 등이 뜬다. 갤러리 보유 비율을 기록한다.

### 2. 상세 화면 기본 (전환 애니메이션 없이)

카드 탭 → 상세 화면(대표 썸네일·제목·브랜드·가격·판매처 버튼) → 뒤로가기.

- **완료 기준:** 카드를 탭하면 **대표 썸네일이 지연 없이 바로** 보이고, 어느 방법으로든 뒤로 가면 피드가 이전 스크롤 위치 그대로 보인다.

### 3. 이미지 슬라이드

첫 장은 항상 대표 썸네일로 고정하고, 좌우 스와이프로 갤러리 이미지를 넘기며 현재 위치가 표시된다.

- **완료 기준:** 상세 진입 직후 첫 장이 썸네일임을 확인하고, 스와이프하면 갤러리 이미지가 이어지며 위치 표시가 따라온다. 갤러리가 없는 상품은 위치 표시 없이 썸네일 한 장만 보인다.

### 4. 카드 확대 전환

탭한 카드가 커지면서 상세로, 뒤로 가면 줄어들며 카드로 돌아가는 전환을 붙인다. 구현 방식(브라우저 View Transitions, FLIP 애니메이션 등)은 여기서 못박지 않는다.

- **완료 기준:** 탭하면 카드 이미지가 확대되며 상세로 이어지는 것이 눈에 보이고, 뒤로 가면 역방향으로 줄어든다. 미지원 브라우저에서는 전환 없이 즉시 이동한다.

### 5. 판매처 이동 + 모바일 확인

- **완료 기준:** `판매처로 이동`을 누르면 무신사 상품 페이지가 새 탭으로 열리고, 돌아오면 상세·피드 상태가 유지된다. iOS 시뮬레이터에서 1~4 동작을 확인하고 `npm run check`·vitest가 통과한다.

## 미정 (지어내지 않고 남겨둔 것)

- 확대 전환의 구체적 구현 방식과 전환 시간·곡선
- 슬라이드 위치 표시의 형태 (점·숫자 등)
- 상세 화면의 URL 구조 (라우팅 방식은 구현에서 선택하되, 브라우저 뒤로가기가 동작해야 한다는 요구만 고정)
- 상세 진입 시 갤러리 이미지 로딩 순서·미리 불러오기 범위

## 실행 기록 (2026-08-13)

- **1단계:** 샘플 400개에 갤러리 병합 — 296개(74%) 보유, 상대경로에 `image.msscdn.net` 접두 적용. 갤러리 URL 실제 로드 확인(500×500).
- **라우팅 방식(미정 항목 결정):** 별도 라우트 대신 **피드 위 전체 화면 오버레이 + history.pushState**를 선택. 피드가 마운트된 채 유지되어 스크롤 위치가 자동 보존되고, 브라우저 뒤로가기는 popstate로 오버레이를 닫는다.
- **확대 전환(미정 항목 결정):** View Transitions 대신 **Web Animations API의 FLIP 방식**(탭한 카드 위치 → 히어로 영역, 280ms). 닫을 때 첫 장에 있으면 역방향 재생, 다른 장이거나 reduced-motion이면 즉시 닫음.
- **검증:** Orca 브라우저 — 탭→상세(첫 장=썸네일), 슬라이드 3장 이동+점 표시, 뒤로가기 후 scrollY 1200 그대로, 열림 2개·닫힘 1개 애니메이션 재생, 판매처 링크 `musinsa.com/products/<번호>`(새 탭, noopener). iPhone 17 Pro 시뮬레이터 — 터치 탭·가로 스와이프·뒤로가기 버튼 동작, 갤러리 없는 상품은 점 표시 없음.
- **품질:** `npm run check` 통과, vitest 18개 통과 (domain·상태 훅·컴포넌트 TDD).

## 0. 이 계획이 하는 일 / 하지 않는 일

| | |
|---|---|
| **한다** | 마이페이지 취향 카드의 **조회와 새로고침을 기록**하고, 그 숫자를 어드민 추천 탭에 카드 하나로 보여준다 |
| **하지 않는다** | 계정 식별자 · 비회원 계측 · 처리방침 문구 · 90일 보존 · 다른 카드의 그림 전환 |

### 기기 단위로 가는 이유와 대가

리텐션·활동 일수 카드가 이미 계정 식별자 없이 기기 단위로 나갔다(#106). 같은 선례를 따르면 **처리방침 문구 수정도 O-24 갱신도 필요 없고 마이그레이션 하나로 끝난다.**

**대가**: 한 사람이 폰과 노트북을 쓰면 둘로 세어지고, 시크릿 모드는 매번 새 기기가 된다. 그래서 **실제 사람 수보다 많게 나온다.** 얼마나 많은지는 알 방법이 없다. 카드 머리에 `단위: 기기`를 붙여 이 사실을 화면이 말하게 한다.

### 용어 — Amplitude·Mixpanel 리포트를 따른다

같은 저장소의 [재방문 곡선 카드](../../admin/metrics/return-curve.ts)가 먼저 이 방식을 택했다. 카드 제목은 `한국어 · English (단위)` 형식으로 달고, 주석에 대조표를 남긴다.

| 우리말 | 표준 용어 | 뜻 |
|---|---|---|
| 퍼널 | **Funnel** | 단계별로 얼마나 남는지 보는 표 |
| 단계 | **Step** | 퍼널의 한 칸 |
| 전환율 | **Conversion rate** | 바로 앞 단계 대비 넘어간 비율 |
| 이탈 | **Drop-off** | 다음 단계로 가지 않은 것 |
| 기기 | **Uniques** | 중복을 뺀 수. Amplitude가 Totals와 구분해 세는 방식 |
| 건수 | **Totals** | 발생 횟수 |
| 결과값 | **Event property** | 이벤트에 딸린 속성 |

카드 제목은 **마이페이지 취향 분석 · Taste analysis funnel (기기 단위)**로 한다.

## 3. 단계

각 단계의 완료 기준은 **어드민 원본 이벤트 화면에서 눈으로 확인되는 것**이다. 확인하지 않았으면 미검증으로 남긴다.

### 배포 A — 계측 (frontend + 데이터베이스)

#### A-1. 새로고침이 세 결과를 구분해 돌려주게 한다

지금 즉시 반영 함수는 **`거짓` 하나로 두 가지를 말한다** — "반영할 것이 없었다"와 "기기 저장소 오류"다. 이대로 기록하면 오류가 「변화 없음」에 섞여 들어가고, **나중에 고쳐도 그 사이 데이터는 영영 섞인 채**다.

세 결과로 가른다: 접었다 · 접을 것이 없었다 · 기기 저장소 오류.

**완료 기준** — 기기 저장소를 막아 둔 상태에서 새로고침을 누르면, 접을 것이 없었을 때와 **다른 값**이 나온다. 단위 테스트로 세 갈래가 각각 나오는 것을 확인한다.

#### A-2. 이벤트 두 종과 결과값 열을 계약에 더한다

`taste_view`와 `taste_refresh`를 이벤트 목록에 넣고, 결과값을 담을 열을 하나 더한다.

| 이벤트 | 결과값(저장) | 화면 라벨 |
|---|---|---|
| `taste_view` | `rendered` | 조회됨 |
| | `insufficient_data` | 취향 부족 |
| | `error` | 로딩 실패 |
| `taste_refresh` | `updated` | 새로 반영됨 |
| | `no_new_activity` | 변화 없음 |
| | `ignored_duplicate` | 중복 클릭 |
| | `error` | 실패 |

이벤트 이름은 기존 목록(`impression`·`tap`·`wish`)과 같은 소문자 밑줄 형식을 쓴다. 결과값은 **이벤트 속성**(event property)이라 `event_type`이 이미 갈라 주므로 두 이벤트가 `error`를 함께 써도 섞이지 않는다.

⚠️ **고칠 자리가 네 곳이고, 검증 목록을 빠뜨리면 행이 사라지는 게 아니라 열이 항상 비어 있게 된다.** 같은 경고가 앞선 마이그레이션 세 개에 이미 적혀 있다. 네 곳은 표 제약 · 기록 함수의 삽입 목록 · 입력 형태 선언 · 값 검증 목록이다.

⚠️ **결과값을 기존 열에 얹지 않는다.** 재는 축이 다르면 열도 달라야 한다 — [대체 피드 마이그레이션](../../backend/supabase/migrations/20260818100000_search_replacement_logging.sql)이 이미 같은 실수를 경고해 뒀다.

**완료 기준** — 데이터베이스에 두 이벤트를 직접 넣어 보면 저장되고, 정의에 없는 결과값을 넣으면 **그 행만 조용히 버려진다.**

> ✅ **2026-08-25 적용·검증함.** 운영 데이터베이스에 적용한 뒤 10행을 보내 7행이 저장되는 것을 확인했다. 버려진 3행은 정의에 없는 값·다른 이벤트의 값·결과값을 안 쓰는 이벤트였다. **결과값이 빈 행은 0**이었다 — 검증 목록을 빠뜨렸다면 여기가 7이 됐을 자리다. 시험에 쓴 7행은 지웠다.

#### A-3. 취향 카드가 두 이벤트를 보낸다

카드가 최종 상태에 도달할 때 한 번, 새로고침 버튼을 누를 때마다 한 번 보낸다.

- **조회**: 카드가 마운트되어 세 상태 중 하나로 끝났을 때 **마운트당 한 번**. 새로고침으로 다시 그려져도 조회를 또 세지 않는다
- **새로고침**: 도는 중이라 막힌 클릭도 **중복 클릭**으로 기록한다. 그래야 "누른 횟수"와 "실제로 돈 횟수"가 둘 다 나온다

**별도의 마이페이지 방문 이벤트를 만들지 않는다.** 취향 카드는 마이페이지에서 항상 마운트되므로 조회 이벤트 세 결과값의 합이 곧 그 분모다.

**완료 기준** — 마이페이지를 열면 원본 기록에 조회 줄이 **한 개** 생긴다. 새로고침을 세 번(그중 한 번은 도는 중에) 누르면 새로고침 줄이 **세 개** 생기고 그중 하나가 중복 클릭이다.

> **여기까지 배포해도 된다.** 사용자가 보는 화면도, 문구도 바뀌지 않는다.

### 배포 B — 어드민 카드

#### B-1. 카드가 그림을 그릴 수 있게 한다

지금 카드 정의는 조회 결과를 표 하나로만 그린다. 이 카드는 KPI 타일·퍼널·가로 막대가 필요하다.

**카드 정의에 자기 그림을 지정하는 칸을 하나 더한다.** 지정하지 않은 카드는 지금처럼 표로 그린다 — **다른 카드 여섯은 건드리지 않는다.**

**완료 기준** — 그림을 지정하지 않은 기존 카드 여섯이 **배포 전과 똑같이** 보인다.

#### B-2. 취향 분석 카드를 추천 탭에 붙인다

조회 결과는 한 벌이고, 그것으로 KPI 세 개·퍼널 세 단계·막대 두 묶음을 그린다.

| 자리 | 내용 |
|---|---|
| KPI | 조회율 · 새로고침율 · 조회당 새로고침 |
| 퍼널 | 카드 열림 → 조회됨 → 새로고침 |
| 이탈 이유 | 취향 부족 · 로딩 실패 |
| 결과 분해 | 새로 반영됨 · 변화 없음 · 중복 클릭 · 실패 |

**갈래는 겹치지 않게 센다.** 한 기기가 날마다 다른 상태를 겪을 수 있으므로, **한 번이라도 내용을 봤으면 조회됨**이고 한 번도 못 본 기기만 이유별로 갈린다. 그래야 세 갈래의 합이 카드 열림과 정확히 맞는다.

**분모를 화면이 말하게 한다.** 막대 아래 비율은 첫 단계 대비, 화살표 옆 비율은 바로 앞 단계 대비다. 두 비율이 한 화면에 있으므로 **위치가 분모를 말해야 한다.**

기간·세션 좁혀 보기를 그대로 받는다.

**완료 기준** — 추천 탭에 카드가 보이고, 갈래 셋의 합이 카드 열림과 같다. 날짜로 좁히면 숫자가 함께 줄어든다. 데이터가 없으면 **"행이 0건"**으로 보이고, 데이터베이스가 끊기면 **화면 전체 오류**로 보인다(둘이 달라야 한다).

## 4. 배포 경계

**A와 B는 Vercel 프로젝트가 달라 원자적으로 나갈 수 없다.** A가 먼저다.

A만 나간 동안은 기록만 쌓이고 볼 화면이 없다. B만 먼저 나가면 **빈 카드가 계측 장애처럼 보인다.**

A-1은 A-2·A-3보다 먼저 나가도 되지만, 같이 나가는 편이 낫다 — 따로 나가면 그 사이 기록이 「변화 없음」에 오류가 섞인 채 쌓인다.

## 5. 검증

실기기에서 **손으로 센 값과 어드민 숫자를 대조한다.** 표를 먼저 적어 두고 그대로 나오는지 본다.

1. 마이페이지를 **세 번** 연다 (취향이 정상으로 그려지는 계정)
2. 상품을 몇 개 누른 뒤 새로고침 → **새로 반영됨**
3. 곧바로 다시 새로고침 → **변화 없음**
4. 새로고침이 도는 중에 한 번 더 → **중복 클릭**
5. 로그아웃 후 마이페이지를 연다 → **아무 기록도 없다** (카드가 회원 전용)

**기존 카드가 흔들리지 않는지도 함께 본다.** 새 이벤트가 들어오면 전체 이벤트를 세는 「이벤트 유입」은 **반드시 늘어난다**(그게 맞는 동작). 나머지 다섯은 배포 전후로 **숫자가 같아야 한다.**

**표만 내지 않는다.** 그 기기의 원본 기록 몇 줄을 함께 내서 사람이 직접 대조할 수 있게 한다.

## 6. 되돌리기

| 무엇 | 어떻게 |
|---|---|
| 이벤트 전송 | 보내는 곳을 빼고 배포한다. 이미 쌓인 기록은 남는다 |
| 어드민 카드 | 카드 명단에서 한 줄을 뺀다 |
| 열과 이벤트 종류 | **되돌리지 않는다.** 비워 두면 그만이고, 지우면 이미 쌓인 기록을 잃는다 |

## 7. 위험

| 위험 | 대응 |
|---|---|
| **검증 목록을 빠뜨려 결과값이 항상 빈다** | 건수만 보면 정상으로 보인다. 배포 직후 **결과값이 실제로 채워지는지**를 눈으로 본다 |

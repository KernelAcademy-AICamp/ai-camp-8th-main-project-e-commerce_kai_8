# 계획 — 티셔츠 카탈로그 전체 데이터 감사 (Gate 0 데이터 항목)

> 근거: [Living PRD §9 데이터·플랫폼 제약](../atee/living/prd.md) · [PRD §11 Gate 0](../atee/living/prd.md) · [백엔드 README "남은 일"](../../backend/README.md)
> 선행 작업: 상세 화면 계획(2026-08-13)이 "다음 후보 ③ 전체 데이터 감사"로 지목

## 배경 (이 repo를 모르는 사람을 위한 설명)

aTee는 무신사 티셔츠 이미지를 무한히 훑는 개인화 탐색 웹앱이다. 상품 데이터는 2026-08-12에 무신사에서 수집해 Supabase의 `c_goods` 테이블에 226,320행으로 적재돼 있다. 지금까지 프론트엔드(피드·상세 화면)는 이 중 400개 샘플로만 동작했다.

PRD는 구현 확대 전에 **Gate 0(데이터·상호작용 준비)** 통과를 요구한다. 데이터 쪽 요구는 "약 22만 개 카탈로그의 실제 총량과 필수 필드 커버리지를 확인한다"이다. 상품이 피드에 노출되려면 유효한 이미지, 현재 가격, 판매처 링크, 그리고 회원 자격 판정(성별·사이즈)에 필요한 데이터가 있어야 한다.

이 감사는 **현황을 정확히 측정하는 것**이 목적이다. "노출 가능 상품 조건"과 Gate 0 통과 기준은 이 감사 결과를 보고 제품 책임자가 확정한다(사전에 임의로 정하지 않기로 결정, 2026-08-14).

## 제품 책임자 결정 사항 (2026-08-14 질문 단계)

- 검증 깊이: **전수 SQL 집계 + 라이브 표본 검증** (이미지·판매처 링크가 실제로 열리는지는 무작위 표본으로 확인)
- 품절·판매 종료: **같은 표본에서 품절률만 추정** (전수 확인은 하지 않음)
- 통과 기준: **현황 측정 먼저, 기준은 결과를 보고 함께 확정**

## 범위

### 포함

- Supabase `c_goods` 전수 대상 필드 커버리지·값 품질 SQL 감사
- 무작위 표본에 대한 라이브 검증: 썸네일·갤러리 이미지가 열리는지, 판매처 페이지가 열리는지, 품절·판매 종료 상태
- 결과 문서화와 "노출 가능 상품 조건" 후보·통과 기준 제안 (확정은 제품 책임자)

### 제외

- 데이터 수정·재수집·갱신 파이프라인 구축 (감사 결과가 근거만 제공)
- `c_goods`를 앱에 노출할 읽기 전용 뷰 생성 (다음 작업 — 이 감사의 산출물이 입력이 된다)
- 추천·개인화용 속성 설계
- 품절 전수 확인

## 단계와 완료 기준

### 1. 전수 커버리지 집계

`c_goods` 전체를 대상으로, 총 행 수와 피드 노출·자격 판정에 필요한 필드별 보유율을 센다. 대상 필드: 썸네일, 갤러리, 정가·판매가, 성별, 사이즈, 브랜드, 제목, 그리고 필요 시 보조 필드(색상, 태그, 시즌 등).

- **완료 기준:** 필드별로 "전체 대비 값이 있는 행 수·비율"이 표로 나온다. 총 행 수가 사용자 제공 정보(약 22만)와 일치하는지 여부가 명시된다.

### 2. 값 품질 확인

값이 "있다"만으로는 부족하므로, 있는 값이 쓸 수 있는 값인지 확인한다. 예: 가격이 0이거나 비정상 범위, 성별 값의 종류와 분포(자격 판정에 쓸 수 있는 형태인지), 사이즈 배열이 비어 있는 경우, 이미지 경로 형식이 예상과 다른 경우.

- **완료 기준:** 필드별 이상값 유형과 건수·비율이 기록되고, "자격 판정(성별·사이즈 필터)에 실제로 쓸 수 있는 상품 비율"이 숫자로 나온다.

### 3. 라이브 표본 검증 (이미지·판매처·품절)

무작위 표본을 뽑아 실제 요청으로 확인한다: 썸네일이 열리는지, 갤러리 첫 장이 열리는지, 판매처 상품 페이지가 열리는지, 품절·판매 종료 상태인지. 표본 크기는 전체 비율을 신뢰할 수 있게 추정할 수 있는 수준으로 실행 시 정하고 문서에 근거를 남긴다. 요청 속도는 수집 때 확인된 안전선(동시 6 이하)을 넘지 않는다.

- **완료 기준:** 표본 수·추출 방법과 함께 이미지 실패율, 판매처 링크 실패율, 품절·종료율이 신뢰구간과 같이 기록된다.

### 4. 결과 문서화와 다음 결정 준비

1~3 결과를 감사 보고서 한 편으로 정리한다. 보고서에는 ① 측정 수치 전부, ② 그로부터 도출한 "노출 가능 상품 조건" 후보(조건을 적용하면 몇 개가 남는지 포함), ③ Gate 0 데이터 항목 통과 기준 제안이 들어간다. 확정은 제품 책임자가 한다.

- **완료 기준:** 보고서를 읽으면 "조건 X를 적용하면 상품 Y개가 노출 가능"이 보이고, 제품 책임자가 통과 기준을 결정할 수 있는 선택지가 제시돼 있다.

## 미정 (지어내지 않고 남겨둔 것)

- 라이브 표본의 정확한 크기와 신뢰수준 (실행 시 산출 근거와 함께 확정)
- "노출 가능 상품 조건"과 Gate 0 통과 임계값 (감사 결과를 본 뒤 제품 책임자가 확정)
- 감사 실행 위치(Supabase 직접 질의 / 로컬 스크립트 등)와 도구 — 특정 방식으로 못박지 않는다
- 품절률이 높게 나올 경우의 갱신 주기 설계 (별도 후속 작업)

## 실행 기록 (2026-08-14)

- **1단계:** 총 226,320행 확인(사용자 제공 정보와 일치). 핵심 필드(썸네일·가격·제목·브랜드·사이즈) 100.0%, 성별 99.2%, 갤러리 76.5%, fit 28.1%.
- **2단계:** 가격 이상값 0건. 성별 값 3종으로 깨끗. 사이즈는 형태 6종 혼재 — 확장 정규화로 72.3% 판정 가능, 성별+사이즈 동시 판정 71.9%(162,735개). 깨진 행 1건(goods_no 7022683, 무신사도 무효 응답).
- **3단계(표본, 미정 항목 확정):** 무작위 600개 = 95% 신뢰수준 ±4%p(p=0.5 최악 가정). 썸네일·갤러리·판매처 100% 유효, 판매중 98.8% ±0.9%p, 가격 일치 93.5% ±2.0%p. 첫 측정에서 `salePrice`와 비교하는 착오가 있었고 재검증으로 `price_final`=쿠폰 포함 `finalPrice` 대응을 확인해 보정.
- **4단계:** 보고서 [`docs/atee/foundation/catalog-audit.md`](../atee/foundation/catalog-audit.md) 작성. 노출 조건 후보 A(226,319)·B(224,408)·C(162,735)와 결정 3건(노출 조건·사이즈 결손·가격 신선도)을 제안으로 정리.

## 이 계획이 끝나면

- Gate 0 데이터 항목("실제 총량과 필수 필드 커버리지 확인")이 수치로 채워진다.
- "노출 가능 상품 조건"이 확정되면, 백엔드 남은 일인 **`c_goods` 읽기 전용 뷰 설계**와 **피드 실데이터 연결**을 바로 시작할 수 있다.

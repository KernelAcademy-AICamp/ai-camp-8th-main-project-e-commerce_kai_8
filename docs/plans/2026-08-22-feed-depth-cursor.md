# 개인화 피드 깊이 — 후보풀 커서 구현 계획 (2026-08-22)

설계 근거: [스펙 2차 개정](../superpowers/specs/2026-08-22-feed-depth-cursor-design.md).
이 계획은 코드 없이 순서와 단계별 완료 기준만 적는다(AGENTS.md 계획 작성 규칙).

## 무엇을 만드나 (이 repo 문맥을 모르는 독자용)

aTee의 홈 피드는 무한 스크롤이다. 행동이 쌓인 사용자에게는 **개인화 믹스**(서버 함수
`c_mix_page`)가 한 페이지 30장을 만든다. 그 30장은 두 계열에서 온다 — **벡터 계열**
(세션·장기: 사용자가 본 상품과 이미지가 닮은 것)과 **후보풀 계열**(부분·반대·다양성:
카탈로그를 시드 해시 순으로 정렬한 상위 1,200개에서 색·그래픽 규칙으로 고른 것).

클라이언트는 이미 받은 상품 번호를 **제외 목록**으로 실어 보내 중복을 막는데, 그 목록에
**600개 상한**이 있고 **가장 오래된 600개에 고정**된다. 그래서 601번째부터 받은 상품은
보호받지 못하고, **630개를 본 뒤로는 같은 30개가 무한 반복**된다.

무작위 경로(`c_feed_page`)는 제외 목록 대신 **키셋 커서**를 써서 같은 문제가 없다
(40페이지 1,200장 전부 고유). 이 작업은 그 방식을 후보풀에 가져온다.

**검증 가설 하나**: 후보풀에 커서를 붙이면 **후보풀 계열이 중복 없이 계속 새 상품을 낸다.**

**벡터 계열의 재등장은 이번에 막지 않는다** — 측정만 하고 다음 조각으로 넘긴다
(사람 결정, 2026-08-22). 이유는 스펙 "보장 범위" 참고.

## 0단계 — 기준선을 고정한다 ✅ 완료 (2026-08-22)

이후 모든 비교의 기준이다. 없으면 "회귀가 없다"를 판정할 수 없다.

**고정 입력** — 성별 남성, 시드 42, 크기 30, boost 꺼짐, 세션 앵커 없음,
장기 앵커 50개(`anchors-male-50.txt`, md5 `94b0e380643b1870374395918f6482e3`, 가중치 전부 1.0).

**제외 목록을 실제 클라이언트대로 만들었다** — 누적 목록의 **앞** 600개.
이전 하네스는 `tail -600`(최근 600)을 써서 **측정 장치가 대상과 달랐다.**
같은 630이 나와 결과는 안 바뀌었지만, 방법이 틀린 채 맞은 것이었다.

### 결과

| 항목 | 값 |
|---|---|
| 100페이지 누적 고유 | **630** |
| 새 상품이 0이 되는 첫 페이지 | **22** |
| 응답 시간 (100페이지) | p50 **481ms** · p95 **1,315ms** · max **1,761ms** |
| 1 / 50 / 100페이지 | 611ms / 451ms / 502ms |

### 절벽의 정체를 확정했다

22페이지부터 100페이지까지 **모든 페이지가 완전히 동일한 30장**이고,
그 30장은 **누적 601~630번째 = 제외 목록에 못 들어간 무방비 집합과 정확히 일치**한다
(30/30, 제외 집합과 겹침 0). 스펙이 "미확인"으로 내려 두었던 항목이 이것으로 확인됐다.

**깊은 페이지 시간은 비교에 쓸 수 없다** — 22페이지 이후 기준선은 같은 630장을 되돌려
주는 퇴화 상태다. 그래서 회귀 판정은 **1페이지**(양쪽이 같은 일을 한다)로 하고,
깊은 페이지는 절대 기준(어떤 페이지도 3초 초과 금지)으로 본다.

**산출물**: `baseline.sh`, `baseline-base.txt`, `baseline-base-ids.txt`, `anchors-male-50.txt`.

## 1단계 — 서버: 후보풀에 커서를 붙인다

- **무엇을**
  - `c_mix_page`에 **커서 인자**(널 기본값, 마지막 인자)를 더한다. 후보풀이 "맨 앞 1,200개"
    대신 **"커서 다음부터 1,200개"** 를 뜬다.
  - 반환에 **다음 커서**를 더한다 = 이번 페이지에서 **후보풀 계열이 고른 것들의 최대 해시값**.
    반드시 **실제로 응답에 나온** 상품에서 계산한다(중간 단계에서 계산하면 최종 조인에서
    탈락한 상품의 값이 섞일 수 있다).
  - 커서는 **해시와 상품번호의 복합 키**다. 해시 단독이면 충돌 시 같은 해시의 미선택 행이
    통째로 사라진다.
  - **후보풀 계열을 하나도 못 골랐는데 창 뒤에 행이 남아 있으면, 커서를 창 끝까지
    전진시킨다.** 그래야 정체가 구조적으로 불가능해진다. 건너뛴 창의 수를 셀 수 있게 한다.
  - 반환에 **소진 신호**를 더한다. 뜻은 하나뿐이다 — "커서 뒤에 후보풀 행이 더 없다".
  - 커서가 널이면 지금과 완전히 같은 동작이다(첫 페이지).
- **반드시 함께**: 반환 열이 바뀌므로 덮어쓰기로는 안 된다 — **지우고 다시 만든다.**
  소유자·권한(`anon`·`authenticated`)과 함수 설정(검색 경로, 작업 메모리 16MB)을 다시
  부여하고, **옮긴 뒤 다시 조회해 보존됐는지 확인한다**(성별 작업에서 함수 설정이 조용히
  사라진 적이 있다).
- **완료 기준**: psql 직접 호출로 —
  1. 커서 없이 부르면 **0단계가 기록한 30개 상품 번호와 같다.**
  2. 반환된 커서가 **응답에 실제로 나온** 후보풀 계열 상품의 최대 복합 키와 같다
     (창을 건너뛴 페이지는 예외 — 그 페이지 수를 따로 센다).
  3. 그 커서를 다시 넣어 부르면 **1페이지의 후보풀 계열과 겹치는 상품이 0건**이다.
  4. 100페이지(또는 소진까지) 이어받으면 **후보풀 계열끼리 중복 0**, 커서가 **단조 증가**.
  5. 스펙의 **응답 상태표** 다섯 줄이 그대로 나온다 — 특히 "행 있음 + 커서 불변"과
     "행 없음 + 소진 꺼짐"이 **각각 0건**이다.
  6. 후보풀이 실제로 소진되면 소진 신호가 켜지고, 그 전에는 안 켜진다.
  7. 옛 호출 형태(커서 없음)가 그대로 동작한다.
  8. 옛 시그니처가 남아 있지 않고 함수 설정이 보존됐다.

## 2단계 — 서버: 건너뜀과 벡터 고갈을 측정한다

이번 조각이 **무엇을 잃는지**와 **다음 조각의 입력**을 함께 만든다.

- **무엇을**: 1단계 함수로 커서를 이어가며 페이지마다 기록한다.
  - **건너뜀** — 분모를 셋으로 나눈다: ⓐ 이전 커서와 새 커서 **사이의 전체 행 수**
    ⓑ 그중 후보풀 자격을 통과한 수 ⓒ 그중 고르지 않은 수. ⓒ가 실제 손실이다.
  - **건너뛴 창의 수** — 후보풀에서 하나도 못 골라 창을 통째로 넘긴 횟수.
  - **버킷별 반환 수** — 벡터 계열이 몇 페이지에서 줄기 시작하는지.
  - **벡터 중복을 두 갈래로** — ⓐ 제외 목록 안에 있는데도 다시 나온 것(**있으면 서버 결함**)
    ⓑ 600을 넘겨 제외가 풀린 뒤 다시 나온 것(다음 조각이 다룰 양).
  - **벡터↔후보풀 교차 중복** — 벡터가 먼저 낸 것을 후보풀이 다시 내는 건수.
- **앵커 변경 대가 측정**: 앵커를 바꾼 뒤 커서를 유지했을 때, **새 조건에서만 자격을 얻는데
  커서 뒤에 있어 못 나오는 상품**이 몇 개인지 한 번 잰다. 스펙 ⑤가 수용한 대가의 크기다.
- **판정**: 벡터가 줄어도 **페이지가 30장으로 유지되면** 설계대로다(다양성이 메운다).
  30장 미만이 되면 **중단하고 보고**한다. 건너뜀에는 판정 기준을 두지 않는다(관찰만).
- **완료 기준**: 위 수치가 전부 이 파일에 적혀 있다.

## 3단계 — 클라이언트: 커서를 왕복시킨다

- **무엇을**
  - 개인화 요청에 커서를 실어 보내고 응답의 커서를 다음 요청까지 들고 있는다.
    **커서는 문자열로 보관·전송한다** — 64비트 해시를 숫자로 다루면 반올림돼 경계가 달라지고
    상품이 누락되거나 다시 나온다.
  - **무작위 경로의 커서와 별개 상태로 둔다.** 무작위 경로는 상품 번호 커서를 쓴다.
  - 서버가 **후보풀 소진**을 알리면 개인화를 멈추고 무작위로 넘어간다.
    **소진 상태는 `(시드, 성별)` 세대에 묶는다** — 그 둘이 바뀌면 소진도 풀려 개인화를 다시
    시도한다. 안 그러면 한 번 소진된 뒤 영구히 무작위로 남는다.
  - 스펙 ⑤의 **세대 계약 표**대로 버리고 유지한다(성별·시드·신원 변경은 버리고,
    앵커 변경·폴백 전환·복귀는 유지).
  - **제외 목록이 최근 600개를 남기도록 바로잡는다.** 지금은 오래된 600개가 남아
    벡터 재등장 측정이 오염된다. 상한 600은 그대로 둔다.
- **완료 기준**: 단위 테스트로 —
  1. 첫 요청에는 커서를 안 싣고, 응답의 커서를 다음 요청에 싣는다.
  2. **큰 양수·음수 경계값**이 왕복 후 그대로다(문자열로 다뤄야만 통과한다).
  3. **행 없음 + 소진 켜짐** → 정상 종료로 처리한다.
     **행 없음 + 소진 꺼짐** → 결함으로 보고 개인화를 멈춘다(무한 대기 금지).
  4. 소진 신호를 받으면 개인화를 멈추고 무작위로 넘어가며, **시드·성별이 바뀌면 다시
     개인화를 시도한다.**
  5. 세대 계약 표의 일곱 줄이 각각 테스트로 있다.
  6. 제외 목록이 **가장 최근** 600개다.
  7. 무작위 경로에 해시 커서가 실려 나가지 않는다.
  8. `npm run check`와 기존 테스트 전체가 통과한다.

## 4단계 — 배포 확인

- **무엇을**: 함수를 지우고 다시 만들면 PostgREST **schema cache**가 새 시그니처를 알아야
  REST 경로가 동작한다. 함수 정의 조회만으로는 검증되지 않는다.
- **완료 기준**: REST로 **옛 body(커서 없음)와 새 body(커서 포함)를 둘 다 호출**해 성공한다.
  갱신 지연이 관찰되면 그 시간과 대응을 적는다.

## 5단계 — 브라우저 확인

- **무엇을**: Aside 브라우저로 개인화가 걸린 계정에서 홈을 오래 스크롤한다.
- **완료 기준**:
  1. **최소 40번 스크롤**하며 화면에 뜬 상품 번호를 모아, **후보풀 계열 기준 누적 고유가
     계속 증가**한다(기준선은 40번 스크롤에 308개에서 멎었다). 벡터 계열 중복은 이번
     조각의 판정 대상이 아니다.
  2. 요청에 커서가 **문자열로** 실려 나간다.
  3. 설정에서 성별을 바꾸면 처음부터 다시 시작한다.
  4. 상세·보관함에 다녀와도 이어서 스크롤된다(세대 계약 "유지" 줄의 실제 확인).

## 6단계 — 검증 기록

- **무엇을**: 스펙 "확인 방법" 10개 항목의 결과를 수치로 적는다.
  **안 돌려본 것은 "미검증"으로 명시한다.**
- **응답 시간 판정**: 워밍업 1회 뒤 같은 입력으로 **5회씩** 재고 p50·max를 남긴다.
  판정은 **1페이지로만** 한다 — 0단계 611ms의 **1.3배(약 795ms)를 넘으면 중단**.
  깊은 페이지는 배수 비교가 성립하지 않으므로(기준선이 퇴화 상태다) **절대 기준**을 쓴다 —
  어떤 페이지든 **3초를 넘으면 중단**한다(실 API 제한 8초).
- **완료 기준**: 위 수치가 이 파일에 있고, 문제 진술 문서
  (`2026-08-22-personalization-cost-problem.md`)의 "두 번째 관측"에 **후보풀 계열은 해결,
  벡터 계열은 다음 조각**이라고 표시돼 있다. 벡터 조각을 위한 문제 진술 문서가 2단계
  측정치와 함께 남아 있다.

## 미정

- **후보풀 창 크기(1,200)** 를 그대로 둘지 — 커서가 붙으면 줄여도 되지만, 줄이면 버킷 규칙
  (색 교집합·그래픽 반전)을 만족하는 후보가 창 안에 없어 페이지가 짧아질 수 있다.
  2단계 관찰 뒤에 정한다.
- **탭 복귀·상세/보관함 복귀가 같은 마운트를 유지하는지** — 세대 계약은 "유지"로 정했지만
  실제 수명주기는 5단계에서 관찰해 확정한다.

## 이 계획이 스스로 경계하는 것

이 저장소에서 **"검증 장치가 대상을 안 보는" 실패가 네 번** 반복됐다
(`2026-08-22-search-test-drift.md` "배운 것"). 그래서 이 계획은 다음을 각각 **별도 항목**으로
둔다 — 하나의 "통과"에 묶으면 가려지기 때문이다.

- 커서 **정밀도**(문자열 왕복) — 숫자로 구현해도 작은 값에서는 통과한다.
- 커서 **단조성**과 **무진행** — 중복 0만 보면 무한 반복을 못 잡는다.
- 커서와 **실제 응답 행의 일치** — 중간 단계에서 계산해도 보통은 같아 보인다.
- **벡터 중복을 따로 센다** — 후보풀과 합쳐 세면 이번 조각의 보장이 참인지 알 수 없다.
- **REST로** 배포를 확인한다 — 함수 정의 조회는 REST 경로를 안 본다.

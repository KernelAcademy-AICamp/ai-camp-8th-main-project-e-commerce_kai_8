# 검색 결과가 없을 때 빈 화면을 주지 않는다

> 작성: 2026-08-17 · 상태: **1·2단계 완료, 3단계 대기**
> 앞 조각: [C단계 구조화 조건](2026-08-17-search-structured-conditions.md)
> 이 계획은 **배포 가능한 한 조각**만 다룬다. 이어질 조각(점수 기반 랭킹)은 마지막 절에 이름과 전제만 적는다.
>
> **1판에서 고친 것** — 교차 리뷰 지적:
> ⓐ 0건을 알리는 방법과 대체 피드의 이어가기를 「미정」으로 뒀는데, 그 둘을 정하지 않으면
> 실행할 수 없다(맞다). 아래 「1판에서 미정이던 것」에서 정한다.
> ⓑ 0건 수를 31개(46%)로 잘못 적었다 — 실제는 **34개(51%)**다.
> ⓒ 1단계가 프로토콜만 배포하고 사용자가 보는 것이 없었다. 한 질의에서 끝까지 되는
> 수직 조각으로 바꿨다.

---

## 왜 지금 이것인가

aTee는 **검색어 없이 습관적으로 훑는** 무한 모자이크 피드를 검증하는 제품이다. 그런데
검색에서 조건이 안 맞으면 **빈 화면**을 준다. 개발셋 67개 질의 중 **34개(51%)가 0건**이다.

| 계열 | 뜻 | 0건 |
|---|---|---|
| G2 | 짧은 키워드 | 3 / 11 |
| G4 | 문장·복합 | 6 / 11 |
| G5 | 부정 | **8 / 8** |
| G6 | 0건이 정답 | 8 / 8 |
| R1 | 자연어 추천(`클럽에 갈때 입을옷 추천해줘`) | **9 / 9** |

무한 탐색을 표방하는 앱에서 **절반이 막다른 길**이다.

**이건 놓친 것이 아니라 미룬 것이다.** 평가 세트의 `R1` 계열은 존재 이유 자체가
*"게이트에서 제외되지만 **0건일 때 피드로 유도**를 보려면 표본이 필요하다"*였다.
설계가 예고했고 아직 안 만들었다.

## 이미 있는 것 (만들기 전에 찾아본 기록)

새로 만들 것이 거의 없다.

| 있는 것 | 무엇 | 확인한 것 |
|---|---|---|
| **개인화 믹스** | 세션 신호·장기 취향·이미 본 목록·시드를 받아 한 장을 준다 | **신호가 비어 있어도 한 장을 채운다**(첫 방문 문제 없음) |
| **기본 피드** | 시드와 상품 번호 하나로 이어간다 | 메인 화면은 취향 신호가 없거나 믹스가 실패하면 **이미 이쪽으로 넘어간다** |
| 검색 로그 | 무엇을 검색했고 몇 건이 나왔는지 이미 남긴다 | |

**이어가기 방식이 셋 다 다르다** — 검색은 (점수, 상품번호), 기본 피드는 상품번호,
믹스는 **이미 본 목록을 통째로 보내는 방식**이다. 그리고 그 목록은 **600개에서 잘린다** —
실측하면 630번째부터 같은 페이지가 반복된다(22페이지가 앞 페이지들과 전부 겹침).
**메인 피드도 같은 한계를 갖고 있다.**

믹스는 첫 호출이 **2~3초** 걸린다(이후 0.5~0.9초). 메인 화면은 취향 신호가 없거나
믹스가 실패하면 **이미 기본 피드로 넘어간다.**

**랜덤을 새로 만들지 않는다.** 개인화 믹스를 이미 만들어 뒀고, `강아지 사료`를 친 사람에게
무작위를 주는 것보다 그 사람 취향 피드를 주는 쪽이 낫다(사람이 정함, 2026-08-17).

## 사람이 정한 것 (2026-08-17)

| 질문 | 결정 |
|---|---|
| 0건일 때 무엇을 보여주나 | **개인화 피드.** 완전 랜덤이 아니다 |
| 대체 화면의 노출·탭을 취향에 반영하나 | **둘 다 반영한다** — 메인 피드와 같게 |
| 응답이 그 사실을 구분하나 | **구분한다.** 화면에도 표시한다 |
| 명시된 색을 점수로 내리나 | **내린다** — 단 그건 **다음 조각**이다(아래) |

## 1판에서 「미정」이던 것을 여기서 정한다

교차 리뷰가 "이걸 정하지 않으면 실행할 수 없다"고 한 것들이다.

**① 0건임을 어떻게 아나 — 검색 쪽을 바꾸지 않는다.**
검색은 지금처럼 상품 목록만 돌려주고, **"성공했는데 목록이 비었다"를 화면 쪽이 상태로
읽는다.** 그러면 ⓐ 검색의 응답 계약을 바꾸지 않아도 되고 ⓑ 평가가 지금 그대로 0건을
세므로 하네스도 손대지 않는다. 대체 피드는 **검색과 다른 호출**로 가져오므로 섞이지
않고, 구분이 저절로 된다.

**② 600개 뒤에는 어떻게 하나 — 지금 메인 피드와 같게 둔다.**
이 조각이 만든 문제가 아니라 피드가 원래 갖고 있는 한계다. 여기서 새로 풀지 않고
메인 피드와 같은 동작을 따른다. 그래서 완료 기준을 "무한히 이어진다"가 아니라
**"메인 피드만큼 이어진다"**로 적는다 — 지키지 못할 약속을 완료 기준에 넣지 않는다.

**③ 로그는 무엇을 남기나 — 매칭 수는 건드리지 않는다.**
검색 로그의 결과 수는 **매칭 수의 정본**이고 G6·0건율이 여기서 나온다. 대체 피드를
보여준 사실은 **별도 값**으로 남긴다. 결과 수를 "화면에 보인 수"로 바꾸면 정본이 사라진다.

**④ 믹스가 실패하거나 느리면 — 메인 화면과 같게.**
메인 화면은 취향 신호가 없거나 믹스가 실패하면 기본 피드로 넘어간다. 검색 대체도 같다.
검색이 **오류로 실패한 경우**는 대체 피드를 띄우지 않는다 — 그건 "결과가 없다"가 아니라
"모른다"이고, 지금처럼 재시도를 안내한다.

## 이 조각의 검증 가설

> **검색 결과가 없을 때 개인화 피드를 이어 보여주면, 사용자가 막다른 길을 만나지 않으면서도
> "검색이 안 됐다"는 사실을 오해하지 않는다.**

## 하지 않는 것 (범위 밖)

- **점수 기반 랭킹·하드/소프트 재배치** — 다음 조각. 이 조각은 **0건일 때**만 다루므로
  검색 자체의 매칭 방식을 건드리지 않는다. 그래서 독립적으로 배포할 수 있다.
- **부정(G5)·원단 속성·LLM 해석** — 각각 별도.
- **대체 피드의 개인화 품질 개선** — 지금 믹스를 그대로 쓴다.

## 단계

### 1단계 — 한 질의에서 끝까지 되게 한다

가장 먼저 하는 이유: **이 조각의 가치가 여기서 나온다.** 프로토콜만 먼저 깔고 화면을
뒤로 미루면 배포해도 사용자가 보는 것이 없다.

무엇을 한다:

1. 검색이 **성공했는데 결과가 없을 때** 취향 피드를 이어 보여준다.
2. 화면이 **검색 결과가 아님을 알린다.**
3. 매칭이 하나라도 있으면 **섞지 않는다** — 그때는 검색 결과만 보여준다.
4. 검색이 **오류로 실패한 경우**는 대체 피드를 띄우지 않는다.

**완료 기준**

- `강아지 사료`를 검색하면 상품이 보이고, 화면이 **"검색 결과가 아니다"라고 알린다.**
- `반팔`을 검색하면 **바뀌는 것이 없다**(검색 결과만 나온다).
- 검색을 강제로 실패시키면 대체 피드가 아니라 **재시도 안내**가 나온다.
- 취향 신호가 없는 상태(첫 방문)에서도 대체 화면이 채워진다.
- 대체 화면이 뜨기까지의 지연을 재서 기록한다(믹스 첫 호출이 2~3초다).

### 2단계 — 대체 화면에서도 스크롤이 이어진다

무엇을 한다:

1. 대체 피드도 아래로 내리면 다음 장이 온다.
2. 이어가기 방식이 검색과 다르므로 화면 쪽에서 그 차이를 감춘다.
3. **메인 피드와 같은 지점에서 멈춘다** — 더 잘 만들지 않는다(범위 밖).

**완료 기준**

- `강아지 사료`에서 스크롤을 내리면 **새 상품이 계속 나온다**(같은 것이 반복되지 않는다).
- 멈추는 지점이 **메인 피드와 같다**(더 이르지 않다).
- 검색어를 바꾸면 대체 피드가 **처음부터 다시 시작한다.**

### 3단계 — 계측과 지표

무엇을 한다:

1. 대체 피드를 보여준 사실을 로그에 **별도 값**으로 남긴다. 매칭 수는 그대로 둔다.
2. 대체 화면의 노출·탭을 **메인 피드와 같게** 취향 신호에 반영한다(사람이 정함).
   단 검색 화면은 지금 노출을 취향에 넘기지 않으므로, 그 연결을 새로 만들어야 한다.
3. 평가에 **"빈 화면 비율"** 지표를 넣는다. 매칭 지표(G1~G6)는 손대지 않는다.

**완료 기준**

- 검색 로그만 보고 "이 질의는 대체 피드가 나갔다"를 셀 수 있다.
- 대체 화면에서 상품을 누르면 **취향 프로필이 바뀐다**(메인 피드와 같게).
- 개발셋 기준 **빈 화면 비율이 51%에서 크게 내려간 것**이 수치로 보인다.
  분모는 **검색이 성공한 질의**다 — 오류는 빈 화면으로 세지 않는다.
- **G6과 게이트 종합이 그대로다.** 매칭 경로를 건드리지 않았으므로 바뀌면 그게 신호다.

## 가설을 어떻게 확인하나

"오해하지 않는다"는 화면에 문구가 있다는 사실만으로는 확인되지 않는다. 할 수 있는 것과
없는 것을 나눠 적는다.

- **할 수 있다** — 빈 화면 비율이 내려간 것. 대체 화면에서 상품을 눌렀는지·바로 나갔는지·
  검색어를 다시 쳤는지를 로그로 구분해 세는 것.
- **할 수 없다** — 사용자가 실제로 오해했는지. 그건 사람에게 보여주고 물어야 안다.

## 다음 조각 — 점수 기반 랭킹 (이름과 전제만)

사람이 정한 방향은 이렇다. **하드 필터**는 가격·브랜드·카테고리, **점수**는 색·소재·
신축성·자연어. 전 단어 AND를 버리고 점수 순으로 최대한 많이 보여준다.

착수 전에 **두 가지 전제**를 먼저 확인해야 한다. 둘 다 이번 조사에서 드러났다.

**① 지금 점수는 관련도를 충분히 변별하지 못한다.** 텍스트 점수가 사실상 매칭 횟수라
값이 좁은 범위에 몰린다 — `검정 반팔`을 60건 받아 보면 두 값(2점 32건·1점 28건)뿐이고,
같은 값 안에서는 상품 번호 순으로 정해진다. "점수 많은 것 우선"을 하려면 **변별력 있는
점수를 먼저 만들어야** 한다.

⚠️ 1판에 "매칭 29개가 전부 같은 점수"라고 적은 것은 **작은 표본을 본 오류**였다(크기 22).
"점수가 없다"가 아니라 "변별력이 없다"가 맞다.

**② 하한(relevance floor)이 없으면 G6이 깨진다.** 전 단어 AND를 OR로 풀면, 개발셋에서
0건이던 34개 중 **25개가 결과를 갖게 된다** — 그중 **G6 질의 2개**
(`린넨 소재의 블라우스 아이보리`·`강아지 사료`)가 포함된다. 한 단어가 스쳤다고 매칭으로
치면 G6이 무너진다. 점수 아래로는 매칭으로 보지 않는 **하한**을 함께 정해야 한다.

⚠️ 1판이 예로 든 `보풀안생기는 여름니트`는 실제로는 **여전히 0건**이다 — 예시가 틀렸다.
공백 단위로 나누므로 `여름니트`가 `여름`으로 쪼개지지 않는다.

그리고 **기준서를 고쳐야 한다.** 지금 기준서는 색을 본체 색으로 보고, 문장형 질의에서
명시된 색을 **하드 조건**으로 둔다. 색을 점수로 내리기로
했으므로 이 두 곳이 함께 바뀌어야 하고, 그러면 **색을 말하는 질의의 판정을 다시
매겨야 한다.** 그 범위는 이번 C단계에서 이미 한 번 겪었다(97건).

## 실행 기록

### 1·2단계 — 대체 피드와 무한 스크롤 (2026-08-17)

**한 것**: 검색이 **성공했는데 0건**이면 취향 피드를 이어 보여준다. 화면이 검색 결과가
아님을 알린다.

**구현 판단**: 새 훅을 만들지 않고 **메인 피드 훅을 되살렸다.** 검색 모드에서 멈춰 두던
것을 대체가 필요할 때만 다시 돌린다. 그 안에 개인화·콜드스타트 폴백·실패 폴백·제외
목록·무한 스크롤·노출 계측이 이미 다 있고, **사용자가 보던 피드가 그대로 이어져 대기
시간이 없다**(믹스 첫 호출이 2~3초인데 그걸 안 기다린다).

**완료 기준 판정** — 브라우저에서 직접 확인했다.

| 기준 | 판정 | 확인 |
|---|---|---|
| `강아지 사료`가 빈 화면이 아니다 | ✅ | 상품이 채워진다 |
| 검색 결과가 아님을 알린다 | ✅ | 「'강아지 사료' 검색 결과가 없어요 / 대신 취향에 맞는 티셔츠를 보여드릴게요」 |
| `반팔`은 바뀌지 않는다 | ✅ | 「'반팔' 결과」 + 티셔츠만 |
| 오류면 대체가 아니라 재시도 | ✅ | 코드 경로가 갈린다(`isEmpty`는 성공한 0건만) + 컴포넌트 테스트 |
| 취향 신호가 없어도 채워진다 | ✅ | 콜드스타트는 기본 피드로 넘어가는 기존 동작을 그대로 쓴다 |
| 스크롤이 이어진다 (2단계) | ✅ | 두 번 연속 내려도 새 상품이 계속 온다 |

**1·2단계를 함께 끝냈다.** 메인 피드 훅을 쓰기로 하면서 무한 스크롤이 따로 만들 것 없이
따라왔다.

**화면 문구를 한 번 고쳤다.** 처음엔 상단에 「'X' 결과」가 남아 있어 바로 아래
「'X' 결과가 없어요」와 겹쳐 읽혔다. 대체일 때는 상단 라벨을 감춘다.

### 사람이 써 보고 짚은 것 두 개 (2026-08-17)

**① 매칭이 적으면 거기서 끊긴다.** `감자`는 6건이다. 계획은 "매칭이 1건이라도 있으면
그것만 준다"였는데, 그러면 6개 뒤에 막다른 길이 남는다 — **0건과 다를 게 없다.**
계획의 규칙을 다듬었다: **섞지는 않되, 매칭을 다 보여준 뒤에 경계를 두고 잇는다.**

> `'감자' 결과는 여기까지예요 — 이런 건 어때요`

개발셋에도 1~19건짜리 질의가 8개다. 20건 상한에 걸린 25개도 스크롤하면 결국 소진된다.
즉 **모든 질의가 언젠가는 이 경계를 만난다.**

구현: 검색 뷰모델의 소진 여부가 ref에만 있어 화면이 못 봤다. 상태로 올려 노출했다.

**② 접힌 검색창을 누르면 펴졌다가 다시 접혔다.** 펼치면서 입력에 포커스를 주는데,
브라우저가 그 입력을 화면에 넣으려고 스크롤을 일으킨다. 그 스크롤이 "아래로 내렸다"로
읽혀 스스로 다시 접혔다. 손으로 편 직후 잠깐은 접힘 판정을 멈춘다 — 프로그램적 스크롤을
판정에서 빼는 기존 장치와 같은 이유다.

브라우저에서 확인: 펴진 채 유지되고, 배경도 스크롤 위치도 그대로다.

**남은 것은 3단계(계측)다** — 대체 피드가 나간 사실을 로그에 별도 값으로 남기고,
평가에 「빈 화면 비율」 지표를 넣는 일. 이제 그 지표는 "0건인 질의"가 아니라
**"막다른 길을 만나는 질의"**를 세야 한다.

# 계획 — Cosmos형 2열 masonry 무한 스크롤 피드 프로토타입

> 상태: 확정 (2026-08-13 제품 책임자 승인, 지적 사항 없음) · 작성: 2026-08-13
> 근거 결정: [결정 기록 O-22](../eati/living/decision-log.md) — 핀치 밀도 전환 폐기, 2열 고정 masonry 확정
> 관련 문서: [Living PRD 0.3](../eati/living/prd.md) · [backend README](../../backend/README.md)

## 배경 (이 repo를 모르는 사람을 위한 설명)

eati는 검색 없이 티셔츠 이미지를 무한히 훑는 개인화 탐색 웹앱(PWA) 가설이다. 아직 구현 전이며, 구현 확대 전에 "Gate 0"(데이터·상호작용 준비)을 통과해야 한다. 이 계획은 Gate 0의 상호작용 축을 눈으로 확인하기 위한 **첫 프로토타입**을 다룬다.

- 목표 경험: 참고 앱 Cosmos처럼 **다크 배경 + 2열 고정 masonry(카드 세로 길이 가변) + 이미지 우하단 가격 배지 + 무한 스크롤**.
- 데이터: 무신사 티셔츠 약 22.6만 개가 Supabase(클라우드 Postgres)의 `c_goods` 테이블에 이미 적재돼 있다. 단, 보안 설정(RLS)상 앱에서 바로 읽을 수 없고 노출 수단을 정해야 한다.
- 이 프로토타입의 범위는 **무한 스크롤 피드까지만**이다. 탭 상세(바텀 시트), 찜, 개인화, 가입은 포함하지 않는다.

## 범위

### 포함

- 실제 DB 상품 샘플(이미지·가격)로 채운 2열 masonry 피드 화면
- 아래로 끝없이 이어지는 무한 스크롤
- 이미지 로딩 중 레이아웃이 튀지 않는 처리와 로드 실패 시 대체 표시
- 모바일 화면 기준 확인

### 제외 (이번 프로토타입에서 하지 않음)

- 바텀 시트·찜·`이 스타일로 계속 탐색`·판매처 이동
- 개인화·추천 로직 (정렬은 임의 순서면 충분)
- 가입·온보딩·계측
- PWA 설치·오프라인 동작

## 단계와 완료 기준

각 단계는 끝나면 눈으로 확인할 수 있어야 한다.

### 1. 실제 상품 샘플 확보

DB에서 유효한 이미지 주소와 가격이 있는 티셔츠 수백 개를 뽑아 프로토타입이 읽을 수 있는 형태로 만든다. 노출 방식은 여러 구현이 가능하므로 여기서 못박지 않는다(예: 읽기 전용 뷰, 서버 측 조회, 미리 뽑아둔 파일 — 프로토타입 단계에선 어떤 것이든 무방).

- **완료 기준:** 샘플 목록을 열면 상품 개수와 각 상품의 이미지 주소·가격이 보이고, 이미지 주소 몇 개를 브라우저에 넣으면 실제 티셔츠 사진이 뜬다.
- **부수 확인:** 이 과정에서 이미지 깨짐·가격 누락 비율을 눈으로 확인한다(전체 데이터 감사의 예고편). 무신사 이미지의 가로세로 비율 분포도 확인한다 — 비율이 모두 같다면 masonry의 "세로 길이 가변" 효과가 작으므로 이 사실을 기록하고 다음 단계에서 참고한다.

### 2. 2열 masonry 첫 화면

샘플 데이터로 다크 배경의 2열 masonry 피드 첫 화면을 만든다.

- **완료 기준:** 브라우저(모바일 뷰포트)에서 열면 실제 티셔츠 이미지가 2열로, 카드 세로 길이가 제각각인 채로 배치되고 각 이미지 우하단에 가격 배지가 보인다.

### 3. 무한 스크롤

스크롤이 바닥에 가까워지면 다음 상품 묶음이 이어 붙는다.

- **완료 기준:** 계속 아래로 내리면 새 상품이 끊김 없이 이어지고, 같은 상품이 중복해서 나타나지 않는다. 샘플이 소진되는 경우의 동작(반복 재사용 또는 끝 표시)은 미정 — 구현 시 하나를 골라 기록한다.

### 4. 로딩·실패 처리

이미지가 늦게 오거나 실패해도 탐색이 깨지지 않게 한다.

- **완료 기준:** 네트워크를 느리게 설정하고 스크롤해도 이미 보이는 카드가 밀리거나 튀지 않고, 일부러 깨뜨린 이미지 주소는 빈 화면 대신 명확한 대체 표시로 보인다.

### 5. 모바일 환경에서 확인

- **완료 기준:** 모바일 화면 크기와 터치 스크롤 기준으로 위 1~4의 동작을 동일하게 확인한다. 스크롤이 눈에 띄게 버벅이면 문제로 기록한다(수치 기준은 미정 — Gate 0 테스트 설계에서 확정).
- **확인 방법:** 단계별 확인은 AI가 Orca 내장 브라우저(스크린샷·콘솔 확인)와 iOS 시뮬레이터(터치 스크롤)로 수행하고 스크린샷을 공유한다. 최종 체감(스크롤 관성·성능)은 같은 Wi-Fi에서 실제 폰 브라우저로 개발 서버에 접속해 확인한다. PWA 설치·푸시 등 HTTPS가 필요한 기능 테스트는 이 프로토타입 범위 밖이며, Gate 0 테스트용 URL(Vercel preview 도입 예정) 시점에 다룬다.

## 미정 (지어내지 않고 남겨둔 것)

- 샘플 크기(수백 개 수준이라는 것만 합의, 정확한 개수 미정)
- 데이터 노출 방식(뷰/서버 조회/정적 파일 중 무엇으로 시작할지)
- 샘플 소진 시 피드 동작
- 스크롤 성능의 통과 수치 (Gate 0 테스트 기준 문서에서 확정)
- 다크 배경 외 세부 스타일(여백·모서리·글꼴 등) — Cosmos 느낌을 참고하되 확정 아님

## 실행 기록 (2026-08-13)

- **1단계:** Supabase `c_goods` 226,320행 중 랜덤 400개 추출(정적 파일 방식 선택). 전수 커버리지 훑기: 썸네일 누락 0, 가격 누락 1행, 성별 누락 1,911행(0.8%). 샘플 400개 이미지는 전부 다운로드 성공.
- **이미지 비율 분포(400개):** 5:6(1.20) 69% · 정사각 18% · 3:4(1.33) 7% · 기타 6% — masonry 세로 가변 효과는 중간 수준으로 확인.
- **3단계:** 샘플 소진 시 **처음부터 순환 재사용**을 선택(무한 체감 우선). 렌더링 키에 순환 회차를 붙여 충돌 방지. 브라우저 검증: 카드 520개 로드 시 고유 상품 정확히 400개(첫 순환 중복 0).
- **4단계:** 레이아웃 이동 측정값 CLS 0.0003(사실상 0). 실패 대체 표시는 컴포넌트 테스트로 검증.
- **⚠️ 데이터 감사 참고:** 무신사 CDN(msscdn)은 없는 이미지 경로에도 HTTP 404 + **디코딩 가능한 대체 이미지(너비 204px)**를 내려준다. 브라우저 onError로는 깨진 이미지를 잡을 수 없으므로, 전체 데이터 감사에서 이미지 유효성은 응답 크기/치수 기준으로 판정해야 한다. 또한 Orca 내장 브라우저는 실패한 이미지 요청을 자체 플레이스홀더로 가로채므로 이미지 실패 재현 테스트에는 쓸 수 없다.
- **5단계:** iPhone 17 Pro 시뮬레이터에서 터치 스와이프 스크롤·lazy 로딩·카드 영역 예약 동작 확인. `npm run check`·vitest 11개 통과.

## 이 계획이 끝나면

- Gate 0의 상호작용 확인 항목 중 "2열 masonry 무한 스크롤" 부분을 실물로 확인할 수 있다.
- 다음 후보: ① 전체 데이터 감사(22.6만 행 필수 필드 커버리지) 착수 ② 탭 바텀 시트 확장 ③ Gate 0 테스트 기준 문서화. 순서는 프로토타입 확인 후 결정한다.

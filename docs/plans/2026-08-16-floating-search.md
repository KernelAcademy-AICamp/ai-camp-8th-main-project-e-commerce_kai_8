# 플로팅 검색 구현 계획

- 설계 문서: [`docs/superpowers/specs/2026-08-16-floating-search-design.md`](../superpowers/specs/2026-08-16-floating-search-design.md) (Codex 리뷰 반영본 — 세부 결정은 모두 이 문서를 따른다)
- 브랜치: `feature/floating-search` (→ `develop` PR)
- 작성일: 2026-08-16

## 목표

aTee 첫 페이지에 하단 플로팅 검색창을 추가한다. 검색어를 제출하면 같은 페이지의 모자이크 피드가 검색 결과로 교체되고, 스크롤을 내리면 검색창이 원형 버튼으로 축소되며, 축소 상태에서 탭하면 다시 펼쳐진다.

## 전제

- 백엔드 검색은 새 Supabase RPC로 만들며, 기본 피드와 동일한 노출 자격(card_ok)을 적용한다.
- 검색 결과 정렬은 상품번호 순(의도적 MVP 선택 — 설계 문서 §1 참고).
- 미정: 2음절 검색어("반팔")의 실측 성능 — 1단계에서 측정해 수용 불가면 그때 대응을 정한다.

## 단계

### 1단계 — 백엔드 검색 RPC (핵심 경로의 시작)

검색 RPC 마이그레이션을 작성해 Supabase에 적용한다. 설계 문서 §1의 요건(노출 자격 동일 적용, 검색어 정규화·특수문자 처리·크기 상한 등 입력 방어, 실행 권한 제한, 텍스트 검색 인덱스와 확장 활성화, 상품번호 keyset 페이징)을 모두 포함한다.

- **완료 기준 1**: DB에 직접 RPC를 호출하면 — "나이키"로 브랜드 매칭 상품이, "나이키 반팔"로 두 단어 모두 포함된 상품이, 커서를 이어 넘기면 중복·누락 없는 다음 페이지가 반환된다.
- **완료 기준 2**: 기본 피드에서 제외되는(card_ok 미달) 상품이 검색 결과에 나타나지 않는다.
- **완료 기준 3**: `%`만 제출하거나 과도한 길이·크기를 제출하면 전체 스캔이 아니라 안전한 거부/제한 동작이 확인된다.
- **완료 기준 4**: 대표 검색어(2음절·3음절·영문 브랜드·복합어)의 실행 계획·소요 시간을 측정해 기록하고, 모두 anon 8초 한도 안에 든다. (미달 시: 대응 방안을 정한 뒤 다음 단계 진행)

### 2단계 — 프론트 검색 데이터 계층·결과 훅

검색 API 래퍼와 검색 결과 무한 스크롤 훅을 만든다. 설계 문서 §2의 요건(입력 중 검색어와 제출된 검색어 분리, 요청 세대 번호로 늦은 응답·해제 후 응답 폐기, 새 검색 시 커서·목록 초기화, 상세·비활성 시 로드 중지)을 포함한다. 기존 카드 표시 타입은 재사용 가능한 위치로 옮긴다.

- **완료 기준**: 프론트 테스트 실행 시 — API 매핑, 검색어 상태 분리, "A 제출 후 B 제출 → 늦게 온 A 응답 폐기", "요청 중 해제 → 폐기", 페이징 이어붙기 시나리오가 모두 통과한다. 기존 테스트도 전부 통과한다.

### 3단계 — 검색창(확장 상태)과 피드 교체 (첫 화면에서 눈으로 확인)

하단 플로팅 검색창(확장 상태만)을 첫 페이지에 붙이고, 제출 시 기본 피드가 검색 결과 그리드로 교체되게 한다. 설계 문서 §2의 모드 전환 요건(기본 피드는 DOM 대신 데이터·스크롤 위치만 보존, 두 피드의 명시적 로드 중지 조건, 스크롤 전이 4단계)을 포함한다.

- **완료 기준 1**: 브라우저에서 첫 페이지를 열면 하단에 다크 테마와 어울리는 검색창이 보이고, 검색어를 입력해 엔터를 치면 피드가 해당 검색 결과로 바뀌며 상단에 검색어 라벨이 보인다.
- **완료 기준 2**: 검색 결과를 아래로 스크롤하면 다음 페이지가 이어서 로드된다.
- **완료 기준 3**: 깊게 스크롤한 뒤 검색했다가 X(지우기)로 해제하면, 원래 피드가 이전 스크롤 위치 그대로 복원돼 보인다.

### 4단계 — 검색 결과에서 상세 연동

검색 결과 카드를 탭하면 기존 상세 화면이 열리고, 뒤로가기·유사 탐색 체인이 기본 피드와 동일하게 동작하게 한다. 검색 노출은 개인화 계측에 기록하지 않는다.

- **완료 기준 1**: 검색 결과 카드를 탭하면 상세가 열리고, 상세 하단 유사 상품으로 체인 탐색 후 뒤로가기를 반복하면 검색 결과 화면으로 정확히 돌아온다.
- **완료 기준 2**: 상세가 열려 있는 동안 검색창이 보이지 않고, 닫으면 입력값이 유지된 채 다시 보인다.
- **완료 기준 3**: 검색 결과 노출은 이벤트 로그에 기록되지 않고, 상세 열기·찜은 기존대로 기록된다(브라우저 확인).

### 5단계 — 축소/확장 애니메이션

스크롤 방향에 따라 검색창이 원형 버튼으로 줄어들고 다시 펼쳐지는 전환을 만든다. 외부 라이브러리 없이 CSS 전환으로 처리하고, 프로그램적 스크롤(복원·상단 이동)은 판정에서 제외한다.

- **완료 기준 1**: 피드를 아래로 스크롤하면 검색창이 부드럽게 원형 버튼으로 줄어들고, 위로 스크롤하면 다시 펼쳐진다.
- **완료 기준 2**: 축소된 버튼을 탭하면 검색창이 펼쳐지며 입력란에 포커스가 잡히고, 축소 전 입력값이 남아 있다.
- **완료 기준 3**: 검색 해제로 스크롤이 복원되는 순간 검색창이 오작동(불필요한 축소/확장)하지 않는다.

### 6단계 — 엣지 케이스·겹침 처리

결과 0건 안내, 오류 시 수동 재시도, 동의 배너와의 겹침, 하단 안전 영역·피드 패딩을 마무리한다.

- **완료 기준 1**: 없는 검색어를 제출하면 "결과 없음" 안내와 지우기 버튼이 보이고, 지우면 원래 피드로 돌아온다.
- **완료 기준 2**: 네트워크를 끊고 검색하면 자동 재시도 반복 없이 오류 안내와 재시도 버튼이 보이고, 재시도 버튼으로 복구된다.
- **완료 기준 3**: 최초 방문(동의 배너 표시) 상태에서 검색창과 배너가 겹치지 않고 둘 다 조작 가능하다.

### 7단계 — 최종 검증·PR

품질 게이트를 모두 돌리고 실제 브라우저로 전체 흐름을 검증한 뒤 PR을 만든다.

- **완료 기준 1**: `npm run check`와 `npm run test`(프론트), `pytest`(백엔드)가 모두 통과한다.
- **완료 기준 2**: Orca 브라우저(iOS 뷰포트)에서 — 검색 → 결과 스크롤 → 상세 체인 → 복귀 → 해제 → 스크롤 복원 → 축소/확장 애니메이션까지 한 흐름으로 확인된다.
- **완료 기준 3**: `develop` 대상 PR이 열리고 CI가 초록불이다.

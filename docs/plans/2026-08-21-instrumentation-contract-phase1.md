## 3. 단계

각 단계의 완료 기준은 **관리자 화면의 원본 기록에서 눈으로 확인되는 것**이다. 확인하지 않았으면 미검증으로 남긴다.

### 배포 A — 사용자 화면과 문구가 바뀌지 않는 것들

#### A-1. 노출 귀속이 새로고침을 견디게 한다

지금은 "방금 이 상품을 보여줬다"는 기억이 메모리에만 있어 새로고침하면 지워진다. 그 뒤 클릭은 어느 추천 때문인지 알 수 없게 되고, 추천 유형별 성적표에서 통째로 빠진다.

**완료 기준** — 피드에서 카드를 본 뒤 **새로고침하고** 그 상품을 열면, 원본 기록의 클릭 줄에 **어느 노출 때문인지가 채워져 있다.** 지금은 비어 있다.

#### A-2. 세션 경계 두 가지를 더한다

- 앱이 백그라운드에 들어간 뒤 **5분 이상** 지나 복귀하면 새 세션
- **로그인·로그아웃·계정 변경** 시 직전 세션을 **끝내고** 새로 연다

두 번째가 중요하다. 지금도 신원이 바뀌면 세션 기억이 지워져 새 세션이 열리지만, **지워진 뒤라 직전 세션의 종료 줄이 남지 않는다.**

**완료 기준** — ⓐ 앱을 백그라운드로 6분 두었다 돌아오면 원본 기록에 **세션 종료 줄과 새 세션 시작 줄이 나란히** 보인다. ⓑ 로그인하면 **직전 세션의 종료 줄이 남는다** (지금은 안 남는다).

#### A-3. 발생 시점의 로그인 상태와 계측 버전을 기록에 담는다

**전송 시점이 아니라 발생 시점의 상태**를 담는다. 기기에 남은 미전송 기록은 신원이 바뀌어도 살아남아 나중에 전송되므로, 이 값이 없으면 **로그인 직전의 행동이 회원 것으로 보인다.**

계측 버전은 이 계약 변경 전후의 데이터를 갈라 보기 위한 표식이다(§7 위험).

**완료 기준** — 새로 들어오는 모든 줄에 두 값이 채워져 있다. 배포 직전 큐에 남아 있던 옛 줄은 **빈 값**으로 들어오고, 화면에서 **"알 수 없음"**으로 보인다 (비회원으로 보이면 안 된다).

#### A-4. 찜 저장 실패를 따로 기록한다

**찜 시도를 취소하지 않는다.** 시도 1줄 + 실패 1줄이다. 실패를 시도에서 빼면 "찜하려 했는데 안 됐다"가 통째로 사라진다.

**완료 기준** — 네트워크를 끊고 찜을 누르면 원본 기록에 **시도 줄과 실패 줄이 나란히** 남는다.

> **여기까지 배포해도 된다.** 사용자가 보는 화면도, 문구도 바뀌지 않는다.

---

### 배포 B — 계정·비회원·문구를 함께

**B의 항목들은 쪼개서 배포하면 안 된다.** B-2가 먼저 나가면 "로그인하지 않으면 기록하지 않습니다"라는 문장이 거짓인 채로 서비스된다.

#### B-1. 계정 식별자를 서버 인증값으로 기록한다

클라이언트가 보낸 값을 믿지 않는다. **서버가 확인한 값으로만** 판정한다.

**과거 기록에 소급하지 않는다.** 기존 익명 기록만 보고 "이 기기가 지금 로그인한 사람의 과거 행동이었다"고 확정할 수 없기 때문이다.

**완료 기준** — ⓐ 로그인한 채 상품을 열면 원본 기록에 **계정이 채워진다.** ⓑ 로그아웃 상태의 줄에는 **비어 있다.** ⓒ 배포 전에 쌓인 줄은 **그대로 비어 있다** (소급되지 않았다).

#### B-2. 비회원 계측을 연다

로그인하지 않은 사람의 **노출·상세 열기·찜 의도·판매처 이동**을 기록한다.

**취향 학습 경로는 건드리지 않는다.** 피드에 취향을 실어 보내는 길을 그대로 두어야 비회원 피드가 계속 무작위다. 여길 건드리면 결정 O-37의 본체가 깨진다.

**완료 기준** — ⓐ 로그아웃 상태로 피드를 훑고 상세를 열면 원본 기록에 **줄이 남는다.** ⓑ 같은 시간 피드는 **여전히 무작위다** — 같은 조건으로 두 번 열어 상품 구성이 취향을 따라가지 않는 것을 확인한다.

#### B-3. 로그인 깔때기를 기록한다

로그인 화면 노출 · 로그인 버튼 클릭 · 성공 / 실패 / 취소. 여기에 **로그인 유도 출처**와 **신규 가입인지 기존 회원 로그인인지**를 함께 담는다.

지금 확인된 유도 출처는 둘이다 — 상세 화면의 하트, 마이페이지의 링크. **전체 목록은 미정(§8).**

**완료 기준** — 하트 → 로그인 화면 → 구글 로그인을 한 번 돌면 **노출·클릭·성공 줄이 순서대로** 남고, **유도 출처가 하트로** 적혀 있다. 도중에 취소하면 **취소 줄**이 남는다.

#### B-4. 로그인 전환 연결을 기록한다

**로그인 성공 시점에만** `비회원 세션 ↔ 기기 ↔ 계정` 연결을 한 줄 남긴다.

**이 연결은 전환 분석에만 쓴다.** 비회원 행동을 회원의 취향 프로필이나 추천 학습에 가져오지 않는다.

**완료 기준** — 비회원으로 훑다가 로그인하면 연결 기록이 **1줄** 생긴다. 그리고 **그 전 세션들의 줄에는 계정이 여전히 비어 있다.**

#### B-5. 화면 문구 다섯 개를 고친다

| # | 위치 | 지금 문장 |
|---|---|---|
| ① | `/privacy` 한 줄 요약 | "로그인하지 않으면 탐색 행동을 기록하지 않습니다" |
| ② | `/privacy` 로그인하지 않아도 | "탐색 행동은 기록하지 않습니다" |
| ③ | `/privacy` 계정과 익명 ID의 관계 | "계정 식별자를 함께 담지 않습니다" |
| ④ | `/settings` 첫 문단 | "로그인하지 않으면 탐색 행동을 기록하지 않습니다" |
| ⑤ | `/settings` 둘째 문단 | "기록은 계정이 아니라 익명 ID에 붙습니다" |

새 문안이 담아야 할 것 — **비회원도 기록한다 · 90일 뒤 삭제한다 · 피드는 개인화하지 않는다 · 로그인 전 기록에 소급하지 않는다 · 로그인 성공 시점에 전환 연결을 남긴다.**

[데이터 수집 방침](../atee/living/data-collection-policy.md)의 같은 문장과 갱신 이력도 함께 고친다.

**완료 기준** — `/privacy`와 `/settings`를 열었을 때 **"기록하지 않습니다"가 어디에도 없고**, 위 다섯 가지가 문장으로 읽힌다.

## 4. 배포 경계

| 배포 | 담기는 것 | 사용자 화면 |
|---|---|---|
| **A** | A-1 ~ A-4 | 변화 없음 |
| **B** | B-1 ~ B-5 **전부 함께** | 문구가 바뀐다 |

**A를 먼저 내는 이유** — A의 항목도 소급되지 않는다. B는 문구 검토를 기다려야 하는데, A까지 같이 기다리면 그만큼 노출 귀속·세션 경계 데이터를 잃는다.

**B를 쪼개면 안 되는 이유** — B-2(비회원 계측)와 B-5(문구)가 갈라지면 공개 처리방침이 거짓인 구간이 생긴다. 그리고 이 repo의 기능 플래그는 빌드 시 고정이라 **환경변수만으로 껐다 켤 수 없다.**

## 5. 검증

**단계별 완료 기준을 실기기에서 순서대로 밟고, 관리자 화면의 원본 기록과 대조한다.**

- 결과는 통과/실패를 항목별로 적은 표로 낸다. **실패·애매한 항목을 먼저 적는다.**
- 표만 내지 않는다. **원본 기록 몇 줄을 함께 낸다.**
- 밟지 않은 항목은 통과가 아니라 **미검증**으로 적는다.

**교차 리뷰를 한 번 받는다.** 계약 변경이라 되돌리기 비싸고, 특히 A-3(발생 시점 상태)과 B-1(서버 인증)은 틀리면 데이터가 조용히 오염된다.

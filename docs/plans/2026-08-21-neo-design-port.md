# 뉴모피즘 시안 이식 — 겉모습과 구조를 시안에 맞춘다

작성일 2026-08-21 · 개정 2026-08-21(2차, 범위 확대) · 상태 **초안(3단계 지적 대기)**

## 왜 하는가

지금 aTee는 거의 검정(`#0a0a0a`) 배경의 다크 화면이고, 화면마다 주소를 갖는
여덟 페이지짜리 구조다. 팀이 직접 만든 시안은 밝은 회색 뉴모피즘이고, **화면 하나
위에 모든 것이 겹쳐 뜨는 구조**다.

**시안이 기준이다. 색만이 아니라 구조도 시안에 맞춘다.** 이식하는 사람이 임의로
재해석하지 않는다.

단, 지금 제품이 들고 있는 동작 규칙은 버리지 않는다. **시안의 겉모습·구조 위에
지금의 로직을 얹는다**(2026-08-21 제품 책임자). 특히 아래 규칙은 이미 두 조각에
걸쳐 세운 것이라 그대로 따른다.

> **화면** — 내용이 통째로 바뀌고 스스로 뒤로가기 수단을 내놓는다. **히스토리에 넣는다.**
> **상태** — 같은 화면의 표시만 달라진다. **히스토리에 넣지 않는다.**
> 판단 근거는 히스토리 항목 자체에 둔다. 화살표는 직전 화면으로 되돌아간다.
> — [상세 오버레이](2026-08-19-detail-screen-stack-history.md) · [페이지 이동](2026-08-19-page-back-navigation.md)

이 규칙을 어기면 "뒤로가기를 눌렀는데 같은 화면이 또 나온다"는 결함이 재발한다.
그 결함은 2026-08-19에 실측으로 잡아낸 것이다.

## 기준 자료

시안 원본 HTML 한 개. 색·그림자·모서리·간격·글꼴 규칙과 화면 구성이 모두 들어 있다.

- 이 저장소 `design/atee-neo-mockup.html` (0단계에서 옮겨 옴)
- 참고할 곳은 파일 앞부분의 스타일 정의 구역이다. 파일이 큰 이유는 예시 사진이
  파일 안에 박혀 있기 때문이다.

시안 안에는 **시안을 보여주기 위한 껍데기**도 있다 — 폰 모양 테두리, 상단 상태바
흉내, 시안 설명 라벨, 비교용 A/B 토글. 이것들은 이식 대상이 아니다.

### 시안의 구조 (실제로 확인한 것)

주소를 갖는 화면이 하나도 없다. 바탕 화면 하나와, 그 위에 겹쳐 뜨는 것들이다.

- **바탕** — 로고줄(로고 + 우상단 하트·My 버튼) · Explore/Curation 알약 토글 ·
  2열 핀그리드 · 무한스크롤 · 하단 검색 dock
- **겹침** — 상품 상세(전체 덮개) · 프로필 사이드바(오른쪽에서 슬라이드, 왼쪽에
  색 채운 세로 레일) · 저장 폴더 패널(페이드+미세 확대로 열림) · 폴더 고르기 시트 ·
  로그인 팝업 · 새 폴더 팝업 · 삭제 확인 팝업 · 최근 본 것 팝업 · 토스트
- **설정은 별도 화면이 아니다.** 사이드바 안 기어 버튼 아래로 펼쳐지는 작은 메뉴다.
- 사이드바가 열리면 뒤의 바탕 화면이 살짝 줄어들며 뒤로 밀린다.

## 확정된 결정

1. **밝은 회색 톤으로 간다.** 시안 기본 배경색. 어두운 버전 색값은 적어만 둔다.
2. **앱 시작 연출은 가져오지 않는다.** 공이 날아와 카드로 펴지는 연출, 로고가
   떨어지는 연출, 태그바가 옆에서 들어오는 연출 모두 제외. 피드가 바로 뜨게 한다.
3. **구조도 시안을 따른다.** 프로필·저장 폴더·설정·로그인·새 폴더·삭제 확인을
   모두 시안처럼 겹쳐 뜨게 바꾼다.
4. **주소는 살린다.** 보이는 모습과 열리는 방식은 시안 그대로 두되, 겹침이 열리고
   닫힐 때 주소와 히스토리도 함께 움직이게 한다. 그래야 새로고침·링크 공유·
   뒤로가기가 지금처럼 동작한다. **주소를 없애는 것이 아니라, 시안의 모습에 지금
   로직을 붙이는 것이다.**
5. **시안에만 있는 기능은 이번에 만들지 않는다.** 상세 하단 세 버튼 바
   (`[공유][저장][더보기]`), 최근 본 것 팝업, 토스트 알림은 제외한다. 있는 기능을
   시안 구조로 옮기는 것까지만 한다.
6. **`/privacy`는 주소를 가진 별도 화면으로 남긴다.** 시안에 없는 화면이고,
   구글 심사가 직접 여는 공개 페이지다([페이지 이동](2026-08-19-page-back-navigation.md)).

## 순서와 완료 기준

각 단계는 그 자체로 배포 가능한 한 조각이다. 끝나면 작업 브랜치에서 `develop`으로
PR을 열고, 자동으로 생기는 미리보기 주소를 **휴대폰에서** 열어 시안과 나란히 비교한
뒤 병합한다.

### 0단계 — 색·글꼴 갈아끼우기 · **작업 완료, 커밋 전**

배경을 밝게 바꾸는 순간 밝은 계열 글자색이 밝은 바탕에 놓인다. 순백색 글자 73곳은
아예 안 보이게 되고, 옅은 회색 글자 86곳은 대비가 무너진다. 그래서 색 규칙을 심는
일과 글자색을 바꾸는 일을 한 덩어리로 했다.

한 것 — 시안 색 토큰 이식 · 눌림/솟음 그림자를 재사용 가능한 이름으로 · 시안 글꼴
적용(제품에는 글꼴 지정이 아예 없었다) · 색 지정 415곳 치환 · 브라우저 상단색과
설치형 앱 스플래시 색 · iOS 상태바 글자색.

**완료 기준:** 모든 화면이 밝은 회색 바탕에 정상적으로 읽힌다. 입체감은 아직 없다.

### 1단계 — 홈 바탕 화면

시안의 카드에는 배경도 그림자도 없다(사진이 곧 카드). 입체감은 카드가 아니라
둘러싼 껍데기에 들어간다.

- 로고줄 — 시안의 로고 표현과 우상단 원형 버튼 두 개(저장·My).
- Explore / Curation — 지금의 밑줄 탭을 시안의 **눌린 알약 + 미끄러지는 색 조각**으로.
- 카드 — 뒤 배경 제거, 모서리를 시안 값으로, 가격 표시를 시안의 모양·크기·굵기로.
  나타날 때 아래에서 살짝 떠오르는 움직임까지.
- 하단 검색 — 시안의 검색 dock 모양으로.
- 위 "미정"의 `/curation` 주소 처리를 여기서 정한다.

**완료 기준:** 홈을 시안과 나란히 놓고 어느 쪽이 시안인지 구분되지 않는다.
카드를 눌러 상세로 들어가고 되돌아오는 기존 동작이 그대로 작동한다.

### 1단계 실행 기록 (2026-08-21)

자동 검사·테스트 421개 통과. 실제 화면을 시안과 나란히 놓고 대조했고, 값은 브라우저에서
직접 읽어 확인했다 — 검색 dock 접힘 폭 58px, dock 그림자 `0 2px 6px rgb(30 38 55 / .22)`,
모드 조각 배경 `#8590A8`, 전환 260ms + 시안의 스프링 곡선. 모두 시안 값과 일치한다.

한 것 — 로고줄(심볼 + 양각 워드마크 + 원형 버튼 둘) · 모드바(눌린 알약 + 미끄러지는 색
조각) · 카드 등장 연출 · 검색 dock(오른쪽 끝 색 원, 접히면 그 원만 남음) · 하단 흐림 띠 ·
피드 여백을 시안 값으로.

**시안을 따르지 않은 곳이 한 군데 있다 — 검색 입력 글자 크기.** 시안은 14.5px이지만
16px을 유지했다. 이 제품에는 "16px 미만 입력에 포커스하면 iOS가 화면을 확대하고 포커스가
풀려도 되돌리지 않는다"는 실측 기록(탭 직후 scale 1.000 → 1.142)과 그것을 지키는 테스트가
있다. 시안보다 실측된 제약을 우선했다. **사람이 다시 정하면 따르겠다.**

**모드 라벨을 시안대로 바꿨다** — BROWSE → Explore, PICKS → Curation. 칸의 식별자는
코드 곳곳이 쓰므로 그대로 두고 사람이 읽는 이름만 바꿨다.

**시안에 기준이 없는 영역을 발견했다.** 시안의 Curation 모드는 비어 있다 — 파일 주석에
"담당 팀원 제작 예정이라 완전히 빈 화면"이라고 적혀 있다. 그래서 제품의 큐레이션 내용은
대조할 기준이 없다. 0단계의 색만 입은 상태로 두었다.

**시안과 다르지만 유지한 동작이 하나 더 있다.** 시안은 모드를 바꿀 때 맨 위로 올린다.
제품은 칸마다 세로 위치를 따로 갖고 유지한다 — 이것은 2026-08-20에 실측으로 정리한
결정이다(`2026-08-20-pane-scroll-isolation.md`).

**사람이 찾아낸 누락 두 가지를 뒤이어 메웠다(같은 날).**

- **뼈대 카드의 물 차오름.** 시안 `.card.skel .ph`는 깜빡이지 않고 아래에서 물이
  차오른다. 제품은 깜빡이(pulse)를 쓰고 있었다. 시안 값 그대로 옮겼다 —
  `water-fill 620ms cubic-bezier(.35,.55,.45,1) forwards`, 채움색은 아래가 진하고
  위로 갈수록 옅어져 사라진다. 시안에서는 이 시간이 **그 배치의 실제 로딩 시간**이라
  물이 꼭대기에 닿는 순간 카드가 나타나는데, 실제 로딩 시간은 미리 알 수 없어
  시안의 기본값을 쓴다(값을 넘길 자리는 열어 뒀다).
- **배치마다 뼈대.** 시안은 무한 스크롤로 배치를 받을 때마다 뼈대를 놓고 그 자리에서
  실제 카드로 바꾼다. 제품은 첫 로딩에만 뼈대를 보여주고 있었다. 피드 끝에 배치
  크기만큼(열당 2장) 이어 붙이도록 고쳤다. 스크롤 실측: 카드 30 → 240장, 그 사이
  뼈대 4장이 반복해서 나타났다 사라졌다.
- **검색 원버튼의 어두운 배경.** 시안은 접힌 원버튼을 **손으로 눌러** 펼쳤을 때만
  배경을 어둡게 하고 피드를 멈춘다(맨 위라서 펼쳐진 것은 평상시 화면이라 어둡게
  하지 않는다). 딤을 탭하면 걷히고, 손으로 편 뒤 더 내리면 다시 원버튼이 된다.
  브라우저 실측으로 시안 값 일치를 확인했다 — 딤 `rgba(23,21,15,.3)`, 검색 dock보다
  아래 층이라 dock은 그대로 조작되고, 열리면 하단 흐림 띠가 걷힌다.
  제품의 접힘 판정(방향 누적·키보드 대응)은 실기기 문제 때문에 만들어진 것이라
  그대로 두고 딤만 얹었다.

**검색 dock을 원버튼으로 시작하게 바꿨다(2026-08-21 제품 책임자).** 시안은 펼친
상태로 시작하지만(`<div class="sdock bar">`), 이 지점은 **의도적으로 시안과 다르게**
간다. 초기 상태만 바꾸면 맨 위에서 아래로 미는 순간 펴졌다가 곧바로 접히는 깜빡임이
생긴다 — "상단이면 무조건 확장"이라는 기존 규칙 때문이다. 그래서 그 규칙을 "**위로
올라와 닿았을 때만** 확장"으로 좁혔다. 검색 제출로 결과 상단에 도달하는 프로그램적
스크롤도 올라오는 이동이라, 축소 잔상을 막던 기존 장치는 그대로 유지된다.
회귀 테스트 두 개를 새로 넣었다(원버튼으로 시작 / 내리기 시작할 때 안 펴짐).

**아직 사람이 정하지 않은 것:** 맨 위로 되돌아오면 다시 펼쳐진다(기존 설계 §3의
"위로 스크롤하면 확장"). 탭할 때만 펼쳐지게 하려면 그 규칙도 빼야 한다.

**남은 것:** 흰 옷 사진 경계가 바탕에 녹는 현상은 그대로다. 시안의 카드에는 배경도
테두리도 없어 시안을 따르는 한 해결책이 없다. 사람이 볼 차례다.

### 2단계 — 상품 상세

이미 전체 덮개라 구조는 같다. 안의 배치와 모양을 맞춘다.

- 상단 뒤로가기 원형 버튼, 사진 캐러셀(좌우 넘기기 + 하단 점), 이름·브랜드·가격의
  자리와 크기.
- 시안의 하단 세 버튼 바는 만들지 않는다(확정된 결정 5). 지금 있는 찜·판매처
  버튼을 시안의 버튼 모양으로 맞춘다.

**완료 기준:** 상세를 열어 사진을 넘기고 찜까지 눌렀을 때 시안과 같은 모습이고,
찜이 실제로 보관함에 들어간다.

### 2단계 실행 기록 (2026-08-21)

자동 검사·테스트 423개 통과. 브라우저에서 값을 직접 읽어 시안과 대조했다 —
사진 틀 여백 `6px 16px 0`, 모서리 10px, 슬라이드 바탕 `#D3D6DE`(시안이 지정한
`--line`), 정보 영역 여백 `18px 20px`, 가격 18px/800 자릿수 고정, 가격줄 사이 16px,
뒤로가기 40px 원에 솟음 그림자, 아이콘 18px. 모두 시안 값과 같다.

한 것 — 뒤로가기를 시안의 솟음 원버튼으로 · 사진을 좌우 16px 안쪽에 넣고 모서리를
카드와 같게(그림자는 주지 않는다, 시안 주석 "플랫 — 피드 카드와 동일하게 입체감 제거") ·
**넘김 점을 사진 아래 줄에서 사진 위 반투명 알약으로 옮기고**, 흰 점 하나가 자리를
옮기며 미끄러지게 · 브랜드·이름·가격의 크기와 자리를 시안 값으로 · 판매처 링크를
글자 화살표에서 시안의 아이콘으로 · 맨위로 버튼을 시안 `.icon-btn`(44px 솟음 원)으로 ·
관련 상품 여백을 시안 `.rel-feed` 값으로.

**시안에 없어서 내가 자리를 정한 것 — 찜 버튼.** 시안의 상세에는 찜이 없다. 저장은
하단 `[공유][저장][더보기]` 바가 맡는데 그 바는 이번에 만들지 않기로 했다(확정된 결정 5).
그래서 제품에 이미 있는 찜 버튼을 **시안의 판매처 링크와 같은 방식**(틀 없는 아이콘,
누르면 움츠러듦)으로 가격 옆에 나란히 두었다. 사람이 다시 정하면 따르겠다.

**시안을 따르지 않은 곳 — 사진 맞춤.** 시안은 `object-fit: cover`다. 제품은 5:6 틀에
`contain`으로 넣어 옷이 잘리지 않게 하고 있는데, 카탈로그 사진 비율이 제각각이라
cover로 바꾸면 소매·밑단이 잘린다. 기존 방식을 유지했다.

**저장 dock을 뒤이어 만들었다(2026-08-22).** 2단계를 끝냈을 때 상세에 저장 버튼이
없다는 지적을 받았다. 원인은 "시안에만 있고 제품에는 없는 것"을 물으며 하단 바를
`[공유][저장][더보기]`라고 설명했고 그것이 제외로 결정된 것인데, **그 바가 곧 저장
버튼이었다.** 설명이 틀렸다 — 기준 파일의 `.ddock-items` 안에는 `<button class="dd-save">`
하나뿐이다. 세 개라는 말은 CSS 주석·HTML 주석·시안 설명문 세 군데에만 남아 있고,
어느 이터레이션에서 둘을 빼며 글만 고치지 않은 것으로 보인다.

만든 것 — 하단 dock(시안 `.ddock`). 맨 위 60px 안에서는 저장 알약, 내려가면 슬레이트
원버튼(맨 위로)으로 접힌다. 접힌 원이 곧 맨 위로 버튼이라, 2단계에서 따로 만들었던
맨위로 버튼과 가격줄에 임의로 두었던 하트를 걷어내고 이쪽으로 합쳤다. 시안의 가격줄에는
판매처 링크만 있다.

저장 흐름은 제품에 이미 있던 것과 같다 — 비회원이면 로그인 화면으로, 아니면 폴더 지정
시트. 저장이 성사되면 버튼 위로 Lottie(티셔츠가 접혀 들어와 체크로)가 한 번 재생되고,
재생 도중(150프레임)에 알약이 눌린 뉴모피즘 "저장됨 ✓"로 넘어간다. 구간·속도 전환
지점은 시안 값 그대로(52~222프레임, 64프레임부터 1.7배).

애니메이션 파일은 10KB이고 **상세 화면에 들어왔을 때만** 내려받는다. 재생기(lottie-web)도
같이 미룬다 — 홈 첫 화면 비용은 늘지 않는다. 움직임 줄이기를 켠 기기에서는 아예 받지
않고 연출 없이 저장됨 모습으로 넘어간다.

브라우저 실측 — 펼침 210px·배경 투명, 알약 `#8590A8`·높이 44px·그림자
`0 5px 14px rgb(30 38 55/.35)`, 접힘 58px·배경 `#8590A8`. 모두 시안 값과 같다.
테스트 423개 통과.

**사람이 정할 것 — 공유·더보기.** 기준 파일 마크업에 없어서 만들지 않았다. 되살린다면
"더보기"가 무엇을 여는지 정해야 한다(제품에 대응 기능이 없다).

### 뒤이은 수정 (2026-08-22)

**저장 연출이 두 벌 만들어져 어긋났다.** 취소 표시를 ref에 두는 바람에 다음 효과
실행이 그 값을 되돌려, 취소된 앞 실행의 로드가 살아나 그림이 둘 붙었다. 보이는 쪽은
재생되지 않고 재생되는 쪽은 크기가 어긋난 채 잘렸다. 취소 표시를 그 실행에만 속한
값으로 바꾸고, 만든 것을 그 실행이 직접 정리하게 했다.

**파괴된 애니메이션에 리스너를 떼려다 오류가 났다.** 정리는 선언 순서대로 돌아서
화면을 떠날 때 로드 효과가 먼저 애니메이션을 없앤다. 살아 있는지 확인하고 건너뛴다.

**도입부가 비어 보였다.** 상자를 다음 프레임에 켜느라 아직 아무것도 그리지 않은
구간이 보였다. 재생기가 첫 프레임을 그릴 때 켜도록 바꿨다. 시안과 나란히 재서
확인했다 — 도입부에 그림이 보이고 끝에서 라벨이 넘어간다.

**검색창은 이제 스크롤로 펼쳐지지 않는다(2026-08-22 제품 책임자).** 내렸다 올리면
다시 열려 거슬린다는 지적을 받았다. 스크롤은 **접기만** 하고, 펼치는 것은 사람이
원버튼을 누르거나 입력에 포커스를 줄 때뿐이다. 맨 위로 돌아와도 원버튼 그대로다.
회귀 테스트를 그 규칙으로 바꿨다.

### 3단계 — 보관함을 겹침으로

지금은 주소를 가진 별도 화면이다. 시안처럼 **홈 위에 페이드와 미세한 확대로 열리는
패널**로 바꾼다. 주소와 히스토리는 함께 움직인다(확정된 결정 4).

- 패널 헤더(닫기·제목·도구줄), 폴더 표지(겹쳐진 카드 스택 + 사진 아래 흐린 띠 +
  이름·개수), 폴더 상세의 2열 배치.
- 폴더 고르기 시트는 이미 시트라 모양만 맞춘다.
- 착수 전에 위 "미정"의 **기준 파일** 문제를 사람이 정해야 한다. 폴더 표지의 띠와
  글자 그림자가 두 판에서 다르다.

**완료 기준:** 홈에서 저장 버튼을 눌러 패널이 열리고, 폴더를 열고, 뒤로가기로
정확히 한 단계씩 닫힌다. 패널이 열린 상태에서 새로고침하면 그 상태로 돌아온다.

### 4단계 — 프로필을 사이드바로 · 설정을 그 안으로

지금은 `/my`와 `/settings` 두 주소다. 시안에서는 사이드바 하나이고, 설정은 그
안 기어 버튼 아래로 펼쳐지는 작은 메뉴다.

- 오른쪽에서 밀려나오는 패널, 왼쪽의 색 채운 세로 레일, 뒤 화면이 살짝 줄어들며
  물러나는 깊이감.
- 안의 내용 — 아바타·이름, 취향 키워드 칩, 내 취향 카드, 최근 저장 줄, 3칸 통계.
- 설정 메뉴 — 기어 버튼 아래 팝오버. 지금 `/settings`에 있는 항목을 옮긴다.
- **기존 동작을 깨뜨리지 않는지 확인한다.** 마이페이지 이동 속도와 뒤로가기 규칙은
  이미 정리된 적이 있다(`2026-08-20-my-page-navigation-latency.md`,
  `2026-08-19-page-back-navigation.md`). 착수 전에 두 문서를 읽는다.
- 시안의 최근 본 것 팝업은 만들지 않는다(확정된 결정 5). 최근 저장 줄까지만.

**완료 기준:** 홈에서 My 버튼을 누르면 사이드바가 나오고, 설정 메뉴가 그 안에서
펼쳐지고, 뒤로가기로 한 단계씩 닫힌다. 사이드바가 열린 상태에서 새로고침하면 그
상태로 돌아온다. 마이페이지 진입이 지금보다 느려지지 않는다.

### 5단계 — 로그인을 팝업으로

지금은 `/login` 주소다. 시안에서는 화면 위에 뜨는 작은 창이다.

- 로그인이 필요한 순간에 팝업이 뜨게 한다.
- 위 "미정"의 확인 결과에 따라, 팝업 안에서 끝나지 않는 부분은 기존 방식을
  유지하고 이유를 문서에 남긴다.

**완료 기준:** 저장처럼 로그인이 필요한 동작을 했을 때 팝업이 뜨고, 로그인을 마치면
**하던 동작이 이어진다.** 취소하면 원래 화면 그대로 남는다.

### 6단계 — 새 폴더·삭제 확인을 팝업으로

지금은 화면 안에 인라인으로 입력·확인이 들어간다. 시안에서는 각각 별도 팝업이다.

- 새 폴더 이름 입력 팝업, 삭제 확인 팝업(예/아니오).
- 이 둘은 "화면"이 아니라 "상태"다(스스로 뒤로가기 수단을 내놓지 않고 취소로 닫힌다).
  위 원칙에 따라 **히스토리에 넣지 않는다.** 다만 안드로이드 뒤로가기로 닫히는 것이
  자연스러운지는 착수 시점에 확인한다.

**완료 기준:** 폴더를 만들고 지우는 과정이 시안과 같은 모습이고, 중간에 끊기지 않는다.

## 매 단계 공통 확인

- 자동 검사(`npm run check`)와 테스트(`npm run test`)가 통과한다.
- **뒤로가기를 실제로 눌러 본다.** 겉모습만 바꾸는 단계에서도, 겹침을 도입하는
  단계에서는 특히. 열고 닫기를 세 번 왕복한 뒤에도 같은 화면이 중복해서 나오지
  않아야 한다.
- PR 미리보기 주소를 **휴대폰에서** 연다. 설치형 앱을 전제로 하는 제품이다.
- 시안과 나란히 놓고 비교한다. 다른 곳이 있으면 시안이 맞다.

## 위험

- **겹침으로 바꾸는 단계(3·4·5)가 이 계획에서 가장 무겁다.** 화면 이동 방식은
  뒤로가기·주소 공유·새로고침·앱 재기동과 모두 얽힌다. 2026-08-19에 같은 성격의
  문제를 두 조각에 걸쳐 고쳤고, 그때 "화면 쪽 메모리와 히스토리 항목의 수명이
  갈리면 어긋나고, 한 번 어긋나면 되돌아오지 않는다"는 것을 실측으로 확인했다.
  같은 실수를 반복하지 않으려면 **판단 근거를 히스토리 항목 자체에 두는** 기존
  방식을 그대로 써야 한다.
- **홈에 상세 스택 주인이 둘이다.** 홈은 두 칸을 동시에 그려 두고 각 칸이 자기
  뒤로가기 처리기를 갖는데, 하나의 브라우저 히스토리에 함께 밀어 넣는다. 지금은
  잠복해 있지만 겹침이 늘면 서로 다툰다([상세 오버레이](2026-08-19-detail-screen-stack-history.md)).
  3단계 착수 전에 이 상태를 다시 확인한다.
- **흰 옷 사진 경계가 흐려진다.** 0단계에서 확인됐다. 시안의 카드는 배경도 테두리도
  없어서 흰 배경 사진이 앱 바탕에 녹는다. 1단계에서 처리한다.
- **한 번에 바꾸는 색이 415곳이었다.** 0단계 PR은 미리보기에서 모든 화면을 한 번씩
  열어봐야 한다.

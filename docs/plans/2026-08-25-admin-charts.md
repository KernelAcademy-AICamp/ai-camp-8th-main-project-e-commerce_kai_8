# 어드민 대시보드 차트 구현 계획 (2026-08-25)


## Context — 왜 하는가

지금 어드민 대시보드는 **모든 카드가 숫자 표**다. 데이터가 맞는지는 보이지만, 어디서
떨어지는지·언제 끊겼는지·분포가 어떤 모양인지는 표를 읽어 머릿속에서 그려야 안다.

목업 두 개로 모양을 확정했고 사람이 눈으로 승인했다.

- [`docs/mockups/2026-08-25-admin-charts-mockup.html`](../mockups/2026-08-25-admin-charts-mockup.html) — 카드 8장, 실제 프로덕션 데이터
- [`docs/mockups/2026-08-25-funnel-options.html`](../mockups/2026-08-25-funnel-options.html) — 세션 퍼널 단독

**이 계획은 그 목업을 실제 화면으로 옮기는 일이다.** 지표 정의(SQL)는 대부분 그대로 두고
표시 방법만 바꾼다. 예외는 세션 퍼널 하나인데, 그건 아래 ②에 적었다.

### 이미 끝나서 전제가 되는 것

| | 상태 |
|---|---|
| 조회 색인 둘 (`occurred_at`, `session_id`) | **프로덕션 적용 완료** — raw-events 242ms → 1.45ms |
| 90일 보존 + pg_cron 예약 | **프로덕션 적용 완료** |
| 기간 필터 (`?days=7\|14\|30`) | **admin 구현 완료**, 테스트 115개 통과 |
| 온보딩 `done` 오염 수정 | **frontend 구현 완료**, 아직 배포 전 |

## 구현 전에 확정된 것

### ① 툴팁은 「직접 표시 + 브라우저 기본」 (사람 결정, 2026-08-25)

측정 결과를 보고 정했다.

- **숫자를 그림 위에 직접 찍는다.** 여섯 카드 중 다섯은 자리가 넉넉하다(칸폭 49~200px).
  숫자가 겹치는 건 일별 기록 건수 하나뿐이다(30일이면 칸폭 17px).
- **자리가 없는 곳만 브라우저 기본 툴팁**(SVG `<title>`)으로 보완한다. 추가 전송량 0 KB.
- 클라이언트 컴포넌트는 **기본으로 안 넣는다.** 지금 admin은 화면 코드에 상태가 없고
  서버에서만 돈다. 그 성질을 유지한다. 필터는 지금 탭·기간 선택기와 같이 **링크**로 만든다.
- 근거: 시각화 통설이 "직접 라벨을 격자선보다 먼저" 그리고 "표 보기가 항상 있어야 한다"
  이다. 목업의 호버 툴팁은 보조 수단이지 주 수단이 아니다.

**단, 자바스크립트가 확실히 나은 자리에는 쓴다** (사람 결정, 2026-08-25).
「기본으로 안 넣는다」는 금지가 아니라 기본값이다. 쓰는 조건은 하나다 —
**링크와 직접 라벨로는 못 푸는 문제일 때.** 지금 예상되는 후보는 둘이고,
둘 다 **먼저 자바스크립트 없이 해 보고 부족할 때만** 꺼낸다.

| 후보 | 자바스크립트 없이 하면 | 언제 꺼내나 |
|---|---|---|
| 조밀한 시계열에서 특정 날짜 집기 | 주 단위로 묶어 막대를 굵게 (0-2) | 묶어도 못 집을 때 |
| 키보드로 데이터점 옮겨 다니기 | 차트 아래 표로 값을 읽음 (1-6) | 표로 부족하다고 판명될 때 |

**쓰기로 하면 그 자리에 왜 필요했는지 남긴다.** "있으면 좋아서"는 이유가 아니다.

### ② 세션 퍼널만 SQL을 바꾼다 — 갈래가 겹치기 때문

찜과 판매처 이동은 **한 세션이 둘 다 할 수 있다.** 지금처럼 나란히 세면 합이 맞지 않는다.
**「둘 다」를 독립된 갈래로 뽑으면** 모든 세션이 정확히 한 곳에만 속한다. 실측 검산:

```
클릭 없음 121 + 찜만 36 + 둘 다 6 + 판매처만 8 + 행동 없음 89 = 260 (노출 세션 수)
```

### ③ 「화면 코드를 안 건드린다」를 깨지 않는다

지금 구조의 핵심 성질은 **새 지표 = 파일 하나 + 명단 한 줄**이고 화면 코드는 그대로라는
것이다(`domain/metric.ts` 주석). 차트를 넣으면서 이걸 깨면 안 된다.

→ `MetricDefinition`에 **표시 방법을 선언하는 칸**을 더하고, 그리는 쪽은 SQL 결과 표를
읽어 그린다. SQL은 계속 유일한 출처다. 선언이 없는 카드는 지금처럼 표로 나온다.

### ①-b 마크에는 `tabindex`를 붙이지 않는다 (1차 검토 반영, 2026-08-25)

목업은 막대·점 하나하나에 `tabindex="0"`을 붙였다. 전체 기간이면 **탭 정지점이 102개**가
된다(일별 60 + 흐름도 7 + 상자수염 12 + 재방문 18 + 활동 5). 키보드로 화면을 지나가려면
102번을 눌러야 한다.

「차트 하나를 포커스하고 화살표로 데이터점을 옮기는」 방식은 **자바스크립트가 필요해서**
위 ①과 충돌한다. 자바스크립트 없이 같은 목적을 이루는 표준 형태를 쓴다.

- **마크에서 `tabindex`를 걷어낸다.** 차트 전체가 `role="img"` + 요약 `aria-label` 하나를 갖는다.
- **값은 아래 표가 책임진다.** `<title>`은 마우스 호버 전용 보조 수단으로만 남는다.
- 이 선택은 터치 영역 기준과도 맞물린다 — [WCAG 2.2 SC 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)(AA, 24×24 CSS px)에는
  **「Equivalent」 예외**가 있어, 같은 기능을 하는 다른 컨트롤이 기준을 만족하면 면제된다.
  **차트 아래 표가 바로 그 컨트롤이다.** 그래서 1-6의 접힌 표는 선택 사항이 아니라 필수다.
- 조작할 수 있어야 하는 것(기간·필터 링크)은 **최소 44×44 CSS px**로 만든다.
  지금 목업의 기간 버튼은 29.4px다 — AA(24)는 통과하지만 [SC 2.5.5](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html)(AAA, 44×44)와
  Apple HIG(44pt)·Material(48dp)에는 못 미친다. 올리는 비용이 거의 없으므로 올린다.

### ④ 세 상태 구분을 차트에서도 지킨다

`값이 있음 / 정상인데 0건 / 실패`는 서로 다른 화면이어야 한다(설계 §7).
**0건인 차트가 고장 난 차트처럼 보이면 안 된다.**

### ⑤ 계속 길어지는 표는 접는다 (사람 요청, 2026-08-25)

날짜·활동일수처럼 **시간이 갈수록 행이 느는** 카드는 앞 몇 줄만 펴 두고 나머지는 접는다.
자바스크립트 없이 되는 방법이면 무엇이든 좋다(`<details>`, CSS 토글, 스크롤 상자 등) —
방법은 구현할 때 고른다.

## 0단계 — 목업 정정 (1차 검토에서 나온 결함 셋)

목업은 **구현이 베껴 쓸 정본**이다. 결함을 남겨 두면 그대로 옮겨진다.
60일치를 실제로 주입해 확인한 결함 셋을 먼저 고친다.

### 0-1. 날짜가 두 달을 설명하지 못한다

일자만 잘라 찍고(`d.slice(3)`) 캡션에 「8월」이 박혀 있다. 두 달이면 같은 일자가 반복되고,
데이터가 6~8월이어도 캡션은 8월이라고 말한다. **화면이 틀린 말을 한다.**

- 눈금을 `7/27` · `8/1`처럼 **월/일**로 찍는다. **월이 바뀌는 첫 날은 솎기와 무관하게 반드시** 찍는다 —
  경계가 사라지면 어디서 달이 바뀌었는지 알 방법이 없다.
- 캡션은 실제 범위에서 계산한다: `2026-06-27 ~ 2026-08-25 · 60일`.
- **완료 기준**: 60일치를 넣었을 때 눈금에 월 경계가 보이고, 캡션의 시작·끝 날짜가
  데이터의 첫날·마지막 날과 같다.

### 0-2. 60일 막대는 보이지만 집을 수 없다

막대 소멸은 이미 고쳤다(폭 하한 2px). 그런데 실측하면 여전히 이렇다.

| 뷰포트 | 30일 | 60일 |
|---|---|---|
| 데스크톱 1120px (7칸) | 11.3px | **2.5px** |
| 모바일 390px (통칸) | 6.0px | **1.3px** |

추세는 보이지만 특정 날짜를 마우스·터치로 집을 수 없다.

- **막대가 얇아지면 주 단위로 묶는다.** 어느 폭에서 묶을지는 **재서 정한다** — 지어내지 않는다.
- **묶었다는 사실을 캡션에 적는다.** 말없이 바뀌면 "왜 막대가 9개지?"가 된다.
- **완료 기준**: 전체 기간에서 막대가 손으로 집을 만한 폭이고, 캡션이 일 단위인지 주 단위인지 말한다.

### 0-3. 탭 정지점 102개

위 ①-b 결정을 목업에도 적용한다.

- **완료 기준**: 탭을 눌러 차트를 지나가는 데 차트당 한 번이면 된다.
  기간 버튼이 44×44 CSS px 이상이다.

**0단계 완료 = 목업이 두 달치 데이터에서 거짓말을 하지 않는다.**

### 0단계 결과 (2026-08-25, 돌려본 것만)

10·30·60·90일치를 **실제로 주입해** 확인했다. 프로덕션 DB는 건드리지 않았다.

| 데이터 | 막대 | 단위 | 캡션 | 월 경계 |
|---|---|---|---|---|
| 10일 | 10 | 일 | `2026-08-16 ~ 2026-08-25 · 10일 · 일 단위` | (한 달 안) |
| 30일 | 30 | 일 | `2026-07-27 ~ 2026-08-25 · 30일 · 일 단위` | `8/1` |
| 60일 | 9 | **주** | `2026-06-27 ~ 2026-08-25 · 60일 · 주 단위 묶음` | `7/4` `8/1` |
| 90일 | 13 | **주** | `2026-05-28 ~ 2026-08-25 · 90일 · 주 단위 묶음` | `6/4` `7/2` `8/6` |

- **날짜 라벨 중복 0건** — 네 경우 모두. `8/16` 같은 월/일 표기라 두 달을 넘겨도 안 겹친다.
- **월이 바뀌는 칸은 솎기와 무관하게 찍고 굵게** 표시한다.
- **주 단위 전환 기준은 31일 초과.** 재서 정했다 — 모바일 390px에서 막대 폭이
  28일 6.6px · 30일 6.0px · 31일 5.7px · 60일 1.3px로 떨어진다. 6px 아래면 못 집는다.
  주로 묶으면 며칠이든 13.5px(모바일) · 25.5px(데스크톱)가 나온다.
- **마지막 주가 짧으면 그렇다고 적는다** — `8/22 ~ 8/25 · 8,398건 — 4일치만 (아직 안 끝난 주)`.
  앞에서부터 묶는 이유가 이것이다. 뒤에서 묶으면 맨 앞이 짧아져 "옛날엔 한산했다"로 읽힌다.
- **탭 정지점 0개.** 마크의 `tabindex`를 전부 걷어냈다(이전 102개). 차트마다
  `role="img"` + 요약 `aria-label` 하나를 갖는다. 마우스 툴팁은 `<title>`이 맡는다.
- **기간 버튼 44×44 CSS px 이상.** 이전 29.4px.

⚠️ **브라우저로 눈 확인은 아직 안 했다.** jsdom은 글자 폭과 CSS를 계산하지 않는다 —
막대 폭·이름표 겹침·버튼 크기는 계산으로만 확인했다.

## 1단계 — 차트 기반과 세션 퍼널

**가장 중요한 카드를 맨 먼저 한다.** 이 프로젝트가 원래 물은 것이
"한 번 들어와서 몇 개를 봤고, 몇 개를 찜했고, 몇 개를 판매처로 나갔나"이고, 세션 퍼널이
거기에 직접 답한다. 그리고 이 카드 하나가 기반 조각을 전부 쓴다 — 되면 나머지는 변형이다.

### 1-1. 숫자를 숫자인 채로 넘긴다

지금 표를 만들 때 숫자를 `"1,457"` 같은 **글자로 바꿔 버린다**(`formatCell`). 차트는 길이와
좌표를 계산해야 하므로 숫자가 필요하다. 글자를 되돌려 읽는 방식은 쓰지 않는다 — 쉼표·단위·
로케일이 섞이면 조용히 틀린다.

- 표에 담는 값에 **원본 숫자를 함께** 싣는다. 지금 글자 칸은 그대로 둔다(표는 안 바뀐다).
- **완료 기준**: 숫자 컬럼이 있는 지표를 돌렸을 때, 글자 `"1,457"`과 숫자 `1457`이 둘 다
  넘어온다는 것이 테스트로 확인된다. 기존 표 화면은 눈으로 봐도 달라진 데가 없다.

### 1-2. 축 눈금 계산기

축을 코드에 박아 두면 **조용히 틀린 그림**이 된다. 이미 그럴 뻔했다 — 재방문 세로축이 20%
고정인데 Day 1이 19.4%였고, 상자수염 축이 120 고정인데 상위 25%가 92였다.

- 최대값을 받아 **읽기 좋은 눈금**(1·2·2.5·5·10의 배수)과 축 최대값을 돌려준다.
- **완료 기준**: 아래가 테스트로 고정된다. 부동소수 찌꺼기(`0.6000000000000001`)가 없다.

  | 넣는 값 | 나오는 눈금 |
  |---|---|
  | 19.4 | 0 · 5 · 10 · 15 · 20 |
  | 6,724 | 0 · 2,000 · 4,000 · 6,000 · 8,000 |
  | 0.42 | 0 · 0.2 · 0.4 · 0.6 |
  | 0 또는 음수 | 터지지 않고 0 · 1 |

### 1-3. 표시 방법 선언 칸

- `MetricDefinition`에 **어떻게 그릴지**를 선언하는 칸을 더한다. 선언이 없으면 지금처럼 표다.
- **완료 기준**: 선언을 안 붙인 카드 일곱 장이 **지금과 픽셀 단위로 같게** 나온다.

### 1-4. 세션 퍼널 SQL을 겹치지 않는 갈래로

`admin/metrics/session-funnel.ts`를 위 ②의 다섯 갈래로 바꾼다.

- **완료 기준**: 화면에서 다섯 갈래를 더한 값이 「노출이 있는 세션 수」와 **정확히 같다.**
  다르면 갈래가 겹쳤거나 빠진 것이므로 그 자리에서 보인다.
- 계약 테스트를 함께 고친다 — 지금 테스트는 옛 모양을 고정하고 있다.

### 1-5. 분기 흐름도를 그린다

- 위에 **단계 머리줄**(상품 노출 → 상품 클릭 → 행동), 아래에 **띠 흐름도**, 맨 아래 **요약 띠**
  (전체 전환율 · 총 이탈 · 가장 큰 이탈 구간). 목업 그대로다.
- **갈래마다 이름과 숫자를 직접 찍는다.** 얇은 갈래(둘 다 6)는 이름표가 겹치므로,
  마디는 제자리에 두고 이름표만 최소 간격으로 밀고 잇는 선을 그린다.
- **필터는 링크다** — 주소에 `전체 / 찜 / 판매처 이동`을 싣는다. 화면 탭·기간 선택기와 같은
  방식이라 새 개념이 없고, 주소를 복사해 넘기면 같은 화면이 열린다.
  이 값은 **표시 방법만 바꾼다** — SQL은 늘 다섯 갈래를 다 가져오고, 그리는 쪽이 합친다.
  질의는 한 번만 돈다.
- **완료 기준**:
  - 주소에 필터를 붙이면 갈래가 둘(했다/안 했다)로 바뀌고 그 버튼이 눌린 것으로 보인다.

### 1-6. 차트 아래 접힌 표 — **필수다**

- **완료 기준**: 펼치면 지금 쓰던 표가 그대로 나오고, 그 숫자가 그림의 숫자와 같다.

1. **실제 데이터로 눈 확인** — 개요·리텐션·원본 세 화면을 기간별로 열어 본다.

## 미정으로 남기는 것

- **세션 요약의 아래 세 줄(찜·판매처 이동)을 뺄지.** 사분위가 전부 0이라 상자가 안 그려지고,
  세션 퍼널이 같은 내용을 %로 보여준다. 2단계에서 화면을 보고 사람이 정한다.
- **온보딩 `done` 제외 기준 시각.** 수정이 배포된 뒤에 확정한다.
- **원본 화면의 세션 표를 그림으로 바꿀지.** 지금은 표가 맞다고 보고 그대로 둔다.
- **어드민만 바뀌어도 앱 버전이 올라가는 릴리즈 구조.** 이 계획 밖의 문제다.

## 알아둘 것 (이 repo의 함정)

- **admin SQL은 `select`나 `with`로 시작해야 한다.** 앞에 주석을 붙이면
  `metrics/index.test.ts`의 읽기 전용 검사에 걸린다 — 주석은 `with` 다음 줄로.
- **날짜 조건은 범위로 쓴다.** `(occurred_at at time zone 'Asia/Seoul')::date = $2`는 컬럼을
  가공해 색인을 못 탄다. 실측 17.07ms 대 1.71ms, 답은 동일했다.
- **`toParams`는 `$1`=세션 · `$2`=날짜 · `$3`=기간 순서로 묶여 있다.** 순서를 바꾸면 조용히 0건이 된다.
- **조인 안에서 `eventFilterSql`을 쓸 때는 별칭을 넘긴다.** 안 넘기면 `session_id is ambiguous`로 죽는다.
- **`format:check` 실패는 무시한다.** 로컬 Windows 줄바꿈 문제이고 CI(Linux)는 통과한다.

## 검증 방법

```
cd admin
npm run dev          # http://localhost:3002
```

**화면에서**

1. `/` — KPI 띠, 일별 막대, 온보딩 퍼널, 세션 요약, 세션 퍼널
2. 기간을 7 · 14 · 30 · 전체로 바꿔 가며 다섯 카드가 다 따라 바뀌는지
3. 세션 퍼널의 `전체 / 찜 / 판매처 이동`을 눌러 갈래가 바뀌는지
4. 각 카드의 「숫자로 보기」를 펴서 **그림의 숫자와 표의 숫자가 같은지**
5. `?screen=retention` — 재방문 곡선, 활동 일수 분포
6. `?screen=recommendation` · `?screen=raw` — 예전과 같은지 (회귀)
7. 없는 값을 넣어 본다 (`?days=9999`) — 「무시한 조건」이 뜨는지
8. **키보드만으로** 탭을 눌러 화면을 끝까지 지나가 본다 — 차트당 정지점이 한 번인지,
   「숫자로 보기」를 펴서 값을 읽을 수 있는지
9. **브라우저 창을 390px로 줄여** 본다 — 막대를 손으로 집을 만한지, 기간 버튼이 44px 이상인지

**두 달 뒤를 미리 본다** — 지금 데이터는 10일치라 두 달 문제가 안 보인다.
0단계와 2-2의 완료 기준은 **60일·90일치를 넣어 확인해야** 판정할 수 있다.
읽기 전용이므로 프로덕션 DB를 건드리지 않고, 목업의 데이터 배열에 60·90일치를 넣어 연다.

**명령으로**

```
cd admin && npm run check   # lint + typecheck + format
npx vitest run              # 지금 115개 + 새로 추가되는 것
npx next build              # 빌드가 되는지
```

**데이터로** — 세션 퍼널의 다섯 갈래 합이 노출 세션 수와 같은지 DB에서 직접 대조한다.
`admin/.env.local`의 읽기 전용 계정으로 확인하고, 결과를 화면 숫자와 나란히 놓는다.

## 체크 (계획이 통과해야 하는 3가지)

- [x] **핵심 기능이 첫 단계인가?** — 원래 물음("몇 개를 봤고 찜했고 나갔나")에 직접 답하는
      세션 퍼널이 1단계다. KPI 띠·꾸미기는 2단계로 미뤘다.
      0단계가 앞에 있는 이유는 기능이 아니라 **정본을 고치는 일**이기 때문이다 —
      결함이 남은 목업을 베끼면 같은 결함이 코드로 들어간다.
- [x] **바로 확인 가능한 크기인가?** — 단계마다 화면에서 눈으로 확인된다.
      1단계만 해도 배포 가능하다(나머지 카드는 표인 채로 남는다).
- [x] **완료 기준이 「X를 하면 Y가 보인다」인가?** — 모든 단계 끝에 관찰 가능한 결과가 있다.
      "구현 완료" 같은 표현은 쓰지 않았다.

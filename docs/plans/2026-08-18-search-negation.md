# 검색 — LLM이 부정과 의도를 읽는다

**조각 범위**: 질의 해석만. 순위식·후보 자격은 [앞 조각](2026-08-17-search-soft-text-scoring.md)에서 끝났다.

## 왜

두 계열이 남았고, **둘 다 카탈로그 값은 있는데 질의를 못 읽어서** 못 푼다.

**① 부정(G5) — 0건율은 0%인데 P@20은 10.6%다.** 결과를 주기 시작했을 뿐 답을 주지 못한다.
실측(2026-08-18):

| 질의 | 결과 | **아는 위반** |
|---|---:|---:|
| `로고 없는 무지 반팔티` | 20 | **20** |
| `프린트 없는 검정 반팔` | 20 | **20** |
| `브이넥 말고 라운드넥 반팔` | 20 | **15** |

`로고 없는`을 검색하면 **상위 20개가 전부 로고 상품**이다.

**② TPO·활동·체형(R1) — 측정조차 안 하고 있었다.** `골프칠때 입을건데 시원한` ·
`요가할때 하늘하늘한 땀흡수` · `바다에서 비키니 위에 입을 얇은` · `팔뚝살 커버` 같은
16개 질의다. 설계 S-08이 게이트에서 뺐고 나는 8단계에서 141건을 채점하지 않았다.
지금 R1이 P@20 0%로 기록돼 있는데 **그건 품질이 아니라 측정이 없다는 뜻이다.**

## 사람이 정한 것 (2026-08-18)

| 질문 | 결정 | 기록 |
|---|---|---|
| R1을 어떻게 하나 | **목표 계열로 올린다** | O-33 |
| 부정을 규칙으로 먼저 하나 | **LLM으로 함께 한다** | O-34 |
| 부정 조건의 강도 | **아는 위반만 제외한다.** 값이 null이면 남긴다 | — |
| 어디서 도나 | **Next.js 라우트 핸들러** | — |
| 모델 | **DeepSeek** | 설계 문서 |

⚠️ **O-34의 대가를 적어 둔다.** 규칙 기준선 없이 LLM을 넣으면 **LLM이 얼마나 보태는지
잴 수 없다.** C단계는 그 반대 순서를 썼고, 그래서 "규칙이 여기까지, LLM이 여기부터"를
말할 수 있었다. 이 조각은 그 구분을 포기한다 — 알고 포기한다.

## 막힌 것 — 사람이 해야 한다

**DeepSeek API 키를 발급해 `frontend/.env.local`에 넣어야 한다.** 나는 키를 만들거나
다룰 수 없다. 키 없이는 3단계 이후를 시작할 수 없다.

- 키 이름은 `DEEPSEEK_API_KEY` (⚠️ **`NEXT_PUBLIC_` 접두어를 붙이면 안 된다** — 그러면
  번들에 박혀 브라우저에 노출된다)
- 프로덕션은 Vercel 환경변수에도 같은 이름으로 넣어야 한다
- `.env*`는 `.gitignore` 대상이라 커밋되지 않는다

## 설계가 이미 정해 둔 제약 (지킨다)

- **S-02** — 실시간 LLM은 문장형 질의에만. 결과를 캐시한다. 1~2초 지연 허용.
  **어느 경로에서도 필수가 아니다** — 실패하면 지금 경로로 그대로 돈다.
- **설계 130행** — hard/soft 판정은 **표로 고정**하고 LLM이 그 분류를 바꾸지 못한다.
  **LLM은 값만 채우고 종류는 우리 표가 정한다.**
- **설계 173행** — 정본으로 결정론적으로 뽑을 수 있는 값은 LLM 대상에서 제외한다.
  **색·카테고리·브랜드·가격은 이미 규칙이 뽑는다. LLM에게 다시 묻지 않는다.**
- **환각 차단** — "입력에 근거가 없으면 null"을 강제하고, 표본을 사람이 검수한 뒤 연다.

## 하지 않는 것 (범위 밖)

- **색·카테고리·브랜드·가격 재해석** — 규칙이 이미 한다. LLM에게 넘기면 결정론을 잃는다.
- **카탈로그에 없는 축**(체형·그림 크기·땀흡수) — 값이 없으면 누구도 못 푼다.
- **키워드 질의에 LLM 호출** — S-02. `검정 반팔`은 LLM을 타지 않는다.
- **progress·holdout 채점** — 봉인이 풀린 상태다. dev만 본다.

## 단계

### 1단계 — 질의 해석 결과를 담을 자리를 만든다 (LLM 없이)

**먼저 하는 이유**: LLM이 무엇을 돌려줘야 하는지가 정해져야 프롬프트를 쓸 수 있다.
그리고 이 단계는 **키 없이** 할 수 있다.

무엇을 한다:
- 검색 RPC가 **부정 조건과 속성 조건을 인자로 받게** 한다. 지금은 질의 문자열만 받아
  전부 스스로 파싱한다.
- 조건의 **종류와 가능한 값을 표로 고정한다**(설계 130행). LLM은 이 표 안의 값만 채운다.
- **아는 위반만 제외한다** — 값이 null인 상품은 남긴다. 커버리지 28%짜리 축을 양성
  필터로 쓰면 값 없는 72%가 사라지는데, 부정은 방향이 반대라 그 문제가 없다.
- 앞 조각의 두 갈래(매칭·나머지) **양쪽에 적용한다.** 한쪽만 하면 나머지 갈래로 샌다.

**완료 기준 (관찰 가능)**
- 손으로 `부정: 로고`를 넣어 부르면 `로고 없는 무지 반팔티`의 아는 위반이 **20 → 0**.
- `프린트 없는 검정 반팔` **20 → 0**, `브이넥 말고 라운드넥 반팔` **15 → 0**.
- 조건을 안 넣으면 지금과 **결과가 같다**.
- 페이징 중복 0, 성능이 이전 상한 안.

### 2단계 — 해석 결과를 캐시할 자리를 만든다 (LLM 없이)

무엇을 한다:
- 정규화한 질의 → 해석 결과를 저장한다. 같은 질의는 LLM을 다시 타지 않는다.
- **무엇으로 해석했는지와 모델·프롬프트 버전을 함께 남긴다.** 프롬프트를 고치면 옛
  캐시가 무효가 되는데, 버전이 없으면 그걸 알 수 없다.

**완료 기준 (관찰 가능)**
- 같은 질의를 두 번 부르면 두 번째는 LLM을 타지 않는다(로그로 확인).
- 프롬프트 버전을 올리면 캐시가 무효가 된다.

### 3단계 — LLM에게 묻는다 ⚠️ **API 키가 있어야 시작할 수 있다**

무엇을 한다:
- Next.js 라우트 핸들러에서 DeepSeek을 부른다. **키는 서버에만 둔다.**
- 프롬프트는 **표가 정한 종류와 값 목록만** 고르게 한다. 자유 서술을 받지 않는다.
- **근거가 없으면 null**을 강제한다.
- **실패·지연은 조용히 지금 경로로 떨어진다**(S-02). 타임아웃을 정하고 지킨다.
- **문장형 질의에만 부른다** — 판정 기준(예: 단어 수)을 정해 적는다.

**완료 기준 (관찰 가능)**
- `로고 없는 무지 반팔티` → 부정 `로고`가 나온다.
- `골프칠때 입을건데 이쁘면서 시원한 운동복` → 활동 `골프`, 쿨링 같은 값이 나온다.
- `검정 반팔` → **LLM을 타지 않는다.**
- 키를 지우면 검색이 **지금과 똑같이** 동작한다(필수 경로가 아님을 확인).

### 4단계 — 표본을 사람이 검수한 뒤 연다

무엇을 한다:
- G5·R1 질의 전부와 다른 계열 표본에 대해 LLM 출력을 **사람이 본다.**
- 환각(근거 없는 값)이 있으면 프롬프트를 고치고 다시 본다.

**완료 기준 (관찰 가능)**
- 검수한 질의 수와 환각 건수가 적혀 있다.
- 환각이 남아 있으면 **그 축을 끄고** 왜 껐는지 적는다.

### 5단계 — G5·R1을 채점하고 무엇이 남았는지 적는다

무엇을 한다:
- G5와 **R1(이제 목표 계열)** 을 기준서 §5대로 독립 2회 채점한다.
- **기준서에 R1을 목표 계열로 올린다**(O-33). 종합 계산에 넣는다.
- **오르지 않은 질의를 따로 적는다.** 카탈로그에 축이 없는 것들은 이 조각으로 오르지
  않는 것이 맞다.
- G1~G4가 내려가지 않았는지 확인한다.

**완료 기준 (관찰 가능)**
- G5·R1 P@20이 이전(10.6% / 미측정)과 나란히 적혀 있다.
- 오르지 않은 질의마다 **왜인지**가 한 줄 있다.
- G1~G4가 내려가지 않았다.

## 실행 기록

### 1단계 — 부정 조건을 받는 자리 (2026-08-18)

**완료 기준 판정**

| 기준 | 판정 | 실측 |
|---|---|---|
| `로고 없는 무지 반팔티`의 아는 위반 20 → 0 | ✅ | 결과 수는 20건 유지 |
| `프린트 없는 검정 반팔` 20 → 0 | ✅ | |
| `브이넥 말고 라운드넥 반팔` 15 → 0 | ✅ | |
| 조건을 안 넣으면 결과가 같다 | ✅ | 세 질의의 goods_no 배열이 동일 |
| 페이징 중복 0 | ✅ | 5질의 × 5페이지 = 50건, 중복 0 |
| 성능이 이전 상한 안 | ✅ | 부정 3개 제외 최대 95ms (상한 101ms) |

**위반 플래그를 미리 계산한다.** 후보 행마다 `c_goods`를 조인해 문자열을 검사하면
검색이 느려진다. 위반은 카탈로그가 바뀔 때만 바뀌므로 빌드 때 한 번 계산하고 질의
시에는 배열 겹침만 본다. 226,304개 중 **75,232개(33%)** 가 하나 이상 위반한다.

| 항목 | 위반 상품 | | 항목 | 위반 상품 |
|---|---:|---|---|---:|
| 신축 | 31,895 | | 그래픽 | 9,273 |
| 비침 | 17,910 | | 두꺼움 | 7,073 |
| 로고 | 14,895 | | 프린트 | 3,325 |
| 얇음 | 14,738 | | 레터링 | 2,997 |
| 슬림핏 | 11,882 | | 자수 · 프린팅 · 브이넥 | 2,118 · 1,623 · 1,000 |

**밟은 함정 셋**

**① 행마다 함수를 부르려 했다.** 처음엔 `c_search_negation_violates(goods_no, ...)`를
만들었는데, 후보 한 건마다 조인이 돈다. 플래그 표로 바꿨다.

**② 권한문이 옛 시그니처를 가리켰다.** 인자가 둘 늘었는데 `grant`를 안 고쳐서 적용이
실패했다 — 그대로 뒀으면 **anon이 검색을 아예 못 부른다.** 새 시그니처로 다시 줬다.

**③ 선행 버그를 발견했다.** 4단계 스크립트 편집이 AND 선검사 블록에 카테고리 조건을
**두 번** 넣어 뒀다(무해하지만 지저분). 여기서 함께 지웠다.

**설계 130행을 코드로 강제한다.** 부정 항목은 `c_search_negation_terms`의 **닫힌 집합**
이고, 표에 없는 값을 넘기면 조용히 무시된다(테스트로 고정). LLM은 값만 고르고 새 축을
만들 수 없다.

실 DB 테스트 160 → **169건**, 전체 287건 통과.

### 2단계 — 해석 캐시 (2026-08-18)

**완료 기준 판정**

| 기준 | 판정 | 실측 |
|---|---|---|
| 같은 질의는 두 번 묻지 않는다 | ✅ | `c_search_plan_get`이 캐시된 해석을 돌려주고 조회 수가 쌓인다 |
| 프롬프트 버전을 올리면 캐시가 무효 | ✅ | ver=2·다른 모델로 조회하면 null |

**모델과 프롬프트 버전이 키에 들어간다.** 프롬프트를 고치면 옛 해석은 다른 규칙으로
만들어진 것이라 그대로 쓰면 안 된다. 키에 없으면 "왜 옛날 답이 나오지"를 나중에 알 수 없다.

**⚠️ 쓰기를 anon에 열지 않았다 — 이게 이 단계에서 가장 중요한 판단이다.**

검색 로그(`c_log_search`)는 anon에 열려 있다. 오염돼도 계측만 더러워지기 때문이다.
그런데 이 표는 **다른 사용자의 검색 결과를 바꾼다.** 누구나 `반팔`의 해석을
"로고 제외"로 덮어쓸 수 있으면 그건 결과 조작이다. **값 검증으로는 막을 수 없다** —
검증은 "형식이 맞나"를 보지 "이 질의의 옳은 해석인가"를 보지 못한다.

그래서 읽기만 anon에 열고 쓰기는 서비스 역할만 부른다. 표 직접 조회도 막았다.

값 검증은 그래도 한다. 닫힌 집합(`c_search_negation_terms`·`c_color_groups`)을 벗어난
값이 하나라도 있으면 **통째로** 거절한다 — 일부만 살리면 무엇이 적용됐는지 알 수 없다.

실 DB 테스트 169 → **177건**.

### ⚠️ 3단계에 필요한 것

- **DeepSeek 키** — 있다(`deepseek-v4-flash`, HTTP 200 확인).
- **`SUPABASE_SECRET_KEY`가 `frontend/.env.local`에 없다.** 캐시 쓰기는 서비스 역할만
  할 수 있으므로 라우트 핸들러가 이 키를 써야 한다. `backend/.env.local`에 같은 이름으로
  있다. 없으면 **읽기 캐시만 동작하고 매번 LLM을 부른다** — 기능은 되지만 비싸다.

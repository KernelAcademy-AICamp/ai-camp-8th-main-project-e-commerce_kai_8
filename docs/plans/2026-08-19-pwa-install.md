# 설치 가능한 PWA — 구현 계획

- 작성: 2026-08-19
- 범위 결정(제품 책임자, 2026-08-19): **설치 가능까지만.** 오프라인·푸시는 하지 않는다 — 푸시는 PRD가 가치 검증 후(P1)로 미뤄뒀고, 오프라인은 관리 부담(캐싱 전략·업데이트 배포) 대비 지금 얻는 것이 없다.
- 아이콘 결정(제품 책임자, 2026-08-19): **글자 기반으로 제작.** 디자인 시안이 없으므로 다크 배경에 글자를 얹은 단순한 아이콘을 만들고, 나중에 디자인이 생기면 교체한다.

코드·함수명 없이 **무엇을 / 어떤 순서로 / 무엇이 되면 끝**만 적는다.

## 기존 도구 조사 (만들기 전에 찾아본 기록)

- **서비스 워커 라이브러리(next-pwa·serwist): 기각.** 서비스 워커는 오프라인 범위에서만 필요한데 이번 범위에 오프라인이 없다. Chrome의 설치 조건도 2023년 이후 서비스 워커를 요구하지 않는다(웹 앱 매니페스트 + 아이콘이면 된다).
- **Next.js 내장 매니페스트 지원: 채택.** 프레임워크가 매니페스트 파일을 라우트로 제공하는 기능을 내장하고 있어 외부 의존이 없다.

## 1단계 — 설치 가능 조건을 채운다

**할 일**

1. 앱 아이콘을 만든다 — 다크 배경 + 글자. 설치에 필요한 두 크기(일반·큰 것)와 마스크 대응(안드로이드가 모서리를 깎아도 글자가 잘리지 않게 여백을 둔 것), iOS 홈 화면용까지.
2. 웹 앱 매니페스트를 추가한다 — 앱 이름, 짧은 이름, 시작 주소, **주소창 없는 전체 화면 표시**, 다크 테마·배경색, 아이콘 목록.
3. iOS는 매니페스트만으로 부족하므로 iOS용 메타 정보(홈 화면 아이콘·전체 화면·상태바)를 함께 단다.
4. 테마색을 브라우저 UI에도 알려 설치 전 브라우저 상단색이 앱과 어울리게 한다.

**완료 기준 (눈으로 확인)**

- 브라우저에서 매니페스트 주소를 열면 위 내용이 담긴 응답이 온다.
- 첫 화면의 문서 머리에 매니페스트 연결·iOS 메타·테마색이 들어 있다.
- Chrome 계열 브라우저가 이 사이트를 **설치 가능**으로 판정한다 (설치 아이콘/메뉴가 뜬다).
- 설치해서 열면 **주소창 없이** 앱처럼 뜨고, 아이콘이 깨지지 않는다.
- 아이콘 파일들이 실제로 요청되고 404가 없다.

**미검증으로 남을 수 있는 것**

- 실제 폰(iOS 홈 화면 추가)의 체감 — 시뮬레이터·데스크톱으로 먼저 보고, 실폰 확인은 제품 책임자가 한다(작업 방식 합의).

**검증 기록 (2026-08-19, 로컬 + Aside)**

| 확인한 것 | 결과 |
|---|---|
| 매니페스트 응답 | 200 — 이름·시작 주소·standalone·다크 색·아이콘 3종 |
| 문서 머리 | manifest 연결·apple-touch-icon·capable·상태바·theme-color 모두 있음 |
| 아이콘 요청 | 4파일 모두 200, 404 없음 |
| 빌드 | `/manifest.webmanifest` 라우트가 정적으로 생성됨 |
| 단위 테스트 | 설치 판정 필드·192/512·마스크 대응·색 일치 4건 |

**미검증**: Chrome의 실제 "설치 가능" 판정과 설치 후 주소창 없는 실행 — 설치 프롬프트는 자동화로 띄울 수 없어 배포 후 실기기/브라우저에서 확인해야 한다. 판정 조건(매니페스트+아이콘+standalone+start_url+보안 출처)은 모두 채웠다.

## 이 계획이 하지 않는 것

- 서비스 워커·오프라인 화면·캐싱 — 범위 밖.
- 푸시 알림 — PRD P1, 가치 검증 후.
- 설치 유도 배너·안내 UI — PRD P1(설치 안내 최적화)에 이미 있고, 첫 화면 배너를 방금 없앤 마당에 새 배너를 만들지 않는다.

## 배경 — 무엇이 잘못됐는지 (2026-08-19 실측, 병합된 develop에서 재현)

제보: **홈 → 마이페이지 → 화면 안 뒤로가기 버튼으로 홈 복귀 → 스와이프 뒤로가기 → 홈이 또 나온다.**

```
0. 홈 첫 진입              len=1  path=/    referrer=""
1. 마이페이지 진입          len=2  path=/my  referrer=""
2. 뒤로가기 버튼으로 홈 복귀  len=2  path=/    referrer=""   ← /my 자리가 /로 덮여 [/, /]
   이후 스와이프 뒤로가기    len=2  path=/                  ← 홈이 또 나온다
```

원인은 두 가지이고 뿌리가 같다. **"직전 화면으로 돌아간다"를 뒤로가기가 아닌 방법으로 흉내 냈다.**

- **마이페이지·로그인 화면의 뒤로가기 버튼**은 "앱 안에서 왔는지"를 **참조 주소**로 판단한다. 그런데 이 앱의 화면 이동은 주소만 바꾸는 방식이라 그 값이 **갱신되지 않는다.** 홈 화면에서 띄운 PWA는 처음부터 비어 있다. 그래서 사실상 항상 "밖에서 왔다"로 판정돼, 뒤로 가는 대신 **홈을 현재 자리에 덮어쓴다.** 덮어쓰기는 앞에 있던 홈을 지우지 않으므로 홈이 두 칸이 된다. 왕복할 때마다 한 칸씩 는다.
- **고정 목적지 뒤로가기 화살표**(설정→마이페이지, 개인정보→설정, 보관함→피드)는 화살표 모양이지만 동작이 **새 화면을 쌓는 것**이다. 보관함은 왕복 1회당 두 칸이 쌓인다.

두 번째 것은 "덮어쓰기로 바꾸면 되지 않나" 싶지만 **안 된다.** 직전 화면이 곧 목적지인 흔한 경우에 덮어쓰면 같은 화면이 연달아 두 칸이 된다 — 첫 번째와 똑같은 결함이 된다. 직전 화면으로 가려면 **뒤로가기를 해야 한다.**

## 확정된 결정

- **화살표는 직전 화면으로 되돌아간다** (2026-08-19 제품 책임자).
- 앞 조각에서 세운 원칙을 그대로 쓴다: **판단 근거를 히스토리 항목 자체에 둔다.** 참조 주소처럼 갱신되지 않는 값을 추측에 쓰지 않는다.

## 미정

- **주소로 바로 들어왔을 때 화살표가 갈 곳.** 뒤로 갈 곳이 없으면 라벨이 가리키는 화면으로 보낸다는 것까지는 정했다. 다만 로그인 화면처럼 "원래 하려던 일"이 있는 경우 그 자리로 보낼지는 정하지 않았다.
- **자바스크립트가 꺼진 환경.** 공개 개인정보 처리방침은 구글 심사가 여는 페이지라 화살표가 스크립트 없이도 동작하는 편이 낫다. 그렇게 만들지는 구현 시점에 정한다.

## 이번 조각에서 하지 않는 것

- 상세 오버레이 관련 동작. 앞 조각에서 끝났다.
- 상세 안에서 로그인 화면으로 빠지는 경로가 남기는 항목 — 이 조각의 규칙이 자리 잡은 뒤에 따로 본다.

## 단계

### 1단계 — 앱이 자기가 어디쯤 있는지 안다

화면을 옮길 때마다 그 히스토리 항목에 **이 세션에서 몇 번째 자리인지**를 적어 둔다. 그러면 "뒤로 가면 앱 안에 머무는가, 앱을 떠나는가"를 추측이 아니라 확인으로 답할 수 있다.

앞 조각과 마찬가지로 **라우터가 쓰던 값을 지우지 않고 얹는다.**

**완료 기준 (눈으로 확인)**

- 홈 → 마이페이지 → 설정으로 옮기면 각 항목에 0, 1, 2가 차례로 적혀 있다.
- 뒤로 갔다 앞으로 와도 번호가 다시 매겨지지 않는다(항목마다 처음 정해진 번호를 지킨다).
- 주소로 바로 마이페이지에 들어오면 그 항목이 0이다.
- 기존 화면 이동이 모두 그대로 동작한다.

### 2단계 — 뒤로가기 버튼이 진짜로 뒤로 간다

마이페이지·로그인 화면의 뒤로가기 버튼이 참조 주소를 보지 않고 1단계의 번호를 본다. 앞에 앱 화면이 있으면 **뒤로 가고**, 없으면(첫 자리면) 라벨이 가리키는 화면으로 보낸다.

**완료 기준 (눈으로 확인)**

- **제보된 순서가 재현되지 않는다**: 홈 → 마이페이지 → 뒤로가기 버튼 → 홈. 여기서 스와이프 뒤로가기를 하면 **홈이 다시 나오지 않고** 앱을 떠난다.
- 이 왕복을 세 번 반복해도 히스토리 길이가 늘지 않는다.
- 주소로 마이페이지에 바로 들어와 뒤로가기를 누르면 홈으로 간다(앱 밖으로 나가지 않는다).
- 로그인 화면의 닫기도 같다.

### 3단계 — 고정 목적지 화살표도 되돌아간다

설정→마이페이지, 개인정보→설정, 보관함→피드 화살표가 새로 쌓는 대신 되돌아간다. 직전 화면이 라벨과 다르면(예: 상세에서 보관함으로 들어옴) 그때는 직전 화면으로 간다 — 그것이 앱에서 기대되는 동작이다. 뒤로 갈 곳이 아예 없으면 라벨이 가리키는 화면으로 보낸다.

**완료 기준 (눈으로 확인)**

- 홈 → 보관함 → 화살표 → 홈. **히스토리 길이가 늘지 않는다** (지금은 왕복 1회당 두 칸이 는다).
- 마이페이지 → 설정 → 개인정보 → 화살표 두 번 → 마이페이지. 되짚어 온 만큼만 줄고, 같은 화면이 연달아 나오지 않는다.
- 주소로 개인정보에 바로 들어와 화살표를 누르면 설정으로 간다.

### 4단계 — 쓰지 않게 된 판정 규칙을 지운다

참조 주소로 목적지를 고르던 규칙과 그 테스트를 없앤다. 남겨 두면 다음 사람이 그것이 동작하는 줄 알고 다시 쓴다.

**완료 기준**

- 그 규칙을 부르는 곳이 하나도 없고, 검사(lint·타입·테스트)가 통과한다.

## 되돌리기

화면 쪽 변경만이고 데이터나 서버 계약을 건드리지 않는다. 문제가 생기면 커밋을 되돌리면 이전 동작으로 돌아간다.

**이미 사용자 브라우저에 쌓여 있는 중복 항목은 이 변경으로 사라지지 않는다.** 새 항목이 더 이상 중복되지 않을 뿐이고, 앱을 새로 띄우면 정리된다.

## 검증 방법

- 각 단계의 완료 기준을 **Orca 브라우저로 직접 밟아** 확인하고 히스토리 길이를 함께 기록한다. 눈으로 안 본 것은 "미검증"으로 남긴다.
- **제보된 순서(홈 → 마이페이지 → 뒤로가기 버튼 → 스와이프 뒤로가기)가 홈을 두 번 보여주지 않는다**를 자동 테스트로 고정한다.

## 구현하며 정한 것 (2026-08-19)

- **자리마다 순번을 매기는 방식은 기각했다.** 상세 오버레이가 만드는 항목은 주소가 바뀌지 않아 번호를 못 받는데, 나중에 그 자리로 뒤로 가면 더 큰 번호가 새로 매겨져 깊이가 거꾸로 늘어난다. 대신 **"앱의 첫 자리인가"만 표시한다** — 첫 자리(`root`)면 뒤로 가면 앱을 떠나고, 안쪽(`inner`)이면 앱에 머문다.
- **표시를 모르면 뒤로 가지 않는다.** 모르는 채로 뒤로 가면 앱 밖으로 튕겨 나갈 수 있어 안전한 쪽을 고른다.
- **화살표는 링크(`a`)로 남겼다.** 스크립트가 꺼져도 `href`로 이동은 되어야 한다 — 공개 처리방침은 구글 OAuth 심사가 여는 페이지다. 스크립트가 있으면 눌렀을 때 되돌아간다.
- **돌려보다 찾은 틈**: 첫 자리에서 되돌아갈 곳이 없어 목적지를 대신 열면, 갈아 낀 자리가 `inner`로 표시돼 **거기서 또 화살표를 누르면 앱 밖으로 나갔다.** 갈아 낀 자리도 여전히 첫 칸이므로 `root`로 적도록 고쳤다. 주소로 개인정보에 바로 들어와 화살표를 두 번 누르는 실제 경로다.

**미검증**

- **홈 화면에 설치한 PWA에서의 실제 손가락 제스처.** 데스크톱 브라우저의 뒤로·앞으로로 확인했고 같은 히스토리 이동을 발동하지만, iOS standalone 체감은 실기기 몫이다. (앞 조각의 실기기 확인도 스와이프 단계에서 멈춰 있다 — 미러링이 iOS의 대화형 가장자리 제스처를 재현하지 못한다.)
- **로그인 화면의 닫기.** 마이페이지와 같은 경로를 쓰지만 따로 밟아보지 않았다.

# 계획 — 개인화 1차: 임베딩 구축 + 유사 탐색 UX (설계 0~3단계)

> 상태: 확정 (2026-08-14 제품 책임자 승인) · 작성: 2026-08-14
> 근거: [개인화 알고리즘 설계](../superpowers/specs/2026-08-14-personalization-algorithm-design.md) (Codex 리뷰 v2) · [임베딩 모델 비교](../atee/foundation/embedding-model-bakeoff.md)
> 후속: 설계 4~6단계(행동 신호 수집 → 찜·스타일 탐색 UI → 취향 프로필·포트폴리오 믹스)는 이 계획 완료 후 별도 계획으로 작성한다.

## 배경 (이 repo를 모르는 사람을 위한 설명)

aTee는 티셔츠 22.6만 개를 2열 무한 피드로 탐색하는 PWA다. 지금 피드는 무작위 순서만 지원한다. 개인화의 토대로, 모든 상품 이미지(썸네일 22.6만 + 갤러리 약 70만 = 약 93만 장)를 임베딩 모델(`google/siglip2-base-patch16-256`, 사전 비교로 확정)로 벡터화해 Supabase에 적재하고, "이 이미지와 닮은 상품"을 조회할 수 있게 만든 뒤, 그 첫 사용처로 상세 화면에서 이어지는 유사 상품 탐색을 붙인다. 갤러리 사진이 더 닮았으면 피드 카드에 그 사진을 보여주고, 상세를 열면 해당 슬라이드에서 시작한다.

## 확정된 결정 (설계 문서에서)

- 모델: SigLIP2-Base, 한국어 텍스트 질의 직접 처리 (비교 문서 참고)
- 저장: Supabase Pro(유료 전환) — 정밀 벡터(halfvec) 서버 보관 + 이진 양자화 인덱스로 후보 생성 → 같은 쿼리에서 정밀 재정렬
- 품질 게이트(전체 적재 전 고정): 사람이 고른 정답셋(앵커 30개 + 텍스트 질의 10개)에서 전수 정밀 검색 대비 Recall@30 ≥ 0.9
- 카드 노출·유사 검색 대상은 이미지 유형 분류(착용샷/단품컷/디테일·원단/사이즈표·라벨)에서 착용샷·단품컷만
- 피드에는 상품당 1장(가장 닮은 이미지)만 노출

## 제약

- 로컬 디스크 여유 약 19GB — 93만 장 원본을 전부 저장하면 약 37~56GB로 초과한다. **이미지는 내려받아 크기 측정·임베딩 후 폐기하는 스트리밍 방식**이어야 하며, 중단·재개가 가능해야 한다. 로컬에 남기는 것은 원본 정밀 벡터(float16 기준 약 1.5GB)와 진행 상태뿐이다.
- 무신사 CDN 다운로드 동시성은 기존 배치에서 검증된 수준(동시 24)을 상한으로 한다.
- Supabase Pro 결제는 제품 책임자가 직접 수행한다(사람 작업).

## 범위

### 포함
- 결정 기록·PRD 갱신 (설계 §1의 결정 5개)
- Supabase Pro 전환
- PoC(부분 적재)로 실제 크기·응답시간·재정렬 품질 측정
- 93만 장 임베딩 파이프라인(다운로드+크기 측정+유형·그래픽 분류+임베딩, 스트리밍·재개 가능)
- 벡터·라벨 적재와 "닮은 상품" 조회 통로(읽기 전용)
- 상세 화면에서 이어지는 유사 상품 탐색 UX(매칭 갤러리 사진 카드 + 상세 슬라이드 딥링크)

### 제외 (후속 계획)
- 행동 신호 수집, 찜·`이 스타일로 계속 탐색` UI, 취향 프로필, 포트폴리오 믹스 (설계 4~6단계)
- LLM 자연어 검색 (별도 스펙)
- Gate 1 실험 인프라, 가입·계정

## 단계와 완료 기준

### 0. 문서 정비 + Supabase Pro 전환

결정 기록에 설계 §1의 결정 5개(익명 기기 ID·보조 검색·SigLIP2·갤러리 포함 임베딩·Pro 전환)를 추가하고, PRD의 관련 절(비회원 장기 개인화, Non-goal의 검색, 데이터·플랫폼 제약)을 갱신한다. 제품 책임자가 Supabase를 Pro로 전환한다.

- **완료 기준:** 결정 기록·PRD에서 새 결정을 읽을 수 있고, Supabase 대시보드에 Pro 플랜이 표시된다.

### 1. PoC — 부분 적재로 실측

표본 규모(약 5만 장)의 벡터를 만들어 실제 테이블·인덱스 크기, 유사 검색 응답시간(p50/p95), 이진 후보→정밀 재정렬의 회수율, 필터(WHERE)를 붙였을 때의 반환 부족 여부를 잰다. 인덱스 방식·oversampling 배수는 여기서 실측으로 고른다(특정 방식으로 못박지 않음).

- **완료 기준:** 위 항목이 수치로 적힌 짧은 보고서가 남고, "93만 장 환산 시 저장량·응답시간이 계획 범위(설계 §12) 안"이라는 판단 또는 조정안이 기록된다.

### 2. 임베딩 파이프라인 — 93만 장 전체

스트리밍 파이프라인(내려받기 → 크기 기록 → 임베딩 → 유형·그래픽 분류 → 이미지 폐기)을 만들어 전체를 처리한다. 실패 URL은 상품 API로 갱신을 시도하고, 최종 실패는 집계한다. 이미지 유형 분류는 적재 전 표본 200장을 사람이 판정해 카드 노출 부적합 이미지의 오통과율을 확인하고 임계값을 조정한다. 품질 게이트(Recall@30 ≥ 0.9)를 통과하면 전체를 적재하고, 앱이 읽을 "닮은 상품" 조회 통로(읽기 전용, 기존 뷰·RPC 방식과 동일한 잠금 원칙)를 만든다.

- **완료 기준:** ① 처리 커버리지(성공/실패 수)가 수치로 나오고 ② 품질 게이트 통과 수치가 기록되며 ③ 아무 상품 번호로 "닮은 상품"을 조회하면 착용샷·단품컷만, 상품당 1장씩 나온다. anon 키로 원본 벡터 테이블 직접 조회는 거부된다.

### 3. 유사 탐색 UX — 상세에서 이어지는 닮은 상품

상세 화면에서 아래로 이어지는 탐색(기존 "상세 하단 탐색 이어가기" 자리)을 현재 상품과 닮은 상품으로 채운다. 갤러리 사진이 매칭된 상품은 카드에 그 사진을 보여주고, 탭하면 상세가 해당 슬라이드에서 열린다. 기존 피드·복원 동작(스크롤 위치, 뒤로 가기)은 그대로 유지한다.

- **완료 기준:** Orca 브라우저와 iOS 시뮬레이터에서 — 상세를 열면 하단에 닮은 상품들이 보이고, 그중 갤러리 매칭 카드는 갤러리 사진으로 표시되며, 탭하면 상세가 그 슬라이드에서 시작한다. `npm run check`와 vitest가 통과한다.

## 실행 기록

- **0단계 (2026-08-14):** 결정 기록 O-24~O-28 추가, PRD 0.5 갱신, Supabase Pro 전환 완료(대시보드 확인). 브랜치 `feature/personalization-embedding`.
- **1단계 PoC (2026-08-14):** 썸네일 49,980장(404 실패 2건 — 알려진 썸네일 노화)을 SigLIP2로 임베딩(41분, M1)해 `c_vec_poc`(halfvec 768 + 이진 양자화 HNSW)에 적재. 실측:
  - Recall@30 (전수 정밀 대비): 후보 ×10 = 0.945, **×20 = 0.981(최저 0.833) — 기본 oversampling ×20 채택.** ⚠️ 기본 `ef_search=40`이 후보를 잘라 recall이 0.617에 고정되는 함정 발견 — `hnsw.iterative_scan=relaxed_order` + `ef_search=후보 수` 설정이 필수.
  - 응답시간: p50 33ms / p95 103ms (×20). 성별 필터+iterative scan: recall 0.953, p50 42ms — 후속 자격 필터 가능 확인.
  - 저장량: 5만 행 = 103.6MB(테이블 82.1 + 인덱스 19.9) → **93만 장 환산 약 1.93GB — Pro 8GB 안에서 진행 가능 판단.**
  - PoC 테이블은 본 테이블 적재 시 삭제 예정.

- **2단계 진행 (2026-08-14 밤):** 전체 96만 7,271장(썸네일 226,313 + 갤러리 741,258 — 상품당 평균 3.3장) 배치 가동, 20~22장/초, ETA 약 13시간. 마이그레이션(`c_img_vecs` + `c_similar_page` RPC) 적용. 발견·수정: ① 부분 적재가 인덱스 생성을 조기 실행 → `--final` 플래그로 분리 ② `maintenance_work_mem 512MB`가 인스턴스 공유 메모리 한도 초과(DiskFull) → 128MB ③ 미적재 앵커가 NULL 거리 정렬로 임의 상품을 반환 → 빈 결과 보장.
- **3단계 선행 검증 (2026-08-14 밤):** 부분 적재 11,179장 상태에서 Orca 브라우저로 확인 — 검정 후드 상세 하단에 닮은 후드들만 정렬(60개 중 갤러리 매칭 33개), 매칭 카드가 갤러리 사진으로 표시되고, 탭하면 상세가 해당 슬라이드(2번째)에서 열림. `npm run check`·vitest 49개 통과. iOS 시뮬레이터·전량 데이터 확인은 배치 완료 후.

- 유사 상품 목록의 페이지 크기와 상세 하단 진입 UI 세부 (3단계 구현에서 결정)

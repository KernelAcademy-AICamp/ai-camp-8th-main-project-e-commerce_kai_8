# 계획 — 읽기 전용 뷰 + 피드 실데이터 연결

> 상태: 확정 (2026-08-14 제품 책임자 승인 — 개인화 방향 강조 반영) · 작성: 2026-08-14
> 근거: [카탈로그 감사](../atee/foundation/catalog-audit.md) · [Living PRD §6·§9](../atee/living/prd.md) · [백엔드 README "남은 일"](../../backend/README.md)
> 선행 작업: 데이터 감사(2026-08-14) 완료, 피드·상세 화면 프로토타입(PR #3·#4)은 400개 샘플로 동작 중

## 배경 (이 repo를 모르는 사람을 위한 설명)

aTee 프론트엔드(2열 masonry 무한 피드 + 카드 확대 상세)는 지금까지 로컬 샘플 400개로만 동작했다. 상품 원본은 Supabase `c_goods`(226,320행)에 있지만 보안 잠금(RLS 기본 거부) 상태라 앱이 읽을 수 없다. 이번 작업은 ① 앱이 읽어도 안전한 읽기 전용 통로(뷰)를 만들고 ② 피드가 실제 카탈로그 전체를 무한 탐색하게 연결한다.

## 제품 책임자 결정 사항 (2026-08-14 질문 단계)

- 피드 순서: **무작위, 접속(세션)마다 다르게.** 같은 세션 안에서는 순서가 유지돼 스크롤 복원이 안정적이어야 한다.
- **무작위는 최종 경험이 아니다 (2026-08-14 제품 책임자 강조):** 무작위 다양성 피드는 ① 첫 방문 콜드스타트 ② Gate 1 대조군 ③ 개인화 폴백 용도다. 재방문 사용자의 첫 화면은 장기 취향 기반 추천에 유사·부분 일치·반대 제안이 비율로 섞여야 하며(PRD §7 추천 포트폴리오), 매일 처음부터 취향을 다시 찾게 하지 않는다. 이를 위한 행동 신호 수집·개인화 데이터 설계·비율 믹스가 이 계획 직후의 우선 작업이다.
- 썸네일 크기(카드 영역 예약용): DB·원본 어디에도 없으므로 **전수 1회 배치 측정**으로 확보한다.
- 프론트용 공개(anon) 키: 같은 Supabase 프로젝트를 쓰는 ecommerce repo(`client/.env.local`)의 publishable 키를 재사용한다.
- (앞선 결정) 회원 자격 필터는 성별만 우선, 사이즈·가격 신선도는 나중에. 노출 조건은 감사 보고서의 조건 A(썸네일·가격·제목 보유) 기준.

## 범위

### 포함

- 22.6만 썸네일의 가로·세로 크기 배치 측정과 `c_goods` 열 추가 (추가 용량 약 2MB)
- 노출 조건을 내장한 읽기 전용 뷰 + anon 읽기 권한 (뷰 외 테이블은 계속 차단)
- 프론트 data 레이어를 샘플 → Supabase 뷰로 교체 (무한 스크롤 페이지 단위 로드)
- 접속마다 다른 무작위 순서 + 세션 내 순서 유지(스크롤·상세 복원 동작 보존)
- 로컬·Vercel 환경변수 반영과 실데이터 동작 확인

### 제외

- 개인화·추천 (열 정리 포함 — 개인화 데이터 설계 후 별도 작업)
- 성별 필터 UI (회원 기능과 함께)
- 가격·판매 상태 재수집 (테스트 직전 별도 실행하기로 결정됨)
- 찜, `이 스타일로 계속 탐색`

## 단계와 완료 기준

### 1. 썸네일 크기 배치 측정 → 열 추가

22.6만 썸네일의 이미지 헤더만 받아 가로·세로를 재고 `c_goods`에 저장한다. 수집 때 확인된 안전선(동시 6)을 지키며, 중단·재개가 가능해야 한다. 소요는 수 시간 — 백그라운드로 돌리고 다음 단계와 병행한다.

- **완료 기준:** 크기 보유율이 수치로 나오고(측정 실패 상품 수 포함), 무작위 표본 몇 개의 저장값이 실제 이미지 크기와 일치한다. 측정 실패 상품의 처리 방침(제외 또는 기본 비율)이 기록된다.

### 2. 읽기 전용 뷰 + 권한

노출 컬럼(상품 번호·제목·브랜드·가격·썸네일·성별·갤러리·이미지 크기)만 담고, 노출 조건(썸네일·가격·제목 보유)을 내장한 뷰를 만든다. anon 클라이언트는 이 뷰만 읽을 수 있고 `c_goods` 원본은 계속 거부된다. 무작위 순서 제공 방식은 특정 구현으로 못박지 않는다(뷰에 준비를 포함할지, 조회 쿼리에서 해결할지는 구현에서 선택).

- **완료 기준:** anon 키로 뷰를 조회하면 상품이 나오고, 같은 키로 `c_goods`를 직접 조회하면 거부된다. 뷰의 상품 수가 감사 보고서 조건 A 수치와 일치한다.

### 3. 피드 실데이터 연결

프론트 data 레이어를 샘플 로더에서 뷰 조회로 교체한다. 무한 스크롤은 페이지 단위로 이어 받고, 접속마다 다른 무작위 순서·세션 내 고정을 보장한다. 기존 샘플은 테스트용으로 유지한다.

- **완료 기준:** 로컬 실행에서 새로고침할 때마다 다른 상품 구성으로 시작하고, 한 세션에서 계속 스크롤하면 중복 없이 이어지며, 22.6만 규모에서 끊김·레이아웃 이동이 눈에 띄지 않는다.

### 4. 상세·복원 동작 실데이터 확인 + 품질 게이트

카드 탭 → 상세(갤러리 슬라이드) → 판매처 이동 → 복귀 시 스크롤 위치 유지가 실데이터에서 동작하는지 Orca 브라우저와 iOS 시뮬레이터로 확인한다.

- **완료 기준:** 위 흐름이 실데이터로 동작하는 것이 확인되고, `npm run check`와 vitest가 통과한다.

### 5. 배포 반영

프론트 환경변수(공개 URL·publishable 키)를 로컬과 Vercel에 넣고 preview 배포에서 실데이터 피드를 확인한다.

- **완료 기준:** Vercel preview URL을 휴대폰에서 열면 실데이터 무한 피드가 동작한다.

## 실행 기록 (2026-08-14)

- **1단계:** `c_thumb_dims` 테이블(16MB)로 저장 — 계획의 "c_goods 열 추가" 대신 별도 테이블 선택(전 행 UPDATE는 MVCC 부풀림으로 무료 500MB 한도 초과 위험). 226,320개 전수 측정 완료. 파서는 샘플 실측 30건과 전건 일치로 검증. 동시성은 6→24로 상향(대상이 API가 아닌 CDN이라 안전선이 다름 — 스로틀 0건, 4.7배 가속). 일시 오류(429·5xx)는 기록하지 않고 재실행 시 재시도하는 구조.
- **1단계 실패분 재검토 (제품 책임자 요청):** 최초 확정 실패 96건을 재조사 — ① 4건은 일시 오류가 잘못 굳은 것(재측정으로 복구) ② 92건은 썸네일 404였으나 상품은 유효 — 무신사가 이미지 경로를 교체한 것. 상품 API에서 새 URL을 받아 90건 복구(`c_goods.thumbnail` 갱신 후 재측정). **최종 실패는 6건(0.003%)** — 새 URL조차 죽어 있어 PRD 원칙(무효 이미지 제외)대로 노출 제외 유지. 교훈: 썸네일 URL도 낡는다 — 가격 재수집 때 썸네일 URL 갱신을 함께 한다.
- **2단계:** `c_feed_products` 뷰 + `c_feed_page` RPC. anon은 뷰·RPC만 접근 가능, 원본 직접 조회 거부 확인. **뷰 상품 수 226,313 = 감사 조건 A 226,319 − 최종 실패 6 (정확히 일치).** 무작위 정렬은 처음 md5 문자열 해시(전체 규모에서 1.1s/페이지)에서 `hashint8extended` 정수 해시로 교체 — 페이지당 ~70ms.
- **3단계(미정 항목 확정):** 무작위 구현 = 서버 해시 정렬(시드는 클라이언트가 세션당 1회 생성해 sessionStorage 유지), 페이지 크기 = 30, 측정 실패 96개 = 뷰에서 제외. 커서는 마지막 goods_no의 (해시, 번호) 키셋 — 중복 없음 검증.
- **4단계:** Orca 브라우저 — 실데이터 렌더, 무한 스크롤 150개, 상세(갤러리 슬라이드·판매처 링크), 뒤로가기 후 scrollY 정확 복원, 새 탭=다른 순서, 새로고침=시드 유지 확인. iPhone 17 Pro 시뮬레이터 — 실데이터 피드 렌더 확인. `npm run check`·vitest 23개 통과.
- **5단계:** Vercel 환경변수 2종을 production·preview·development에 등록. PR 없이 CLI(`vercel deploy`)로 preview를 만들어 확인 — 실데이터 피드 렌더·무한 스크롤(30→60개) 동작. preview URL은 Vercel 배포 보호(SSO)가 걸려 있어 소유자 로그인 브라우저에서만 열린다.

## 이 계획이 끝나면

- 피드가 400개 샘플이 아니라 실제 카탈로그 22.6만 개로 동작한다 — Gate 0 상호작용 항목("무한 스크롤이 끊김 없이", "복귀 후 위치 유지")을 실데이터로 확인할 수 있다.
- 백엔드 "남은 일"이었던 읽기 전용 뷰가 완료된다.
- 다음 우선 작업(제품 책임자 방향, 2026-08-14): ① 행동 신호 수집(노출·탭·찜·판매처 이동 이벤트) ② 개인화 데이터 설계(유사도·반대 제안 계산 축 확정 — 보류된 열 정리 결정 포함) ③ 추천 포트폴리오 비율 믹스 1차. 사용성 테스트 준비(Gate 0 기준 문서화)는 병행 후보.

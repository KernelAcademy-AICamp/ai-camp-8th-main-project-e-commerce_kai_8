# 검색 성능 합격 상한

> 확정: 2026-08-17 · 계획: [A단계](../../plans/2026-08-17-search-korean-index.md) 0단계
> 설계 §10이 "아직 게이트가 아니다"라고 남긴 것을 여기서 닫는다.
> **이 문서 없이 색인 작업을 시작하지 않는다** — 상한을 나중에 정하면 공유 DB에 안 맞는다는 사실이 너무 늦게 드러난다.

## 지금 값 (비교 기준)

| | 값 |
|---|---|
| 현행 검색 웜 p50 | **75ms** |
| 현행 검색 웜 p95 | **385ms** |
| 현행 검색 최악 | 874ms |
| 검색 텍스트 크기 | 28MB / 226,304행 |
| anon SQL 제한 (서버 고정) | **8초** |
| 벡터 경로 동시 4요청 (기존 실측) | 각 **16~18초 — 이미 한계 초과** |

측정: `c_search_page` 5개 질의 × 3회, 웜 상태. 지금 검색은 좁은 테이블 전체 스캔이라 빠르지만, **그 대가로 아무것도 못 찾는다**(기준선 종합 27.8%).

## 합격 상한

| 항목 | 상한 | 근거 |
|---|---|---|
| **텍스트 갈래 웜 p50** | ≤ 300ms | 현행 75ms의 4배까지 허용. 색인이 붙으면 느려질 수 있지만 체감 한계 안 |
| **텍스트 갈래 웜 p95** | ≤ 1,000ms | 현행 385ms의 2.6배. 플로팅 검색은 제출 후 결과라 1초가 체감 상한 |
| **전체 응답 p95** (프론트 기준) | ≤ 1,500ms | 위 + 네트워크·직렬화 여유 |
| **콜드 p95** | ≤ 3,000ms | 캐시가 식은 첫 질의. 8초 제한의 절반 이하로 둔다 |
| **동시 4요청에서 각 p95** | ≤ 3,000ms | 벡터 경로가 여기서 16~18초로 무너졌다. 텍스트 갈래는 이 선을 지켜야 B에서 갈래를 합칠 수 있다 |
| **timeout·폴백 발생률** | ≤ 1% | 정상 부하에서 |
| **temp spill** | 0 | 발생하면 work_mem 밖으로 나간 것 — 공유 DB에 위험 |
| **색인 크기** | ≤ 500MB | 현행 검색 텍스트 28MB 대비. 넘으면 공유 DB 저장소 압박 |

## 실측 결과 (2026-08-17, A단계 `c_search_page_v2`)

| 항목 | 상한 | 실측 | 판정 |
|---|---|---|---|
| 텍스트 갈래 웜 p50 | ≤ 300ms | **12ms** | ✅ |
| 텍스트 갈래 웜 p95 | ≤ 1,000ms | **92ms** | ✅ |
| 콜드 p95 | ≤ 3,000ms | **236ms** | ✅ |
| 동시 4요청 각 p95 | ≤ 3,000ms | **최대 330ms** | ✅ |
| 색인 크기 | ≤ 500MB | **77MB**(테이블+색인) · DB 총 +242MB | ✅ |
| 전체 응답 p95 (프론트) | ≤ 1,500ms | **미측정** | ⏳ 클라이언트 전환(4-1) 후 |
| timeout·폴백 발생률 | ≤ 1% | **미측정** | ⏳ 위와 같음 |
| temp spill | 0 | **미측정** | ⏳ |

**측정 한계 (정직하게 적는다)**: 문서의 "콜드" 정의는 각 질의의 첫 회를 뜻하며, `DISCARD ALL`은 세션 상태만 버리고 **PostgreSQL shared buffers나 PGroonga 캐시를 비우지 않는다.** 공유 DB라 강제로 비울 수도 없다. 따라서 위 콜드 수치는 "캐시가 완전히 식은 상태"가 아니라 "이 세션에서 처음"이다.

**아직 닫히지 않은 게이트가 3개 있다.** 프론트 전체 지연·폴백률은 클라이언트 전환 전에는 측정할 수 없고, temp spill은 EXPLAIN 계측이 더 필요하다. **성능 게이트 전체 통과를 주장할 수 없다** — 통과한 5개만 표시한다.

## 미달이면 무엇을 하나

순서대로 시도하고, **결정과 근거를 A단계 실행 기록에 남긴다.**

1. **토크나이저를 바꾼다** — 형태소 ↔ n-gram. n-gram은 색인이 크고 느리지만 사전이 필요 없다.
2. **색인 대상 필드를 줄인다** — 확장어·태그를 빼고 브랜드·제목만 남긴다.
3. **컴퓨트를 올린다** — Micro → 상위. 공유 DB라 ecommerce에도 이득이지만 비용이 는다. **사람 승인 필요.**
4. **되돌린다** — 색인을 지우고 현행 검색을 유지한다. 확장은 남긴다(다른 곳이 쓸 수 있으므로 삭제하지 않는다).

**세 번째까지 갔는데도 안 되면 A단계를 중단하고 B(벡터)로 우회할지 다시 판단한다.** 텍스트 색인이 공유 DB에 안 맞는다는 뜻이기 때문이다.

## 측정 방법

- 웜: 같은 질의를 3회 이상 돌려 첫 회를 버린다.
- 콜드: `discard all` 후 첫 질의. 공유 DB라 버퍼를 강제로 비우지는 않는다.
- 동시: 4개 세션에서 같은 시각에 서로 다른 질의를 던진다.
- 질의는 **개발셋에서** 뽑는다(진행셋·홀드아웃을 성능 측정에 쓰지 않는다 — 열람 규칙).

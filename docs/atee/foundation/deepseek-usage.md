# DeepSeek 사용 정보 — ecommerce에서 이식

> 작성: 2026-08-17 · 출처: `ecommerce`(search-by-llm) 프로젝트에서 실제로 돌고 있는 구현을 읽고 정리
> 쓰는 곳: [검색 업그레이드 설계](../../superpowers/specs/2026-08-17-search-upgrade-design.md) §6 C2(오프라인 배치) · §7 D(질의 이해)
> 이 문서는 **정보 이식**이다. 코드는 옮기지 않았다 — 어휘·도메인이 달라 그대로 쓸 수 없고(§5), 우리 D단계는 A·B 뒤 조건부이기 때문이다.

## 1. ecommerce가 실제로 쓰는 구성

LLM을 쓰는 모듈이 셋이고 **전부 OpenAI 호환 chat completions**를 직접 `fetch`로 호출한다(SDK 없음).

| 모듈 | 기본 엔드포인트 | 기본 모델 | 하는 일 |
|---|---|---|---|
| `parse-query-intent.ts` | NVIDIA `integrate.api.nvidia.com/v1` | `meta/llama-3.1-8b-instruct` | 자연어 → 구조화 `QueryIntent` |
| `relation-linker.ts` | **`https://api.deepseek.com`** | **`deepseek-v4-flash`** | 의미 링커 |
| `interpret-semantic.ts` | 위 env 공용 | 위 env 공용 | 의미 해석 |

**주의 — 이름이 오해를 부른다.** 환경변수가 `NVIDIA_API_KEY` / `NVIDIA_BASE_URL` / `NVIDIA_MODEL`인데, 이건 **범용 LLM 엔드포인트 변수로 재사용**되는 것이지 NVIDIA 전용이 아니다. `relation-linker.ts`는 같은 변수로 DeepSeek을 부른다. `client/.env.example`의 현재 값은 `NVIDIA_MODEL=qwen/qwen3-next-80b-a3b-instruct`다.

**즉 "ecommerce = DeepSeek 검색"이 아니다.** DeepSeek은 의미 링커의 기본값이고, 질의 파서의 골든셋(250건)에서는 **모델 A/B 비교 기준**으로 쓰였다(`parser-golden.json` meta: `"deepseek-v4-flash 기준(모델 A/B 비교에도 사용)"`).

**우리는 변수 이름을 목적에 맞게 새로 짓는다** — 남의 벤더 이름을 물려받지 않는다. 키는 서버 전용이고 저장소에 커밋하지 않는다.

## 2. 반드시 알아야 할 운영 함정 — thinking 모드

세 모듈 모두 같은 분기를 갖고 있고, 주석에 이유가 적혀 있다.

> **DeepSeek V4 계열은 기본 thinking 모드가 켜져 있어 `max_tokens`를 추론에 소진하고 `content`가 비는 문제가 있다** — 파싱·번역류 작업이라 비추론 모드로 고정.

→ 모델명에 `deepseek`가 들어가면 요청 본문에 **`thinking: { type: "disabled" }`** 를 넣는다. 이걸 빼면 **오류 없이 빈 응답**이 온다. 우리 C2 배치처럼 22.6만 건을 돌리는 작업에서 이걸 모르면 비용만 쓰고 결과가 안 나온다.

그 밖의 호출 파라미터: `temperature: 0`, `max_tokens: 400`(파서 기준), 메시지는 system(스키마+어휘) + user(질의 원문).

## 3. 출력 신뢰 구조 — enum 주입 → 추출 → drop → 안전 강등

우리 설계 §7 D의 "LLM 출력을 신뢰하지 않는다"가 여기서는 이미 구현돼 있다. 그대로 채택한다.

1. **enum 주입** — 허용 어휘(색·패턴·소재·핏·착용감·리뷰태그)를 시스템 프롬프트에 **목록으로 박아 넣는다.** "목록에서만 고르라"고 지시한다.
2. **JSON만 출력** — "설명·코드펜스 없이 JSON 객체 하나만".
3. **관대한 추출** — 그래도 코드펜스가 섞여 올 수 있으므로 응답에서 `{...}` 구간을 정규식으로 뽑아 파싱한다. 실패하면 null.
4. **validate-drop** — 파싱된 값을 어휘 목록과 대조해 **목록 밖 값은 조용히 버린다.** 숫자는 범위·정수 검증. 즉 LLM이 무엇을 뱉든 우리가 아는 값만 남는다.
5. **안전 강등** — 키 없음 / HTTP 실패 / 파싱 실패 / 예외 **전부** 빈 의도 + `degraded: true`로 반환한다. **예외를 던지지 않는다.** 검색은 LLM 없이도 계속 돈다.

이 구조가 우리 설계의 "LLM은 어느 경로에서도 필수가 아니다"(§5.6)와 정확히 같은 계약이다.

## 4. 실측으로 얻은 프롬프트 설계 교훈

코드 주석에 근거 수치까지 남아 있다. **백지에서 다시 시행착오할 필요가 없다.**

1. **통제 어휘를 수기로 나열하지 말고 어휘 목록에서 구조를 파생 생성하라.** 색을 평평하게 나열하면 "계열을 어디까지 확장할지"가 모델 재량으로 남아 **같은 질의가 호출마다 다른 집합을 낸다**(실측 15회 중 5회 불안정). ecommerce는 색 이름의 접미 관계와 톤 접두(`라이트`·`다크`·`연`·`진`·`중`)로 계열 트리를 코드에서 만들어 넣는다 — 어휘가 바뀌면 프롬프트가 자동으로 따라간다.
2. **근사 지침은 전역 규칙이 아니라 해당 블록 안에 둬라.** 근사 지시를 전역 규칙 섹션에 놓았더니 가격·성별·핏이 주의를 뺏겨 정확도가 떨어졌다 — **250건 실측에서 가격 정확도 100% → 86%, 방향 뒤집힘 5건 → 10건.**
3. **"환각 금지"와 "근사 매핑"은 충돌하므로 명시적으로 갈라줘라.** 지시가 없으면 환각 금지가 이겨서 어휘 밖 색(터콰이즈·건메탈·먹색)이 빈손이 된다. ecommerce는 이렇게 적었다: *"목록 밖 값 금지"는 목록에 없는 이름을 새로 만들지 말라는 뜻이지 근사하지 말라는 뜻이 아니다.*
4. **가격 방향은 자주 틀리므로 경고를 박아라.** `"N원 이하"`를 `priceMin`에 넣는 실수가 잦아 프롬프트에 ⚠️ 표시와 예시를 명시했다. 우리 평가셋 `g16`(`블랙 오버핏 반팔티 3만원 이하`)이 정확히 이 케이스다.
5. **일반어를 키워드에서 빼라.** `티`·`반팔`·`티셔츠`·`옷`·`상의` 같은 카테고리어가 키워드로 들어가면 전 카탈로그가 매칭된다.
6. **추측 금지 축을 명시하라.** "두꺼운·부드러운·오버핏만 보고 계절을 추측해 넣지 마라" 같은 지시가 없으면 없는 조건을 만들어낸다.

## 5. 우리가 그대로 못 쓰는 것

- **통제 어휘가 다르다.** ecommerce는 자체 vocab(`COLORS`·`PATTERNS`·`MATERIALS`·`FITS`·`REVIEW_TAGS` 89종·`WEAR_CHARS_VOCAB`)을 쓴다. 우리는 무신사 공식 54색 정본(`c_color_groups`)·`tags`·`base_cat`·착용감 6축이 재료다. **enum 주입 대상 목록을 우리 것으로 바꿔야 한다.**
- **출력 스키마가 다르다.** ecommerce의 `QueryIntent`는 그 제품의 필터 UI와 DB 스키마에 맞춰져 있다. 우리는 설계 §5.3의 **hard/soft 구분**이 스키마에 들어가야 한다(ecommerce에는 `promote`/`exclude`가 그 역할을 일부 한다 — 참고할 만하다).
- **리뷰 태그 89종**은 ecommerce의 `m_*` 테이블 자산이다. 우리 `c_goods.ai_summary`에 대응물이 있는지 미확인(설계 §11 미정 7).

## 6. 비용 (2026-08-17 공식 가격표 확인)

peak/off-peak 시간대 요금제다. **peak = 01:00–04:00, 06:00–10:00 UTC**(한국시간 10–13시·15–19시), 나머지는 off-peak이고 off-peak가 절반이다.

| 모델 | 캐시 히트 | 캐시 미스 | 출력 |
|---|---|---|---|
| `deepseek-v4-flash` (off-peak) | $0.007 | $0.22 | $0.66 |
| `deepseek-v4-flash` (peak) | $0.014 | $0.44 | $1.32 |
| `deepseek-v4-pro` (off-peak) | $0.022 | $0.66 | $1.98 |

1M 토큰당. 캐시 히트는 미스의 약 1/31이다. **C2 배치는 off-peak 시간대에 돌리고, 시스템 프롬프트(어휘 목록이라 길다)를 캐싱 대상으로 고정한다.**

## 7. 우리 프로젝트에서 쓸 곳

| 단계 | 용도 | 이식 대상 |
|---|---|---|

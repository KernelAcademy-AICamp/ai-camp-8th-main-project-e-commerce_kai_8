## 1. 세션 정의

아래 중 **하나라도** 해당하면 새 세션을 시작한다.

| 계기 | 조건 |
|---|---|
| 활동 없음 | 마지막 계측 활동 후 **30분 초과** |
| 백그라운드 복귀 | 앱이 백그라운드에 들어간 후 **5분 이상** 지나 복귀 |
| 신원 변경 | **로그인 · 로그아웃 · 계정 변경** |

- **정확히 30분은 기존 세션이다.** 초과여야 새 세션이다.
- **백그라운드는 정확히 5분이어도 새 세션이다.** 30분과 반대로 "이상" 기준이다.
- **기기 ID는 세션이 바뀌어도 유지한다.**

### 왜 백그라운드 5분인가 (2026-08-24 결정)

**모바일 앱의 업계 관행이다.** 웹은 무활동 30분을 쓰고, 앱은 백그라운드 5분 무이벤트를 쓴다.
aTee는 PWA지만 사용자가 만나는 형태는 모바일 앱이므로 앱 관행을 따른다.

30분 규칙만으로는 안 되는 이유가 있다. 앱을 백그라운드로 보내면 아무 기록도 안 생기므로,
20분 뒤에 돌아와도 마지막 기록으로부터 20분밖에 안 지나 같은 방문으로 이어진다. 그러면
8분 본 사람이 28분 본 것으로 나온다.

> **정확한 값은 아직 실측하지 않았다.** 3분이나 10분이어도 되고, 데이터가 쌓이면 백그라운드
> 이탈 시간의 분포를 보고 다시 정할 수 있다. 짧은 알림 확인과 진짜 이탈이 갈리는 지점이 있을
> 것이다. 지금은 관행값을 쓴다.

### 세션 길이 — 나가 있던 시간은 뺀다 (2026-08-24 결정)

**두 값을 따로 낸다.**

| 값 | 계산 |
|---|---|
| **전체 길이** | 첫 기록부터 마지막 기록까지 |
| **실제 탐색 시간** | 전체 길이 − 그 세션에서 백그라운드에 있던 시간의 합 |

5분 넘게 나가면 세션이 갈리지만, **5분이 안 되는 이탈은 여전히 한 세션 안에 남는다.**
4분 나갔다 오면 그 4분이 전체 길이에 그대로 들어간다. 그래서 나가 있던 시간을 **누적해서**
세션에 함께 기록하고, 화면에서 빼서 보여준다.

**이 결정 전에는 반대로 적혀 있었다.** "길이에 자리 비운 시간이 포함되니 몰입도로 읽지 말라"는
단서를 달아두는 방식이었다. 이제 단서 대신 값을 나눈다.

## 2. 세션 구분 — 관찰(observed) / 자발(organic)

세션마다 둘 중 하나를 기록한다.

| 값 | 언제 |
|---|---|
| `observed` | **연구용 전용 링크나 코드**로 시작한 세션 |
| `organic` | 그 외 전부 |

**계정에 영구적으로 붙이지 않는다. 세션마다 판정한다.** 같은 사람이 인터뷰 때는 `observed`, 다음 날 혼자 열면 `organic`이다.

이 구분이 없으면 **우리가 불러서 만든 방문을 자발 방문으로 세게 된다**(§7 습관 지표).

## 3. 이벤트 정의

세션당 아래 넷을 측정한다.

| 지표 | 세는 단위 |
|---|---|
| **본 상품 수** | 노출된 **고유 상품 수** |
| **상세를 본 상품 수** | 상세를 연 **고유 상품 수** |
| **찜 수** | 찜 버튼을 누른 **시도 횟수** |
| **아웃바운드 수** | 판매처 이동 **클릭 횟수** |

앞의 둘은 **고유 상품 수**, 뒤의 둘은 **횟수**다. 노출·상세는 "얼마나 많은 티셔츠를 만났나"가 질문이고, 찜·이동은 "몇 번 행동했나"가 질문이라 단위가 다르다.

**노출 중복은 수집 단계에서 거른다**(2026-08-25 결정). 같은 세션에서 같은 상품이 다시 화면에 들어와도 보내지 않는다. 전에는 발생 횟수도 함께 받아 "되돌아본 정도"를 보려 했는데, 그 숫자로는 추천이 좋은지 나쁜지 가릴 수 없었다 — 스크롤을 위아래로 하면 그냥 늘어난다. 그리고 그 중복이 전체 노출의 13.4%였고 노출이 전체 이벤트의 95%라 요청 부담이 컸다. 세션이 바뀌면 다시 센다.

### 찜 저장 실패

**찜 시도를 취소하지 않는다.** 별도 오류 이벤트로 남긴다.

> 찜 시도 1회 **＋** 저장 실패 1회

실패했다고 시도를 지우면 **"찜하려 했는데 안 됐다"가 통째로 사라져**, 제품이 멀쩡한 것처럼 보인다.

## 4. 기기와 계정 연결

**모든 행동에 기기 ID를 유지한다.**

| | 기기 ID | 계정 ID |
|---|---|---|
| 비회원 행동 | 있음 | **없음** |
| 회원 행동 | 있음 | 있음 (**서버가 확인한 값**) |

- **로그인 전 기록에 계정 ID를 소급해서 채우지 않는다.**
- **로그인 이후에는 새 세션을 시작한다**(§1).
- **클라이언트가 보낸 계정 ID를 그대로 믿지 않는다.** 서버 인증값으로 판정한다.

### 왜 소급하지 않는가

기존 익명 기록만 보고 **"이 기기가 지금 로그인한 사람의 과거 행동이었다"고 확정할 수 없기 때문이다.** 한 기기를 여러 사람이 쓸 수 있다. 그래서 **기존 행을 수정하지 않는다.**

## 5. 비회원 → 회원 전환

### 비회원에게도 계측하는 것

| 묶음 | 이벤트 |
|---|---|
| 탐색 | 상품 노출 · 상세 열기 · 찜 의도 · 판매처 이동 |
| 로그인 퍼널 | 로그인 화면 노출 · 로그인 버튼 클릭 · 로그인 **성공 / 실패 / 취소** |
| 로그인 맥락 | **신규 가입인지 기존 회원 로그인인지** · **로그인 유도 출처** |

### 연결 기록

**로그인 성공 시점에만** 아래 연결을 만든다.

> 비회원 세션 ↔ 기기 ↔ 로그인한 계정

**이 연결은 전환 분석에만 쓴다.** 비회원 행동을 **회원의 취향 프로필이나 추천 학습 데이터로 가져오지 않는다.**

### ⚠️ 발생 시점의 로그인 상태를 보존한다

**로그인 전에 대기열에 들어간 이벤트가 로그인 후에 전송되더라도 비회원 이벤트로 남아야 한다.**

전송 시점이 아니라 **발생 시점**의 상태가 진실이다. 이걸 놓치면 로그인 직전의 탐색이 회원 행동으로 둔갑해 전환 분석이 통째로 틀어진다.

## 7. 분석 지표

### 대표값

**표본이 작으므로 평균을 대표값으로 쓰지 않는다.**

| 역할 | 값 |
|---|---|
| **대표값** | **중앙값** |
| 함께 표시 | **사분위 범위** |
| 원본 확인 | **세션 하나당 점 하나인 분포** |
| 참고값 | 평균 |

**사분위는 연속 백분위수로 계산한다**(2026-08-21 결정). Postgres `percentile_cont`가 그대로 지원해 질의와 화면이 갈라질 여지가 가장 작다. 방식을 정하지 않으면 같은 34개 표본에서 21.25–43.25 / 21–41 / 20.5–44.75로 **셋 다 다른 답**이 나온다.

**같은 값을 두 곳에 손으로 적지 않는다.** 합계·중앙값·사분위·비율은 전부 원본에서 계산하고, 질의에 **숫자 계약 테스트**를 둔다. 목업에서도 마찬가지다 — 실제로 목업의 요약 숫자와 원본 배열이 어긋나 검토에서 다섯 건이 잡혔다.

### 행동률 — 세션 단위로 센다

| 지표 | 계산 |
|---|---|
| **상세 세션률** | 상세를 1번 이상 연 세션 ÷ **노출이 있는 세션** |
| **찜 세션률** | 찜을 1번 이상 시도한 세션 ÷ **상세를 연 세션** |
| **아웃바운드 세션률** | 판매처 이동이 있는 세션 ÷ **상세를 연 세션** |

분모가 상품 수가 아니라 **세션 수**다. 표본이 작을 때 한 세션의 폭주가 비율을 지배하는 것을 막는다.

**기본은 자발 세션만이다**(2026-08-21 결정). 관찰 세션을 섞으면 우리가 옆에서 시켜 만든 행동이 들어가 **실제 자발 사용보다 좋아 보인다.** 필요할 때 필터로 관찰을 포함해 본다.

### 추천 유형별 성과

**상세를 연 (상품, 세션) 쌍 ÷ 노출된 (상품, 세션) 쌍.** 분자·분모를 **둘 다 화면에 적는다.**

중복 제거 기준을 (상품, 세션) 쌍으로 못 박는 이유는, 같은 세션에서 같은 상품이 여러 번 노출되면 분모만 부풀어 전환율이 내려가기 때문이다.

### 직선 퍼널 금지

**찜과 아웃바운드는 상세 이후 갈라지는 행동이다.** 노출 → 상세 → 찜 → 이동 형태의 직선 퍼널은 **쓰지 않는다.** 그렇게 그리면 그림이 "찜한 다음 이동한다"는 없는 흐름을 주장한다.

```
노출 ──→ 상세 열기 ──┬──→ 찜
                     └──→ 판매처 이동
```

### 습관 지표

> 2026-08-21에 `measurement-plan.md`를 없애면서 그 문서의 성공 지표 정의를 여기로 옮겼다.

**자발 세션만 센다. 관찰 세션은 제외한다.** 우리가 불러서 만든 방문을 자발 방문으로 세면 안 된다.

| 용어 | 정의 |
|---|---|
| **유효 탐색** | 상품을 **1개 이상 연** 날. 스크롤만 한 방문은 세지 않는다 |
| **7일 구간** | 달력 주가 아니라 **각 참가자의 첫 경험일부터** 7일씩 |
| **2일** | **서로 다른 2일.** 같은 날 두 번 열면 1일이다 |

**3주 동안 "유효 탐색을 1주에 2일 이상 한 주"가 몇 개인가**로 단계를 나눈다.

| 단계 | 조건 |
|---|---|
| **① 습관 시작** | 유효 탐색을 1주에 2일 이상 |
| **② 습관 형성 중** | 그런 주가 **2번 이상** |
| **③ 습관 강화** | **3주 내내** 주 2일 이상 |

**왜 주 2일인가** — 반복이 습관의 기제이기 때문이다. 원문을 확인한 정의가 *"Habit develops when a behaviour is repeated in a consistent context"* 다 (Gardner, Rebar & Lally 2022, *Cogent Psychology* 9:1 — PDF 원문을 직접 대조함). 주 1일은 한 주기 안에서 단발이라 **반복을 관측하는 단위가 되지 못한다.**

**왜 횟수가 아니라 날 수인가** — 같은 날 두 번보다 **다른 날 두 번**이 "일관된 맥락에서의 반복"에 가깝다.

**왜 7일 구간인가** — ⓐ 확인된 자연 사용 주기의 하한(주 1회)과 창을 맞춘다 ⓑ 3주 관측에서 구간이 3개 생겨 **계단(시작→형성→강화)을 만들 수 있다.** 14일 창이면 구간이 하나뿐이라 3단계가 성립하지 않는다.

**왜 첫 경험일 기준인가** — 참가자마다 시작 요일이 다르다. 달력 주로 끊으면 금요일에 시작한 사람의 첫 주가 이틀뿐이라 같은 기준으로 잴 수 없다.

#### ⚠️ 0을 실패로 읽으면 안 된다

습관 성장 곡선의 모양은 **학계에서 합의되지 않았다.** 두 모델 중 한쪽(Fournier 2017)은 **초기 반복의 효과가 미미하다**고 본다. 그 모델이 맞다면 **습관이 결국 형성될 사람에게서도 3주 안에는 아무것도 안 보인다.**

**"습관이 안 생긴다"와 "아직 안 보이는 구간이다"를 이 표본으로는 구분할 수 없다.** ①이 0명이면 중단을 검토하되, 그 결론에 **이 한계를 반드시 함께 적는다.**

**3주는 정착이 아니다.** 추적 연구들은 30·84·90일을 쓴다. ③의 이름이 "정착"이 아니라 **"강화"**인 이유다.

## 8. 관리자 화면

### 지금 화면 (2026-08-25 구현 완료)

| 화면 | 카드 | 형태 | 상태 |
|---|---|---|---|
| 개요 | 이벤트 유입 | 큰 숫자 다섯 칸 | ✅ |
| 개요 | 일별 기록 건수 | 세로 막대. **31일 넘으면 주 단위로 묶음** | ✅ |
| 개요 | 온보딩 전환 | 좁아지는 띠 | ⚠️ `done` 제외 중 |
| 개요 | 세션 요약 | 상자수염. **줄마다 자기 축** | ✅ |
| 개요 | 세션 퍼널 | **분기 흐름도** + 필터(전체/찜/판매처) | ✅ |
| 리텐션 | 재방문 곡선 | 비율 선 + 코호트 막대를 **세로로 나눠** 그림 | ✅ |
| 리텐션 | 활동 일수 분포 | 가로 막대 + 머리글 | ✅ |
| 추천 | 두 카드 | **표 유지** | 아직 표 |
| 원본 | 세션 · 이벤트 | **표 유지** | ✅ |

**모든 그림 카드 아래에 「숫자로 보기」 표가 있다.** 편의 기능이 아니다 — 마크에
`tabindex`를 안 붙이므로 그 표가 **키보드로 값을 읽는 유일한 경로**이고, 얇은 마크가
터치 영역 기준을 면제받는 근거이기도 하다(WCAG 2.2 SC 2.5.8의 「Equivalent」 예외).

**행이 많은 표는 앞 8줄만 펴 두고 접는다.** 자바스크립트 없이 CSS로 켠다.

**세션 퍼널만 SQL을 바꿨다.** 찜과 판매처 이동은 한 세션이 둘 다 할 수 있어 나란히
세면 합이 노출 세션 수를 넘는다. **「둘 다」를 독립된 갈래로 뽑아** 모든 세션이 정확히
한 곳에만 속하게 했다. 갈래를 더한 값이 노출 세션 수와 다르면 그 자리에서 보인다.

⚠️ **온보딩 `done`은 빼고 그린다.** 계측이 「온보딩을 마쳤다」가 아니라 「이미 온보딩한
사람이 앱을 켰다」를 셌다(하루에 `gender 11` 대 `done 25`). 수정은 배포 대기 중이고,
배포 후 `ADMIN_ONBOARDING_DONE_FROM`에 배포일을 넣으면 다시 나온다.

### 처음 정했던 형태 (2026-08-21)

| 카드 | 형태 |
|---|---|
| 이벤트 유입 | 스탯 타일 + 일별 막대 |
| 세션 요약 | 중앙값 타일 + 세션별 점 분포 |
| 행동 흐름 | 노출·상세 아래에서 찜과 이동이 **갈라지는 분기 막대** |
| 세션 목록 | **표 유지** + 횟수 인라인 막대 |
| 습관 지표 | **참가자 × 연속 7일 구간**의 유효 탐색 일수 격자 |
| 추천 유형별 성과 | 값순 가로 막대 |
| 원본 이벤트 | **표 유지** |

바뀐 것 셋. **세션 요약은 점 분포가 아니라 상자수염**이 됐다 — 세션이 수백 개라 점을
다 찍으면 뭉친다. **습관 격자는 안 만들었다** — 임계값을 근거 없이 정하지 않기로 했고,
리텐션과 활동 일수로 나중에 만들 수 있다. **화면은 넷이 아니라 넷 그대로**지만
「세션」·「습관」 대신 「리텐션」·「추천」이 됐다.

### 화면은 넷으로 나눈다 (2026-08-21 결정)

**시간 기준이 서로 달라 한 페이지에 담으면 모순된다.** 상단 필터가 "최근 7일"인데 습관 격자는 3주를 보여주는 상태가 실제로 나왔다.

| 화면 | 담는 것 | 시간 기준 |
|---|---|---|
| **개요** | 계측 상태 → 핵심 지표 → 일별 추세·행동 흐름 → 분포·추천 성과 | 전역 기간 필터 |
| **세션** | 세션 목록과 세션 상세 | 전역 기간 필터 |
| **습관** | 참가자별 3주 코호트 격자 | **참가자의 첫 경험일부터 3주 — 전역 필터를 받지 않는다** |
| **원본** | 원본 이벤트 검색·페이지 넘김 | 전역 기간 필터 |

**모든 위젯을 같은 크기로 두지 않는다.** 그러면 핵심 지표와 대조용 원본이 구분되지 않는다. 개요 첫 화면에는 세션 수 · 본 상품 중앙값과 사분위 · 상세/찜/아웃바운드 참여 세션 수와 비율 · 찜 저장 실패율만 크게 둔다. 카드 아래 긴 설명은 지표 정의 패널로 내리고, **표본 부족·계측 장애 경고만 상시 노출**한다.

### 추천 유형 지표는 하나로 묶는다 (2026-08-24 결정)

지금 관리자 화면에 추천 유형을 보는 카드가 **둘로 나뉘어** 있다.

| 카드 | 묻는 것 |
|---|---|
| 추천 유형별 전환 | 유형마다 얼마나 눌렸나 |
| 추천 유형별 탐색률 (취향 vs 비취향) | 한 세션에서 **취향과 비취향을 둘 다** 눌렀나 |

**둘 다 같은 축(추천 유형)을 본다.** 표로 두 장을 놓으니 갈라져 보일 뿐이다.
그림으로 옮길 때 **한 카드로 합치고 필터로 가른다** — 유형 여섯 개를 낱개로 볼지,
익숙함·새로움 두 계열로 묶어 볼지를 고르게 한다.

`partial`은 어느 계열에도 넣지 않았다. 성별·가격대만 맞추고 이미지는 무작위로
고르기 때문에, 취향을 쓰지 않으니 익숙함이 아니고 성별·가격은 맞으니 완전한
낯섦도 아니다. 숫자를 본 뒤에 정한다.

### 계측 상태와 사용자 활동량을 섞지 않는다

**이벤트 0건은 계측 장애가 아니라 사용자가 없었다는 뜻일 수 있다.** 둘을 따로 보여준다.

| 무엇 | 어떻게 |
|---|---|
| 사용자 활동량 | 일별 이벤트 수 |
| 계측 상태 | 마지막 저장 성공 시각 · 저장 오류 · 수집 경로 상태 |

**오늘 막대는 "오늘 00:00~현재"인지 "최근 24시간"인지 화면에 정확히 적는다.**

### 식별자는 가명으로 보여준다

계정 ID를 기록하기로 했으므로(§4) 화면 기본값에 **이메일이나 이름을 쓰지 않는다.**

| 대상 | 표시 |
|---|---|
| 계정 | `acct_a91c…` |
| 기기 | `dev_3f2a…` |
| 연구 참가자 | `P01` |

이메일·이름은 **별도 권한이 있는 상세 화면에서만** 보여준다.

- **모든 시간 표시는 관리자 화면에서 KST.**
- **필터**: 기간 · 계정·기기 · 관찰/자발 세션 · 계측 버전
- **필터 기본값** — 세션 구분은 **자발**, 계측 버전은 **현재 버전**. 정의가 다른 버전을 합치면 추세가 왜곡된다.

## 10. 구현 순서

1. **계측 계약과 익명 → 회원 연결 ＋ 문구**
   세션 계기 3종 · observed/organic · 발생 시점 로그인 상태 · 계정 ID(서버 인증) · 찜 실패 이벤트 · 로그인 퍼널 · 연결 기록 · **처리방침·설정 문구 5개**(§6)
2. **데이터 보존**
   90일 규칙과 삭제 작업 · (별도 진행) 법적 동의 검토
3. **분석 SQL**
   중앙값·사분위 · 세션률 3종 · 습관 격자

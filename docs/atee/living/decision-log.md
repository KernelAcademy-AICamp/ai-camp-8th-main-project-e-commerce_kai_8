# aTee 결정 기록

> 최종 수정: 2026-08-14 · 상태: 현재 제품 결정

## 결정 목록

| ID | 결정 | 근거와 의미 |
|---|---|---|
| O-01 | aTee는 기존 `search-by-llm`과 별도 제품이다. | 자연어 검색을 개선하는 기능이 아니라 검색 없이 탐색하는 별도 경험이다. |
| O-02 | 문제를 ‘쇼핑 피로’로 정의하지 않는다. | 인터뷰 참여자는 베스트 목록 반복 스크롤에 뚜렷한 불만을 표현하지 않았다. aTee는 불편 제거가 아니라 개인화된 새 가치를 검증한다. |
| O-03 | 1차 타깃은 매주 무신사 베스트를 훑고 장바구니에 담아두었다가 구매하는 사용자다. | 기존 LLM 검색 인터뷰 5~10명 중 약 70%에서 관련 패턴이 회고됐다. |
| O-04 | 완료·후보 압축 없이 무한 탐색을 유지한다. | 2~5개 후보를 남기는 목표는 제품 책임자의 의도와 다르므로 폐기했다. |
| O-05 | 2차원 궤도형 공간 대신 세로형 모자이크 피드를 사용한다. | 인스타그램처럼 위에서 아래로 탐색한다. |
| O-06 | ~~기본 3열, 축소 5열 이미지 전용, 확대 2열 이미지+가격을 사용한다.~~ | 2026-08-13 O-22로 대체됨. |
| O-07 | ~~탭은 바텀 시트를 열고, 상세의 `이 스타일로 계속 탐색`이 이후 피드 방향을 바꾼다.~~ | 2026-08-13 O-23으로 대체됨. |
| O-08 | 피드 카드는 이미지와 가격에 집중한다. | 브랜드·평점·리뷰·인기 신호보다 디자인과 지불 가능성을 먼저 보게 한다. 가격은 이미지 위 배지로 노출한다. |
| O-09 | 장기 취향과 현재 세션 방향을 분리한다. | 세션 선택은 빠르게 반영하되 장기 취향을 소량 유지하고 단발 행동이 프로필을 덮지 않게 한다. |
| O-10 | 유사·최근 관심·부분 일치·반대 스타일을 모두 포함하고 비율을 자동 조절한다. | aTee는 닮은 상품만 보여주는 추천기가 아니라 취향 경계를 계속 시험하는 발견 시스템이다. |
| O-11 | 개인화는 반복 탐색, 스타일 계속 탐색, 찜, 판매처 이동을 사용한다. | 찜과 판매처 이동은 강한 긍정 신호지만 실제 구매로 간주하지 않는다. 명시적 부정 신호는 후속 단계다. |
| O-12 | 비회원은 비개인화 탐색을 먼저 경험하고 회원만 장기 개인화를 받는다. | 가입 전에 가치를 보여주며, 가입 전 임시 이력은 계정으로 승계한다. |
| O-13 | 가입 시 연령대·성별·키·사이즈를 받는다. | 성별·키·사이즈는 착용 자격, 연령대는 세그먼트 분석에 사용한다. |
| O-14 | 모바일 우선 PWA로 제공한다. | 설치 없이 진입하고 설치 후 앱처럼 재방문한다. 제스처에는 항상 명시적 대체 동작을 제공한다. |
| O-15 | 초기 카탈로그는 현재 DB의 무신사 티셔츠 약 22만 개로 제한한다. | 수량은 사용자 제공 정보이며 필드 커버리지와 실제 총량은 MVP 전 감사가 필요하다. |
| O-16 | aTee는 상세 화면까지만 담당하고 거래는 외부 판매처로 연결한다. | 판매처 이동은 구매 의도 대리 지표이며 실제 결제·매출이 아니다. (2026-08-13 바텀 시트 → 상세 화면 표현 갱신) |
| O-17 | 초기 성공은 D7 재방문과 유효 탐색으로 판단한다. | 첫 목표는 가치 검증이며 수익화는 범위 밖이다. 체류시간은 혼란 가드레일과 함께 본다. |
| O-18 | 같은 aTee UI의 비개인화 피드와 개인화 피드를 먼저 비교한다. | UI의 신기함과 개인화 효과를 분리한 뒤 무신사 베스트와 전체 경험을 비교한다. |
| O-19 | 유기적 재방문 확인 전 푸시를 실험에 섞지 않는다. | 가치 확인 뒤 충분히 개인화된 회원에게 동의를 받아 푸시의 증분 효과를 별도로 측정한다. |
| O-20 | 광고·제휴·유료 기능 없이 가치 검증에 집중한다. | 수익 최적화가 추천 신뢰와 초기 학습을 왜곡하지 않게 한다. |
| O-21 | 서비스명을 `aTee`로 확정한다 (2026-08-13, 임시명 Orbit과 중간 표기 eati·EaTee 폐기). | 같은 날 eati → EaTee → aTee로 표기를 다듬어 최종 확정했다. 초기 안 eati는 미국 슬랭 "eat"("eat, i")과 "이 티(셔츠)"의 중의적 의미에서 출발했다. |
| O-22 | 핀치 밀도 전환 없이 2열 고정 masonry(카드 세로 길이 가변) 피드를 사용한다 (2026-08-13). | 제품 책임자가 Cosmos형 무한 스크롤 경험으로 확정했다. O-06의 5·3·2열 핀치 전환을 대체한다. |
| O-23 | 탭은 바텀 시트 대신 카드가 확대되는 전환의 상세 화면을 열고, 상품 이미지들을 슬라이드로 본다 (2026-08-13). | 단일 탭 상세 원칙은 유지하되 형태를 확대 전환 상세로 바꿨다. 상세의 `이 스타일로 계속 탐색`이 피드 방향을 바꾸는 역할과 길게 누르기 단축 동작도 유지한다. 뒤로 가면 카드로 줄어들며 피드 스크롤 위치로 복귀한다. |
| O-24 | 장기 개인화를 익명 기기 ID로 먼저 검증한다 (2026-08-14). | O-12("회원만 장기 개인화")의 완화. 가입·계정 전에 개인화 파이프라인이 돌고 체감되는지 확인하는 **익명 개인화 프로토타입**이며, PRD의 Gate 1(회원 D7 실험)은 아니다. 계정 도입 시 기기 프로필을 승계한다. [설계](../../superpowers/specs/2026-08-14-personalization-algorithm-design.md) |
| O-25 | LLM 자연어 검색을 보조 진입점으로 추가한다 (2026-08-14). | Non-goal "검색을 주 경험으로 제공하지 않는다"는 유지하되, 말로 방향을 주고 싶을 때의 보조 수단으로 허용. 검색 결과도 피드 형태로 이어져 탐색으로 복귀한다. 상세는 별도 스펙에서 설계한다. |
| O-26 | 이미지 임베딩 모델을 `google/siglip2-base-patch16-256`으로 확정한다 (2026-08-14). | 실데이터 1,498장으로 3종(Marqo-FashionSigLIP·SigLIP2·jina-clip-v2) 비교 — 속도(93만 장 하룻밤)·한국어 직접 처리·Apache 라이선스로 선택. [비교 문서](../foundation/embedding-model-bakeoff.md) |
| O-27 | 임베딩 대상은 썸네일+갤러리 전체(약 93만 장)로 한다 (2026-08-14). | 유사 상품에 갤러리 사진이 매칭되면 그 사진을 피드 카드로 노출하고 상세를 해당 슬라이드에서 연다(딥링크). 유형 분류로 착용샷·단품컷만 노출 대상으로 한다. |
| O-28 | Supabase를 Pro(유료)로 전환한다 (2026-08-14). | 무료 500MB로는 93만 장 벡터가 물리적으로 불가(Codex 리뷰 Blocker). 정밀 벡터 서버 보관 + 이진 후보→정밀 재정렬 구조를 위해 전환. 검증 종료 후 벡터 테이블 삭제로 무료 복귀 가능(원본 벡터는 로컬 보관). |
| O-29 | 세션 경계를 비활성 30분으로 확정한다 (2026-08-16). | 설계의 미정 플래그 해소. 세션 종료는 클라이언트가 마지막 활동 후 30분 무활동 기준으로 판정하며, 세션 프로필 수명과 장기 프로필 반영 시점(세션 종료 시 반영)의 기준이 된다. 계측 결과를 보고 추후 조정할 수 있다. [구현 계획](../../plans/2026-08-16-personalization-signals-profile-mix.md) |
| O-30 | 상세의 `이 스타일로 계속 탐색` 전용 버튼을 없애고, 상세 하단 닮은 상품 탐색을 진입 즉시 자동 로딩한다 (2026-08-16). | 버튼이 어차피 보이는 하단 그리드로 스크롤만 해 존재 이유가 체감되지 않았다(제품 책임자 결정). O-23의 "스타일 탐색이 피드 방향을 바꾼다" 역할과 길게 누르기 단축 동작(P0)은 **보류**로 조정 — 명시적 스타일 탐색 신호(신호 서열 2번째)와 세션 부스트(노출 60장)는 코드에 휴면 상태로 남기고, 세션 방향 전환 UI의 재도입 여부는 사용성·계측을 보고 재검토한다. |
| O-31 | 이미지 노출 필터를 "착용샷·단품컷만"에서 "디테일·원단만 제외"로 바꾼다 (2026-08-16). | 표본 200장 사람 판정 결과: 노출 대상 오통과율 ≤5%(임계값 미도입), 디테일 제외는 오류 0/50으로 깨끗. 그러나 **"표·라벨" 클래스(6.1만 장, 6.3%)는 표본 50/50이 오분류 — 사실상 뒷모습·전신 착용샷 모임**(고신뢰 0.9+ 표본도 착용샷, 진짜 사이즈표 0장)이라 멀쩡한 이미지가 잘못 제외되고 있었다. O-27의 "착용샷·단품컷만" 문구를 대체. 표·라벨 프롬프트 개선·재분류는 후속 과제. |

| O-33 | **TPO·활동·체형 질의(R1)를 참고 계열에서 목표 계열로 올린다** (2026-08-18). | 설계 S-08은 이 계열을 "카탈로그 속성으로 답이 나오지 않는다"는 이유로 게이트에서 뺐다. 실측해 보니 **절반만 맞다** — `골프` 3,360건 · `러닝` 3,412건 · `요가` 1,213건은 태그로 잡히고 `thickness`·`elasticity`·`sheer`는 커버리지 28%지만, `흡습` 11건 · `속건` 121건 · `통기` 49건은 사실상 없다. 제품 책임자는 `발리 가서 입기 좋은`·`축구할 때 입기 좋은` 같은 표현이 **LLM이 담당해야 할 몫**이라고 판단했다. Non-goal "검색을 주 경험으로 제공하지 않는다"는 유지된다 — 검색 결과는 여전히 피드로 이어지고 사용자는 탐색으로 복귀한다. 게이트에 넣는다는 것은 **그 계열의 품질을 측정하고 책임진다**는 뜻이지 검색을 주 경험으로 승격한다는 뜻이 아니다. ⚠️ **답이 없는 축은 여전히 답이 없다** — `땀흡수 잘되는`은 카탈로그에 근거가 없어 LLM으로도 못 푼다. 그것까지 오르리라 기대하지 않는다. |
| O-34 | **부정과 의도 해석을 LLM 한 조각으로 함께 한다** (2026-08-18). | 원안은 규칙+표를 먼저 넣고 LLM을 그 다음 조각으로 미루는 것이었다(C단계에서 같은 순서를 썼고, 그 덕에 LLM이 얼마나 보태는지 잴 수 있었다). 제품 책임자는 부정(`로고 없는`)과 의도(`축구할 때`)가 **사용자에게는 한 가지 일**이라 판단해 함께 가기로 했다. ⚠️ **대가**: 규칙 기준선이 없어 LLM의 기여도를 따로 잴 수 없다. 문제가 생겼을 때 규칙 탓인지 LLM 탓인지 가릴 수 없다는 것도 함께 받아들인다. |

## 대체된 결정

| 이전 방향 | 대체 이유 | 현재 결정 |
|---|---|---|
| 후보 2~5개를 남기고 선택을 끝냄 | 제품 책임자는 완료보다 무한 탐색을 원함 | O-04 |
| 상품이 중심이 되고 주변 궤도가 재배치됨 | 세로 이미지 전수조사 습관과 맞지 않음 | O-05, O-23 |
| 첫 탭은 재배치, 두 번째 탭은 상세 | 재탭 규칙이 숨겨져 발견하기 어려움 | O-23 |
| 후보·맥락 손실이 핵심 고통 | 인터뷰에서 현재 방식의 불만이 확인되지 않음 | O-02 |
| 그리드보다 공간 지도가 우월한지 검증 | 현재 제품은 공간 지도가 아님 | O-05, O-18 |
| 핀치로 5·3·2열 밀도를 전환하고 5열에서 가격을 숨김 | 제품 책임자가 2026-08-13 Cosmos형 2열 고정 masonry로 단순화 결정 | O-22 |
| TPO·체형·코디 질의는 참고 계열로 두고 게이트에서 제외 (설계 S-08) | "카탈로그 속성으로 답이 나오지 않는다"가 절반만 맞았고, 제품 책임자가 LLM의 몫으로 판단 | O-33 |
| 부정은 규칙+표로 먼저, LLM은 다음 조각 | 사용자에게는 부정과 의도가 한 가지 일 — 규칙 기준선을 잃는 대가를 알고 함께 감 | O-34 |

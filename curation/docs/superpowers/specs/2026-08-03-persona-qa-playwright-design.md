# 페르소나QA × Playwright 전환 설계

2026-08-03 확정 · 같은 날 codex 리뷰(High 4·Medium 8·Low 2) 반영 개정. 페르소나QA 에이전트의 브라우저 구동을 claude-in-chrome에서 Playwright MCP로 전환하고, 구동 직후 페르소나 인터뷰 단계를 추가한다.

## 배경

- 페르소나QA 에이전트(`.claude/agents/페르소나QA.md`)는 가상 구매자 페르소나로 배포된 웹 UI를 탐색·검증하는 "제품의 검증 장치"다. 정의(프롬프트)만 있고 실행된 적은 없다.
- 현재 tools가 `mcp__claude-in-chrome__*`로 되어 있는데, 이 프로젝트의 브라우저 자동화 방침과 어긋나고 사용자가 Playwright 기반 동작을 결정했다.
- 기존 네이버 블로그 발행 도우미(루트 `scripts/*.mjs`, `.pw-profile/`)는 삭제됨.
- 이 제품의 성공 행동은 자체 결제가 아니라 **무신사 상품 페이지로의 outbound 이동**이다(PRD). 페르소나의 "구매"도 이 경계 안에서 정의한다.

## 범위

**포함**
1. `.claude/agents/페르소나QA.md` 개정 — frontmatter `mcpServers` 인라인으로 Playwright MCP 등록, tools 최소 권한 교체, `name: persona-qa` slug 전환, 가드레일·인터뷰 프로토콜·로그 계약 반영
2. 루트 `package.json`의 `playwright` devDependency 제거 (MCP는 자체 Playwright를 쓰므로 현재 미사용 — 반복 하니스가 실제로 생길 때 그 시점 버전으로 추가)
3. 전환 후 localhost 대상 1회 smoke 구동 + 구동 직후 페르소나 인터뷰 실행으로 검증

**제외 (후속 작업)**
- client 앱의 `user_type=agent` 태깅 구현 — 태깅이 생길 때까지 아래 가드레일로 대응
- 대규모 반복 하니스 코드 작성 (YAGNI) — 관례와 실행 상한 규칙만 이번에 문서화
- 실사용자 보정(calibration) 인터뷰 설계 — 별도 작업

## 설계

### 1. Playwright MCP — 에이전트 frontmatter 인라인 등록 (최소 권한)

- 루트 `.mcp.json`이 아니라 **에이전트 frontmatter의 `mcpServers` 필드**로 stdio 서버를 인라인 정의한다(Claude Code 2.1.212에서 공식 지원 확인). Playwright 도구가 페르소나QA에만 노출되고 메인 세션·타 에이전트에는 열리지 않는다.
- `@playwright/mcp`는 **정확한 버전으로 고정**한다(`@latest` 금지, 현 시점 0.0.78). `npx`는 설치 확인 프롬프트가 서버 기동을 막지 않도록 **비대화식 플래그로 실행**하고, 최초 1회 네트워크 다운로드가 필요함을 에이전트 문서에 명시한다. 버전을 올릴 때는 도구 목록과 smoke를 재검증한다. 구동 로그에는 **실제 연결된 서버의 버전**을 기록해 캐시된 다른 버전이 아님을 확인한다.
- 서버 옵션: **`--isolated`를 기본**으로 해 실행 간 쿠키·스토리지 누수를 막는다(페르소나 간 독립 비교 보장). 병렬 구동은 금지. 로그인 상태가 필요한 시나리오는 별도 검토 후 명시적 주입으로만. **headless·고정 viewport(데스크톱 1종)를 기본**으로 해 실행 간 비교 가능성을 보장한다(정확한 값은 구현 시 확정해 에이전트 문서에 명시).
- `name:`은 `persona-qa` slug로 바꾼다(2.1.218부터 소문자+하이픈 강제 — 미리 준수). 파일명·한글 설명은 유지.

### 2. 도구 allowlist — 와일드카드 금지

- `tools:`에 `mcp__playwright__*` 와일드카드를 쓰지 않고 **필요 도구만 명시 열거**한다: 탐색, 클릭, 입력, snapshot, screenshot, 콘솔 읽기, 네트워크 읽기 수준.
- 다음은 **제외**한다: 임의 코드 실행 계열(`browser_run_code_unsafe`, `browser_evaluate`), 파일 전송 계열(`browser_file_upload`, `browser_drop`). 정확한 도구명은 구현 시 서버의 실제 tools 목록을 확인해 확정한다.
- 비브라우저 도구도 줄인다: `Edit`·`Bash`·`Skill`을 제거한다(이번 범위의 라이브 탐색에는 쓰이지 않음 — 반복 하니스가 실제로 생길 때 그 작업 주체에 별도 부여). `Write`는 `docs/persona-qa/` 로그 기록 용도로만 쓴다고 문서에 못박고, 구동 후 변경 파일 목록으로 로그 폴더 밖을 건드리지 않았는지 확인한다.

### 3. 데이터 오염 가드레일 — 환경별 원칙 분리

- 태깅 원칙을 환경별로 분리한다(분리하지 않으면 "모든 트래픽 태깅, 안 되면 중단"이 태깅 미구현 상태의 localhost 구동까지 논리적으로 막는 모순이 생긴다):
  - **analytics가 연결된 환경(프로덕션 포함)**: `user_type=agent` 태깅이 없으면 조작 전 중단. 태깅이 구현되기 전에는 단건이든 반복이든 전면 금지.
  - **analytics가 비활성인 localhost·preview**: 미태깅 합성 실행을 한시 허용하되, 로그에 `tagging=unavailable`, `analytics=disabled`를 기록한다.
- preflight는 2층으로 한다(네트워크 관찰은 페이지를 연 후에만 가능하므로, 열고 나서 확인하는 것만으로는 "사전" 검사가 아니다):
  1. **브라우저를 열기 전**: 환경 분류가 프로덕션이면 즉시 거부. 대상의 HTML/설정에 GA 로더가 있는지 실행 없이 점검한다.
  2. **안전 판정 후 첫 로드에서**: 네트워크에 analytics 요청이 없음을 재확인한다. 감지되면 즉시 중단·보고.
- preflight에서 거부된 호출은 run으로 치지 않으며 행동 로그를 만들지 않는다(중단 사유는 부모 세션에 보고만 한다).

### 4. 행동 경계 — "구매"의 재정의

- 이 에이전트에서 "구매"는 **자사 앱 안에서 상품 상세 진입 또는 outbound(무신사) 링크 클릭 의사/시도까지**다. 허용 origin(자사 앱)을 벗어나는 이동은 URL과 클릭 의사만 기록하고 실제 이동 전에 멈춘다.
- 금지 행동: 외부 사이트 로그인·회원가입, 장바구니·주문·결제, 개인정보 입력, 파일 업로드, 동의 상태 변경.

### 5. 호출 계약 (preflight)

- 서브에이전트는 구동 중 사용자에게 질문할 수 없으므로, **호출하는 부모 세션이 다음 필수 입력을 모두 수집해 첫 프롬프트로 넘긴다**: 페르소나 ID·정의, 대상 URL, 환경 분류(localhost/preview/프로덕션), 허용 origin, 최대 행동 수·시간, 성공·이탈·중단 조건. 하나라도 빠지면 에이전트는 브라우저를 열기 전에 중단한다.
- 반복 구동은 실행 전에 run 수·동시성(기본 직렬)·최대 비용/시간·중단 조건을 사용자 승인받는다. localhost/preview라도 검색 백엔드가 외부 API(LLM 등)를 부르므로 비용 상한 없이 대량 실행하지 않는다.

### 6. 대규모 반복 = 하니스 관례만 명시

- 에이전트 문서에 "반복 구동은 `scripts/persona-qa/` 아래 Playwright 스크립트로 실행하며, 하니스가 실제로 생길 때 필요한 의존성·실행 권한을 그 작업 주체에 부여한다"는 관례만 명시한다. 하니스 코드·의존성·권한은 이번에 만들지 않는다.

### 7. 구동 직후 페르소나 인터뷰

- 구동이 끝나면 같은 **에이전트 컨텍스트**에서(브라우저 세션과 무관) 페르소나 역할을 유지한 채 표준 질문 세트에 답해 기록한다.
- 표준 질문 세트: ① 무엇을 찾으려 했고 찾았는가 ② 가장 불편했거나 막힌 순간 ③ 왜 (구매의사/이탈)했나 ④ 검색 결과 신뢰도 — 5점 척도 + 근거 인용 ⑤ 재방문 의향 — 5점 척도 + 근거 인용.
- 답변 규칙: 행동 로그에 있었던 관찰에만 근거한다. 근거가 없는 질문은 "관찰 근거 없음"으로 기록한다.
- 산출물에는 인터뷰가 **합성 페르소나 자기보고이며 미보정·실사용자 인터뷰 대체 불가**임을 명시하고, `관찰 사실 / 페르소나 해석 / 미확인·추론`을 구분해 적는다.

### 8. 산출물 계약 (성공·실패 공통)

- 한 번의 구동 = `docs/persona-qa/` 아래 로그 파일 1개 (첫 구동 때 폴더 생성). 페르소나 정의는 별도 파일로 두고, 로그는 정의의 ID·버전을 참조하며 짧은 요약만 담는다(중복 복제 금지).
- 로그 필수 메타데이터: run ID, 시작·종료 시각, 대상 URL과 배포 식별자(commit/deployment), 환경 분류, `tagging`·`analytics` 상태, 페르소나 ID·버전, 실제 연결된 MCP 서버 버전, 브라우저·viewport, 최종 상태, 주요 콘솔·네트워크 오류.
- 종료 상태는 `구매의사 / 이탈 / 차단 / 기술실패 / 사용자중단`으로 구분한다. **실패·중단 시에도** 마지막 관찰 단계와 오류를 담은 partial 로그를 남기고, 인터뷰는 답 가능한 항목만 기록한다.
- 시각 판단 한계: 행동 타깃 선택은 accessibility snapshot 기반으로 하되, 검색 결과 등 주요 화면에서는 screenshot을 함께 관찰한다. 이미지 내용(색·프린트)을 실제로 판정하지 못했으면 로그에 "시각 검증 안 됨"을 남긴다.

## 완료 기준 (관찰 가능하게 분해)

1. 페르소나QA 에이전트 구동 시 Playwright MCP 서버가 연결되고, 고정 버전(`@playwright/mcp@0.0.78`) 실행을 확인하고, 실제 연결 서버 버전은 관측 가능한 경로(JSON-RPC 실측 등)로 기록하되 에이전트 도구로 관측 불가한 경우 "미관측" 기록을 허용하며, 노출된 도구 목록에 allowlist 도구만 있고 임의 코드 실행·파일 전송 계열이 없음이 확인된다.
2. preflight 음성 경로 3종이 각각 관찰된다: ① 필수 입력이 빠지면 브라우저를 열기 전에 중단 보고 ② 환경 분류가 프로덕션이면 즉시 거부 ③ 통제된 로컬 조건에서 analytics가 감지되면 중단(실제 GA 속성으로 이벤트를 보내는 테스트는 금지). 거부 시 행동 로그가 만들어지지 않는다.
3. **최종 의존성 상태에서**(루트 `playwright` 제거 후) localhost 정상 smoke 1회: 인터뷰 답변·필수 메타데이터·종료 상태가 포함된 로그 파일이 `docs/persona-qa/`에 보이고, 전체 탭·navigation 기록에 허용 origin 밖 문서가 없으며(outbound는 URL·의사·중단 이유만 로그), 주요 화면의 screenshot 관찰 근거 또는 "시각 검증 안 됨" 표기가 보이고, 구동 후 변경 파일이 로그 폴더 안에만 있다.
4. 통제된 기술실패 1회(외부 부작용 없는 로컬 실패 조건)에서 `기술실패` 상태·마지막 관찰·오류·미응답 인터뷰 처리가 담긴 partial 로그가 보인다(검증용 로그는 커밋하지 않고 폐기).
5. `--agent persona-qa`(또는 Agent 위임)로 새 이름의 에이전트가 정상 호출된다.
6. 루트 `package.json`에 `playwright` 직접 의존성이 없고, 의존성 설치가 오류 없이 성공하며, pre-commit 훅(husky)이 여전히 동작한다.

# 페르소나QA 에이전트 Playwright 전환 구현 계획

> 근거 스펙: `docs/superpowers/specs/2026-08-03-persona-qa-playwright-design.md` (2026-08-03 codex 설계·계획 리뷰 2회 반영 개정본). 이 계획은 코드 없이 "무엇을, 어떤 순서로, 무엇이 되면 끝"만 적는다.

**목표:** 가상 구매자 페르소나로 웹 UI를 탐색·검증하는 "페르소나QA" 에이전트(`.claude/agents/페르소나QA.md`)가 claude-in-chrome 브라우저 확장 대신 Playwright MCP 서버로 동작하게 바꾸고, 최종 의존성 상태의 localhost에서 정상 smoke 1회 + 통제된 실패 1회 + 구동 직후 페르소나 인터뷰까지 확인한다.

**맥락(이 repo를 모르는 독자용):** 이 repo는 "프린팅 티셔츠를 보이는 속성(바탕색×프린트색×위치)으로 찾는 LLM 상품검색 MVP"다. `client/`에 Next.js 앱이 있고, 페르소나QA는 그 앱을 실제 사용자처럼 탐색하는 검증용 서브에이전트다. "D17"은 첫 타겟 사용자 정의(프린팅 티를 시각 속성 조합으로 찾고 싶은데 못 찾는 사람)를 가리키는 내부 결정 번호다. MCP(Model Context Protocol)는 에이전트에 외부 도구를 꽂는 표준이고, Playwright MCP는 브라우저 조작 도구 모음이다. 제품의 성공 행동은 자체 결제가 아니라 무신사(외부 쇼핑몰) 상품 페이지로 이동하는 것인데, 이 링크는 새 탭을 열므로 "클릭 전 중단"이 검증 포인트다.

**전제 조건(스펙에서 확정된 결정):**
- Playwright MCP는 에이전트 파일 안(frontmatter)에 인라인 등록. 버전 0.0.78 고정, 비대화식 설치, 격리 모드·headless·고정 viewport 기본.
- 브라우저 도구는 allowlist만 명시 열거(임의 코드 실행·파일 전송 계열 제외). 에이전트의 셸 실행·파일 수정·스킬 도구는 제거, 파일 쓰기는 로그 폴더 용도로만.
- 태깅 원칙은 환경별 분리: analytics 연결 환경은 태깅 없으면 중단(=프로덕션 전면 금지), analytics 비활성 localhost/preview는 미태깅 한시 허용 + 로그에 상태 기록.
- git은 develop에서 딴 feature 브랜치에서 작업하고, 단계별 커밋 후 develop 대상 PR(squash)까지 진행한다(사용자 승인 완료).

## 단계 0 — 작업 트리 분류·보존과 브랜치 준비

- 현재 작업 트리의 변경을 목록화하고 이번 작업 포함/비포함으로 분류한다:
  - **포함(이번 브랜치에서 커밋):** 삭제된 네이버 블로그 스크립트 4개(별도 chore 커밋), 이번 스펙·계획 문서(docs 커밋), 이후 단계의 산출물.
  - **비포함(커밋하지 않고 그대로 보존):** `docs/retrospective/`, `docs/superpowers/plans/2026-08-01-p3a-color-lexicon-shadow.md` 등 이번 작업과 무관한 기존 변경. 임의 stash·reset 금지.
- 기준을 최신 `origin/develop`으로 맞춘 뒤 feature 브랜치를 만든다(브랜치 네이밍은 repo 규칙 `feature/<kebab>` 따름).
- **완료 기준:** 새 브랜치가 체크아웃되어 있고, 기준 커밋이 최신 `origin/develop`과 일치하며, 비포함 변경이 작업 트리에 그대로 남아 있는 것이 보인다.
- 커밋 2회(스크립트 삭제 chore / 스펙·계획 docs). 각 커밋 전 staged 목록에 해당 범위 파일만 있는지 확인.

## 단계 1 — 에이전트 정의 개정 (핵심 기능)

- `.claude/agents/페르소나QA.md`를 스펙대로 다시 쓴다. 반영 항목:
  - 에이전트 식별자를 소문자-하이픈 슬러그(persona-qa)로 변경 (파일명·한글 설명은 유지)
  - Playwright MCP 서버 인라인 등록: 버전 0.0.78 고정, 비대화식 설치, 격리 모드, headless·고정 viewport(값은 여기서 확정해 문서에 명시)
  - 도구 목록 교체: claude-in-chrome 도구 9개 제거. Playwright 도구는 서버가 실제 광고하는 목록을 확인해 allowlist로 명시 열거(탐색·클릭·입력·접근성 스냅샷·스크린샷·콘솔 읽기·네트워크 읽기 수준만, 임의 코드 실행·파일 전송 계열 제외). 셸 실행·파일 수정·스킬 도구 제거, 파일 쓰기는 `docs/persona-qa/` 로그 용도로만 한정 명시
  - 가드레일: 환경별 태깅 원칙(analytics 연결 환경 중단 / 비활성 환경 한시 허용 + `tagging`·`analytics` 상태 기록), 2층 preflight(열기 전 정적 점검 → 첫 로드 후 네트워크 재확인), preflight 거부는 run이 아니며 로그를 만들지 않음, "구매" 재정의(outbound 링크는 클릭하지 않고 URL·의사만 기록 — 새 탭이 열리는 구조이므로 클릭 자체가 금지선), 외부 사이트 상태 변경 금지, 호출 계약(필수 입력 6종 없으면 브라우저 열기 전 중단), 반복 구동 사전 승인 규칙과 하니스 관례
  - 시각 검증 규칙: 행동 타깃은 접근성 스냅샷 기반, 주요 화면은 스크린샷 병행 관찰, 이미지 내용을 판정 못 했으면 "시각 검증 안 됨" 표기
  - 인터뷰 표준 질문 5개(④⑤는 5점 척도+근거 인용), "합성 자기보고·미보정" 명시, 관찰사실/해석/추론 구분
  - 산출물 계약: 로그 위치·필수 메타데이터(실제 연결 서버 버전 포함)·종료 상태 5분류·실패 시 partial 로그
- **완료 기준:** 새 슬러그로 에이전트를 호출하면 MCP 서버가 연결되고 **실제 서버 버전이 고정 버전과 일치**하며, 쓸 수 있는 도구 목록에 allowlist만 보이고 임의 코드 실행·파일 전송 계열이 없다.
- 커밋 1회(에이전트 파일만).

## 단계 2 — 루트 playwright 의존성 제거 (smoke 전에)

- 루트 `package.json`의 `playwright` 직접 의존성을 제거하고 lockfile을 갱신한다. MCP가 루트 설치에 기대지 않고 자체 다운로드로 동작함을 최종 상태에서 증명하기 위해 **smoke보다 먼저** 수행한다.
- **완료 기준:** 루트 `package.json`에 playwright 직접 의존성이 없고, 의존성 설치를 다시 실행해도 오류가 없으며, pre-commit 훅(husky)이 여전히 동작하고, 이 상태에서 에이전트를 다시 호출하면 MCP가 여전히 연결된다(단계 1 확인 재실행).
- 커밋 1회(package.json·lockfile만).

## 단계 3 — preflight 음성 테스트 3종

- 각각 별도로 에이전트를 호출해 거부 경로를 확인한다:
  1. **입력 누락:** 필수 입력 6종(페르소나 정의, 대상 URL, 환경 분류, 허용 origin, 행동 상한, 종료 조건) 중 일부를 뺀 호출 → 브라우저를 열기 전에 "입력 부족 중단" 보고.
  2. **프로덕션 분류 거부:** 환경 분류를 프로덕션으로 준 호출 → 브라우저를 열기 전에 즉시 거부.
  3. **analytics 감지 거부:** 외부로 아무것도 전송되지 않는 통제된 로컬 조건(예: analytics 요청을 흉내 내는 로컬 페이지)을 만들어 호출 → 감지 후 중단 보고. 실제 GA 속성으로 이벤트를 보내는 방식은 금지.
- **완료 기준:** 세 경우 모두 중단·거부 보고가 보이고, `docs/persona-qa/`에 행동 로그가 생기지 않았음이 보인다. 검증용 로컬 조건 산출물은 repo에 남기지 않는다.
- 에이전트 문서 수정이 생겼으면 커밋.

## 단계 4 — 첫 페르소나 정의(D17 기반 초안) 작성

- D17 타겟 정의를 바탕으로 첫 페르소나(예산·구매 의도·성향·찾는 티셔츠의 시각 속성 조합)를 `docs/persona-qa/` 아래 별도 파일로 초안 작성한다. ID와 버전을 부여한다(행동 로그가 참조).
- 초안을 사용자에게 보여 확정받는다. (스펙의 유일한 미정 항목 — 여기서 해소)
- **완료 기준:** 사용자가 확인한 페르소나 정의 파일이 `docs/persona-qa/`에 보인다.
- 커밋 1회(페르소나 정의만).

## 단계 5 — 최종 상태에서 localhost 정상 smoke + 인터뷰

- client dev 서버가 떠 있는지 확인하고, 없으면 띄운다(이 프로젝트 방침: dev 서버는 Orca 터미널에 띄워 유지).
- 부모 세션이 필수 입력 6종을 채워 에이전트를 구동한다. 진행 순서: 2층 preflight → 페르소나 탐색(상품 상세 도달 포함) → outbound 링크 앞 중단 → 종료 → 인터뷰.
- **완료 기준:** `docs/persona-qa/`에 로그 파일이 생기고 안에 ①필수 메타데이터(실제 서버 버전·브라우저·viewport·`tagging`/`analytics` 상태 포함) ②시간순 행동 로그 ③종료 상태 ④인터뷰 답변(불가 항목은 "관찰 근거 없음") ⑤"미보정·합성 자기보고" 표기 ⑥주요 화면 스크린샷 관찰 근거 또는 "시각 검증 안 됨" 표기가 모두 보인다. 또한 전체 탭·이동 기록에 허용 origin 밖 문서가 없고(outbound는 URL·의사·중단 이유만 기록), 구동 후 변경된 파일이 로그 폴더 안에만 있음이 보인다.
- 커밋 1회(smoke 로그만).

## 단계 6 — 통제된 기술실패 smoke (partial 로그 검증)

- 외부 부작용이 없는 로컬 실패 조건(예: 응답하지 않는 로컬 주소)으로 에이전트를 구동한다.
- **완료 기준:** `기술실패` 종료 상태, 마지막 관찰 단계, 오류 내용, 답 못한 인터뷰 항목의 "관찰 근거 없음" 처리가 담긴 partial 로그가 보인다. 이 검증용 로그는 확인 후 폐기하고 커밋하지 않는다.

## 단계 7 — PR 생성

- 커밋 전 staged 목록이 각 단계 범위와 일치했는지 최종 확인하고, 변경 전체를 develop 대상 PR로 올린다(제목은 Conventional Commits 형식, 본문에 무엇을/왜·스펙 문서 링크).
- PR 본문의 "확인 방법"에 CI로 검증되지 않는 항목의 수동 검증 결과를 체크리스트로 남긴다: MCP 서버 버전·도구 allowlist 확인, 프로덕션 분류 거부, analytics 음성 테스트, 외부 탭 미생성, 정상 smoke 로그 경로, 실패 partial 로그 확인.
- **완료 기준:** PR 페이지에서 CI(client lint·typecheck·build)가 초록불이고, 본문에 위 수동 검증 체크리스트가 모두 체크된 상태로 보인다.

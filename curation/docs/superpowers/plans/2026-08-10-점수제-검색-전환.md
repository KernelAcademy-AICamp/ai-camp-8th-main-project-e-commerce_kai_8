# 점수제 검색 전환 — 하드 필터를 점수 + 상대 컷으로

- 작성일: 2026-08-10
- 상태: **초안 — 재작성 필요.** 외부 AI 검토(codex)에서 이 계획의 **핵심 근거가 오독임이 드러났다**(§3-①).
  방향(점수 + 상대 컷)은 살아 있으나 단계 구성과 선후관계를 다시 짜야 한다. 상세는 §9.
- 선행 작업 상태: 파서 지시문 변경은 **구현·측정·커밋 완료, PR #57 열림, 미병합**.
- 앞선 문서: `2026-08-10-감각어-리뷰태그-매핑.md` (v1~v3). 그 계획의 단계 2·3(리뷰 태그 전용
  점수·OR 컷)은 이 문서의 일반 규칙에 흡수된다. 그 문서의 단계 1(파서 지시문)은 **이미 완료**했고
  결과는 §3-⑥에 있다.

## 1. 문제 — 0건이 너무 자주 난다

사용자가 실제로 보고한 것들이다.

| 질의 | 결과 | 죽인 것 |
| --- | ---: | --- |
| `귀여운` | 0 | 상품명 하드 필터 (카탈로그에 "귀여" 제목 0개) |
| `귀여운 티셔츠` | 0 | 같음 |
| `힙한 프린팅 티셔츠` | 0 | 같음 |
| `화려한 프린팅 티셔츠` | 0 | 같음 |
| `귀여운 프린팅 티셔츠` | 0 | 같음 (프린트 조건은 766건 매칭인데도) |

공통 원인은 하나다. **어떤 축이든 하드 필터로 걸리면 교집합이 비는 순간 결과가 0이 된다.**
지금 저장소에는 이 증상을 막으려는 구제 경로가 여럿 붙어 있다 — 상품명 tier 폴백
(완전일치→AND→OR), 스타일 하드 필터 제거 후 재조회, 상품명 토큰 폐기 후 재조회.
전부 "하드라서 0건이 되는" 문제의 반창고이고, 서로 발동 조건이 달라 어떤 질의는 구제되고
어떤 질의는 안 된다.

---

## 2. 방향 — 점수화하고, 최고점 대비 크게 낮은 것을 자른다

후보를 확보할 만큼의 조건만 데이터베이스에서 걸고, 나머지 축은 전부 관련도 점수로 바꾼 뒤,
최고점 대비 크게 낮은 것을 잘라 노출을 정한다. 아무 조건도 맞지 않았다면 결과를 내지 않는다.

교집합이 비어서 0건이 되는 구조가 사라지고, 대신 "덜 맞는 것"이 아래로 밀린다.
마지막 규칙이 "아무것도 안 맞으면 일반 상품을 보여주지 않는다"는 기존 원칙(설계 §4.4)을 지킨다.

## 3. 실측 (2026-08-10, 개발 서버·현재 운영 모델)

### ① 상대 컷은 "후보 안에서의" 경계만 찾는다 — 최초 해석은 오독이었다

현행 가중치로 대리 점수를 계산해 최대 인접 갭을 찾은 결과, 갭 지점이 태그 보유 건수와
정확히 일치했다. 처음에는 이를 "상대 컷이 하드 필터와 같은 경계를 자동으로 찾는다"는
근거로 삼았다. **그 해석은 틀렸다.** 비교 대상이 카탈로그의 진짜 정답 수가 아니라,
이미 잘린 후보 집합 안의 수였다.

| 질의 | 후보 안 태그 보유 = 갭 지점 | 카탈로그 전체 | 후보가 놓친 정답 |
| --- | ---: | ---: | ---: |
| `귀여운 티` | 172 | **295** | 123 (42%) |
| `커플티` | 98 | **151** | 53 (35%) |
| `러닝용 티셔츠` | 180 | **301** | 121 (40%) |

후보는 리뷰 점수 상위 약 1,000건이다(조회기가 `review_score` 내림차순으로 정렬한 뒤
상한에 걸린다 — 코드 주석도 이 한계를 `Phase 1.5b`로 적어 두었다). 따라서 누락된
35~42%는 **리뷰 점수가 낮은 태그 보유 상품**이며, 임의 누락이 아니라 편향된 누락이다.

이것은 이 계획 이전에 **현재 동작의 결함**이기도 하다. 리뷰 태그처럼 조회 조건이 아닌
축만 있는 질의는 지금도 정답의 35~42%를 랭커가 보지 못한다.

그리고 임계 비율 50%와 90%가 같은 결과를 낸 것도 근거가 약하다. 단일 신호 질의에서는
점수가 "가중치 아니면 0"인 이진 분포라 어떤 비율을 골라도 같은 곳에서 잘리는 게 자명하다.
복합 질의의 임계 정책을 정당화하지 못한다.

### ② 복합 질의에서는 임계값이 노출 폭 손잡이가 된다

`러닝할 때 입을 시원한 검정 티` (최고점 8.00, 결과 898건):
90% 컷 → 50건(전 조건 만족) · 70% → 237건 · 50% → 504건.
조건을 몇 개 만족했는지가 연속 스펙트럼이라 "전부 만족(AND)"과 "하나라도(OR)"의
딜레마가 사라진다.

### ③ 다중 조건에서 AND는 무너지고 개수 점수는 층을 만든다

| 질의 | 조건 수 | 현재 | 하나라도 | 전부 | 일치 개수 분포 |
| --- | ---: | ---: | ---: | ---: | --- |
| 잠옷 편한 티 | 2 | 1000 | 515 | 121 | 2개=121 · 1개=394 |
| 러닝 시원 검정 티 | 3 | 898 | 450 | 125 | 3개=125 · 2개=127 · 1개=198 |
| 뱃살 넉넉한 티 | 4 | 726 | 189 | **17** | 4개=17 · 3개=35 · 2개=41 · 1개=96 |

일치 개수로 정렬하면 상위 10건의 평균 일치가 전 질의에서 만점이다.
현재 점수에는 **리뷰 태그 2개분 상한**이 걸려 있어 3·4개 층이 구분되지 않는다.

### ④ 후보 상한이 전면 소프트화를 막는다

```
카탈로그 전체 2,472 상품   /   DB 후보 상한(PostgREST max_rows) 1,000
```

모든 축을 소프트로 바꾸면 DB가 임의의 1,000건(40%)을 주고, 정답이 나머지 1,472건에
있어도 랭커가 보지 못한다. **최소 한 축은 DB에서 후보를 좁혀야 한다.**

### ⑤ 소프트 랭킹은 상위는 완벽하지만 개수가 거짓말을 한다

`커플티`: 태그 보유 98건이 1~98위를 정확히 차지하고 99위부터 902건의 무관한 꼬리.
`러닝용`·`잠옷용`도 상위 50건이 50/50. 순서는 하드 필터와 같지만 개수가 부정확하다.
③의 컷이 이 꼬리를 잘라낸다.

### ⑥ 감각어 매핑은 이미 고쳤다 (앞 계획의 단계 1 — PR #57)

파서 지시문에서 리뷰 태그 매핑 범위에 "디자인 인상"을 열고, 한 단어 질의도 축에 배정되도록
예시를 하나 넣었다. 특정 단어 규칙은 넣지 않았다 — 축은 태그 이름으로 가리켰고,
예시는 목표 단어가 아닌 다른 형용사를 썼다.

| | 전 | 후 (각 5회 반복) |
| --- | ---: | ---: |
| `귀여운`(단독) | 0/5 · 0건 | **5/5** · `디자인귀여움` |
| `귀여운 티` | 0/5 · 0건 | **5/5** · `디자인귀여움` |
| `귀여운 티셔츠` | 0/5 · 0건 | **5/5** · `디자인귀여움` |
| `커플티`(대조) | 5/5 | 5/5 |
| 대조군 10건 조건 추출 | — | 10/10 동일 |
| 20건 라이브 골든셋 | 39/42 | 39/42 (변경 무관 — stash 후 재측정으로 확인) |

대가는 §3-⑧에 있다.

### ⑦ 모델이 완전 결정적이지 않다

`temperature=0`인데도 동일 지시문에서 `부드러운 촉감 반팔`의 리뷰 태그 침범이
한 번은 나오고 한 번은 안 났다. **모든 측정은 반복해야 한다.**

---

### ⑧ 한 단어 질의를 축에 배정시키면 리뷰 태그 축 활성도가 전반적으로 오른다

`귀여운` 단독은 리뷰 태그가 5회 중 0회 붙었다(노이즈가 아니라 결정적 실패).
반면 다른 한 단어 형용사는 각자 축으로 잘 갔다 — `시원한`→계절·두께, `부드러운`→촉감,
`넉넉한`→핏. 즉 "한 단어라서"가 아니라 리뷰 태그 축만 지고 있었다.
지시문의 특징어 설명이 "느낌"을 자기 것이라고 선언해 리뷰 태그와 경쟁한 것이 원인으로 보인다.

해결 시도 세 가지를 측정했다.

| 시도 | `귀여운` 단독 | 부작용 |
| --- | ---: | --- |
| 일반 규칙 추가("상품 이름 없어도 축을 채워라") | 0/5 | 타깃 전체가 2/3 → 0/3으로 **역행** |
| 일반 규칙 추가(축 우선순위 — 통제 어휘 있는 축 우선) | 0/5 | `귀여운 티`가 매핑을 잃고 0건으로 **역행** |
| 예시 추가(다른 형용사 한 단어 → 리뷰 태그) | **5/5** | 착용감 표현의 리뷰 태그 중복이 증가 |

예시 방식만 통했고, 규칙 추가는 두 번 다 역효과였다. 예시 단어를 착용감과 무관한 것으로
바꿔도 중복은 줄지 않았다(오히려 증가). **원인은 단어 선택이 아니라 형태 학습 자체다.**

이 결과가 §8의 판단을 뒤집는다.

## 4. 결정

### 확정

- **결정 1 — 노출 경계를 최고점 대비 상대 컷으로 정한다.** 축마다 하드/소프트를 개별로
  정하지 않는다(실측 ①).
- **결정 2 — 최고점의 조건 점수가 0이면 결과를 내지 않는다.** 설계 §4.4의 기존 원칙과 동일.
- **결정 3 — 후보 확보용으로 최소 한 축은 DB 하드 조건을 유지한다.** 카탈로그가 후보 상한의
  2.5배이기 때문이다(실측 ④). 이건 걸러내기가 아니라 "정답을 후보에 넣기" 목적이다.
- **결정 4 — 전환은 축 단위로, 관측 → 적용 순서로 한다.** 저장소의 기존 관례(shadow 모드 후
  적용)를 따르고, 환경 변수 스위치를 둔다. 꺼짐이 기본이며 꺼진 동안 동작은 현행과 동일하다.
- **결정 5 — 리뷰 태그 점수의 개수 상한을 푼다**(실측 ③).

### 이 계획에서 측정 후 확정 (지금 정하지 않음)

- **미정 A — 임계 비율.** 단일 신호에선 둔감하지만 복합 질의에선 노출 폭을 정한다
  (50건 vs 504건). 관측 단계 데이터로 정한다.
- **미정 B — 후보 확보 축 선택 규칙.** 어느 축을 DB 하드로 쓸지. 후보 수 기준으로 고를지,
  우선순위를 고정할지, 여러 축을 OR로 묶을지는 열어둔다.
- **미정 C — 점수 가중치.** 리뷰 태그 상한을 풀면 4개 일치가 색·상품명을 압도한다.
  기존 하드 축의 상위 노출이 밀리지 않는 값을 실측으로 고른다.

## 6. 단계

### 단계 0 — 앞 계획의 파서 지시문 변경을 먼저 낸다

**무엇을**: 실측 ⑥의 변경(미커밋)을 단독으로 낸다. 이 계획과 독립적이고 그것만으로도
사용자가 보고한 `귀여운 티셔츠` 0건이 풀린다.

**완료 기준**: `귀여운 티`·`귀여운 티셔츠`가 0건이 아니고, 대조군 10건과 20건 골든셋이
변경 전과 같다는 수치가 붙은 상태로 병합된다.

### 단계 1 — 점수 컷을 계산만 하고 결과는 바꾸지 않는다 (관측)

**무엇을**: 현재 결과 집합에 대해 최고점·점수 분포·최대 갭·임계 비율별 컷 지점을 계산해
응답에 관측 값으로 싣는다. 결과 순서·개수·모드는 건드리지 않는다. 스위치는 기본 꺼짐.

**완료 기준**: 대표 질의 10건 이상에서 응답에 컷 지점이 보이고, **결과 상품 번호 집합과
순서가 변경 전과 완전히 같다.** 관측 값을 표로 뽑아 이 문서에 붙인다.

### 단계 2 — 임계 비율과 가중치를 확정한다 (미정 A·C)

**무엇을**: 단계 1의 관측 데이터로 임계 비율을 고르고, 리뷰 태그 개수 상한을 푼 뒤
가중치 후보를 실측 비교한다.

**완료 기준**: 고른 값에서 ⓐ 단일 신호 질의의 컷 지점이 조건 충족 건수와 일치하고
ⓑ 색·핏이 함께 있는 질의(`러닝할 때 입을 시원한 검정 티`)의 **상위 20건이 모두 요청한
색을 유지**한다. 고른 값과 근거 수치를 이 문서에 적는다.

### 단계 3 — 상품명 축을 하드에서 점수로 옮긴다 (핵심)

**무엇을**: 상품명 토큰을 하드 조건에서 빼고 점수 가점으로만 쓴다. 컷은 단계 2 값으로 건다.
상품명 tier 폴백을 점수로 일반화할지(완전일치에 더 큰 가점) 여부는 열어둔다.

**완료 기준**:
- `귀여운`, `힙한 프린팅 티셔츠`, `화려한 프린팅 티셔츠`, `귀여운 프린팅 티셔츠`가 **0건이 아니다.**
- `스누피 티셔츠`처럼 카탈로그에 없는 고유명사 질의는 **여전히 0건이다**(결정 2가 지킨다).
- 상품명이 실제로 맞는 질의(`나이키 반팔` 등)에서 상위 20건이 변경 전 상위 20건과 같다.

### 단계 4 — 리뷰 태그 축을 점수 컷 체계로 편입한다

**무엇을**: 리뷰 태그 개수 상한 해제를 적용하고, 컷이 태그 경계를 잡는지 확인한다.

**완료 기준**: `커플티`·`러닝용 티셔츠`·`귀여운 티`의 결과 수가 **그 시점 카탈로그의
해당 태그 보유 상품 수와 같다.** 다중 태그 질의에서 상위 10건의 평균 태그 일치가 최대치다.

### 단계 5 — 후보 확보 축 선택 규칙을 정한다 (미정 B)

**무엇을**: 어느 축을 DB 하드 조건으로 남길지의 규칙을 정하고 적용한다.

**완료 기준**: 조건이 둘 이상인 질의에서 **후보 수가 상한(1,000) 미만**이 되고,
각 조건을 단독으로 걸었을 때의 결과가 전부 후보 안에 포함된다.

### 단계 6 — 반창고 구제 경로를 걷어낸다

**무엇을**: 상품명 tier 폴백, 스타일 하드 필터 제거 재조회, 상품명 토큰 폐기 재조회 중
점수 컷으로 대체된 것을 제거한다. 무엇을 남기고 무엇을 지울지는 단계 3~5 결과를 보고 정한다.

**완료 기준**: 제거 후에도 단계 3·4의 완료 기준이 전부 유지되고, 제거한 경로가 담당하던
질의 유형마다 대표 질의 하나씩으로 회귀가 없음을 보인다.

### 단계 7 — 계약·회귀 자산·기록을 갱신한다

**무엇을**: "리뷰 태그는 하드 필터 금지" 등 바뀐 계약 문구, 하드 조건 후보를 기술하는
조회 계획·결정성 기록을 갱신한다. 라이브 20건 스크립트에 리뷰 태그 채점을 추가한다
(현재 없다). 골든셋 250건은 **실행 러너가 없으므로** 최소한 이번에 관련된 항목을 확인할
수단을 만든다.

**완료 기준**: 라이브 스크립트를 돌리면 기존 20건 점수가 유지되고 새 케이스가 통과한다.
설계 문서에 ① 점수 컷으로 바꾼 이유와 실측 근거 ② 고른 임계 비율·가중치 ③ 측정 모델과
측정일 ④ 재측정 조건이 각각 적힌다.

## 7. 위험

- **후보 상한**: 카탈로그 2,472 > 상한 1,000. 결정 3이 완화하지만 근본 해결은 페이지네이션이다.
  단계 5의 완료 기준이 이 위험을 감시한다.
- **임계값이 곧 정책**: 복합 질의에서 컷 비율이 결과 폭을 직접 정한다(50 vs 504건).
  단일 신호에선 둔감하다는 실측이 있지만 복합 질의는 값에 민감하다.
- **모델 비결정성**: 실측 ⑦. 단계별 판정은 반복 측정으로 한다.
- **한 번에 하나씩**: 축을 동시에 옮기면 회귀 원인을 분리할 수 없다. 단계 3·4를 나눈 이유다.
- **기존 계약 변경 폭**: 리뷰 태그 하드 금지, 상품명 하드 게이트, 구제 경로가 모두 바뀐다.
  스위치 꺼짐이 기본이고 꺼진 동안 현행과 동일해야 한다(결정 4).

## 8. 이 계획 뒤에 남는 별건 — 축 소유권

한 표현이 여러 축에 중복 배정된다. 실측: `잠옷으로 입을 편한 티`에서 "편한"이 촉감 축과
리뷰 태그에 이중 배정, `러닝할 때 입을 시원한 검정 티`에서 "시원한" 하나가 두께·계절·
흡습속건·냉감 네 조건이 된다.

**당초 "전제조건이 아니다"라고 적었으나 뒤집는다.** 두 가지가 그 판단을 무너뜨렸다.

첫째, 상대 컷에서는 중복 가점이 **멤버십을 바꾼다.** 같은 개념이 두 축에서 두 번 가점되면
그 상품의 점수가 부풀어 컷 경계를 넘고, 한 번만 가점된 상품이 밀려난다. 소프트 랭킹에서
순서만 흔들리던 것과 성격이 다르다.

둘째, 실측으로 중복이 더 늘었다. 한 단어 질의를 축에 배정하게 만드는 예시를 지시문에
추가하자(§3-⑧) 착용감 표현이 리뷰 태그로도 함께 잡히는 빈도가 올라갔다 —
`두꺼운 무지 반팔`이 5회 중 0회에서 5회로, `부드러운 촉감 반팔`이 1회에서 3회로.
예시 단어를 착용감과 무관한 것으로 바꿔도 줄지 않고 오히려 늘어(부드러운 5/5), 원인이
단어 선택이 아니라 "한 표현을 축에 배정하라"는 신호 자체임이 드러났다.

따라서 **축 소유권 정리는 리뷰 태그를 컷·조건으로 승격하기 전에 끝나야 한다.**

해법 방향은 실측돼 있다: 각 추출이 "내가 원문에서 무엇을 소비했는지"를 함께 내놓고,
같은 조각을 둘 이상이 소비하면 한쪽으로 정리한다. 리뷰 태그 전용 추출 실험에서 소비 조각이
80건 중 76건 정확히 채워졌다. 저장소에는 같은 목적의 소비 표현 계산 기능이 이미 있으나
운영 경로에 연결돼 있지 않다. 별도 계획으로 다룬다.

## 9. 외부 검토 반영 — 이 계획을 다시 짜야 하는 이유

외부 AI 검토(codex)에서 나온 지적을 실물 대조해 확인한 결과다. 대부분 타당했다.

### 근거가 무너진 부분

- **핵심 실측이 오독이었다**(§3-①). 갭 컷이 찾은 경계는 후보 안의 경계였고, 후보는
  이미 정답의 35~42%를 놓치고 있었다. "점수 컷이 좋은가"보다 **랭커가 정답을 전부 보는가**를
  먼저 증명해야 한다.
- **임계값 둔감성 근거가 약하다**. 단일 신호에서 점수가 이진 분포라 자명한 결과였다.
- **"최대 갭"과 "최고점 대비 고정 비율"은 서로 다른 알고리즘인데** 측정과 결정에서 섞여 있다.
- **축 소유권은 전제조건이 맞다**(§8에서 뒤집음).

### 설계가 아직 정의하지 못한 것

- 조건 점수를 무엇으로 셀지. 현재 점수 계산에는 상품 리뷰 점수 보너스가 섞여 있어,
  아무 조건도 안 맞아도 최고점이 0이 되지 않는다. 조건 점수와 총점을 분리해야 한다.
- "최고점의 조건 점수가 0이면 결과 없음"과 기존 mode 판정의 관계. 전자는 조회 후 적합성,
  후자는 조회 전 실행 자격이라 이중 판정은 아니지만, 점수 0일 때 mode를 실패로 바꾸면
  기존 계약과 충돌한다. mode는 그대로 두고 결과만 비우거나, mode 계약 변경을 별도로 정해야 한다.
- 결정화 레인에서 리뷰 태그는 출처 기록에 남지 않아, 점수 컷에 닿기 전에 신호 판정에서
  탈락할 수 있다. 적용 전에 정합성을 정해야 한다.
- 배제 조건(`검정 말고`)을 점수로 다룰 수 없다. 완전 배제인지 감점인지 먼저 정해야 한다.
- 후보 확보용으로 남기는 축을 점수에도 포함할지. 제외하면 어느 축이 후보로 뽑혔는지에 따라
  최고점과 컷 위치가 달라진다.
- "모든 축"이라고 했지만 단계는 상품명과 리뷰 태그만 다룬다. 성별·사이즈·가격·색·핏·소재·
  패턴·컬러웨이의 분류가 없다.
- 반복 측정을 요구하면서 반복 횟수·통과율·집계 방식이 완료 기준에 없다.

### 순서가 위험한 부분

- 상품명을 조회 조건에서 빼면서 기존 tier 폴백과 구제 경로를 단계 6까지 남겨두면,
  실제로 제목을 거르지 않은 후보에 `titleTier` 표시만 남는 등 의미가 어긋난다.
  새 경로는 **그 단계부터** 기존 tier·구제 경로를 우회해야 한다.
- 컬러웨이는 일치 상품이 상한을 넘으면 랭킹 뒤에 사후 교집합을 적용한다. 컷을 랭킹 안에
  넣으면 나중에 제거될 상품이 최고점을 만들어 실제 일치 상품이 과도하게 잘릴 수 있다.
  **컬러웨이 최종 적격 집합을 정한 뒤 최고점을 계산해야 한다.**
- 조회 계획·결정성 기록 갱신을 마지막 단계로 미루면 적용 단계와 기록이 어긋난다.

### 다시 짤 때의 순서

1. "반드시 만족해야 하는 제약"과 "관련도 선호"의 경계를 먼저 확정한다.
   배제·브랜드·가격·사이즈·컬러웨이까지 전부 어느 쪽인지 명시한다.
2. 카탈로그 전체를 정답 기준으로 삼아 후보 방식별 재현율을 측정한다.
   **후보 안에 전역 최고점과 최종 생존자가 모두 들어오는지가 완료 기준이다.**
3. 그걸 만족하는 방식이 없으면 페이지 수집·데이터베이스 내부 점수 계산·축별 후보 합집합 중
   하나를 범위에 넣거나, 적용 가능한 질의 범위를 제한한다.
4. 확보된 후보 위에서만 점수 분포와 임계값을 측정한다.
5. 상품명 전환 단계에서 새 경로가 기존 tier·구제 경로를 즉시 우회하게 한다.
6. 축을 하나씩 적용하면서 각 단계에 조회 계획·결정성 기록·고정 카탈로그 기준 테스트를 함께 갱신한다.
7. 마지막에 쓰이지 않는 구제 코드를 삭제한다.

### 계획 규칙 위반으로 지적된 것

- 방향 절이 의사코드 형태였다 → 산문으로 고쳤다(§2).
- 상태 기록이 세 군데에서 서로 달랐다 → 앞머리에 사실 하나로 정리했다.
- 단계 3의 완료 기준(`귀여운`이 0건이 아니다)이 자체 설계와 모순이었다. 리뷰 태그가 붙지
  않으면 조건 점수가 0이라 "조건 점수 0이면 결과 없음" 규칙에 걸린다. 지금은 §3-⑧의
  예시 방식으로 `귀여운` 단독에도 태그가 붙게 되어 이 모순 자체는 해소됐으나,
  **완료 기준을 태그 매핑 성공 여부로 다시 써야 한다.**

## 배경 — 이 작업이 무엇이고 왜 하는가

색은 hard-safe 기준 1(충전율 99.0%)을 통과한 첫 파일럿 축이다. 3a는 색 표현의 추출권을 LLM에서 **결정적 facet 사전**으로 이관한다: 기본색 사전(표현→카탈로그 어휘) + 수식어 문법(연한→라이트\*, 진한→다크\*). **사용자 노출은 하지 않는다** — 결정화 경로는 P3-F의 flag(기본 off) 뒤에 있고, 이번 단계는 shadow 계측(결정화 plan을 병렬 계산해 현행과 비교 기록)으로 분포를 측정한다. 사용자 노출 cutover는 3b와 원자적으로 한다(설계 §2 — 과도기 요동 금지).

성공하면: 기준 2(매핑 precision ≥95%)·기준 3(색 축 누락률 ≤5%)을 실측 통과해 **색 축 하드 승격 판정이 3중 기준으로 완성**되고, baseline(LLM 36.9%) 대비 개선이 정량화된다.

## 확정 사항 (1단계 질문 답변 포함)

- **골든셋 참조 허용**: 색 골든셋은 실쿼리 기반 요구 명세로 사전 구축에 참조한다. 이 경우 기준 2 통과는 "골든셋 커버 증명"이지 일반화 증명이 아님을 판정 문서에 명시하고, 일반화 검증은 3c의 unresolved_facet 계측 루프가 담당한다.
- **shadow 계측 = GA4 파라미터 배포**: flag-off 상태에서 결정화 plan을 병렬 계산해 shadow 요약을 GA4 `search_performed` 파라미터로 전송(고카디널리티 원문 금지 — 설계 §3.7). 오프라인 E2E 재측정(baseline 스크립트 flag-on)도 참고로 병행한다.
- **골든셋 동결이 착수 게이트**: 사전 구현 시작 전에 색 골든셋을 동결(`frozen: true`)한다 — 구현에 맞춰 정답을 고치는 자기확증 차단(T0a 계약).
- **가점 cap 0 — 실제 의미를 고정한다**: 결정화 경로(flag-on)에서 **LLM-only 색은 랭킹 가점 0(무효)이고, 반영되지 않으므로 응답 칩에서도 제거**된다("적용된 조건=표시된 칩" 불변식 — 반영 안 된 값은 표시하지 않는다). 사전 추출 색만 하드 조건·칩으로 남는다. ⚠️ P3-F가 구현한 "LLM 색 소프트 강등+칩 유지"는 cap>0 일반 정책이었으므로, 3a에서 cap 0 확정에 맞게 flag-on 랭킹·응답 경로를 조정하고 테스트로 고정한다(설계 §3.3·§7-2 — cap 0.25~0.5 활성화는 별도 게이트).
- **LLM 계약 불변**: 프롬프트·스키마 무수정. 사전이 커버한 색 축에서 LLM 값은 무시된다(사전 우선 — 설계 §3.3).
- **flag-off 동작 불변**: 현행 사용자 경험은 어떤 단계에서도 바뀌지 않는다(shadow 계측 추가만).

## 단계

### 1. 골든셋 동결 (착수 게이트)

- 색 표현 골든셋의 동결 표식을 켜고, 이후 변경은 사유·버전 기록을 남기는 규칙을 무결성 테스트로 고정한다.
- **완료 기준: 골든셋 파일에 동결 표식이 보이고, 무결성 테스트가 통과한다.**

### 2. 기본색 사전 — 데이터와 추출기 (핵심)

- 표현→카탈로그 어휘 매핑 데이터를 만든다. 소스: 색 골든셋(요구 명세) + 어휘 파일의 전 색상명 자체 표기 + 일반 한국어 색 표현. 1표현→다값은 같은 축 내 OR(설계 §3.1).
- 매핑 target이 전부 현행 자동 생성 어휘에 실존함을 자동 검사로 고정한다(어휘 재생성 표류 방지 — 골든셋과 같은 방식).
- 추출기는 토큰 경계를 보존하는 자체 정규화(NFKC·소문자·조사 스트립)를 쓴다 — 브랜드 정규화 함수 전체 재사용 금지(설계 §3.1).
- **완료 기준: 골든셋의 직접·계열 매핑 항목을 추출기에 넣으면 기대값과 일치하는 테스트가 통과한다.**

### 3. 수식어 문법 — 합성과 실패 시 기본색 유지

- 수식어(연한·밝은→라이트\*, 어두운·진한·딥→다크\*) 합성을 구현한다: **최장 구문 우선**("다크 네이비"를 "다크"+"네이비"보다 먼저), **합성 실패 시 기본색 유지**("아주 은은한 파랑"→파랑 계열), 합성 결과가 어휘에 없으면 기본색으로 폴백("진한 하늘색"→스카이 블루).
- **최소 문맥 규칙(함정 게이트 통과 수단 — 착수 전 확정)**: ①색 표현 **직후에 비대상 상품 명사**(신발·바지·모자·가방 등 티셔츠가 아닌 품목의 작은 명시 목록)가 오면 그 색은 include에서 억제("노란색 신발"의 노란색은 옷 색이 아님) ②색 표현이 **부정 문맥**("없으면"·"빼고"·"제외"·"안")의 스코프 안이면 include에서 억제(하드 배제 전환은 3b exclude 재정의에서 — 3a는 억제만). 규칙은 소비 span 위에서 동작하며, 목록·패턴은 좁게 시작하고 실존 테스트와 골든셋 함정 케이스로 고정한다.
- **완료 기준: 골든셋의 수식어·합성 실패 항목 전부와 함정 쿼리(q001·q005·q015·q028)·부정 문맥(q004의 "노란색이 없으면") 억제가 기대값과 일치하는 테스트가 통과한다.**

### 4. 소비 span과 제목 토큰 통합 (표류 차단)

- 추출기가 소비한 원문 구간(span: 시작·끝·원문)을 기록하고, 제목 잔여 토큰 추출이 그 구간을 제외하도록 연결한다(설계 §3.1 — 브랜드 소비 토큰 패턴의 span 격상).
- 제목 추출기의 색 스톱워드 목록과 사전을 **단일 소스로 통합**한다 — 두 목록이 따로 놀면 다시 표류한다.
- **완료 기준: 색 표현이 포함된 쿼리에서 제목 토큰에 색 표현이 새지 않고, 스톱워드-사전 단일 소스를 검증하는 테스트가 통과한다.**

### 5. 파이프라인 통합 — 사전 우선·LLM 색 무시

- 사전 추출 색을 provenance 메타(facet 사전 출처·hard·span 근거)로 내부 해석 산물에 주입한다. 사전이 커버한 색 축에서 LLM 색 값은 무시된다(사전 결과가 항상 우선 — 빈 결과 포함).
- P3-F의 결정화 레인은 값 단위 출처로 판정하므로 사전 색은 추가 분기 없이 flag-on 하드가 된다(기존 테스트로 고정됨). flag-off에서는 현행 동작 그대로(사전은 shadow 계산에만 참여).
- **cap 0 반영**: flag-on에서 LLM-only 색이 랭킹 가점을 받지 않고(가점 0) 응답 칩에서도 제거됨을 구현·고정한다("확정 사항"의 cap 0 정의).
- **완료 기준: flag-on 테스트에서 ①사전 색만 하드 조건·칩으로 남고 ②LLM-only 색은 랭킹 점수에 영향을 주지 않으며(동점 순위로 검증) ③flag-off 전체 테스트가 기존과 동일하게 통과한다.**

### 6. 기준 2·3 실측 — 색 축 하드 승격 판정 완성

- **기준 2**: 동결된 골든셋 50항목으로 사전의 집합 precision·recall을 순수 함수 테스트로 측정 — **게이트: precision ≥0.95**(전 항목·저확신 포함, T0a 확정), recall ≥0.90 참고.
- **기준 3 — counterfactual로 축별 귀속**: 스냅샷(2,472행) 기반 시뮬레이션에서 **같은 계획에 색 하드 조건만 켠 경우와 끈 경우를 비교** — 색 조건을 켰을 때만 사라지는 정답이 색 축 귀속 누락이다(E2E와 달리 원인 귀속 가능). **게이트: 색 축 누락률 ≤5%.**
- **함정 게이트(필수)**: `expected.colors=[]`인 함정 쿼리(q001·q005·q015·q028)에서 사전이 색을 include로 추출하지 않음(문맥 오추출 0)을 별도 게이트로 단언한다 — 이것 없이는 양성 쿼리만으로 ≤5% 통과가 가능해 핵심 함정 회귀를 놓친다. 통과 수단은 아래 "최소 문맥 규칙"(단계 3에 포함).
- 판정 문서에 색 축 3중 기준 표(충전율 99.0% ✓ / precision 실측 / 누락률 실측)를 완성하고, 골든셋 참조 구축이므로 "커버 증명" 한계를 명시한다.
- **완료 기준: precision·counterfactual 누락률·함정 세 게이트 테스트가 통과하고, 판정 문서에 색 축 3중 기준 완성 표가 보인다.**

### 7. GA4 shadow 계측 배선 (additive envelope 경로)

- **전달 경로 계약**: GA4 이벤트는 클라이언트에서 발화하므로, 서버가 계산한 shadow 요약을 **검색 응답에 additive 필드(shadow envelope)로 추가**해 응답→원격 호출부→뷰모델로 전달하고, 뷰모델이 계측 파라미터로 전송한다. **기존 응답 필드(결과·intent·mode·tier 표시)·화면·DB 호출은 완전 동일** — UI는 envelope를 무시한다.
- **전송 값은 유한 집합만**: 차이 유형(동일/사전만/LLM만/상이), 사전 추출 색 개수, canonical 색 값(통제 어휘 — 기존 parsed_* 관례와 동일), 규칙 버전. **후보 계획 키(전체 호출열 JSON)는 전송 금지** — 고카디널리티이며 원문 파생 정보 노출.
- **fail-open**: shadow 계산이 실패해도 검색은 정상 응답한다(envelope 생략) — shadow는 어떤 경로에서도 검색을 막지 않는다.
- **비용 상한**: shadow 계산은 추가 DB·LLM 호출 0(이미 있는 해석 산물의 순수 재계산만) — 완료 기준에서 확인.
- **완료 기준: dev에서 검색하면 계측 이벤트에 shadow 파라미터가 보이고(콘솔 관측), shadow 계산 실패 주입 테스트에서 검색이 정상 응답하며, DB 호출 횟수가 기존과 동일함이 테스트로 보인다.**

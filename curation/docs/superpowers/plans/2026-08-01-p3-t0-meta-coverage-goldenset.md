## 배경 — 이 작업이 무엇이고 왜 하는가

Phase 3는 색·핏·패턴·소재 같은 "닫힌 어휘" 검색 조건을 LLM 대신 결정적 사전이 추출해 하드필터로 쓰는 전환이다. 그런데 정확히 추출한 하드필터도 **카탈로그 메타데이터가 부실한 축에서는 정답 상품을 지운다**. 그래서 어떤 축을 하드필터로 승격해도 안전한지("hard-safe")를 데이터로 판정하는 3중 기준이 설계에 확정돼 있다:

1. **메타 충전율** — 해당 축 값이 채워진 검색 대상 상품 비율 ≥90% (빈 비율 ≤10%)
2. **매핑 precision** — 사용자 표현→카탈로그 어휘 매핑 정답률 (골든셋 필요)
3. **의도별 누락률** — 하드필터 적용 시 정답 상품이 빠지는 비율 (쿼리 골든셋 필요)

P3-T0는 이 판정의 **재료를 만드는 선행 측정 작업**이다: 기준 1은 지금 실측해 1차 판정까지 내고, 기준 2·3은 이후 단계(3a 이후, 사전 구현 뒤)에 측정할 수 있도록 골든셋을 구축한다. **제품 코드 변경은 없다.**

## 확정 사항

- **T0a/T0b 분리**: T0a(약 1일 — 골든셋 2종·독립 2회 라벨링 포함 시 반나절은 비현실적) = 충전율 전 축 측정·판정 + **색** 표현 골든셋 + 쿼리 골든셋 — 3a(색 축 파일럿)에 필요한 재료를 전부 확보한다. T0b = 핏·패턴·소재 표현 골든셋 — 3b 착수 전까지 완료하면 된다. 이 문서의 단계 1~6이 T0a, 단계 7이 T0b다.
- 충전율은 **원격 운영 DB를 읽기 전용으로 직접 측정**한다. 재실행 가능한 측정 스크립트를 repo에 커밋한다(도구·언어는 자유).
- 표현→어휘 골든셋의 정답 라벨은 **Claude가 단독 확정**하되, 아래 "라벨 신뢰 절차"를 따른다.
- 쿼리 골든셋은 **실사용 로그 기반**(GA4 `search_performed` 이벤트에 쿼리 원문이 실리는 것을 코드에서 확인함) + **설계 문서 §1의 실측 요동 쿼리**를 회귀 케이스로 포함한다.
- 사용자 원문 표현 수집용 서버 사이드 샘플링 로그는 **이 작업 범위가 아니다**(Phase 3c로 연기). 상위 설계 문서는 아직 "P3-T0에서 설치"로 적혀 있으므로 **단계 6에서 설계 문서도 이 일정 변경으로 갱신**한다.

## 측정·평가 방법 정의 (골든셋이 기준 2·3을 실제로 측정 가능한 형상이 되도록 T0에서 확정)

- **충전율의 주 판정 대상은 검색이 실제 조회하는 뷰(`search_goods`)의 최종 컬럼값**이다 — 하드필터가 이 뷰의 색·패턴·소재·핏 배열 컬럼과 성별·사이즈 컬럼을 직접 보기 때문이다. 무신사 facet 원천 테이블(`m_raw_facets`)은 뷰 값이 빈 **원인 진단용 보조 수치**로만 쓴다.
- **사이즈 축의 유효 충전 정의**: 검색은 표준 사이즈 배열이 겹치거나 **프리사이즈 표시가 참**이면 통과시키므로, "표준 사이즈 배열이 비어있지 않음 **또는** 프리사이즈 참"을 채워진 것으로 센다. 표준 사이즈 단독 측정은 프리사이즈 상품을 누락으로 오판한다.
- **원시/유효 충전율 병기**: 축별로 ①값이 하나라도 있는 비율(원시) ②무의미 값("기타색상"류)을 빈 값으로 취급한 비율(유효)을 둘 다 산출한다. 어느 쪽으로 판정할지는 단계 2 판정 문서에서 결론 낸다(열어두지 않는다).
- **매핑 평가식(기준 2)**: 1표현→다값이므로 표현 단위로 기대 집합과 산출 집합의 **집합 단위 precision·recall을 모두 기록**하고, 승격 판정의 주 지표는 precision으로 한다(설계 §3.2 문언과 일치). 임계값 수치는 지어내지 않는다 — **골든셋이 완성된 뒤인 단계 5에서 측정 분포를 근거로 제안하고, 사람이 확정**한다(결정 주체·시점을 이렇게 못박는다. 재료가 없는 단계 2에서 결정하지 않는다).
- **누락률 측정 형상(기준 3)**: 쿼리별로 "하드필터를 적용해도 반드시 남아야 할 **정답 상품 집합**"(상품 번호 소집합, 쿼리당 약 3~10개)을 라벨한다. 정답 상품은 **고정 카탈로그 스냅샷 기준**으로 고른다 — 스냅샷 = 충전율 측정 시점에 검색 뷰에서 **정답 판정에 필요한 최소 컬럼(상품 번호·제목·브랜드·색·패턴·소재·핏·성별·표준 사이즈 배열(size_std)·프리사이즈 여부(size_free)·가격)을 추출한 불변 export 파일**로 저장하고, 식별 정보(추출 시각·전체 행 수·콘텐츠 hash)를 함께 기록한다 — 행 수만으로는 속성 변경을 재현할 수 없으므로 내용 자체를 고정한다.
- **골든셋 동결**: 사전(3a) 구현이 시작되기 전에 골든셋을 동결하고, 이후 변경은 사유와 함께 버전 기록을 남긴다 — 구현에 맞춰 정답을 고치는 자기확증을 막는다.

### 라벨 신뢰 절차 (Claude 단독 확정의 리스크 완화)

- 라벨링을 **독립 2회**(항목 순서를 섞어 시차를 두고) 수행해 불일치 항목을 표시하고, 불일치는 재검토 후 확정한다.
- 확신이 낮은 항목은 확신 플래그로 표시한다. **분모 정책은 지금 고정한다**(사후 조정 금지): 주 판정 지표는 **저확신 포함 전체 지표**이고, 저확신 제외 지표는 진단 참고로 병기만 한다 — 분모에서 항목을 빼는 방식으로 지표를 개선할 수 없게 한다.

## 범위에서 제외 (비목표)

- facet 사전(기본색+수식어 문법) 구현 — Phase 3a.
- 기준 2(precision)·기준 3(누락률)의 **실측** — 사전이 생긴 뒤에만 가능. T0는 재료(골든셋)까지.
- 서버 사이드 샘플링 로그 — Phase 3c.
- 제품 코드·스키마 변경 일체.

## 단계 — T0a (약 1일)

### 1. 축별 메타 충전율 측정 (핵심 — 기준 1 실측)

- 대상 축: 색·패턴·소재·핏·성별·사이즈. **주 판정은 검색 뷰의 최종 값**, facet 원천 테이블은 보조(위 "측정·평가 방법 정의" 준수 — 사이즈는 프리사이즈 포함 정의).
- 원격 운영 DB에 읽기 전용 질의로 측정하고, 같은 측정을 누구나 다시 돌릴 수 있는 스크립트를 repo에 남긴다.
- 측정 결과 기록 항목: 실행 시각, 대상 환경 식별자, 축별 분모 정의, 전체 행 수, 축별 분자·원시 충전율·유효 충전율, 값 분포 상위 항목(무의미 값 비중), 상품당 값 개수.
- **완료 기준: 스크립트를 실행하면 위 기록 항목이 전부 포함된 축별 충전율 표(90% 통과 여부 포함)가 출력되어 보인다.**

### 2. hard-safe 1차 판정 문서화

- 1의 수치로 축별 **기준 1 판정만** 문서로 남긴다: 통과 축/미달 축, **무의미 값 처리의 결론**(원시/유효 중 무엇으로 판정하는지와 근거), 3a(색 축 파일럿)에 주는 시사점. 기준 2·3 임계값과 실쿼리 적합성 결론은 재료(골든셋)가 생긴 뒤 단계 5에서 다룬다 — 순서 역전 금지.
- 판정은 "기준 1만 통과한 상태"임을 명시한다 — 하드 승격은 기준 2·3까지 통과해야 하므로, 이 문서는 최종 승격 판정이 아니다.
- **완료 기준: 문서를 열면 축별 판정 표·미달 축 목록·무의미 값 결론·3a 시사점이 보인다.**

### 3. 색 표현→어휘 골든셋 구축 (기준 2 재료 — 3a 파일럿 대상 축)

- 색 축 30~50개 사용자 표현과 그 기대 매핑을 만든다.
- 표현 소스: **단계 4에서 GA4로 추출한 실쿼리에 등장한 색 표현(우선)**, 일반 한국어 색 표현(곤색·먹색·쥐색 등 사전 공백 후보 포함), 설계 문서의 예시 표현, §1 실측 쿼리에 등장한 표현, 팀 인터뷰·기획 문서에 있는 표현. (GA4 추출은 단계 4와 공유하므로 추출 작업을 먼저 해도 된다 — 단계 3·4의 순서는 자유.)
- 항목 구성: 사용자 표현 → 기대 카탈로그 어휘 값(1표현→다값이면 같은 축 내 전부 나열) + 비고 + 확신 플래그. 다음 케이스 유형을 **각각 최소 3개** 포함한다:
  - 직접 매핑(빨강→레드), 계열 매핑(파랑→블루 계열 여러 값), 수식어 합성(연한/진한/딥 + 기본색), 합성 실패 시 기본색 유지 케이스, **"매핑되지 않음이 정답"인 케이스**(사전이 침묵해야 하는 표현).
- 기대값은 전부 **현재 자동 생성 어휘 파일에 실존하는 값**만 쓴다. 실존 여부를 기계적으로 확인하는 자동 검사를 골든셋과 함께 둔다(어휘 재생성 시 표류 방지). 표현 중복·상호 모순 항목이 없는지도 같은 검사에서 확인한다.
- 라벨은 "라벨 신뢰 절차"(독립 2회·불일치 재검토·확신 플래그)를 따라 Claude가 확정한다.
- **완료 기준: 골든셋 파일을 열면 30개 이상 항목이 케이스 유형별 최소 3개씩·확신 플래그와 함께 보이고, 실존·중복 검사를 돌리면 통과가 보인다.**

### 4. 의도별 쿼리 골든셋 구축 (기준 3 재료)

- 실사용 검색 쿼리 원문을 GA4에서 추출한다. **추출 기간·건수·중복 제거 방법·개인정보 정제 결과(식별자성 문자열 제거)를 골든셋에 기록**한다.
- 추출한 쿼리를 의도 유형별로 분류·선별한다: 색 명시 / 핏·소재·패턴 명시 / **성별·사이즈 명시 / 정렬 요청 / 강제 표현("무조건"·"~만")** / 복합 조건 / 가격·브랜드 결합 / 착용감·감각 표현 / 일반 의류어 단독(browse 후보) / 배제 표현("~빼고").
- §1의 실측 요동 쿼리("2만원 이하 가성비… 바람 슝슝… 그림 간지…" 등)를 회귀 케이스로 반드시 포함한다.
- 목표 규모: **의도 유형별 최소 3개, 전체 30개 이상**. 실쿼리가 부족한 유형은 부족 현황을 보고하고 창작 보강 여부를 사람과 결정한다(미정 플래그 ①).
- 각 쿼리에 ①기대 해석(명시 조건이 무엇인가) ②**정답 상품 집합**(고정 스냅샷 기준 상품 번호 약 3~10개 — "측정·평가 방법 정의" 준수)을 라벨한다.
- **완료 기준: 골든셋 파일을 열면 추출 메타(기간·건수·정제 결과)와 의도 유형별 쿼리(유형별 3개 이상, 전체 30개 이상), 각 쿼리의 기대 해석·정답 상품 집합이 보인다.**

### 5. 판정 문서 보완 — 기준 2·3 준비 상태 결론 (골든셋 완성 후)

- 골든셋이 완성된 시점에 판정 문서에 추가한다: **기준 2·3 임계값 제안치**(골든셋 구성·측정 분포 근거 — 사람 확정 대기 표시), **실쿼리 양·질 결론**(추출 건수·유형 커버리지·부족 유형과 보충 결정).
- **완료 기준: 판정 문서를 열면 임계값 제안치와 실쿼리 적합성 결론이 골든셋 근거와 함께 보인다.**

### 6. 산출물 정리·PR (T0a 마감)

- 상위 설계 문서를 갱신한다: P3-T0 항목에 산출물 링크, **샘플링 로그의 3c 연기 반영**, T0a/T0b 분리·규모 재산정 반영.
- `develop` 대상 PR을 연다(측정 스크립트·골든셋 2종·스냅샷 export·판정 문서·설계 문서 갱신 — 제품 코드 무변경이므로 회귀 위험 없음).
- **완료 기준: PR을 열면 CI 초록불과 산출물 목록이 보이고, 설계 문서 diff에 3c 연기·T0a/T0b 분리가 보인다.**

## 단계 — T0b (3b 착수 전까지)

### 7. 핏·패턴·소재 표현→어휘 골든셋

- 단계 3과 동일한 절차·케이스 유형·검사·라벨 신뢰 절차로 축별 30~50개를 만든다.
- **완료 기준: 세 축 각각 단계 3과 같은 완료 기준을 통과한 것이 보인다.**

## 미정 플래그 (임의로 가정하지 않은 것)

- ① **실쿼리의 양·질**: GA4에 쌓인 쿼리가 적거나 팀 테스트·에이전트 트래픽이 섞여 있을 수 있다. 단계 4에서 추출 현황을 보고하고, 부족하면 보충 방법(타겟 정의 기반 창작 보강 등)을 사람과 결정한다. **단계 5에서 판정 문서에 결론을 기록한다.**
- ② **기준 2·3 임계값 수치**: 단계 5에서 측정 분포를 근거로 제안하고 사람이 확정한다(제안까지가 T0a 범위).

# 설계·계획 — 검색 결과 카드 호버 속성 요약 오버레이

작성일 2026-08-06 · 대상 브랜치 `fix/mobile-liquid-glass-ui`(진행 중 색-매칭 썸네일 작업 위에 얹음)

## 목적
검색 결과 리스트에서 상세 페이지에 들어가지 않고도 상품을 비교할 수 있게,
데스크톱에서 카드에 마우스를 올리면 이미지가 살짝 어두워지며 그 위에
핵심 속성(색·핏·소재·착용감) 요약을 띄운다.

## 확정 결정 (codex 리뷰 반영)
- 내용: 색(colors) / 핏(fits) / 소재(materials) / 착용감(wearChars). 값이 있는 축만.
  착용감은 한 줄로 묶음. 4축 모두 비면 오버레이·스크림 미표시.
- 표시 조건: `@media (hover: hover) and (pointer: fine)`의 호버 + 링크 `:focus-visible`.
  (`:focus-within`/`:focus` 금지 — 터치 후 잔류로 "모바일 무영향"과 충돌.)
- 모바일/터치: 변화 없음(탭 → 상세).
- 데이터: 검색 리스트 응답에 이미 colors/fits/materials/wear_chars 포함 → 백엔드/API 변경 없음.
- 카드 전체는 여전히 상세 `<Link>`. 오버레이는 `pointer-events:none` + `aria-hidden="true"`
  (스크린리더 접근성 이름 오염 방지; SR은 기존처럼 상세로).
- 대비: 이미지 전체 ~40% 스크림 + 텍스트 영역 뒤 더 진한 그라데이션.
- 모션: 기존 카드 호버(리프트+확대)는 유지, 그 위에 스크림+요약 레이어를 얹는다.
  `prefers-reduced-motion`이면 스크림·오버레이 전환 모두 즉시.
- 배지 겹침: 색 배지(`.tf-card__color`)는 호버 시 오버레이 아래로(오버레이가 우선).

## 구조 (작게 분리)
1. 순수 함수 `client/features/search/domain/card-summary.ts`
   - `Goods → { label, value }[]` (표시할 행만, 고정 순서).
   - 순서: 색 → 핏 → 소재 → 착용감.
   - 배열 축(색/핏/소재): 최대 3개 표시, 초과 시 `+N`.
   - 착용감: `WEAR_AXES` 순서(촉감→두께→비침→신축성→계절)로 `축 값` 쌍을 ` · `로,
     빈 값·미지 키 제외. 최대 3개 표시, 초과 시 `+N`.
   - 단위테스트로 순서·생략·+N·빈 입력([]) 검증.
2. `ResultList.tsx`: `.tf-card__frame` 안에 오버레이 마크업 하나 추가(요약 행이 있을 때만).
3. `globals.css`: `.tf-card__frame`에 스크림 가상요소 + 오버레이 표시 규칙(호버/포커스 미디어쿼리),
   텍스트 그라데이션, reduced-motion, 배지 z-index 조정.

## 단계별 완료 기준
1. card-summary 테스트 red → 구현 green (색·핏·소재·착용감 순서, +N, 빈→[]).
2. ResultList에 오버레이 마크업 추가 → 호버 시 요약이 이미지 위에 뜬다(눈으로 확인).
3. CSS: 데스크톱 호버에서 어두워지며 요약 표시 / 터치·키보드에서 의도대로 동작 / reduced-motion 즉시.
4. `npm run check` 통과 + 브라우저에서 호버 표시·터치 무영향·대비 확인.

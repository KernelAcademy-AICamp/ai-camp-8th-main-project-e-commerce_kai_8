# 리퀴드 글래스 디자인 적용 계획 (홈 → 결과 → 상세)

## 배경 (이 repo를 모르는 사람을 위한 설명)

- 이 서비스는 무신사 반팔 티셔츠를 자연어 문장("검정 바탕에 흰 레터링 백프린트")으로 검색하는 웹 앱이다. Next.js(App Router) + Tailwind 4 + Supabase로 만들어져 있고, 홈 / 검색 결과 / 상품 상세 3개 화면이 이미 동작한다.
- 2026-08-04~05에 디자인 리뉴얼 시안이 확정됐다. 시안은 `docs/design/mockups/` 폴더의 HTML 파일 4개다:
  - 홈: `2026-08-04-home-final.html`
  - 검색 결과: `2026-08-05-results.html`
  - 빈 결과(0건): `2026-08-05-results-empty.html`
  - 상품 상세: `2026-08-05-detail.html`
- 확정된 디자인 언어: 다크 배경(#0d0f13) + 네 모서리 잉크색(블루·퍼플·오렌지·그린) 글로우, 투명한 "워터드롭 유리" 검색창(캡슐 가장자리 굴절 + 상단 하이라이트), 숨어 있던 UI가 물방울 맺히듯 통통 튀며 나타나는 등장 모션, 텍스트 최소화, 서체는 Pretendard.
- 사용자 결정 사항: ① 홈부터 한 화면씩 적용하며 눈으로 확인, ② 배경 영상(4.6MB)은 repo(client/public/)에 커밋, ③ 서비스 이름은 "티:파운드"로 확정(타이틀·메타데이터 포함 교체).

## 이 계획이 하는 일 / 하지 않는 일

- 하는 일: 기존 3화면의 **겉모습(스타일·모션·레이아웃)을 시안대로 교체**하고, 빈 결과 상태 화면을 새로 추가한다. 검색 로직·데이터 흐름·URL 구조는 그대로 둔다.
- 하지 않는 일: 검색 파서 기능 확장(아래 미정 참고), 새로운 페이지 추가, 배포(릴리즈는 별도 절차).

## 미정 (지어내지 않고 남겨두는 것)

- **조건 토큰의 분류 체계**: 시안은 "바탕색 × 프린트색 × 위치" 3분류를 보여주지만, 현재 검색 파서는 색·패턴·핏·가격·성별까지만 추출한다(바탕/프린트/위치 구분은 P3 로드맵). → 이번 적용에서는 **파서가 실제로 추출한 속성을 토큰으로 표시**하고, 3분류 토큰은 파서가 확장되는 시점에 다시 다룬다.
- **빈 결과의 "조건 완화 제안" 개수 표시**: 시안은 각 제안 옆에 상품 개수를 보여준다. 개수를 실시간으로 세는 방법(추가 쿼리)과 개수 없이 제안만 보여주는 방법이 모두 가능하다. → 구현 시점에 간단한 쪽부터 시도하되 방식은 못박지 않는다.

## 단계

### 1단계 — 홈 화면 (공통 디자인 기반 포함)

무엇을:
- 배경 영상(`docs/design/mockups/assets/hero-loop.mp4`)과 포스터 이미지를 client의 정적 파일 폴더로 옮긴다.
- 디자인 공통 요소(다크 배경 색, 유리 질감, 물방울 등장 모션, 오로라 글로우)를 전역 스타일로 정의해 이후 화면에서 재사용할 수 있게 한다.
- 홈 화면을 시안대로 교체한다: 영상 배경(부메랑 루프) + 헤드라인 2줄 + 워터드롭 검색창. 검색창을 클릭하면 검색 버튼과 추천 질의 칩 3개가 물방울 모션으로 나타나고, 플레이스홀더에 예시 질의가 타이핑된다. 검색 실행 시 기존과 동일하게 결과 화면으로 이동한다.
- 서비스 이름을 "티:파운드"로 교체한다(화면 워드마크, 브라우저 탭 제목, 메타데이터).
- 접근성·성능 처리: 모바일/데이터 절약/모션 최소화 환경에서는 영상 대신 포스터만 보여준다.

완료 기준(관찰 가능):
- 로컬 서버에서 홈에 접속하면 시안과 같은 화면이 보인다.
- 검색창에 문장을 입력하고 실행하면 기존처럼 결과 화면으로 이동한다.
- 브라우저 탭에 "티:파운드"가 보인다.
- 브라우저 폭을 모바일 크기로 줄이면 영상 대신 정지 이미지가 보인다.

### 2단계 — 검색 결과 화면 + 빈 결과 상태

무엇을:
- 결과 화면을 시안대로 교체한다: 다크 오로라 배경, 상단 고정 헤더(축소형 유리 검색창, 아래로 갈수록 배경이 흐려지며 사라지는 처리), 검색 API 응답의 해석 결과(intent)를 물방울 토큰으로 표시(색 토큰에는 색상 견본 원 포함), 결과 개수, 상품 카드 그리드(로드 시 순차 등장, 호버 시 떠오름 + "조건 일치" 배지).
- 결과가 0건일 때: 시안의 빈 결과 상태를 보여준다 — 안내 문장 두 줄 + 조건 완화 제안 칩(누르면 완화된 질의로 재검색).
- 기존 검색 동작(질의 파라미터, 재검색, 상세 이동 링크)과 GA 계측은 그대로 유지한다.

완료 기준(관찰 가능):
- 실제 질의("검정 오버핏 반팔")로 검색하면 시안과 같은 결과 화면이 보이고, 해석된 조건이 토큰으로 나타난다.
- 결과가 0건인 질의를 넣으면 빈 상태 화면과 완화 제안이 보이고, 제안을 누르면 재검색된다.
- 카드를 누르면 기존처럼 상세 화면으로 이동한다.

### 3단계 — 상품 상세 화면

무엇을:
- 상세 화면을 시안대로 교체한다: 좌측 이미지 갤러리(썸네일 클릭으로 메인 교체), 우측 정보 패널(브랜드/제목/가격/별점, 속성 물방울 토큰, 색상 견본, 사이즈 칩, 리뷰 키워드 일부, "무신사에서 보기" 버튼).
- 헤더는 검색창 없이 뒤로가기 버튼 + 워드마크만 둔다. 뒤로가기는 직전 검색 결과로 돌아간다.

완료 기준(관찰 가능):
- 결과 화면에서 카드를 누르면 시안과 같은 상세 화면이 보인다.
- 썸네일을 누르면 큰 이미지가 바뀐다.
- "무신사에서 보기"를 누르면 해당 무신사 상품 페이지가 새 탭으로 열린다.
- 뒤로가기를 누르면 검색 결과로 돌아간다.

### 4단계 — 품질 마무리

무엇을:
- 코드 품질 검사(lint·타입·포맷)를 통과시킨다.
- 3화면을 데스크톱/모바일 폭, 모션 최소화 설정에서 눈으로 점검한다.
- 기존 GA 이벤트가 그대로 발생하는지 확인한다.

완료 기준(관찰 가능):
- `npm run check`가 통과한다.
- 모바일 폭에서 가로 스크롤이 없고, 터치 요소가 잘리지 않는다.
- 검색 실행 시 GA 이벤트가 이전과 동일하게 기록된다(디버그 화면 또는 네트워크 요청으로 확인).

## 진행 방식

- 각 단계는 develop에서 딴 작업 브랜치에서 진행하고, 단계 완료 시 사용자가 눈으로 확인한 뒤 다음 단계로 넘어간다. 커밋·PR은 사용자가 요청할 때 만든다.
- 시안 HTML은 참조 원본으로 계속 보존한다(`docs/design/mockups/`).

## 한 줄 요약

**클라이머가 "튀는 색 클라이밍화에 맞출 백프린팅 티"처럼 말로 표현한 시각·감각 속성으로 프린팅 반팔티를 찾고 한눈에 비교하는 LLM 발견 검색.** 지금은 검색 프론트·데이터 수집·배포 인프라가 동작하고, 다음 관문은 **상품 속성 자동 추출의 정확도**입니다. 이 프로젝트의 목표는 "완성된 서비스"가 아니라 **"데이터로 의사결정하는 3×2주 린 루프"를 입증**하는 것입니다.

---

## 1. 무엇을 만드나

**문제.** 그래픽·프린팅 티는 온라인에 많지만 **흩어져 있고**, "흰 바탕에 노란 백프린팅"처럼 **말로 떠오르는 시각 속성으로는 검색·비교가 안 됩니다.** (PM 본인이 이런 티를 네이버·무신사에서 4시간 찾다 실패한 관찰이 출발점 — 단, 현재 근거는 n=1이라 인터뷰로 확대 검증이 필요합니다.)

**타겟 (beachhead).** **클라이머.** 클라이밍은 백프린팅 문화에 진심이고, "튀는 색 클라이밍화에 코디할 티"라는 뚜렷한 JTBD가 있어 첫 교두보로 선택했습니다.

**솔루션.** 자연어 질의를 LLM이 **속성 조합(바탕색 × 프린팅색 × 프린팅 위치 × 핏 × 기능성 …)** 으로 해석하고, 결과를 카드로 한눈에 비교하게 합니다. 색은 옷 전체색이 아니라 **바탕색과 프린팅색을 분리**해 다루는 것이 킬러 포인트입니다.

**범위 (일부러 좁힘).** 카테고리는 **프린팅 반팔티 1종**으로 고정. 실결제·장바구니·찜은 MVP에서 제거했고, 전환 신호는 **상품 페이지로 나가는 outbound 클릭**으로 잡습니다.

## 2. 어디까지 왔나

### 동작하는 것 ✅

| 영역 | 상태 |
|---|---|
| **검색 프론트** | 검색 랜딩 → 결과 → 상세 3화면. 자연어 → LLM 파싱 → Intent → 검색. **정확 일치 / 부분 일치 구분**, LLM이 이해한 조건을 **의도 칩**으로 보여주고 `×`로 삭제·재검색. (Next.js 16 · React 19 · Clean Architecture/MVVM) |
| **데이터 파이프라인** | **네이버 쇼핑 API 수집 → Supabase 적재** 동작. 브랜드 사전 99개 시드, 성별 분류, upsert 충돌키 정리. (Python) |
| **인프라·운영** | Vercel 자동 배포(수동 Release 버튼), CI(lint·typecheck·build), CodeRabbit 코드리뷰, **Sentry 에러추적 3면 + Sentry→Slack 알림 릴레이**까지 완비. |

### 핵심 공백 ⚠️

- **상품 속성 자동 추출이 아직 안 돌아, Supabase 속성 컬럼(바탕색·프린팅색 등)이 대부분 비어 있습니다.** 그래서 실데이터 조건 검색은 대부분 0건이고, 지금까지는 **목업 + 단위 테스트로 검색 UI만 선(先)검증**한 상태입니다. → 이것이 다음 최우선 과제(3-4번 참조).
- **행동 계측(Amplitude)은 seam만 준비**되어 있고 실제 연동은 Loop2 예정. (`track()`이 현재 no-op 스텁)

## 3. 앞으로 계획

전체 실행 구조는 **3 × 2주 = 6주, Build–Measure–Learn 린 루프**입니다. 지금은 **Loop1 후반**입니다.

**Loop1 남은 일 (지금~게이트).**
1. **비전 LLM 속성 추출 배치** — 수집한 상품 이미지에서 바탕색/프린팅색/위치를 뽑아 속성 컬럼을 채운다.
2. **사람 검증 + 정확도 측정** — 골든셋 대비 추출 정확도를 잰다 (임계 예: ≥80%).
3. **클라이머 인터뷰 3~5명** — 문제·솔루션이 진짜인지, "쓰겠다"가 나오는지 확인.

**Loop1 의사결정 게이트.** 위 세 신호(추출 정확도 / 검색 성공률 / 인터뷰 반응)를 보고 **Loop2에 무엇을 투자할지** 결정합니다 — 카탈로그 확장, 추출 정밀화, 신발색 매칭 훅 등.

---

## 4. 무엇에 중점을 두나

1. **"데이터로 의사결정"의 입증이 이 프로젝트의 본질입니다.** 화려한 완성도가 아니라, 각 루프에서 지표를 보고 다음 투자처를 정하는 과정을 증명하는 것이 목표입니다.
2. **최대 기술 리스크 = 바탕색/프린팅색 분리 추출 정확도 (H1).** "흰 바탕 + 노란 프린팅"을 두 색으로 정확히 분리하는 것이 솔루션 전체의 성패를 가릅니다. OpenCV + 비전 LLM 하이브리드로 접근 중.
3. **지표.** 북극성 = **구매 진입(상품 페이지 outbound 클릭) 비율.** 선행 퍼널(검색 성공률 → CTR → 상세 도달 → 구매 진입)과 가드레일(no-result율·오검색)로 받칩니다. (부트캠프 규정상 GMV·CVR 직접 주장은 금지.)

## 5. 멘토님과 논의하고 싶은 것

**프로젝트 실행 관점**

1. **우선순위·범위** — 6주 안에서 지금 **속성 추출에 집중하는 판단이 맞는지**, 더 줄이거나 당겨야 할 것은 없는지.
2. **기술 리스크 돌파** — **바탕색/프린팅색 분리 추출(H1)** 정확도를 끌어올리는 접근과, 리뷰·상세정보가 없는 데이터 한계를 메우는 전략에 대한 조언.
3. **지표·의사결정** — 북극성(구매 진입 클릭)과 **Loop1 게이트 판정 기준(정확도 임계·인터뷰 신호)이 타당한지**, 표본이 작은 초기에 무엇을 믿고 결정할지.

**PM 커리어 관점** — 이 프로젝트를 저(신규 PM 지원자)의 역량 증거로 봐 주신다면:

4. **가산 요소 vs 주의 요소** — 채용하는 시니어 PM의 눈으로 볼 때, 이 프로젝트에서 **플러스로 읽히는 지점**은 어디이고, **오히려 감점·의심을 살 수 있는 지점**(예: n=1 근거, 미완성 범위)은 무엇인지. 어떻게 보완하면 좋을지.
5. **린 · 데이터 기반 과정을 전면에 녹이는 게 유효한지** — "최소 MVP를 린하게 돌리고 → **유저 데이터로 의사결정을 반영·수정**하는 과정 자체"를 이 프로젝트의 핵심 서사로 내세우는 것이, PM 역량을 보여주는 방식으로 실제로 설득력 있는지. 결과물의 완성도보다 이 과정을 강조하는 방향이 맞는지.

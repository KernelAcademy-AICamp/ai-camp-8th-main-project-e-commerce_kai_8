## 1. 데이터 — 수집·품질

### 1-1. 네이버 API의 구조적 한계 → 결국 무신사 피벗 (D14)

- **문제**: 검색축을 채울 데이터가 네이버 쇼핑 API에서 안 나왔다. 소재·리뷰·상세설명 미제공, brand 필드 76% 빈값, 긴팔/반팔 분류 약 24% 오분류.
- **버틴 방법**: 제목 우선 소매 필터, 제목·mall_name 발굴 + 도메인 지식의 반자동 브랜드 큐레이션(사전 53개), `classify_gender(title)` 백필.
- **한계와 결정**: 우회로 채울 수 없는 건 데이터 소스 자체의 품질이었다. 무신사는 44색 공식 필터·정돈된 카테고리를 제공 → **데이터 소스를 무신사로 전환**(D14, 7/30). 문제 정의(D2)는 불변, 바뀐 건 운영상 데이터 품질 판단.
- **결과**: raw 랜딩 ELT 재구축(m_raw_goods 3,658건 → searchable 2,472건), 네이버 코드 31파일 삭제 (#32).

### 1-2. DB 오염 — 티셔츠가 아닌 상품 혼입

- **문제**: 바지·양말·아우터·긴팔이 DB에 유입. 카테고리만 믿은 필터가 원인 — 네이버 검색은 키워드만 맞으면 티셔츠로 분류했다.
- **해결**: 제목 기반 네거티브 필터 보강 (#25). 아우터라도 제목에 '티셔츠'면 유지해 과차단 방지.
- **결과**: 실 DB 1,685건 재적용 시 아우터/바지/양말 잔존 0건, 정상 반팔 오차단 0건. 기존 오염분 121건은 별도 삭제.

### 1-3. 무신사 수집의 제약 — 공식 API 없음

- **문제**: 무신사는 공식 오픈API가 없고, 약관 원문도 확인 불가.
- **해결**: 공개 상품정보를 소량·저빈도(UA/Referer 헤더, sleep 0.3s+, 429/5xx 백오프)로 수집하고, 범위를 포트폴리오·비상업으로 한정. "상업적으로 문제없다"고 **주장하지 않는** 리스크 관리 (D16). 다중디자인 번들("N종")은 `searchable=false`로 검색에서 격리.

## 2. LLM 검색 품질 — 가장 굵은 줄기

프로젝트 전체를 관통하는 서사: **LLM에 맡겼던 판단을 하나씩 결정론(사전·정규식·하드필터)으로 회수해온 과정.**

### 2-1. 파싱 모델 선택 반전 — 벤치마크와 실서비스는 다르다

- **문제**: 벤치마크로 채택한 qwen3-next-80b(≈2s, 환각 0)가 실서비스에서 15~45초 → 클라이언트 7초 타임아웃에 걸려 상시 규칙 파서 폴백, 사실상 미사용 상태.
- **해결**: 벤치마크에서 환각이 많아 탈락시켰던 llama-3.1-8b(평균 0.8s)로 교체하고, 환각은 프롬프트로 억제 (#20).
- **교훈**: 속도는 품질의 전제조건이었다. 환각은 이후에도 계속 문제가 되어(§2-4) 결정론 레인의 근거가 됐다.

### 2-2. "하나도 못 찾네" — 구조화 속성만으로는 못 찾는다

- **문제**: LLM이 뽑은 소수 구조화 속성만 매칭해서 제목·설명의 표현("홀로그램", "곰")으로 상품을 못 찾았다.
- **해결**: 의미(임베딩)+어휘(제목)+속성 3축 하이브리드 랭킹 (#24).
- **결과**: 골든쿼리 "홀로그램…" 상위 10개 전부 정답(이전 0개). 단, 리뷰에서 어휘 축이 사실상 주도하고 임베딩은 보조임이 드러남 — 이후 lexical 레인 강화의 복선.

### 2-3. "흰티가 60개만 나와요" — 소프트 신호의 한계

- **문제**: 화이트 상품이 DB에 734개인데 60개만 노출. top-N 컷 + 색이 순위만 매기는 소프트 신호였던 게 원인.
- **해결**: 색·패턴·소재·핏을 하드 필터로 전환, 결과 상한 60→300 (#33).
- **결과**: "흰티" → 300건 전부 화이트. 그러나 하드필터는 새 문제를 낳았다(§2-4, §2-7).

### 2-4. 하드필터 × 파서 환각의 충돌

- **문제**: "여자 전용상품만 추천해줘"에 LLM이 size 90·화이트·면을 환각. 색이 하드 필터가 된 직후라(§2-3) 환각이 결과를 실제로 잘못 좁혔다.
- **해결**: 프롬프트에 환각 금지 규칙 강화 (#34). 단, 이는 대증요법 — codex 리뷰에서 8b 모델 기반 하드필터의 구조적 취약성이 드러나 브랜드 하드검색을 보류하고 **결정적 사전 기반 재설계**로 방향 전환.

### 2-5. 브랜드·제목·가격 — 정확 토큰은 LLM에 태우지 않는다

- **문제**: 브랜드 검색이 안 됐고, "택티컬 티셔츠"는 환각 패턴 6종 때문에 0건, "2만원"은 2,000원으로 오파싱, 대화 필러("내가 105 입는데…")가 제목 하드 게이트가 돼 0건.
- **해결**: 정확 토큰은 결정적 경로로 —
  - 브랜드: 운영 사전(218행) n-gram 정확 매칭 + eq 하드필터 (#35)
  - 제목: tier 폴백(정확 구문→AND→OR) + 전 tier 0건이면 환각 필터 벗겨 재시도 (#36)
  - 가격: 결정적 정규식 파서가 LLM 값을 덮어씀 (#36)
  - 빈 파싱 시 상위 300개가 결과처럼 노출되던 구멍은 `mode: full|lexical_only|failed` 계약으로 봉쇄 (#35)
- **결과**: 브랜드 리콜 217/217·오탐 0, 제목 상위10 정밀도 100%.

### 2-6. LLM 비결정성 실증 — "같은 검색=같은 결과"가 성립하지 않는다

- **문제**: temperature 0으로도 같은 쿼리의 결과가 회차마다 요동(LLM 호스팅 비결정성).
- **측정**: 골든셋 3회 반복 채점 (#39) — 색 매핑 precision **36.9%**, coverage 68.9~100% 요동, 침묵 정확도 0%("먹색"은 매회 다른 오답), E2E 정답 누락 68.3%.
- **의미**: Phase 3 closed-world 결정화(색 등 닫힌 어휘를 LLM 대신 사전이 추출)가 감이 아니라 **측정된 근거 위의 결정**이 됐다.

### 2-7. 하드필터가 정답을 지우는 함정 — 축별 hard-safe 판정

- **문제**: 정확히 추출한 하드필터도 카탈로그 메타가 부실한 축에서는 정답 상품을 지운다.
- **해결**: 축별 메타 충전율 실측으로 하드 승격 가부를 데이터로 판정 (#37) — 색 99.0%·패턴 99.8%·성별 99.7%·사이즈 96.4% 통과 / **소재 85.9%·핏 42.7% 미달 → 하드 승격 금지, 소프트 유지**. 패턴은 충전율 통과에도 메타 오기(스트라이프)로 위험 판정.
- **구조 정비**: LLM 값과 결정적 값이 출처 구분 없이 섞여 있어 "어떤 값을 하드로 믿어도 되는가"를 코드가 알 수 없던 문제를 provenance 구조(값 단위 ConstraintMeta·QueryPlan 분리·feature flag)로 해결 (#38).

## 3. 프로세스 — 근거가 틀렸을 때 고친 기록

### 3-1. D7 근거 오류 — "PM 본인=클라이머"가 사실이 아니었다

- **문제**: 첫 타겟(클라이머)의 근거였던 "PM 본인=클라이머(직접 관찰)"가 사실과 달랐다 — 클라이머는 팀원 1명이고, 문서가 PM이 체감하지 못하는 언어로 쌓여 서사와 산출물이 어긋나 있었다.
- **해결**: 근거를 정정하고 타겟을 재정의(D15: "등이 보이는 운동" → 이후 D17). 단일 사건에 기댄 "장비색 코디" 축은 하위 트리거로 격하.

### 3-2. "우리가 대던 근거가 틀렸다" — VoC 리서치로 주장 교정 (D17)

- **문제**: "사용자가 원래 바탕색/프린트색을 나눠 말한다"는 우리의 전제가 약했다 — 웹 리서치 결과 사진을 던질 수 있으면 아무도 색을 말로 안 쓰고, 종목 트리거 중 클라이밍(원래 진입점)이 최약(언급 1건, 러닝 25건).
- **해결**: 주장을 "사진 없이 설명할 때만 바탕색/프린트색/위치로 쪼갠다(영어권 72%)"로 교정하고, 타겟 정의에서 트리거를 빼고 검증된 축만 남김(D17). 트리거는 인터뷰로 검증할 가설로 강등.
- **교훈**: 이 축은 사용자가 먼저 꺼내는 언어가 아니라 **시스템이 제공해야 고를 수 있는 축**이다. 미검증 가설을 정의에 박지 않는다.

### 3-3. Phase 3a 착수 보류 — 사람이 멈춘 결정

- **문제**: 색 사전 결정화(3a)를 현 데이터만으로 진행하면 과적합 우려. D17의 코어 축(프린트색·위치·subject)이 현 카탈로그 메타에 아예 없다는 것도 명시적 blocker.
- **결정**: baseline 실측(§2-6)까지 마친 상태에서 **착수 보류**(8/1, 사람 결정). 데이터 보강(프린팅 정보 메타·리뷰 수집) 선행 후 재개.

## 4. 반복된 패턴과 다음 단계

**패턴 — 프로젝트가 반복적으로 배운 것:**

1. **LLM 판단의 결정론 회수**: 파싱 환각(§2-4) → 브랜드 사전(§2-5) → 가격 정규식(§2-5) → 색 사전 계획(3a). 확률적 추출은 열린 표현에만, 닫힌 어휘·정확 토큰은 결정적 경로로.
2. **감이 아니라 측정으로 결정**: 모델 교체(실측 지연), 하드 승격(충전율), 결정화(baseline 36.9%), 타겟 재정의(VoC 계수). 큰 결정마다 앞에 측정이 있었다.
3. **틀린 근거는 문서로 정정**: D7 근거 오류, VoC 주장 교정 모두 기록으로 남기고 결정 체계(D번호)를 갱신했다.

**다음 단계 (2026-08-01 기준):**

- Phase 3a(색 사전 shadow)는 보류 중 — 재개 조건: 프린팅 정보 메타 확보 + 리뷰 수집·적재
- 하드 승격 게이트: precision ≥ 0.95 · 축별 누락률 ≤ 5% (사람 확정)
- 미배포 잔여: #36~#39가 develop에만 있음 (프로덕션 v0.2.6)

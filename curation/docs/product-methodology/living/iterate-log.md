## Loop 1 (W1-2) — 가치검증 + 최소 자동추출

### 중간 의사결정 — 데이터 소스 전환: 네이버 쇼핑API → 무신사 (2026-07-30 기록)
- **결정**: 카탈로그·속성 추출의 데이터 소스를 네이버 쇼핑API에서 무신사로 전환. README D3·D4 폐기 → D14로 대체.
- **이유 (솔직 버전)**: 문제가 바뀌어서가 아니라 **운영상 데이터 품질** 때문. 태깅·검증 파이프라인을 돌려보니 무신사가 54색 공식 색 필터·정돈된 카테고리·상품정보를 제공해 자동추출 검증과 바탕색 기준표 수립에 유리했다. (근거: 무신사 필터 컬러칩 수집·기준표 비교 — 태깅 repo 커밋 `cfe4e84`)
- **문제정의에 미치는 영향**: 핵심 문제(D2 "말로 표현한 시각·감각 속성으로 못 찾음")는 불변. 문제 무대가 "포털 검색 전반" → "무신사 내 발견"으로 좁혀져 오히려 선명해짐 — 상품과 필터가 다 있는 플랫폼에서도 '바탕색×프린팅' 조합 발견은 불가.
- **후속 조치**: problem-validation·data-feasibility·PRD §1·§6·§7·§10 갱신 (2026-07-30 문서 갱신에서 처리)

### 중간 의사결정 — 첫 타겟 조정: 클라이머 → "등이 보이는 운동"을 하는 사람 (2026-07-30 기록, D15)
- **결정**: beachhead를 "클라이머"에서 **"등이 보이는 운동을 하는 사람"**(러닝·라이딩·클라이밍·크로스핏 등)으로 조정. **Loop1 표본 = 클라이밍 + 크로스핏**(현실적으로 닿는 두 종목). README D7 갱신 → **D15** 신설.
- **축을 고른 이유(핵심)**: 운동 중 **남에게 보이는 건 등판**이라 이 사람들에게 티셔츠의 정면은 사실상 등이다. 이 한 문장이 **P0 설계 전체를 설명한다** — 결과 카드가 왜 대표컷이 아니라 등판 컷을 먼저 보여야 하는지, 왜 무신사 54색 색상 필터로는 구조적으로 도달이 안 되는지(등판 그래픽 색은 상품 대표색에 안 잡힘). 게다가 쇼핑몰이 등판을 대표컷으로 안 쓰는 한 이 페인은 **구조적**이라 개인 취향 사건에 안 기댄다.
- **중간에 거쳐간 안**: "장비색 코디"(튀는 색 신발에 색 맞추기)를 한 번 축으로 세웠으나, 조합 검색 필요는 잘 설명해도 **근거가 팀원 1명의 단일 사건**이라 세그먼트를 지탱하기엔 약했다 → 축이 아니라 **하위 트리거**로 격하.
- **이유 (솔직 버전)**:
  1. **D7의 근거가 사실과 달랐다.** D7·customer-profile은 "PM 본인=클라이머(직접관찰)"를 세그먼트 선택 근거로 걸었는데, **클라이머는 팀원 1명이고 PM은 그 도메인 밖**이다. 4시간 탐색 실패 사건도 그 팀원의 경험이다(2026-07-30 정정). 근거 자체는 살아 있다 — 겪은 사건이지 도메인 전문성 주장이 아니었으므로.
  2. **도메인 감각이 팀원 1명에 걸린 단일 의존점.** 클라이밍 특화로 파고들수록 그 팀원이 없는 자리에서는 팀이 감으로 판단하게 되고, 문서도 PM이 체감 못 하는 언어로 쌓인다(실제로 문서가 그렇게 됐다). 대응은 두 갈래: **종목 고유 지식이 있어야 성립하는 요구사항은 P0에서 뺀다**(지금 P0는 전부 종목 무관이라 충족), **클라이머 인터뷰 모집·용어 검수는 그 팀원이 오너**로 남긴다.
  3. **제품이 이미 종목 무관이었다.** 카탈로그는 무신사 프린팅 반팔티 일반이고 속성 스키마(바탕색·프린팅색·위치·핏·소재)에 종목 축이 없다. 문서만 클라이밍이라 **서사와 산출물이 어긋나 있었다** — 어긋난 걸 맞춘 것이지 방향을 튼 게 아니다.
- **문제정의에 미치는 영향: 없음.** 5Why 재정립(구조화의 축 ≠ 사용자의 탐색 언어)에는 종목이 한 글자도 안 걸려 있다. 요구사항(P0)·지표·스키마 전부 불변. **바뀐 건 "누구부터 만나느냐" 하나.**
- **왜 더 넓히지 않았나**: "그냥 프린팅 티 찾는 사람"까지 가면 **등판이 왜 중요한지가 사라져** 카드 설계·색 분리의 근거가 통째로 없어진다.
- **감수한 것(플래그)**: ① 세그먼트 **모수 미조사** — 클라이밍 ~50만은 한 종목 숫자이므로 전체 크기로 쓰지 않는다. ② **Loop1 표본이 실내 시설 종목 2개로 치우침** — 축의 대표인 러닝·라이딩은 지금 모집 경로가 없다. 결과를 축 전체로 일반화하지 않는다.
- **되돌리는 조건(줌인 신호)**: ① 인터뷰에서 **"등판이 보인다"를 아무도 스스로 말하지 않으면** 축이 무너진 것 → 재정의. ② 원하는 게 대부분 **굿즈(암장·박스 티)**면 무신사 기성품으로는 못 푸는 문제 → 세그먼트 재검토. 넓힌 게 아니라 흐려진 것이 이 결정의 실패 모드다. (되돌릴 경우 클라이밍 특화 판단은 클라이머 팀원이 오너 — 위 ②.)

### 중간 의사결정 — 타겟 정의에서 연령 제거 (2026-08-03 기록, D20)
- **결정**: 첫 타겟 정의를 "…못 찾는 **20~30대**"에서 **"운동할 때 입을 티도 '보여지는 나'로 여겨 색·그래픽까지 취향대로 고르는 사람(연령 무관)"**으로 바꾼다. 사람을 가르는 변수는 연령대가 아니라 **'운동복을 취향으로 고르느냐'는 행동**이다. D17의 정의 문구만 갱신하고 축은 그대로다.
- **이유**: "20~30대"는 **문제 축도 아니고 보이는 속성도 아닌 조건**이었다. 조합 검색이 안 되는 건 나이와 무관하고, 근거로 쓰는 VoC는 **연령을 측정한 적이 없다.** 검증 안 된 조건을 정의에 넣는 건 D15·D17에서 이미 두 번 고친 실패 모드(미검증 축 위에 정의를 세움)의 반복이다.
- **문제정의에 미치는 영향: 없음.** 검증된 하한선은 여전히 **문제 축**(프린팅 티를 바탕색×프린트색×위치 조합으로 못 찾음). '등판 보임'·'장비색 깔맞춤'도 그대로 **진입 트리거 가설**이고 정의에 넣지 않는다(D17 불변). 요구사항·지표·스키마 불변.
- **감수한 것(플래그)**: 행동 기준 정의는 **인터뷰 스크리닝으로 판별하기가 나이보다 어렵다** — "운동복을 취향으로 고르는가"를 우리가 물어보면 유도가 되므로, 블록1·2에서 자발 서술로 읽어야 한다(→ [interview-guide](interview-guide.md)).
- **되돌리는 조건**: 인터뷰·데이터에서 연령대가 실제로 행동을 가르는 변수로 드러나면 그때 근거와 함께 다시 넣는다. 지금은 근거가 없어서 뺀 것이다.

### 중간 의사결정 — 범위 = 스포츠 프린팅 티셔츠 전반 (2026-08-03 기록, D19 · D18 폐기)
- **결정**: 우리가 다루는 범위는 **스포츠 프린팅 티셔츠 전반**이다. VoC에서 조사한 종목 전체(러닝·클라이밍·크로스핏·골프·테니스 등)를 타겟 범위로 두고, **Loop1 모집 표본도 한 종목으로 고정하지 않는다**(종목 혼합). 같은 날 아침에 넣은 D18(크로스핏 제외 → 클라이밍 단독)은 폐기한다. 세그먼트 정의(D17 문제 축)는 그대로다.
- **왜 D18을 폐기하나**: D18의 관찰(크로스핏 근거 0건)은 맞았지만 **대응이 틀렸다.** 근거가 없으면 표본을 좁히는 게 아니라 **표본의 근거를 종목별로 기록**하면 된다. 한 종목으로 좁히는 순간 D15에서 이미 겪은 실패 모드로 되돌아간다 — **문서만 한 종목이고 제품은 종목 무관**인 상태(카탈로그는 무신사 프린팅 반팔티 일반이고 속성 스키마에 종목 축이 없다).
- **조사 근거도 클라이밍 단독을 지지하지 않는다**: 종목별 신호는 러닝 25 ≫ 골프 11 > 테니스 3 ≫ 클라이밍 1이다. 표본을 클라이밍으로 고정하면 **조사에서 가장 약했던 종목만 보게 된다.**
- **문제정의에 미치는 영향: 없음.** D2·요구사항·지표·스키마 불변. 바뀐 건 범위 인식과 표본 구성 방식.
- **감수한 것(플래그)**: ① 종목별 신호 편차가 크고, VoC는 "스포츠 전반으로 넓히면 신호가 희석된다"고 경고한다 → 대응은 **인터뷰에서 종목을 반드시 기록하고 결과를 종목별로 쪼개 읽는 것**이지, 표본을 좁히는 것이 아니다. ② 러닝·라이딩은 아직 모집 경로가 없어 **실제 표본 구성은 미정**(모집 가능한 종목부터, 최소 1명 클라이머). ③ 축 전체 모수는 여전히 미조사 — 숫자 주장 금지.
- **되돌리는 조건**: 인터뷰에서 **종목마다 페인의 형태가 근본적으로 다르면**(예: 골프처럼 상의가 아니라 벨트·모자 매칭) 범위를 종목군으로 쪼갠다. 그때도 기준은 "모집이 되느냐"가 아니라 **"같은 축으로 설명되느냐"**다.
- **후속 조치**: README 결정표(D18 폐기·D19 신설), PRD 머리말·§4·§10·변경이력, customer-profile, interview-guide, mvp-plan, problem-validation, context, 루트 README 갱신(2026-08-03 처리).

### 중간 의사결정 — 색 수치 3종 분리: 54색 / 53종 / 44색 (2026-08-04 기록)
- **결정**: 문서에서 "무신사 44색" 하나로 뭉쳐 쓰던 것을 **재는 대상이 다른 세 값으로 분리**한다. 어느 것도 폐기하지 않는다.

| 값 | 무엇을 재나 | 출처 |
|---|---|---|
| **54색** | 무신사가 제공하는 색 필터 전체 | 사이트 직접 확인(반소매 티셔츠 `/category/001001`, 2026-08-04) |
| **53종** | 우리가 수집한 상품에 실제 등장한 색 | `m_raw_facets` → `musinsa-vocab.ts` 자동 생성 |
| **44색** | **바탕색 기준표에 쓸 수 있는 색** | **팀 실측 판단**(태깅 repo `cfe4e84`) |

- **어떻게 발견했나**: 멘토링 발표자료 준비 중 문서의 숫자를 코드와 대조하다 불일치를 발견 → 무신사 사이트를 직접 열어 전수 대조.
- **54 vs 53 = `흑청` 1개**. 흑청 상품이 우리 수집 카탈로그에 한 건도 없어 facet에 안 잡혔다. vocab은 "무신사가 제공하는 색"이 아니라 **"우리가 실제로 수집한 상품에 등장한 색"**이므로 정상 동작이다.
- **54 vs 44 = 10색**. 바탕색 기준표는 **ΔE(Lab 거리) 비교**로 검증하는데, 대표 RGB 하나로 환산이 안 되는 색은 기준표에 넣을 수 없다 — 청 워싱 5(데님·연청·중청·진청·흑청)·메탈릭 3(골드·실버·로즈골드)·클리어·기타색상. **이 제외 판단은 스크립트가 만들 수 없는 값이고, 사람(시각속성 검증)이 내린 것이다.**
- **왜 셋 다 남기나**: 앞의 둘은 "무신사에 무엇이 있는가"를 재고, 44는 **"그중 우리가 색으로 검증할 수 있는 것이 무엇인가"**를 잰다. 대체 관계가 아니다. 문서에서 **용도를 밝히지 않고 숫자만 쓰는 것**이 이번 혼선의 원인이었다.
- **문제정의에 미치는 영향: 없음.** 핵심 주장("색 필터는 상품 대표색 1개 기준이라 바탕/프린트 조합 축이 없다")은 색 개수와 무관. 요구사항·지표·스키마 불변.
- **감수한 것(플래그)**: 54색은 **반소매 티셔츠 카테고리 1회 관측**이다 — "무신사 전체가 54색"으로 일반화하지 않는다. 무신사가 색 체계를 바꾸면 vocab 재생성(`gen_musinsa_vocab.py`) + 기준표 재검토.
- **후속 조치**: root README·product-methodology README(D14)·PRD §1·§7·customer-profile·problem-validation·context·data-feasibility 정정(2026-08-04 처리).

- **결정**: Loop1 모집 표본을 **클라이밍 단독**으로 좁힌다. 세그먼트 정의(D17 문제 축)는 건드리지 않는다.
- **이유**: 문서를 다시 훑다가 크로스핏의 근거가 비어 있는 걸 발견했다. 7/31 VoC 4번 조사에 **크로스핏 언급이 0건**이다(러닝은 11회). 표본에 넣은 근거는 "주변에서 모집 가능" 하나뿐이었고, "클라이밍과 구조가 같다(실내 시설·굿즈 티·등 노출)"는 것도 검증한 게 아니라 우리 추정이었다.
- **왜 지금 빼는가**: 검증 안 된 종목이 표본에 있으면 인터뷰 결과를 어디까지 일반화할 수 있는지가 흐려진다. 표본을 늘리는 것보다 **표본의 근거를 아는 것**이 Loop1에서 더 중요하다.
- **문제정의에 미치는 영향: 없음.** D2·요구사항·지표 불변.
- **감수한 것(플래그)**: ① 표본이 한 종목뿐이라 편중이 더 커졌다. ② 인터뷰 3~5명을 전부 클라이머로 채워야 하는데 섭외는 팀원 1명에게 달려 있다. ③ 클라이밍은 같은 조사에서 트리거가 가장 약했던 종목(1건)이다 — 즉 지금 표본은 "검증에서 최약인 종목 단독"이다.
- **되돌리는 조건**: 러닝 모집 경로가 생기면 **러닝을 우선 추가**한다. 크로스핏 복귀가 아니다. 러닝은 같은 조사에서 25건으로 1위였고 한국어 사례가 나온 유일한 종목이다.
- **후속 조치**: PRD §4·§10·머리말, customer-profile, interview-guide, mvp-plan, problem-validation, context, README 2곳 갱신(2026-08-03 처리). customer-profile에 러닝 확장 후보 프로필 신설.

### 중간 의사결정 — 무신사 수집 범위: 포트폴리오 범위에서 진행 (2026-07-30 기록, D16)
- **결정**: 공식 오픈 API가 없다는 이유로 멈추지 않는다. **사이트에 공개된 상품정보를 소량·저빈도로 수집**해 포트폴리오·비상업 범위에서 진행한다.
- **이유**: 상품 정보 자체는 무신사 사이트에 공개돼 있고, 이 프로젝트의 산출물은 판매·수익화가 없는 검증용 MVP다. 6주 안에 약관 원문 해석까지 끝내려다 카탈로그가 멈추면 정작 검증할 게 없어진다.
- **명시적으로 주장하지 않는 것**: "그러므로 상업적으로 문제없다"는 **아니다.** 약관 원문 미확인 상태이고, **상업화·서비스화 시점에는 원문 확인이 선행 조건**이다. 발표·문서에서 이 선을 넘지 않는다.
- **지키는 것**: 소량·저빈도 수집, 리뷰는 샘플만(D5), 수집 코드에 레이트리밋 유지.

### 중간 의사결정 — 캐파 전제 재정의: "1인" → 코드 1인 + 검증 3인 (2026-07-30 기록)
- **결정**: data-feasibility의 현실성 판단 기준을 "6주/1인"에서 **두 개의 예산(코드 1명 / 사람 검증 3명)**으로 분리(§0 신설). 종합 섹션은 무신사 기준으로 재작성.
- **이유**: 기존 서술이 팀을 1인으로 축약해 **비개발 3명의 캐파를 문서에서 지우고 있었다.** 실제로 색 기준표 실측·태깅·오답률 집계는 전부 그 3인 캐파의 산출물이고, D6 파이프라인(자동추출→사람 샘플검증)이 그 위에 서 있다. 또한 종합 섹션이 D14 이후에도 폐기된 네이버 API를 뼈대로 가리키고 있었다.
- **왜 중요한가**: "사람이 더 붙으면 되는 문제"(태깅·검증·인터뷰)와 "붙어도 안 되는 문제"(크롤링 차단·약관·모델 성능)를 섞지 않게 된다. 리뷰 크롤링 비권장 결론은 후자라 캐파와 무관하게 유지.
- **발표 서사**: "개발 1명이라 자동화에 다 걸 수 없었다 → **사람 3명이 검증 루프를 돌려 정확도를 담보했다**"가 이 팀 구성의 실제 이야기이고, 이전 문서는 그 절반만 쓰고 있었다.

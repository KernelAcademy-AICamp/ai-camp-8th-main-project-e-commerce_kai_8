# 고객 인터뷰 가이드 (실사용자 회고)
> 유형: living · 2026-07-27 · 방법: The Mom Test 기반 열린 질문 중심 반구조화 인터뷰 (30분) + 앵커 2문항
> 대상: **배포된 웹페이지를 스스로 써본 실사용자** · 목표 n = 3~5명(운동 종목 혼합 — D19 범위 = 스포츠 프린팅 티 전반)
> 연계 문서: [customer-profile](customer-profile.md) · [problem-validation](../foundation/problem-validation.md) · [metrics](metrics.md)

## 0. 이 인터뷰로 알고 싶은 것 (목적)

Loop1 정량 지표(GA4 퍼널)만으로는 **"왜"** 가 안 보인다. 실사용자를 만나 정성으로 그 "왜"를 채우고, 문서에 남아있는 미해결 과제를 검증한다.

| 검증 타깃 | 왜 필요한가 | 근거 문서 |
|---|---|---|
| **JTBD 일반성** | n=1(팀 내 클라이머)의 "등판 그래픽 티를 못 찾음" pain이 다른 사람에게도 실재하는가 | customer-profile 미해결, problem-validation 종합 |
| **트리거 검증 (D17)** | 두 진입 트리거("등판이 보인다"·"장비색 맞춤")를 **스스로** 말하는가. 세그먼트 정의는 문제 축이고, 두 트리거가 다 안 나오고 조합검색 필요도 자발 언급이 없으면 축 재검토 신호(PRD §11 Kill ③) | customer-profile 세그먼트 축, README D17 |
| **굿즈 vs 기성품 (반증)** | 원하는 게 암장·박스 굿즈 티라면 무신사 기성품 카탈로그로는 못 푼다 | customer-profile 통찰4·미해결 |
| **사용성·오검색** | 실제로 원하는 걸 찾았나 / 어디서 막혔나 / 카드 정보·색 분리가 통했나 | metrics 가드레일(오검색 체감) |
| **대안 충분성(반증)** | 네이버·무신사·SPIRI7·인스타 공구로 이미 충분한 것 아닌가 | problem-validation 남은 리스크 |
| **구매 진입(북극성) 정성** | '상품 보러가기'를 눌렀나/안 눌렀나, 그 순간 무엇이 확신/불안을 줬나 | metrics 북극성 = outbound 클릭 |

> **핵심 원칙**: 이 인터뷰는 우리 가설을 *확인*하러 가는 게 아니라 *반증*하러 간다. "이거 좋죠?"가 아니라 "실제로 뭘 어떻게 했는지"를 듣는다.

## 1. 방법론 원칙 — 열린 질문으로 무의식을 끌어내기

직접 질문("편했어요?", "쓸 것 같아요?")은 사용자가 **머리로 지어낸 답**(합리화·희망사항·예의성 칭찬)을 끌어낸다. 우리는 **실제로 겪은 행동과 감정**을 끌어내야 한다. 아래 기법을 스크립트 전체에 적용한다.

1. **스토리 재생(Grand-tour)** — 가정이 아니라 사건을 묻는다.
   - ❌ "검색이 편했나요?" → ⭕ "가장 최근에 티 찾던 그때로 돌아가 볼게요. 그날 뭘 하고 있었고, 어쩌다 찾기 시작했어요?"
2. **래더링(왜를 계속)** — 표면 니즈 → 무의식적 동기까지 내려간다.
   - "신발색이랑 맞추고 싶었다" → "그게 왜 중요했어요?" → "…" (기능 요구 뒤의 정체성·소속감까지)
3. **투사형(Projective)** — 방어를 낮춘다.
   - "친구가 '그거 뭐야?' 물으면 뭐라고 설명해요?" / "이 검색이 사람이라면 어떤 점원 같았어요?"
4. **침묵·에코·중립 프롬프트** — 유도 없이 더 끌어낸다.
   - "…음, 그래서요?" / "방금 '짜증났다'고 하셨는데, 그 장면 좀 더요."
5. **화면 회상 자극(retrospective think-aloud)** — "그때 화면 다시 띄워놓고, 그때 생각을 소리 내서 말해주세요."

### 하지 말 것 (유도·오염 방지)
- 우리 가설(색 분리·백프린팅 카드·기능성 필터)을 **먼저 설명하지 않는다.** 사용자가 스스로 꺼내야 신호다.
- 칭찬을 유도하거나 받아 적지 않는다("멋지다", "좋은 아이디어네요"는 데이터가 아님).
- 미래·가정을 **행동의 대용으로** 묻지 않는다("~하면 쓰실래요?"). 행동은 과거의 구체적 사건으로 확인한다. — 단, **재사용/구매 의향·매직완드**처럼 의도된 *태도·발산* 질문은 예외이며, 이건 행동 사실과 **분리해** 분석한다(뒤 앵커·블록6).
- 두 개를 한 번에 묻지 않는다(더블배럴). 한 번에 한 질문 — 아래 스크립트의 팔로업 묶음도 그대로 읽지 말고 하나씩.
- 내가 답을 채우지 않는다. 침묵을 견딘다.

## 2. 대상 & 모집

- **대상**: 배포된 검색 페이지를 실제로 사용해 본 사람(자발적 사용자 우선).
- **스크리닝(2~3문항, 사전)**: ① 최근 3개월 내 운동 경험(종목 무관 — **종목을 기록**), ② 운동용/일상용 티를 온라인에서 찾아본 적 있음, ③ 우리 페이지를 최소 1회 실사용.
  - ⚠️ **"튀는 색 장비 쓰세요?"는 스크리닝에서 묻지 않는다.** 그게 우리 가설이라 미리 물으면 표본이 오염된다 — 트리거는 블록2에서 **스스로 나오는지**로 본다.
- **목표 인원**: 3~5명(customer-profile·problem-validation의 필수 산출물 기준). **모집 = 운동 종목 혼합**(D19 — 범위가 스포츠 프린팅 티 전반이라 한 종목으로 고정하지 않는다). 실제 구성은 모집 가능한 종목부터이고 **최소 1명은 클라이머**(섭외는 클라이머 팀원이 오너). 러닝·라이딩은 지금 모집 경로가 없다. 누가 모이느냐는 **세그먼트 정의가 아니라 연줄 모집 편의**이므로(D17), **결과를 축 전체로 일반화하지 않는다.**
  - ⚠️ **종목을 반드시 기록하고 결과를 종목별로 쪼개 읽는다.** VoC 4번 조사에서 종목별 신호 편차가 컸고(러닝 25 ≫ 골프 11 > 테니스 3 ≫ 클라이밍 1) "스포츠 전반으로 넓히면 신호가 희석된다"는 경고가 있었다. 대응은 표본을 좁히는 게 아니라 **분해해서 보는 것**이다.
- **사례**: 커피 기프티콘 등 소액 사례(선택). 사례가 칭찬 편향을 만들지 않도록 "솔직한 혹평이 가장 도움 된다" 사전 고지.

## 3. 모더레이터 준비 체크리스트 (인터뷰 전/시작 시)

- [ ] 녹취(오디오/화면) **동의** 받기 — 목적·보관기간·삭제방침 고지. **동의 없으면 녹음하지 않는다**(메모만 진행). 동의 여부·녹음파일 ID·삭제예정일은 아래 템플릿에 기록.
- [ ] "정답 없음 / 제품이 아니라 **제품을 평가받는 자리** / 혹평 환영" 톤 세팅
- [ ] 참여자가 **실제로 썼던 검색어·화면**을 다시 띄울 수 있게 준비(가능하면 화면 공유)
- [ ] 기록자 1명 분리(모더레이터는 대화에 집중) — 어려우면 녹취 후 정리
- [ ] 타이머(블록별 시간 배분) · 아래 응답 템플릿 열어두기
- [ ] 첫 5분은 절대 우리 제품 설명 금지(라포·배경 먼저)

## 4. 인터뷰 스크립트 (30분 · 6블록)

각 블록: **메인(열린) 질문 → 팔로업 프롬프트 → ⚠️ 이렇게 묻지 마세요**.

> **팔로업은 한꺼번에 읽는 대본이 아니다.** 아래에 `·`로 나열한 프롬프트는 상황 봐서 **하나씩, 답을 기다린 뒤** 골라 쓰는 후보다(더블배럴 금지 — §1).

### 블록 0 — 오프닝 & 세팅 (2분)
- "오늘 편하게 대화하듯 하면 돼요. 정답은 없고, 제가 만든 걸 평가받는 자리라 **혹평일수록 도움**이 돼요. 녹음해도 괜찮을까요?"
- 워밍업: "요즘 운동은 자주 하세요?"

### 블록 1 — 배경 & 맥락 (4분) · *세그먼트 확인*
- **메인**: "무슨 운동을 얼마나 하세요? 어떤 스타일로 하시는지도요."
- **메인**: "운동할 때 입는 티는 보통 어떻게 마련하세요? 마지막으로 산 티 얘기 좀 해주세요."
- 팔로업: "운동할 때 쓰는 신발이나 장비는 어떤 거 쓰세요?" ← **색은 먼저 묻지 않는다.**
- ⚠️ **"등판"·"남들이 본다"는 절대 먼저 꺼내지 않는다.** 그게 D17 축이라 우리가 말하면 검증이 아니라 주입이 된다. 사용자가 "뒤에서 보이니까", "등에 뭐 있는 거 좋아해서" 같은 말을 **스스로** 하는지가 신호.
- 팔로업: "그거 어디서 어떻게 골랐어요?" · "고를 때 뭘 제일 봤어요?"
- ⚠️ "패션에 관심 많으시죠?" (가정·유도) → ⭕ "옷 고를 때 어떤 걸 신경 쓰세요?"

### 블록 2 — 최근 실제 경험 재구성 (6분) · *JTBD 일반성 (핵심)*
> 여기서 '등판 / 남들이 본다 / 백프린팅 / 기능성' 같은 우리 언어를 **절대 먼저 꺼내지 않는다.** 사용자가 스스로 말하는지가 검증 포인트.
- **메인(Grand-tour)**: "가장 최근에 '이런 티 하나 있으면 좋겠다' 싶어서 찾아봤던 때로 돌아가 볼게요. 그날 상황이 어땠어요? 뭘 하다가 찾기 시작했어요?"
- 팔로업: "그때 머릿속에 어떤 티를 그리고 있었어요?" · "어디서(어느 앱/사이트) 어떻게 찾았어요?" · "그래서 어떻게 됐어요 — 찾았어요, 못 찾았어요?"
- **래더링**: (색/그래픽/기능성 언급 시) "그게 왜 중요했어요?" → 한 번 더 "왜요?"
- 투사형: "그 티를 결국 어디서 어떻게 해결했어요(직구·중고·포기 등)?"
- ⚠️ "장비색이랑 맞추려고 찾은 거죠?" (우리 가설 주입) → ⭕ "그 티, 왜 하필 그런 걸 찾고 있었어요?"

### 블록 3 — 우리 페이지 실사용 회고 (8분) · *사용성·오검색 (핵심)*
> 가능하면 **그때 화면을 다시 띄워** think-aloud.
- **메인(재현)**: "우리 페이지 쓰셨을 때 화면 다시 볼게요. 처음 들어와서 뭐부터 하셨는지, 그때 생각을 소리 내서 말해주세요."
- 팔로업: "그때 검색창에 뭐라고 쳤어요? 왜 그렇게 쳤어요?" · "결과 보고 첫 느낌이 어땠어요?" · "여기서 막히거나 헷갈린 데 있었어요?"
- **핵심(비유도) 프로브**: "결과에 나온 걸 보고 '이건 내가 찾던 거랑 다르다' 싶었던 게 있었어요? 있었다면 어떤 점이?" (→ 오검색 체감)
- 투사형: "이 검색을 친구한테 설명한다면 뭐라고 해요?"
- ⚠️ "바탕색이랑 프린팅색 따로 검색되는 거 좋았죠?" (기능 자랑·유도) → ⭕ "결과가 어떻게 나왔을 때 '오 이거네' 혹은 '어 아닌데' 싶었어요?"

### 블록 4 — 대안 비교 (4분) · *대안 충분성 반증*
- **메인**: "이거 말고, 그런 티 찾을 때 원래 쓰던 데가 있어요(네이버·무신사·인스타·중고 등)?"
- 팔로업: "그것들이랑 비교하면 이번엔 뭐가 달랐어요 — 나은 점, 못한 점?" · "원래 쓰던 걸로 돌아갈 것 같아요, 아니면?"
- 반증 프로브: "사실 원래 쓰던 걸로도 충분하지 않아요? 굳이 이게 필요한 순간이 있었어요?"
- ⚠️ "우리가 훨씬 낫죠?" → ⭕ "솔직히 어디가 더 편했어요, 왜요?"

### 블록 5 — 구매 진입 & 의향 (4분) · *북극성(outbound) 정성 + 앵커*
> 열린 탐색을 **먼저** 하고, 블록 끝에 앵커 2문항을 유도 없이 던진다.
- **메인(열림)**: "결과 보다가, 실제로 '이건 좀 사고 싶다' 싶은 게 있었어요? 그때 어떻게 하셨어요?"
- 팔로업: "그 순간 뭘 보고 사고 싶어졌어요 / 뭐가 걸려서 안 눌렀어요?" (확신 vs 불안 요인)
- **⚓ 앵커 1 (행동 사실)**: "실제로 '상품 보러가기'까지 눌러서 쇼핑몰로 나가 보셨어요?" → **예 / 아니오** *(GA4 `outbound_click`와 대조용. 단 현재 `client/shared/analytics.ts`의 `track()`는 no-op이고 GA4 연동은 Loop2 예정 — 계측 라이브 전이면 **자기보고로만 기록**하고 로그 대조는 Loop2로 보류)*
- **⚓ 앵커 2 (태도 척도)**: "이 검색으로 찾은 티, 실제로 **살 마음**이 **1~5** 중에 몇이에요? 그 숫자인 이유는요?" *(metrics `purchase_intent_rated`(=구매의향)와 의미 일치. 재사용 의향이 아니라 **구매 의향**을 묻는다.)*
- ⚠️ 앵커를 블록 앞에 두거나, 숫자만 받고 이유를 안 물으면 안 됨.

### 블록 6 — 마무리 (2분) · *발산*
- **매직완드**: "마법 지팡이로 이 검색에서 딱 하나 바꿀 수 있다면 뭘 바꿀래요?"
- **딱 하나**: "오늘 얘기 중에 '이건 꼭 알아줬으면' 싶은 거 하나만."
- **안 물어본 것**: "제가 안 물어봤는데 중요한 게 있을까요?"
- 소개 요청(스노볼): "비슷하게 티 찾느라 고생하는 분 아세요? 소개해주실 수 있어요?"

## 5. 응답 기록 템플릿 (참여자 1명당)

> **사실(관찰가능)과 의견(해석)을 분리**해서 적는다. 인용은 **말 그대로** 옮긴다(요약·미화 금지).

## 6. 분석·정리 (인터뷰 후, 3~5명 종합)

1. **인용 기반 정리**: 참여자별 강한 육성을 검증 타깃(§0 표)에 매핑.
2. **JTBD 일반성 신호**(일반화 '판정' 아님): "색/백프린팅/기능성을 *스스로* 언급한 사람 수 / n"은 자발 참여 3~5명 표본이라 모집 편향이 크다 → **질적 지지/반증 신호**로만 다룬다. **세그먼트별 커버리지와 부정 사례(언급 안 한 사람의 이유)를 함께 기록**하고, 다수/소수는 결론이 아니라 다음 리서치 방향(트리거 재정의·표본 확대)으로 연결(customer-profile 미해결 갱신).
3. **정성 × 정량 대조**(계측 라이브 시): 앵커1(말한 outbound) vs GA4 `outbound_click`, 앵커2 평균 vs 퍼널. 어긋나면 그 갭 자체가 인사이트. **단 `track()`가 no-op인 Loop1 동안은 로그 대조를 보류**하고 자기보고만 정리한다.
4. **오검색 패턴**: 블록3의 '안 맞음' 사례를 속성별(색/사이즈/소재)로 묶어 추출 정확도 가드레일에 연결.
5. **대안 반증 결과**: "기존 대안으로 충분" 다수면 가치제안 재검토, 소수면 차별점 확증.
6. **Loop1 판정 반영**: metrics의 Loop1 지속/피봇 기준(§루프별 판정)에 정성 근거로 첨부하고, [iterate-log](iterate-log.md)에 요약 기록.

> 산출물: 참여자별 기록 + 종합 인사이트 1페이지(강한 인용 3~5개 + §0 타깃별 판정 + 다음 액션). customer-profile·problem-validation의 "인터뷰로 검증" 항목을 이 결과로 업데이트한다.

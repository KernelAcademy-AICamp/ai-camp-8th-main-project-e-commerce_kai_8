## 1. 배경과 문제 정의

### 무엇이 문제인가

사람들은 옷을 **'보이는 속성'의 조합**으로 설명한다. 바탕색, 프린트색, 프린트위치, 그래픽처럼 눈에 보이는 것들이다. 그런데 검색과 필터는 그 축을 주지 않는다. (첫 타겟 정의는 §4)

이건 프린팅 티만의 문제가 아니다. 사진 없이 옷을 설명할 땐 예외 없이 이렇게 쪼개서 말하고, 이건 두 언어권에서 재현됐다([voice-of-customer](../foundation/voice-of-customer.md) §3). **프린팅 반팔티로 좁힌 건 문제가 좁아서가 아니라 6주 안에 검증할 범위를 정한 것이다**(§6).

무신사에는 상품도 있고 54색 공식 색 필터도 있다. 하지만 색 필터는 상품 대표색 1개를 기준으로 하기 때문에, "바탕은 흰색인데 백프린팅만 노란색" 같은 조합을 표현할 축이 없다. 검색도 키워드 매칭이라 조합 질의를 해석하지 못한다.

결과 화면에 나오는 것도 대표 썸네일뿐이다. 쇼핑몰이 등판을 대표컷으로 쓰지 않으니 등을 보려면 상품마다 상세페이지를 열어야 하고, 소재와 사이즈도 마찬가지다. 등판 그래픽 색은 상품 대표색에도 잡히지 않는다.

팀 내 클라이머가 네이버와 무신사에서 4시간을 탐색하고 실패했다(직접 관찰).

### 근본 원인

근본 원인은 속성을 구조화하는 축이 사용자의 탐색 언어와 어긋나 있다는 것이다. 그래서 우리는 무신사 위에 '발견 레이어'를 얹는다. 어긋난 두 언어를 잇는 변환, 즉 사용자의 말을 속성으로 옮기는 일을 LLM이 맡는다(§7).

### 진입 트리거 (가설)

사용자가 이 축을 원하게 되는 진입 트리거로는 두 가설이 있다. 하나는 운동 중 남에게 보이는 게 등판이라 등판 그래픽 티를 원한다는 것, 다른 하나는 튀는 색 장비에 옷 색을 맞춘다는 것이다(관찰된 원사례: 노란 클라이밍화에 맞출 백프린팅 티). 둘 다 세그먼트를 정의하는 조건이 아니라, Loop1 인터뷰에서 자발 언급으로 검증할 가설이다.

근거: [problem-validation 5Why 재정립](../foundation/problem-validation.md). 데이터 소스 = 무신사(D14), 첫 타겟 = 축 기준 재정의(D17, §4), 수집 범위 = 포트폴리오(D16).

## 2. 목표 (SMART)

- 6주 안에 3×2주 린 루프로 MVP를 배포한다. 각 루프가 끝날 때마다 GA4 데이터와 인터뷰에 기반한 의사결정을 1건씩 문서로 남긴다([iterate-log](iterate-log.md)).
- Loop 1 종료 시점에 세 가지를 확보한다. 배포 URL, 속성 추출 정확도 베이스라인, 검색 성공률 베이스라인 측정.
- 이 프로젝트의 핵심 성과는 제품 자체가 아니라 **"데이터로 의사결정하는 과정"을 3루프로 입증하는 것**이다.

## 3. 성공 지표 → 상세 [metrics.md](metrics.md)

- **북극성**: 검색 세션당 "구매 진입(상품 페이지 이동 · outbound 클릭)" 비율 / 구매 진입까지 시간
- **선행**: 검색 성공률·CTR·상세 도달률·**구매 진입 클릭률**·구매의향·탐색시간
- **가드레일**: no-result율·오검색 체감
- **H2(가치) 측정 = 과제 기반**: 인터뷰이에게 고정 과제("이런 티 찾아보세요")를 주고 **우리 검색 vs 무신사**에서 탐색시간·성공 여부를 비교 측정(실사용 GA4 로그는 보조). 타이머 시작·성공/실패 판정·timeout(5분, 잠정)·비교 순서 교차 등 **측정 프로토콜은 [metrics.md](metrics.md) "H2 측정 프로토콜"이 원본**이다. "4시간→수분" 류 탐색시간 주장은 **이 과제 기준으로만** 하고, 과제 소요 시간은 GA4 세션 길이와 **섞지 않고 따로 보고**한다.
- 부트캠프 규정: GMV·구매CVR·Add-to-Cart 직접개선 주장 금지 → 선행지표로 검증

## 4. 타겟 → [customer-profile.md](customer-profile.md)

**타겟 정의 = "운동할 때 입을 티도 취향으로 고르는 사람"** — 운동복도 '보여지는 나'로 여겨 색·그래픽·조합까지 취향대로 고르는데(연령 무관), 원하는 조합(바탕색×프린트색×위치)을 지금 도구로는 표현할 축이 없어 매번 탐색에 실패한다. **나이로 정의하지 않는다** — 사람을 가르는 변수는 연령대가 아니라 '운동복을 취향으로 고르느냐'는 행동이다.

'등판이 보인다'·'장비색을 맞춘다'는 이 축을 원하게 되는 **두 진입 트리거(가설)**일 뿐, **정의에 넣지 않고** Loop1 인터뷰에서 자발 언급으로 검증한다(§5 JTBD·§7-1의 '등판'은 이 트리거의 예시). 검증된 하한선은 **문제 축**(프린팅 티를 바탕색×프린트색×위치 조합으로 못 찾음 — VoC 웹 검증).

**범위 = 스포츠 프린팅 티셔츠 전반**(VoC 조사 종목 전체 — 러닝·클라이밍·크로스핏 등, D19)이고 **Loop1 모집 표본도 한 종목으로 고정하지 않는다**(종목 혼합, 실제 구성은 모집 가능한 종목부터 · 최소 1명 클라이머 — 연줄 모집 편의). 종목별 신호 편차가 크므로 **인터뷰에서 종목을 기록해 결과를 종목별로 쪼개 읽는다.** 상세 [customer-profile.md](customer-profile.md). (첫 타겟=beachhead)

## 5-1. 사용자 시나리오

> 성공 = 관찰 가능한 한 행동(구매 진입 클릭).

1. 노란 클라이밍화를 새로 산 사용자가 검색창에 **"흰 바탕에 노란 백프린팅, 오버핏"** 입력
2. 결과 카드에서 **등판 컷 + 바탕/프린팅 색칩 + 핵심속성**(핏·소재·사이즈유무)으로 한눈에 비교
3. 마음에 드는 티의 **무신사 상품 페이지로 이동** = 구매 진입(성공 행동, GA4 기록)

엣지 흐름(케이스만 명시 — 구현 방법은 열어둠):
- (a) **결과 0건** → no-result 이벤트(가드레일) + 조건 완화 제안.
- (b) **조건 일부만 맞음** → 부분매칭을 랭킹으로 노출하되 **어떤 조건이 빠졌는지** 카드에 표시.
- (c) **파싱 애매**("파란 느낌 티") → 최선 해석 결과 + 사용자가 바로 고칠 수 있는 장치(재질문/필터 편집).

## 6. 요구사항

> **MVP 범위 = 프린팅 반팔티 한 카테고리.** 문제 자체는 품목에 걸려 있지 않지만(§1), Loop1에서 검증 가능한 크기로 카테고리를 하나만 연다.

### P0 (Loop 1)

- **카탈로그**: Supabase 적재 전체(1,685행, 선별 풀)에서 무신사 프린팅 반팔티 **50~100개** 큐레이션(D14) = **Loop1의 평가·노출 대상**. 적재 전체는 MVP 대상이 아니며, **정확도·검색 지표의 분모는 이 50~100개에 고정**한다(→ [metrics.md](metrics.md))
- **속성 추출**: 상품 이미지 → **비전 LLM 단일 호출 → JSON**. 스키마 아래 §7.
- **검증 루프**: 자동추출 → 사람 샘플 검증(속성별 정확도) → 임계 미달 속성은 검색 노출 제외/플래그
- **자연어 검색**: 쿼리 → LLM 파싱(속성화) → 속성 필터·랭킹
- **결과 카드**: 등판 이미지 · 추출 색칩(바탕/프린팅) · 핵심속성(핏·소재·사이즈유무) 미리 노출
- **상품 페이지 이동(구매 진입, outbound) 링크** + **GA4 계측**(§metrics 이벤트) + Vercel 배포

### P1 (Loop 2~3)

- 카탈로그 확장(200~500) · 추출 정밀화(색 분리 OpenCV 보조/OCR) · 신발색 매칭 훅 · 필터 고도화

### P2 (v2+)

- 리뷰 본격 · 비주얼 유사검색 · 대화형 재질문 · **확장 종목**(러닝·라이딩·스케이트/서핑 — 축엔 맞으나 Loop1 미검증) · 장비색 매칭 훅

## 7. 데이터·기술

**왜 LLM인가.** 사용자가 쓰는 말("흰 바탕에 노란 백프린팅")과 DB의 속성 사이를 이어주려면 자연어를 속성으로 옮기는 단계가 필요하다. 키워드 매칭으로는 조합 질의가 해석되지 않고(§1), 상품 이미지에서 바탕색과 프린트색을 나눠 읽는 것도 규칙으로는 안 된다. LLM은 그 변환기로 쓰는 것이지 그 자체가 목적이 아니다.

- **속성 스키마**: 바탕색 / 프린팅색 / 프린팅위치(앞·뒤·전체) / 그래픽유형(레터링·캐릭터·로고·패턴) / 핏(오버·레귤러·슬림) / 소재·기능성(면·폴리·기능성; 추정 플래그) / 사이즈(유무·프리) / 가격 / 몰링크·이미지
- **아키텍처(안)**: 무신사 상품 수집(백엔드) → 이미지 비전LLM 추출(**Loop1 = 비전 LLM 단일 호출 단독. OpenCV/OCR 보조는 Loop2/P1 정밀화** — D12 ·[data-feasibility §5](../foundation/data-feasibility.md)) → 속성 DB(Supabase) → 검색(쿼리 LLM 파싱→속성 랭킹) → 프론트(Next.js + shadcn) → Vercel 배포 → GA4 로그
- **색 기준**(용도가 다른 두 값 — → [iterate-log 2026-08-04](iterate-log.md)):
  - **라벨링 어휘 = 우리 카탈로그 색 어휘 53종** — 바탕색·프린팅색 추출 결과를 이 어휘로 표기하고 필터도 같은 축을 씀
  - **바탕색 검증 기준표 = 44색** — 대표 RGB가 있어 ΔE(Lab 거리) 비교가 가능한 색만. 태깅 정확도 검증은 이 기준표로 한다
- **데이터 제약**(→ [data-feasibility §6](../foundation/data-feasibility.md)): 무신사 공개 API 없음 — 수집은 사이트에 공개된 상품정보를 소량·저빈도로(D16, 포트폴리오 범위). 소재(상품정보 고시) 필드 일관성 미실측 → 소재는 추정 플래그 유지, 리뷰는 소규모 샘플 실험만.

## 7-1. 디자인 고려사항

- 결과 카드는 **등판 컷 우선**(대표컷 아님) — 단 이는 **가설 A에 기댄 베팅**(Loop1서 검증), 확정 근거는 "대표 썸네일 부족 → 상세 노가다 제거".
- 바탕색/프린팅색 **색칩 분리 표기** — 조합 검색의 가치를 눈으로 증명(전 플랫폼 미해결 축, VoC §3)
- **구매 진입 링크는 카드에서 가장 분명한 자리에** — 성공 행동을 정하지 않으면 모든 요소가 같은 무게가 된다
- **모바일 우선** — 무신사 사용자 절대다수가 모바일. 좁은 폭에서도 등판컷+색칩+핵심속성이 **한 카드에 한눈에** 들어오게.
- **미확정 속성은 정직하게 표기** — 추정(소재 등)·추출 실패·임계 미달 속성은 "추정/모름"으로 구분 표기(확정값처럼 안 보이게). 검색 노출에서 제외된 속성은 카드에서도 단정하지 않는다.
- 필터·정렬 문법은 **무신사 UI를 표준 멘탈모델**로 따름 — 익숙한 것을 새로 발명하면 장벽

## 10-1. 경쟁 지형 (요약)

위험표 마지막 행의 근거다. 상세·출처는 [market-and-competition](../foundation/market-and-competition.md).

| 서비스 | 검색 방식 | 바탕색/프린트색 분리 | 프린트 위치 | 우리와 관계 |
| --- | --- | --- | --- | --- |
| **우리** | **자연어 조합** | **O(핵심)** | **O** | — |
| 무신사 자체 AI | 이미지+키워드 | ✕ | ✕ | 올라탈 플랫폼·최대 위협 |
| 네이버 Cue: | 자연어(범용) | ✕ | ✕ | 국내 자연어 근접 |
| 에이블리·지그재그 | 이미지 | ✕ | ✕ | 국내 이미지검색 |
| Daydream·Depict(해외) | 자연어 | ✕ | ✕ | 수요 증명 |
| Google·Amazon·Shopify | 키워드+필터 | ✕ | ✕ | 전 플랫폼 미해결 확인 |
| 무신사·네이버·29cm 필터 | 키워드+필터 | ✕(대표색 1개) | ✕ | 실패 지점 |

표에서 볼 것은 세 가지다.

- **빈 열이 우리 자리다.** 부위별 색 축은 확인한 범위 안에서 어디도 주지 않는다.
- **Daydream은 위협이 아니라 근거다.** "말로 찾는 패션 검색"에 이미 수요와 투자가 있다는 증거이고, 국내·무신사는 안 다룬다.
- **최대 위협은 무신사 자신이다.** 이미지검색·색상명 표기까지 왔다. 부위별 색 축을 자체 도입하면 차별점이 사라진다(§10 반증 모니터링).

⚠️ 전수 조사가 아니다. WebSearch가 미국 인덱스라 국내 소규모 서비스는 누락 가능하고, 지그재그 최신 AI 검색은 미확인이다. "국내에 없다"가 아니라 **"확인한 범위에선 못 찾았다"**로만 말한다.

## 11. 릴리즈·실험 계획

Loop 1(W1-2) 가치검증+최소추출 → Loop 2(W3-4) 데이터가 가리키는 곳 투자 → Loop 3(W5-6) 정밀화·확장·마감. 매 루프 GA4+인터뷰 → 의사결정([iterate-log](iterate-log.md)). 최종 산출물: PRD·배포URL·랜딩·인터뷰·인사이트 보고서·발표자료.

### Loop1 종료 게이트 — Kill / Pivot 기준
세 가설을 각각 신호로 본다. **하나만 실패 → 그 부분만 고쳐 Loop2(국소 수리). 두 축 동시 붕괴 → 전제가 틀린 것(킬/전면 피봇).**

- **① 기술(H1)**: 사람 검증에서 검색에 쓸 수 있는 핵심 속성이 **바탕색/프린트색/위치 중 2개 미만**이고 OpenCV·OCR 보조로도 안 오르면 → 스키마 축소·추출법 교체(피봇). (정확도 임계 수치는 Loop1 베이스라인 후 확정 — 미정 플래그)
- **② 가치(H2)**: 과제 기반 측정([metrics.md](metrics.md) 프로토콜 — 실패는 timeout 값으로 기록하고 **성공률과 함께** 본다)에서 우리 검색이 무신사 대비 탐색시간·성공률을 **유의미하게 못 줄이면** → 파싱·랭킹 개선(피봇). 재측정에도 차이 없으면 → 핵심 가치 부재(킬/전면 피봇). 단, 순서 효과와 구분이 안 되면 판정 보류 후 표본을 늘려 재측정.
- **③ 수요·축(H3)**: 인터뷰에서 **아무도 조합검색 필요("색 분리"·"뭐라고 검색해야 할지 모름")와 두 트리거(등판·장비색)를 자발 언급 안 하면** → 세그먼트/축 재검토(피봇). **굿즈 수요가 압도적**이면 → 세그먼트 킬.
- **종합 킬 라인**: **①(색 분리 추출 바닥) AND ③(축을 아무도 자발 언급 안 함)이 동시에** 나오면 → 제품 전제가 틀린 것. 피봇(다른 문제/축) 또는 킬.

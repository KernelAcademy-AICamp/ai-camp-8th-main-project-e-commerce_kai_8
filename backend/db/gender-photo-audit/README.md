# 썸네일 모델 성별 전수 조사 (2026-08-23~24)

무신사 성별 라벨은 맞는데 **사진 속 모델이 반대 성별**인 상품을 사람이 눈으로 전수 판정한 기록이다.
적용은 [`20260824100000_photo_gender_verdicts.sql`](../../supabase/migrations/20260824100000_photo_gender_verdicts.sql).

## 왜 했나

사용자가 "남성으로 설정했는데 여성 상품이 자주 보인다"고 신고했다. 들어가 보니 **성별 필터는 정상**이었고,
지목한 상품(밀로키 `쿨 앤 쿨 반팔티`)은 무신사 라벨이 `남성`, 어깨 53cm로 치수도 정상 남성복이었다.
썸네일만 여성 모델이었다.

규칙 v1(제목 낱말·어깨 치수)이 원리적으로 못 잡는 것이다 —
[`20260822500000`](../../supabase/migrations/20260822500000_gender_label_flags.sql) 머리주석도
"남성복인데 여성 모델이 입은 사진 — 이미지 판별은 별도 작업"이라고 적어 뒀다.

**왜 "가끔"이 아니라 "자주"로 느껴졌나**: 무작위 피드 48장 표본에서는 여성 모델이 1장(2%)이었지만,
그 상품의 **유사 결과 48장에서는 약 11장(23%)**이었고 상위 1~5번이 전부 같은 밀로키 색상 변형이었다.
이미지 임베딩이 촬영 스타일을 인코딩해서, 이런 상품 하나가 들어오면 한 화면에 5~6장이 연달아 나온다.

## 어떻게 판정했나

1. **후보 좁히기** — `card_ok`이고 slot 0 썸네일이 착용샷(`img_type=0`)인 것.
2. **모델 채점** — SigLIP2 텍스트 프롬프트 6개(여성 3 / 남성 3, `siglip_prompts.txt`)를 임베딩해
   `c_img_vecs`의 이미지 벡터와 코사인 → softmax로 `p_female`을 매겼다.
   **검증**: 여성 라벨 62,726장 중 98.5%가 `p_female>0.5`(중앙값 0.985), 남성 라벨 중앙값 0.040.
3. **사람 눈 판정** — `p_female` 순으로 56칸 대조 시트를 만들어 **전수**를 봤다.
   판정은 세 갈래: **이성 단독**(제외) / **혼성**(유지 — 해당 성별 모델도 함께 나온다) / **동성·모델없음**(유지).
   애매하면 빼지 않는 쪽으로 판정했다.

## 결과

| 구간 | 대상 | 시트 | 확정 |
|---|---|---|---|
| 선행 + A — 남성 라벨 착용샷 | 38,029 | 793 + 502 | **여성 단독 3,619** |
| C — 여성 라벨 착용샷 | 62,671 | 1,120 | **남성 단독 754** |
| 혼성(남녀 함께) | — | — | 598 — **빼지 않음** |

발생률은 `p_female`에 강하게 붙어 있다(남성 라벨 기준):

| p_female | 여성 단독 |
|---|---|
| ≥ 0.10 | 36.1% |
| 0.05~0.10 | 0.6% |
| < 0.05 | 0.06% |

적용 후 영향: 남성 노출 −3.88%(3,619/93,326) · 여성 −0.84%(754/89,874).
밀로키 6개는 피드·유사 결과에서 사라졌고, 남성 피드 48장 표본에 남은 여성은 커플 촬영 1장뿐이다.

## 함께 나온 것 — 죽은 썸네일 285개

카드로 노출되는 썸네일 **226,196개를 전수 확인**했다. HEAD 조사와 GET 조사가 서로 달라
(HEAD는 200을 주고 GET은 404인 것이 있었다) 한 번이라도 실패한 297개를 **동시 4로 3회 재확인**해
**285개**를 확정했다. 여성 124 · 남성 103 · 공용 58, **찜과 겹침 0건**. 목록은 `dead_thumbs.txt`.

아직 지우지 않았다. 기존 절차 [`delete_dead_goods.sql`](../delete_dead_goods.sql)에 이 목록을 넣으면 된다.

## 잡지 못하는 것

- **착용샷이 아니라고 분류된 썸네일 82,356개는 보지 않았다.** `img_type` 분류기가 틀려서 모델컷이
  그쪽에 섞여 있을 수 있다 — 반대 방향 오류(단품컷이 착용샷으로 분류)는 판정 중 50건 넘게 확인했다.
- 사람 한 명의 1회 판정이다. 중성적인 모델은 오판 여지가 있다. `p_female` 0.70 아래부터 판단이 어려웠다.
- 갤러리 이미지는 보지 않았다 — 피드 카드가 쓰는 것은 썸네일뿐이다.
- **혼성 598건을 어떻게 할지는 미정**이다. 세어만 뒀다.

## 다시 돌리려면

카탈로그를 갱신하면 새 상품에는 판정이 없다.

1. `p_female`을 다시 매긴다 — `siglip_prompts.txt`의 벡터를 `c_img_vecs`와 코사인 후 softmax.
2. 미판정 상품만 `build_phase.py`로 시트를 만들어 사람이 본다.
3. 판정 결과를 `c_gender_photo_verdicts`에 넣고 `select c_gender_label_flags_rebuild();`.

되돌리려면 `delete from c_gender_photo_verdicts` 후 재계산한다.
